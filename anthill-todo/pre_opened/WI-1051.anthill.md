## description

DO WE TRACK AN ABSTRACT GAMMA DURING ABSTRACT INTERPRETATION? Open design question, deliberately PRE-OPENED — the answer shapes effect elimination and probably more, but the questions ahead of it (docs/brainstorms/rules-and-effects.md) are not settled and this should not be built first.

THE QUESTION. WI-580 derives an operation's equational and relational views from its BODY by abstract interpretation. WI-067 (delivered) discharges a guarded effect by REFUTING its guard from Gamma — the flow-sensitive logical environment — plus ground eval and the KB. Gamma's producers today are `if`-branch conditions, `match` arm facts, and match guards (WI-537/WI-550). The question is whether the abstract interpreter should itself carry and propagate a Gamma: an environment of facts about the intermediate values it computes, so that what it LEARNS while interpreting a body becomes available to guard refutation and to any other consumer that reasons about a term's value.

THE MEASUREMENT THAT RAISES IT (this session, driven):

    operation head(xs: List) -> xs.T effects { Error[EmptyStream] :- isEmpty(xs) }   -- list.anthill:223
    operation insert(c: List, elem: T) -> List = cons(head: elem, tail: c)           -- list.anthill:254

    operation probe(xs: List[T = Int64], e: Int64) -> Int64 = xs.insert(e).head()
      -> error: type mismatch in probe.effects (op-effects):
         expected declared: [], got undeclared effect: Error[T = EmptyStream]

`insert` prepends a `cons`, so `isEmpty(insert(xs,e))` is FALSE, so the guard is refuted, so the Error is not in the row — a guarded atom is 'present iff `guard` is not refuted' (node_occurrence.rs, proposal 048 / WI-478). It does not discharge, and the reason is NOT a missing refutation engine: the expression has no `if` and no `match`, so Gamma has no producer and says nothing about the argument. The fact needed — that `insert(xs,e)` IS a `cons` — is exactly WI-580's body-derived equation for `insert`, which nothing carries into Gamma.

SO THE NARROW VERSION is: can `refute_guard` / `prove_from_gamma` reach a callee's body-derived equation for an operation in ARGUMENT position? And the general version, which is the one worth deciding first: is Gamma a thing the abstract interpreter MAINTAINS as it goes (learning `v = cons(...)` when it interprets `insert(xs,e)`), or does it stay a purely syntactic flow environment fed only by branch conditions?

WHY IT IS BIGGER THAN EFFECT DISCHARGE — and why it is pre-opened rather than open: an abstract Gamma is a shared substrate, so its shape should be chosen against several consumers at once, not retrofitted for one. Known consumers: effect discharge (WI-067 tier 1); the value-precondition check (WI-539/WI-602, which already distinguishes a REFUTED obligation from a FLOATING one — the WI-067/WI-292 polarity, 'act on a DECIDED obligation, never on an UNDETERMINED one'); in-body proofs (WI-538); and the `[simp]` firing site, which is type-directed and already resolves the carrier. Note WI-537's two DEFERRED Gamma producers are the same shape of gap — a `let x = e` binding fact has no indexable Gamma form because a binder ref is `Expr::VarRef` -> `ViewHead::Opaque`, and binder/constructor pattern facts need a reified form (050 open question C). An abstract Gamma would have to answer those too.

RELATED, and possibly the same design: `has_effect` / `hasno_effect` as PREDICATES in the rule vocabulary (rules-and-effects.md Q4a). Guarded effects already condition an EFFECT on a PREDICATE; the dual — conditioning a RULE on the ABSENCE of an effect — has no spelling, and would need the row in a reified, queryable form. That is the same reification an abstract Gamma would want, and the same one Q7's 'both sides of an equation carry the same row' needs. Three consumers, one representation question — decide it once.

BEFORE STARTING: read docs/brainstorms/rules-and-effects.md. Q3 is DECIDED (effect-polymorphic => potentially effectful, one verdict; the post-typing simp mode is WI-1050, post-release). Q8 argues the direct-style surface cannot spell an effect-preserving law at all, which bounds what any of this buys for REWRITING — the payoff is likelier in proofs and in discharge than in simp. REFERENCE: WI-580 + docs/design/abstract-interpreter-and-rules.md §3.3; WI-067 (the two-tier discharge) + proposal 048; WI-537/WI-538/WI-539/WI-550/WI-602 (Gamma substrate and consumers); proposal 050 (local interpretation) open question C; WI-1049/WI-1050.

THE GUARDED DECLARATION IS ALREADY THE DEFINITION — so the per-label predicate needs no new analysis, and this is the strongest argument for the reification.

From the stdlib verbatim (int64.anthill:65):
    operation div(a: Int64, b: Int64) -> Int64 effects { Error[DivisionByZero] :- eq(b, 0) }
reads directly as
    effect_present(div(?a, ?b), Error[DivisionByZero]) :- eq(?b, 0)      -- the declaration, verbatim
    effect_absent(div(?a, ?b), Error[DivisionByZero])  :- neq(?b, 0)     -- its REFUTATION

MIND THE POLARITY: the absence side carries the REFUTATION of the guard, not the guard. `Err :- eq(b,0)` says the error is present WHEN b = 0, so absence is conditioned on neq(b, 0). Inverting this would license dropping the error exactly where it fires. (The conversation's sketch had it as `:- y = 0`; the correct reading is `:- neq(y, 0)`.)

And it must be CONSTRUCTIVE. WI-067 already decided this in the same words — 'drop the guarded element only on a positive proof of ¬G (never NAF)' — and framed the whole mechanism as 'SLD refutation over the effect-row-as-Horn-theory'. So this is not a new predicate so much as A NAME FOR ONE WI-067's DISCHARGE ALREADY COMPUTES.

WHAT THE HORN READING DOES NOT COVER IS EXACTLY THE Q3 BOUNDARY, which is a consistency check on both: a GUARDED atom has a clause; an UNGUARDED atom (s.E, {External}) has none, so there is nothing to refute; a row VARIABLE has none either. Both stay UNDETERMINED, and under never-NAF neither predicate succeeds there. The Horn reading buys the guarded case and leaves the polymorphic case exactly where Q3 put it.

NAMING: has_effect/hasno_effect are placeholders and should not survive.
