## Description

Custom unification / custom search at a discrimination-tree node: let a node delegate matching of a subterm to on-demand unification (over TermView) instead of materializing that subterm's structure into the trie. Today insert_walk materializes the FULL nested structure of every fact head as DiscrimNodes (multi-level structural dispatch) and queries descend the same way; for a non-discriminating / structurally-large / opaque-headed subterm this is wrong+wasteful. MOTIVATING CASE: an operation BODY (an Expr occurrence) nested in an OperationInfo fact -- its control-flow forms (let/if/match) read Opaque in occ_head (no DiscrimKey), so deep-indexing it (a) builds a per-body structural MIRROR in the trie that NO query prunes on, (b) needs occ_head to mirror the whole Expr enum (duplicating occurrence_term's reflection; occ_head is shared with the simp matcher), and (c) risks deep recursion (the simp engine had to go iterative for the same body depth, WI-278). THE FEATURE: at a node, switch to a custom-unification hook -- read the candidate's subterm via TermView on demand and unify it against the query's subterm -- so values like bodies can live in facts AND support discrim-level shape queries (e.g. 'operations whose body starts with let') WITHOUT a materialized trie mirror or an occ_head change. Two related themes: (a) custom unification (a discrim node delegates to a unify routine); (b) custom search (query descent driven by custom logic, not trie structure). DRIVING CONSUMER: the op_bodies -> OperationInfo.body collapse (WI-348 follow-up). The body is keyed data (op Symbol -> body) that should ALSO be a fact (everything-is-facts / proposal 022 / typing-as-transform). Until this feature exists, op_bodies stays as the keyed store behind the operation_body relation (body relationally readable today via the builtin; typer still mutates the side-table on the [simp] write-back). Design principle from the dialogue: a 'side index' should itself be a relation / the discrim tree, never a bespoke Rust map -- and the discrim tree already IS the Symbol->fact index via name: Ref(op). Acceptance: feature design + impl; cargo-test green.
