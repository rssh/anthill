## Description

GHC-style constraint inference for Sort.requires (future direction). Currently anthills Sort.requires is source-level explicit and the typer validates that body walking does not surface envs outside the declared set. Future direction: instead of declaring requires, let body walking generate them — the user lists operations and bodies, and the typer infers this sort needs requires A, Eq, ... as the inferred signature. This is what GHC does for top-level let bindings (foo x = show (x + 1) inferred as Num a, Show a context). Distinction: this is NOT conditional instance derivation (anthill already has that via Horn-clause facts + SLD resolution); it is signature inference for sort.requires from bodies. Trade-off: less syntax, less self-documenting (a user reading a sort declaration must walk all bodies to see what envs are required). Acceptance: design proposal landed in docs/proposals/ describing the inference algorithm, error messages for ambiguous inference, and migration path for existing sort declarations; cargo-test green with at least one inferred-requires sort in stdlib. Depends on operation-call-model decision shipping (the body-walk machinery enables this trivially once it is in place). Reference: docs/design/operation-call-model.md.
