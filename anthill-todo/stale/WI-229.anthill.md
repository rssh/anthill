## Description

Operation-call-model: let-binding hoist for repeated projection IR subexpressions. Follow-up to WI-226. When the requirement-insertion pass emits the same projection expression (requirement_at_current(slot=i), requirement_at_sort(chain, slot=k), or a construct_requirement(...) tree) more than once in a body, hoist the projection into a fresh let_expr(pattern: req_<n>, value: <projection>, body: <body with var_ref(req_<n>) substituted>) wrapping the body. At runtime the interpreter reduces the projection once into the let-bound local; subsequent var_ref(req_<n>) reads are O(1) frame-local lookups. Reflect IR's let_expr (stdlib/anthill/reflect/reflect.anthill:322) is already in place; no grammar change. Concerns this WI must address: (a) scoping interactions with already-existing let_expr in user bodies (don't shadow inner let-patterns, pick fresh symbol names); (b) cross-branch projections in match_expr / if_expr — hoist to the nearest common dominator or replicate per-branch; (c) lambda capture interaction — closures over var_ref(req_<n>) must capture the local from the enclosing let; (d) interpreter handling of the new let_expr form may need verification — most paths should already work since let_expr is part of the typed IR, but inserted-after-typing let_exprs may bypass type checks. Acceptance: cargo-test green; new tests pin (1) a body with three identical requirement_at_current(0) projections rewrites to one let_expr plus three var_ref's; (2) interpreter executes the rewritten body and produces the same Value as the un-hoisted form; (3) repeated projections inside an if_expr's then- and else-branches are not erroneously hoisted to a common position that changes evaluation semantics. Reference: docs/design/operation-call-model.md §'Pass structure'.

## Reason

Superseded by WI-234 (Model-1 redesign). Under the redesign, the apply_within requirements channel has a single entry (the dispatching dictionary), and the body's sub-instance accesses are var_ref to elaborator-synthesized named bindings — not repeated requirement_at_* projections — so there are no duplicates to hoist. Hoist pass is no longer needed.
