## Description

Finiteness Phase D (proposal library/003, OPTIONAL cleanup): replace the separate finite combinator carriers (FiniteMappedStream/FiniteFilteredStream) with conditional-instance reuse of the single mapped/filtered carrier — 'a mapped stream is finite when its source is finite' via the witness-sort + requires pattern (EqList precedent). NOT LANDED, and why. The stdlib consolidation needs THREE more things; one is a design detail, two are kernel gaps.

(1) SETTLED, design detail. The source field must be typed on the `Iterable` SPEC VIEW (`source: Iterable[C = Source, Element = Src, E = ES]`), not a bare `Source`. A bare param leaves `Src`/`ES` with no binder — they appear in no other field — so every construction leaks them. `Iterable` and not `Stream` because Stream is SELF-RECEIVER and cannot name which carrier it is. The peel becomes the qualified `Stream.splitFirst(Iterable.iterator(src))`; `splitFirst`'s tail must be declared a bare `Stream`, NOT `MappedStream[Source = Source]` — the tail wraps the SOURCE's tail, so its Source is that tail's sort, and claiming otherwise would have the witness read finiteness off the wrong sort.

(2) KERNEL GAP, construction side. `FiniteCollection.map`'s `mapped(c, f)` puts `c : C` into a field typed on `Iterable`, which the enclosing sort merely REQUIRES — the ambient-`requires` face of `carrier_provision_short_bindings`. I implemented it and it worked (Source/Src/ES all bound), but REMOVED it before commit: the only fixture I could build to drive it also type-checks with the change backed out, because its declared return pins exactly the params the construction leaves free. It measured nothing, so it does not ship. NOTE for whoever lands it: the effect-row value must NOT be row-wrapped on this path (a `provides` fact writes a row, a `requires` clause writes the bare row PARAM); wrapping gives `ES = {E}` and the witness's own `requires FiniteCollection[E = ES]` then has to discharge `{E}` against `E`, which silently stops matching.

(3) KERNEL GAP, unsolved — THE BLOCKER. A DERIVED (default-bodied) FiniteCollection op dispatched on a witness-provided carrier does not ground its effect row. Localized by probe against the full consolidation: `FiniteCollection.collect` — the primitive the witness SUPPLIES — works (its row comes from the witness op's own declaration); `size` does NOT (`xs.map(inc).size()` and the qualified `FiniteCollection.size(FiniteCollection.map(xs, inc))` both fail with `undeclared effect: ?_`), and so would `foldLeft`/`foldRight`. ROOT CAUSE, traced: a WITNESS keys its carrier as an APPLICATION (`fact FiniteCollection[C = MappedStream[Source = S, Src = Src, T = T, ES = ES, EF = EF]]`) and writes its other bindings (`E = {ES, EF}`) in its OWN variables; `bind_spec_params_from_carrier_param` grounds via `typaram_ref_vid(..., carrier_sym)`, which finds no MappedStream param inside them, so the value never grounds. `provision_binds_param_to_carrier` DOES return the view and `transitive` is FALSE (no eval deferral) — the view is simply in the wrong variables. The old `FiniteMappedStream` never hit this because its `provides` keyed the BARE carrier, whose bindings are already in the carrier's own params. FIX DIRECTION: the fact's carrier application IS the dictionary relating the two (`Source -> S, ES -> ES, ...`); invert it and substitute before grounding. I attempted exactly that and it did not move `size` while it BROKE a previously-green probe, so the substitution is firing somewhere other than the site that grounds a derived op's row — find that site first. `xs.map(f).size()` is wi492/eval_test's headline assertion, so nothing consolidates until this is fixed.

ALSO MEASURED, so it is not rediscovered: `FiniteCollection.map` must return the BARE carrier, not the `FiniteCollection[C = ...]` view. The view spelling does not load at all — the value's `EF` is an OPEN row (`open[tail = EffP]`, from the `-Modify[x]` lack on the callback) while the written `EF = EffP` elaborates to a bare var, and no source spelling produces the open form (`{EffP}` over-wraps). The ticket's own earlier note ("bare carrier ... chaining resolves") is confirmed correct. And `Iterable.map`/`filter` must KEEP their `Stream[...]` return: refining them to the concrete carrier makes `Iterable.iterator` on the result compose transitively and leak the row (wi492's `lazy_map_iterator_count`).
