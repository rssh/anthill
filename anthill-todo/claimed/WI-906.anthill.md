## Description

WI-903 follow-up: the typed-bound DOT-rule refusal is keyed on @[simp] alone, which is wider than 'the typer can fire it', and the @[unfold] carve-out rests on an UNMEASURED premise. WI-903 refuses a typed pattern bound on any rule matching simp_rewrite::is_typer_fired_dot_rule = is_simp_equation && stored LHS is Expr.dot_apply. Two residuals, both raised by /code-review on the WI-903 diff, both code-read not driven. (a) OVER-BROAD: typing::try_fire_dot_rule additionally applies a per-receiver ENCLOSING-SORT guard (same_sort_canonical(recv_sort, rule_domain(rid)) || sort_provides(...)). A dot_apply-headed @[simp] rule whose rule_domain no receiver can conform to -- e.g. one written at NAMESPACE level, whose domain is not a sort at all -- can therefore never fire at the typer, so only the resolver fires it, and the resolver DOES enforce the bound (fire_simp_equation gates on is_directional_equation, which accepts @[simp] as well as @[unfold], then calls typed_pattern_bounds_hold). Such a rule is refused today with a message that says the bound would be silently ignored, which would be false for it, and no alternative spelling preserves its firing sites. (b) UNMEASURED PREMISE: WI-903 deliberately KEEPS the bound on an @[unfold] dot rule on the grounds that the resolver enforces it there, but nothing drives a resolver fire against a dot_apply TERM redex -- wi903_typed_bound_dot_rule_test::typed_bound_on_an_unfold_dot_rule_is_kept asserts only that rule_type_bounds is installed (storage, not enforcement). If the resolver in fact never reaches such a redex, the @[simp]/@[unfold] asymmetry is unjustified and BOTH should be refused. FIRST STEP: drive (b) -- construct a goal carrying an Expr.dot_apply term and an @[unfold] dot equation over it, and assert the bound decides firing. (b)'s answer settles (a): if the resolver never fires these, refuse both and delete the carve-out; if it does, narrow the refusal to rules whose rule_domain is a sort. ACCEPTANCE: the @[simp]/@[unfold] split is either justified by a driven enforcement test or removed; the doc comments at simp_rewrite::is_typer_fired_dot_rule and docs/kernel-language.md section 5.3 state whichever is true; cargo-test green via scripts/test.sh.
