## Description

Proposal 032 — smt-gen migration to unified head-as-conclusion encoding. Today the rustland loader keeps a transitional shape: labeled non-equational positive rules synthesize a 0-arg label-functor as the KB head and place the user-written head term(s) in 'conclusion'. The legacy assert_rule_debruijn_with_conclusion path stays alive only to keep smt-gen working without modification. Migration: rewrite smt-gen's collect_rule (anthill-smt-gen/src/lib.rs ~line 290) to use the rule head AS the conclusion when the head is positive (run it through process_body_goal and route into conclusion_assertions); when head is Bottom, conclusion_assertions stays empty (denial form). Drop the result_var extraction from the head's pos_args (the synthetic-label-with-result-var pattern goes away under 032). Once smt-gen runs on the unified encoding: simplify the loader to assert_rule_debruijn(head, body) without a conclusion vec. Acceptance: cargo test green; lift_implication_test exercises the new encoding; lf1 step_distance_lemma proof still discharges the same way.
