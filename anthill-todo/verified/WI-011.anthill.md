## Description

Typing as rules: express the typing pass as anthill rules (not just operations) using type_of(?env, ?occ, ?type) 3-arg relation. TypingEnv as data sort with constructors (empty, bind). Requires: (1) Sort in unifications (WI-010), (2) forward chaining or materialization to persist derived TypeOf facts, (3) tabling/memoization for recursive derivations. See Proposal 022 and 011 discussion. CLOSED 2026-04-23 (decision verified, scope abandoned): the original premises are addressed without needing the Horn-rules lift. (a) Sort participation in unification is implemented — types are plain Term::Fn and unify structurally via SLD; rust unify_types (typing.rs:1131) is the operational helper. (b) Typing logic is already expressed in anthill code via typing_pass_spec.anthill (operations-form spec, not Horn-rule form, but serving the same documentation/specification purpose). (c) Forward chaining and tabling infrastructure is significant work with no current consumer — better added when a real use case appears. Followup: WI-079 covers parity-testing between the operations-form spec and the Rust implementation. Do not reopen without a concrete use case for the Horn-rules form specifically.
