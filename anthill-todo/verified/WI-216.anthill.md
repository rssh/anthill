## Description

rustland anthill-smt-gen extract_define_funs has O(n²) advance pattern. In `rustland/anthill-smt-gen/src/outcome.rs:127-156`, the while-loop body advances `rest = &after[1..]` (one char past the matched `(define-fun ` marker) on both the skip path (line 140) and the success path (line 153). Each iteration re-runs `rest.find("(define-fun ")` from position 0 of the remaining string, so the find scans from `p+1` across the whole `(define-fun NAME () SORT VALUE)` block to locate the next marker — O(n) per iteration × O(n) iterations = O(n²) on input length. Scaland mirror in `scaland/anthill-smt-gen/src/main/scala/anthill/smtgen/Outcome.scala::extractDefineFuns` already has the fix (advances by `marker.length` so the next scan starts after the consumed prefix; see WI-213 commit 955ff7a). Bring rustland into parity. Acceptance: cargo-test green; the existing 7 outcome tests still pass byte-identically; benchmark on a representative Z3 model (kilobytes of `(define-fun ...)` entries) shows linear scaling, not quadratic. Driver: scaland↔rustland byte-identical Z3 model parsing parity (incidental; not user-visible at typical model sizes ≤10 KB, but the asymptotic class differs). Independent of WI-213/WI-214.
