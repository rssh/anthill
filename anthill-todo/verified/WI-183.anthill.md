## description

Bundle perf: O(N) linear scans dominate cmd_list / cmd_graph runtime. The anthill bundle's read-only commands take ~16s on the anthill-todo dataset (180 items) in release mode. Algorithm is correct but every map-like lookup is O(N) linear scan over a List[Pair[String, X]]: status_for (used by partition_ready/blocked's any_unmet), direct_dependents (used by count_transitive and cmd_graph's print_tree). count_transitive in particular needs unique-reachable-set semantics for diamond dependency patterns (sum-memoization double-counts), so the per-call visited list is currently re-scanned linearly. Three follow-up options: (a) wire a Set/Map builtin (List[Pair[K, List[V]]] indexed by K, with Hash-based lookup) so direct_dependents is O(1); (b) topo-sort with union-of-reachable-sets giving true O(N+E) for transitive counts, requires Set primitives; (c) interpreter-level optimization (compile pattern matches to dispatch tables, cache operation lookups) so the recursive walks themselves are faster. Driver: WI-009 phase 2 reaches feature parity but the user-visible CLI feels sluggish vs the legacy Rust binary's <1s. Not a correctness blocker; tracked separately so phase 3 (mutating commands) can land first.
