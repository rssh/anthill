## description

NOTHING ENFORCES THAT THE IMPLICIT VOCAB'S SHORT NAMES ARE DISTINCT, so a duplicate would make one entry DEAD SILENTLY. `implicit_qualified` (rustland/anthill-core/src/kb/load.rs) resolves by LAST DOT-SEGMENT — `kernel_vocab_qualified(name).or_else(prelude_qualified(name))`, each a linear `find` over its `&[&str]` — so if two entries ever share a short name (within a list, or across the two), the first wins and the second can never be reached by any of the four consumers. Checked at filing: all 61 entries (28 KERNEL_VOCAB_QUALIFIED + 33 PRELUDE_QUALIFIED) have distinct short names today, so this is a guard against rot, not a live bug. It is the second way these tables can go quietly wrong; WI-900 closed the first (an entry whose TARGET is not declared, now pinned by `implicit_target_orphans` + `wi900_implicit_tier_agreement_test::every_implicit_target_is_declared_by_the_standard_load`). Deliberately NOT folded into WI-900: it is a different invariant about the same table, and the ticket-spinoff rule says a surviving follow-up becomes its own ticket. ACCEPTANCE: a test (or a const-time check) fails when two implicit entries share a short name, naming both; the check lives beside the tables like `implicit_target_orphans` does; cargo-test green via scripts/test.sh.
