## Description

One AMBIGUITY, reported TWICE — an occurrence remapped at two scopes, and WI-745's dedup cannot see it.

FOUND WHILE DRIVING WI-994, which made the shape reachable and PINNED the
double rather than fixing it (wi994_variant_exposure_test::
one_variant_name_exposed_by_two_namespaces_is_ambiguous expects 5 errors, of
which 2 are the same finding).

MEASURED. One occurrence at 6:7, two errors:
  6:7: ambiguous symbol 'guarded' in scope 'p':   candidates [...]
  6:7: ambiguous symbol 'guarded' in scope 'amb': candidates [...]
'p' is the operation, 'amb' the enclosing namespace — the same written name
remapped once per scope. Only the AMBIGUITY rows double; the field-label and
type-mismatch rows for the same occurrence appear once, so this is not a
general 2x on name remapping and the cause is specific to the ambiguity path.

WHY THE EXISTING DEDUP MISSES IT. LoadError::dedup_key is deliberately
INJECTIVE — the full rendering, span included — and its doc says so on purpose:
two references to one bad name in same-short-named but DISTINCT scopes must
both survive, since a short scope name is not a unique identity
(no-short-name-comparison). Here the two renderings differ ONLY in the scope
name, so nothing collapses them. WI-745 met the same class of duplicate (a head
functor resolved for owner-tracking AND for the term build) and eliminated it
AT THE PRODUCER for exactly this reason; this is a second producer pair doing
the same. WI-745's own CLI test asserts the property this violates —
run_cmd_test.rs asserts the ambiguous-symbol message appears exactly once.

EASY TO MISS, which is why it went unnoticed: name the namespace and the
operation alike and the two renderings COINCIDE and dedup. The probe WI-994 was
written from did exactly that (namespace wi994.p, operation p) and reported
4 errors; the test fixture renamed the namespace and reported 5.

WORK: find the two producers (there are 5 push_ambiguous_symbol call sites in
kb/load.rs, one shared spelling) and establish which two both remap the SAME
occurrence at different current_scope values — then eliminate one, as WI-745
did, rather than widening dedup_key. Widening it is refused for the reason its
doc already gives.

ACCEPTANCE: the wi994 fixture reports the ambiguity ONCE (the pinned list drops
to 4, and that edit is the test the fix must come with); the WI-745 CLI
count-is-1 assertion still holds; a CONTROL showing two genuinely distinct
references to one bad name in two scopes still report twice. cargo-test green
via rustland/scripts/test.sh.
