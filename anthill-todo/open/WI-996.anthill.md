## Description

UMBRELLA for docs/proposals/059-secondary-entries.md — secondary entries: one scope,
a main entry and secondary ones. 059 is the spec for this work; do NOT re-decide its
rules in a child ticket. If an implementation cannot meet a rule, AMEND 059 rather
than diverging from it.

WHAT 059 SETTLES. A `namespace X` at an address that already has a main entry
(`sort X` / `enum X` / `entity X`) is a SECONDARY ENTRY to that type's scope — not a
module attached to it. Measured, the visibility is already symmetric in every
direction: a secondary entry reads the sort's type parameters, calls its members
bare, names its variants in a match; the main entry sees the secondary entry's
members and dot-dispatches them on its own receiver. NOTHING IS MISSING IN THE
WIRING. What is missing is BOUNDS — today two secondary entries declaring one member
name is silent last-wins, a secondary entry redeclaring a main-entry member silently
wins, and a second `sort C { … }` body silently reopens a closed ADT.

THE RULES, and where each lands:
  R1 a type is defined once ........................ ledger ticket
  R2 a secondary entry declares members of X ....... NO WORK — measured, already true
  R3 members and spec claims, never identity ....... classification ticket
  R4 FILL, never DISPLACE (3 clauses) .............. three tickets
  R5 §6.3's remedy restated ........................ doc only, spec-sync ticket
  R6 head binding independent of order ............. WI-980 (exists)

R2 IS DELIVERED BY MEASUREMENT, NOT BY CODE. It is listed so nobody builds it: the
scope sharing it describes is what the loader already does. Its only follow-up is
WI-978 — the backing obligation for a `provides` does not reach one declared in a
secondary entry, so R3's allowance of spec claims there is unguarded until that lands.

STILL OPEN AND NOT OWNED HERE: WI-994 (variant exposure is order-dependent),
WI-995 (an import is scoped to the address, not the file — 059 states the rule,
that ticket implements it), WI-895 + WI-980 (both gate 059's NARROW rule for rules
in a secondary entry; until they close the enforced rule is the blanket ban).

ONE DEPENDENCY OUTSIDE THIS REPO'S DELIVERED STATE: 059's R4 clause 2 and its
spec-claim arbitration both rest on 058 §3.6 (`one_default`, no-displacement), which
is PROPOSED, not delivered. 059's banner promises every claim is measured against the
Rust loader; that one is not. Resolve before R4 clause 2 lands.
