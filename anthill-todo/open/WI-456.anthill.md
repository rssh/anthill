CITATION CORRECTED 2026-09-21. My 2026-09-20 entry above ends by blaming the remainder on WI-402 ("no dictionary travels with a value") and WI-1093. BOTH ARE DELIVERED, and WI-402 is not that question at all: it is `ensures Spec[C]`, the output dual of `requires` — a dictionary flowing OUT of an operation's RETURN (delivered 2026-06-14, both halves). A dictionary stored in a DATUM is a different thing and has no ticket. I took the citation from sortedset.anthill's header and from the 2026-09-20 note rather than reading WI-402, and then propagated it; the earlier entries are left as the record of what was believed, and the live guidance is fixed in stdlib/anthill/prelude/sortedset.anthill, docs/design/058-implementation.md (the deferred row and §32) and docs/scala-forward-mapping.md.

WHAT IS ACTUALLY TRUE about the remainder: a spec DEFAULT body reaching an ordering-reading operation by VALUE is refused, and the refusal is real and measured (`NamedSlotNotCarried`) — a value names its sort and carries none of its type parameters, so `resolve_bridge_requirements` re-resolves the chain from the argument values and the slot's goal is SEARCHED rather than read back. Searching re-decides a question the construction site already decided, which is why it must refuse rather than answer.

AND IT IS NOT BLOCKED ON TYPE SAFETY, which my earlier framing implied and is wrong: a comparator can be a type PARAMETER and a stored witness at the same time — `std::set<T, Compare>` does exactly that, keeping two differently-ordered sets distinct TYPES while the container holds an instance. The coherence obligation (stored dictionary agrees with the type parameter) is constructor-enforced, not a soundness hole. `anthill.realization.runtime.Dictionary` is ALREADY a first-class value (`alloc_dictionary`, layout-checked against `dict_layout`), so the carrier exists. What stands in the way is representation and reach, and it should be stated that way: `tip` is nullary so an empty set has nowhere to put one; `bin` IS the set, with no root wrapper, so a per-node field would duplicate it n times; `eq` is extensional and would have to exclude the field; the discrimination tree indexes structure, so an embedded dictionary joins the indexed term; and SMT terms are data. None of those is 'cannot be type-safe' — they are costs, and a language-wide decision rather than a SortedSet patch.
