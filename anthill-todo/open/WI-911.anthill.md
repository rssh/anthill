## Description

`register_extent_owner` refuses an `internal` functor with `UnresolvableName` — the mount takes only the ladder's VISIBLE half. WI-908 routed `KnowledgeBase::resolve_name_in_global` through the shared ladder (`resolve_name_in_kb_opt`), which runs `resolve_dotted_in_kb` with `DottedVisibility::VisibleOnly`; the ladder's DIAGNOSTIC half (`Loader::forbid_if_dotted_internal`, load.rs ~8216 — an `Any` pass run after `VisibleOnly` comes up empty, documented as 'for the positions that have an error channel') is a `Loader` method and unreachable from kb/extent.rs. So a host name that EXISTS and is HIDDEN is reported as one that does not exist — the misleading-diagnostic case WI-752 split the ladder to avoid. The mount HAS an error channel (`ExtentRegError`). DRIVEN: wi908_global_name_ladder_test::an_internal_member_is_not_mountable_from_global pins today's `UnresolvableName` and says at the site that it is loud but imprecise. FIRST STEP: lift the `Any` pass off `Loader` so a free `&KnowledgeBase` caller can run it. ACCEPTANCE: mounting an `internal` functor reports a distinct `ExtentRegError::ForbiddenInternal { functor }` naming the owning scope; the WI-908 test flips to it; cargo-test green via scripts/test.sh.
