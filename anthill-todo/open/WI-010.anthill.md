## Description

Implement type-unification helpers as anthill rules so type_of(?env, ?occ, ?type) rules (WI-011) can reason about types declaratively. Three relations to define: (a) subtype(?sub, ?sup) / assignable(?from, ?to) covering primitive subtyping and structural compatibility; (b) resolve_sort_alias(?sort, ?canonical) walking SortAlias facts; (c) unify_type(?a, ?b) orchestrating structural match + alias resolution + subtyping. The Rust unify_types (typing.rs:1131) stays as the operational fast path used by type_check. Note: Type values are already plain Term::Fn and unify structurally via SLD — the original 'Sort is opaque' framing was inaccurate. The unused sort_as_term/term_as_sort/can_be_sort stubs in reflect.anthill:136-140 should be removed as cleanup.
