## Description

A sort whose operations receive on itself is its own carrier: `List provides Stream`, a `List` is a `Stream`, and a position typed `s: Stream` takes one, with or without bindings. A spec over a parameter is one whose operations receive on that parameter (`operation probe(x: C)`) or, where it declares no operation that says, one a provision binds a parameter of to the providing sort (`provides Base[B = Carrier]`). A sort that provides such a spec is that parameter of it. ¶ A position typed at a spec over a parameter takes a value of any sort that provides it. The value is an instance of the spec: it carries its sort's provision with it, and the spec's parameter is the value's type. So `w: Tagger` is a value of `w.C`, and a call at `w.C` takes its dictionary from `w`: [direct(w: Tagger) = Tagger.probe(w); go() = direct(b(k: 0)) -- 7] ¶ The provision is chosen where the value meets the spec, by its type: by §8.7's order, or, under `requires Tagger[C = P]`, the clause's own. No value chooses one. A function's parameter typed at the spec is an instance too, so one function is applied at several types, each call passing its own value: [applyBoth(f: (x: Additive, y: x.T) -> x.T) with f(1, 2) and f(3.0, 4.3) -- (3, 7.3) with lambda (x: Additive, y: x.T) -> x + y] ¶ The position written by the provider's sort, with the spec required of it — a type parameter under a clause, or the spec's member (§5.4) — takes the same values, the caller passing the provision beside the value: [bound[P](w: P) requires Tagger[C = P]; member(w: Tagger.C)] ¶ A spec application, `Tagger[C = B]`, is a type wherever it is written.
