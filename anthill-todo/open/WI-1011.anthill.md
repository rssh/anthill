## Description

Memoize the spec-op supplier lookup WI-1010 put on two hot paths. WI-1010 pointed both WI-444 sites (typer 'check_apply_iter', eval 'resolve_carrier_override_by_value') at 'carrier_override_suppliers' -> 'spec_op_suppliers_for_carrier', replacing a ~3-hash-probe route-1 read ('carrier_own_op') with a WALK over the spec's provision bucket plus a per-provision decode ('fact_head_named_args', two 'get_named_arg', 'sort_ref_functor', 'unwrap_spec_view' with a named-args clone, 'witness_dispatch_carrier' -> 'provision_carrier_sort'). The walk IS bounded by 'provides_rids_by_spec' (3-6 provisions per spec across the corpus, NOT a KB scan), but the FULL cost is paid by the calls producing NO candidate, which is the common case. BOUNDED SO FAR: the TYPER site is per apply-site-per-load, estimated well under 1ms against a 0.12s release / 0.77s debug stdlib load - negligible. The EVAL site is per INVOCATION of an unpinned DEFAULTED spec op, which includes Stream.head/tail/takeN/find/isEmpty/headOption/iterator - the interpreter's collection inner loop - and is UNMEASURED. WI-842's '63.2s -> 63.7s' does NOT transfer and must not be cited for these callers: it sampled 592 BODY-LESS value-directed dispatches, a population disjoint from the DEFAULTED ops these sites serve (058 impl doc S12 records this). WORK: (a) MEASURE FIRST - a thread-local counter in 'spec_op_suppliers_for_carrier' printed at exit gives the real invocation count on a stream-heavy program under 'anthill run'; wi_tests is a poor instrument (wall-clock dominated by 1833 stdlib loads, which will bury an eval regression). (b) If it matters, add a '(spec_op, canonical carrier) -> SmallVec<[SpecOpSupplier;2]>' memo storing the LIST, so multi-candidate visibility is preserved bit-for-bit unlike any short-circuit. Precedent 'sort_param_pairs_cache' (kb/mod.rs), whose doc names these same two hot paths; both readers take '&KnowledgeBase' so a RefCell<HashMap> needs no signature change. INVALIDATION IS REQUIRED and is what the precedent does not need: 'eq_derive::run' asserts provides facts MID-LOAD, so clear at both 'build_provides_index' sites and wherever 'sort_ops' is rebuilt. TRAP, verified: do NOT filter the walk through 'ProvidesIndex.by_carrier' - it keys on the provision's 'sort_ref', which for a WITNESS is the witness sort and not the dispatch carrier, so that bucket silently drops every route-3 supplier. NO SOUND SHORT-CIRCUIT EXISTS: skipping the provision walk on an own-member hit is exactly the first-match blindness WI-1010 removed. SEPARATELY, cheap and semantics-preserving, worth doing regardless of the memo: 'provision_carrier_sort' re-decodes a spec view that 'provisions_of_spec' already decoded and even hands to 'provision_supplier' (passing the bindings down removes half the decode and one heap alloc at all three call sites plus the load-time eq index), and 'provision_supplier' asks the expensive 'witness_dispatch_carrier' BEFORE the cheap 'does this provision supply the op at all' question. ACCEPTANCE: an invocation-count measurement recorded before any optimization; if a memo lands, a test proving a SECOND candidate is still seen through it, and the invalidation driven by a mid-load provides assertion.
