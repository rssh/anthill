## Description

RUST CODEGEN RENDERS A PARAMETERIZED SPEC CLAIM AS A BARE SUPERTRAIT, DROPPING EVERY BINDING, AND THE RESULT DOES NOT COMPILE. `codegen/rust.rs`'s sort-body walk turns an in-sort spec claim into a Rust supertrait bound. `extract_fact_sort_name` answers a `Term::Fn` head with its FUNCTOR's local name alone, so `fact Iterable[C = Stream, Element = T, E = E]` renders `: Iterable` — the three bindings gone. WI-862 MEASURED that this is not merely lossy but non-compiling: widening the sibling `Item::ProvidesClause` arm to every provision made the stdlib's pre-existing `sort Stream { provides Iterable[C = Stream, Element = T, E = E] }` emit `pub trait Stream<T, E>: Iterable` into `stream.rs`, a `suppress_imports: true` target whose whole premise (anthill-stl/build.rs, WI-553) is that "the signature-only output never references" `Iterable` — `cargo build` fails with E0405. WI-862 therefore narrowed its new arm to BARE specs (`TypeExpr::Simple`), which is the `sort NonMonotonicStore { provides Store }` shape the 058 §4 retirement needed, and left the parameterized case to this ticket with the reason recorded at the site. NOTE THE DEFECT IS THE GENERATOR'S, NOT THE RETIREMENT'S: the `fact` spelling has the identical hole and is simply unreached today, because no file in the seven-file codegen corpus writes a parameterized spec claim with the `fact` spelling inside a sort. SCOPE: (a) render the type arguments — `provides Iterable[C = Stream, Element = T, E = E]` is `: Iterable<Stream<T, E>, T, E>` or whatever the trait's generic order actually is, which means reading the spec's declared param order the way `type_to_rust` already does for a field type; (b) make the supertrait's name reachable — under `suppress_imports` no `use` is emitted at all, so either the bound's name is enrolled in a per-file import set (which is WI-587's replacement for `suppress_imports`) or the emitter qualifies it; (c) ONE OWNER for the two arms: `Item::Fact` and `Item::ProvidesClause` must render the same bound from the same helper, since 058 §4 says the two spellings record one provision, and today they agree only because both are equally wrong. ACCEPTANCE: a fixture with a parameterized in-sort provision generates a supertrait bound carrying its arguments; the generated file compiles (drive it, do not eyeball the string); the `fact` and `provides` spellings of that fixture generate BYTE-IDENTICAL output; `stream.rs` keeps compiling with the widened arm restored; full workspace green via rustland/scripts/test.sh. RELATED: WI-587 (prune unreferenced imports, replacing per-file suppress_imports), WI-586 (per-op method type-param collision). REFERENCE: proposal 058 §4; docs/design/058-implementation.md §29.
