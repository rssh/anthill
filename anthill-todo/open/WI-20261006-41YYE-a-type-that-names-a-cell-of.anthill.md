## Description

A TYPE THAT NAMES A CELL OF THE ENCLOSING OPERATION IS NOT CHECKED AS AN ARGUMENT, NOR JOINED: a pure-declared operation hands a function that writes the cell to a parameter typed pure, loads, and writes it. Over `sort Box { effects BE = ?  entity box(f: (x: Int64) -> Int64 @ {BE}) }`, `bump(k: Cell[V = Int64], x: Int64) -> Int64 effects {Modify[k]}` (adds `x` to `k`, answers `x`) and `runPure(b: Box[BE = {}], x: Int64) -> Int64 = match b case box(f) -> f(x)`. (1) THE ARGUMENT CHECK. `operation use(k: Cell[V = Int64], b: Box[BE = {Modify[k]}]) -> Int64 = runPure(b, 5)` — declared pure, passing a box that writes `k` where a pure box is expected — LOADS. Driven by `build(k: Cell[V = Int64]) -> Int64 effects {Modify[k]} = let b: Box[BE = {Modify[k]}] = box(lambda (x: Int64) -> bump(k, x))  use(k, b)` and a pure `main` answering `build`'s answer × 100 + the cell, it answers 505: the cell was written through `use`. The ground twin is refused: `use(b: Box[BE = {Error[String]}]) -> Int64 = runPure(b, 5)` is "type mismatch in runPure.b (op-arg): expected Box[BE = {}], got Box[BE = {Error[T = String]}]". ANOTHER CELL PASSES TOO: `runAt(j: Cell[V = Int64], b: Box[BE = {Modify[j]}], x: Int64) -> Int64 effects {Modify[j]}` given the box that writes `k`, from `use(k: Cell[V = Int64], j: Cell[V = Int64], b: Box[BE = {Modify[k]}]) -> Int64 effects {Modify[j]} = runAt(j, b, 5)`, loads, and `k` is written under a declaration that names `j` alone (550 for answer × 100 + k × 10 + j). The stdlib shape is the same: `consume(s: Stream[T = Int64, E = {}]) -> Int64` takes a `Cnt[T = Int64, EC = {Modify[k]}]` over `Cnt provides Stream[T = T, E = {EC}]`, where `EC = {Error[String]}` is refused "expected Stream[T = Int64, E = {}], got Cnt[…]". (2) THE JOIN OF A TYPE PARAMETER. Over `sort Walk { sort C = ?  effects E = ?  operation run(c: C, x: Int64) -> Int64 effects E }`, `Box provides Walk[C = Self, E = BE]` (its `run` running the function) and `second[A](x: A, y: A) -> A = y`: `use(k: Cell[V = Int64], p: Box[BE = {}], w: Box[BE = {Modify[k]}]) -> Int64 = Walk.run(second(p, w), 5)` — pure — LOADS and writes (505), where the ground twin `use(p: Box[BE = {}], w: Box[BE = {Error[String]}])` is refused "expected one type for `A`: the join of the arguments that bind it, got no common type for type parameter `A` of `second`: Box[BE = {}] (x), Box[BE = {Error[T = String]}] (y)". WHY. Both read one gate, `resolved_type_is_ground` / `resolved_type_is_determined` (rustland/anthill-core/src/kb/typing/type_preds.rs), which asks of a value in a type position that it be CLOSED (`denoted_value_is_closed`): no logical variable and no reference to a value place — a parameter, a field, a let-local, a result. A type that is not closed is not judged at all: `validate_arg_against_param` checks only a determined pair, and `join_repeated_type_params` (typing/join_instantiation.rs) keeps only the determined contributions. The reason given at the gate is a CALLBACK's own parameter — `Modify[c]` with `c` the callback's binder is comparable only once the two binders are aligned, which `validate_callback_effect_row` does. A cell of the ENCLOSING operation is not that case: `k` is one place throughout the body, and `Modify[k]` against `{}` or against `Modify[j]` is decided by the place. The gate does not tell the two apart, so the whole argument goes unchecked. DIRECTION, not decided: closedness relative to a binder — a place bound outside the type being compared (an enclosing operation's parameter, a let-local in scope at the call) compares by identity, and only a place the type itself binds (a callback's own parameter) waits on alignment. NOT THIS: a row variable is not bound from a label that holds a value (`bind_row_tail`), which is why WI-20260829-2NMXA's rows write the transform's row at `map[EffP = …]`.
