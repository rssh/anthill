## Description

Quasi-quote patterns: pattern-match through reify brackets so KB queries, structural term inspection, and rule heads share one syntactic form with normal value pattern matching. Surface: `match t case ↑WorkItem(id: ?id, status: ↑Claimed(agent: ?ag, ...), ...) -> ...` matches t structurally against a quoted constructor pattern with sub-pattern bindings. Variables prefixed `?` inside the bracket are fresh logical vars in the surrounding scope; `↑sub-pattern` recursively quotes a nested term-shape. Subsumes the WI-182 fresh_var / make_fn / pattern_query trio: cmd_next becomes `for ↑claimable(?id, ?desc) in kb-stream { ... }` or similar, no manual goal construction. Work: (a) pattern-side grammar additions inside ↑ brackets (recognize ?vars as logical vars, recursive `↑` for nested quotes); (b) typer: pattern conformance against the bracket's target sort; (c) loader / lowering: pattern → SLD goal, with bracket-bound ?vars allocated as Var::Global at query-build time; (d) integrate with `match` / `case` / `for` desugarings; (e) port cmd_next to use the bracket form; (f) update reflect stdlib's LogicalQuery sketch to match the new surface. Acceptance: cmd_next drops fresh_var + make_fn + pattern_query in favor of a single `↑pattern` form; cargo test green; the WI-182 builtins get marked deprecated. Depends on WI-189 (the bracket operators must be in place first). The maximalist staging design — out of scope of WI-189 to keep that smaller.
