## Description

THE IMPLICIT TIER IS ABSENT FROM TYPE POSITION: `Loader::remap_symbol_strict` and `Loader::remap_name` (rustland/anthill-core/src/kb/load.rs) run scope resolution, the dotted ladder and the `internal` diagnostics, then intern + `UnresolvedName`/`TypeName` — they never call `resolve_implicit`. So an implicit-tier SORT (`SortInfo`, `OperationInfo`, `FieldInfo`, `SortView`, the literal carriers) resolves bare in TERM and QUERY position but requires an explicit import in TYPE position. That is the term-vs-type asymmetry WI-752's headline symptom describes, one tier down. Currently UNEXERCISED: stdlib/anthill/reflect/typing.anthill imports all of them explicitly, which is why nothing fails. NOT DRIVEN: raised by /code-review's altitude pass on the WI-900 diff (which unified the tier's other four readers behind `resolve_implicit`), code-read only — stated as an asymmetry read, not a defect measured. FIRST STEP: drive it — a user file naming `SortInfo` bare in a type annotation with no import, against the same name bare in term position, and record which resolves. Then decide: extend the tier to type position (the tier's own doc says these names 'always denote their target'), or state that the type namespace is deliberately import-only and say so at both sites. ACCEPTANCE: the two positions agree, or the divergence is documented at `remap_symbol_strict` and tested; the reflect typing.anthill import stays valid either way; cargo-test green via scripts/test.sh.
