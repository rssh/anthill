## Description

THE KERNEL DESUGARING VOCAB'S 28 QUALIFIED NAMES ARE HARDCODED IN RUST, and nothing but a test keeps them true. `KERNEL_VOCAB_QUALIFIED` (rustland/anthill-core/src/kb/load.rs:4907) is 28 stdlib addresses written in the kernel — `anthill.reflect.Expr.if_expr`, `anthill.reflect.Pattern.wildcard`, `anthill.reflect.ListLiteral`, `anthill.reflect.field_access`, … — consulted by `resolve_implicit` as the lowest rung of the name ladder. The direction is backwards: the CONVERTER is what mints these names (convert.rs `alloc_marker_term("if_expr", …)`, `intern("field_access")`, `alloc_fn_term("ListLiteral", …)`), so the kernel legitimately knows WHAT it builds; it should not also know WHERE the declaration lives. Today a rename or move in reflect.anthill does not fail — the name silently stops resolving, which is exactly why WI-900 had to add `implicit_target_orphans` + a test to stand in for a load error.

THE CHANGE: invert it. The reflect declaration CLAIMS the role — a `[kernel]` flag on its own declaration — and the loader builds a role map from those claims at scan time. `kernel_vocab_qualified()` becomes a lookup in that map and the const is deleted. Because the role IS the short name the converter already mints, this removes 28 strings from Rust and adds NONE: the converter's mint strings were always there. Two invariants stop being tests and become load errors: an orphan is unrepresentable (the map is built FROM declarations), and two claims of one role is a located refusal (which is WI-910's invariant for this half).

MEASURED THIS SESSION, and the first measurement is the one that makes the change safe:
  - ALL 28 SHORT NAMES APPEAR IN .anthill SOURCE ONLY AT THEIR OWN DECLARATION. Two look like exceptions and are not: `field_access`'s six extra hits are PROSE inside `stdlib/anthill/prelude/sort.anthill`'s description blocks (lines 121-127), and `as_term`'s extra hits sit under an explicit `import … {as_term}` at `rustland/anthill-todo/anthill/store.anthill:30`. So no .anthill file reaches these names THROUGH the tier; the only consumers are converter-minted occurrences. The bare-name reach can go without a migration.
  - WI-909's site census (recorded on that ticket): 10 of the 28 answer at NO site — `Expr.var_ref`/`bigint_lit`/`float_lit`/`bool_lit` and all six `Pattern.*`; `match_expr`/`if_expr`/`let_expr`/`lambda_expr` DO answer at `remap_name_str_inner`. Those ten keep their claim after this change and keep answering nothing — the change is not the place to delete them, and deleting them needs the path that feeds them found first (that ticket's own warning).
  - BOOTSTRAP HAS ITS OWN COPY AND IT IS A SUBSET. `register_stdlib_scopes` (load.rs:9548) hand-defines `anthill.reflect.{TupleLiteral, SetLiteral, ListLiteral, Pattern.wildcard, Expr.apply, Expr.constructor}` so a stdlib-less KB resolves them; the other 22 are absent there. The role map must be SEEDED at bootstrap for exactly the names bootstrap defines, or a `KnowledgeBase` built without loading the stdlib regresses. This adds no new hardcoding — those names are already written at that site — but it is the step the change fails without, and `wi1129_rule_head_capture_test::the_capture_record_constructor_is_bootstrapped` is the row that would catch it (`CAPTURE_RECORD_CONSTRUCTOR` = `anthill.reflect.TupleLiteral`, asserted absent on `KnowledgeBase::new()` and present after a bare `load_all`).

THE VEHICLE EXISTS; NO GRAMMAR CHANGE. `entity_declaration` already carries `optional($.meta_block)` (tree-sitter-anthill/grammar.js:740) and the flag form `[kernel]` is shorthand for `[kernel: true]` (grammar.js:1137). OPERATIONS MUST USE THE CLAUSE FORM `meta [kernel]` (WI-087, grammar.js:564) and not a trailing bare block: that note records the measurement — a bare `[...]` after a return type is grabbed as return-type application args. Six of the 28 are operations (`field_access`, `as_term`, `occurrence_term`/`_span`/`_owner`, `sub_occurrences`), 22 are entities. Readers are `load::meta_has_flag` / `meta_value`; `Entity.meta` is already in the parse IR (parse/ir.rs:746).

SCOPE IS SOURCING ONLY — the resolution ORDER does not change. The role map stays the LOWEST rung, consulted after `lookup_local_name`, `resolve_in_scope` and the dotted ladder (load.rs `remap_name_str_inner`), so a user's same-spelled name still wins exactly as the WI-040 doc says it should. THAT IS A CAPTURE FOR A MINTED OCCURRENCE and it is VT8CF's defect one coordinate over — a user `entity wildcard(type_ann: …)` in scope would take the desugaring of `_`. NOT FIXED HERE and NOT DRIVEN: probed via the CLI this session and neither arm could be made to EVALUATE (`eq` suspends into a residual, `<=>` unifies structurally without evaluating), so the capture is a code read of the fallback order and nothing more. It needs an operation-body drive, as VT8CF's own note prescribes, and it is a behaviour change with its own control — its own ticket.

CONTROL. Back the change out and the suite must fail on the ROLE MAP, not on loadability: the row to write asserts that a minted `if` in an operation body resolves to the symbol whose qualified name is `anthill.reflect.Expr.if_expr` AND that removing the `[kernel]` claim from that one declaration in reflect.anthill makes it stop resolving there — mutate one claim, do not delete the declaration (a deletion measures whether the stdlib loads, not whether the map works). A second row: two declarations claiming one role is a located load error naming both. Say at each row which back-out fails it.

ACCEPTANCE: `KERNEL_VOCAB_QUALIFIED` deleted; the 28 claims live in stdlib/anthill/reflect/reflect.anthill; the role map is seeded at bootstrap for the six names `register_stdlib_scopes` defines; `implicit_target_orphans` / `implicit_tier_short_names` / `CAPTURE_RECORD_CONSTRUCTOR` updated to the new source; duplicate-claim refusal tested; full workspace green via rustland/scripts/test.sh.
