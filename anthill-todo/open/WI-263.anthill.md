Visibility on operation declarations: grammar+spec say yes, practice says no — decide. (Originally filed as WI-260; renumbered when remote landed a different WI-260 for reflect.term_as_entity.) Current state: grammar.js:305 has optional($.visibility) on operation_declaration, docs/kernel-language.md:732 shows [Visibility] on the Operation production, but zero stdlib/example files use the prefix on an operation and the loader doesn't pick up the field. Effectively dead syntax with an inconsistent triple — grammar accepts, spec promises, loader ignores. Choice: (A) Wire it up — make 'export operation foo(...) -> T' actually export at the loader level; aligns spec/grammar/semantics, completes what was intended. (B) Remove it — strip from grammar.js:305 and kernel-language.md:732; operations get exported via the namespace 'export' clause only; tightens surface to match practice. Meta-question if (B) is chosen: why is const (proposal 039) different? 039 currently puts [Visibility] on the const grammar via the argument that standalone declarations like sort/entity/const get inline prefixes while members like operation don't. But this is a soft distinction — operations can also appear at namespace top level, and const can also appear inside a sort body. The 'peer vs member' split is convention, not structure. If we remove from operations, the same logic might argue for removing from sort/entity/const too (all could use the namespace 'export' clause exclusively). Sub-options under (B): (B1) Remove only from operations; keep on sort/entity/const where it's actually used. (B2) Remove from operations AND drop the per-declaration form from 039's const grammar; require the export clause. (B3) Audit all constructs and adopt a uniform rule (either all support inline visibility, or none do). Driver: 039 needs to commit to a position for its const grammar. Cleanest answer probably influences the broader visibility decision across constructs. Acceptance: pick one of A/B (and sub-option if B); update grammar.js, kernel-language.md, and 039 to match; stdlib parses unchanged; cargo test green.
