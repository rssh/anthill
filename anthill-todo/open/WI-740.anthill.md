## Description

examples/classic-mini/eight-queens — the N-queens search in anthill, the example proposal 052 has been citing all along. CONTEXT: 052 uses 'queens' / 'Queen.find' as its RUNNING EXAMPLE throughout (052:18, :71, :91-95, :310-327) — 'a relation with only board free is Relation[Board], so queens.head : Board' — and NO implementation exists anywhere in the repo ('queens' occurs only in proposals, design docs and Rust comments). So the canonical illustration of the language's headline feature has never been written or run. Part of the WI-736 classic-mini collection, SPLIT OUT because it is the one classic example BLOCKED on unimplemented engine work, whereas the arithmetic-free examples are not. BLOCKED ON (both verified empirically 2026-07-17): (1) WI-738 — the diagonal test is ARITHMETIC in a rule body ('no queen attacks another' = abs(Qi - Qj) /= abs(i - j), i.e. neq(sub(?x,?y), ?d)), and a builtin nested as an OPERAND is today neither reduced nor delayed but compared STRUCTURALLY, so the guard is silently, unconditionally TRUE — probed: neq(sub(?x,?y),1) admits (2,1). Writing queens today would ship an example that 'runs' and prints garbage rather than failing loudly. (2) WI-739 — queens is queried with the ANSWER FREE ('queens(?board)', the (out) mode), and a rule carrying a comparison guard FLOUNDERS in that mode: probed, 'num(?x), num(?y), neq(?x,?y)' with both columns free yields ONE row with unbound vars instead of 6, while the same rule applied as distinct_pair(1) (mode (in,out)) yields the correct 2. Generate-and-test with the answer free is exactly queens' shape. NOTE the not(eq(..)) workaround (verified to enumerate where neq(..) flounders) covers the COLUMN-distinctness half but NOT the diagonal half, which is irreducibly arithmetic — queens stays blocked on WI-738 regardless. SCOPE when unblocked: the board encoding (a List of column positions, one per row — permutation-style, so column distinctness is structural), the safety rule, the finite domain via facts (fact col(1)..col(8); there is NO between/range in the stdlib and SLD enumerates facts fine), and consumption through the WI-714 Relation face — 'queens' cited BY NAME is Relation[Board] (1-collapse), drained via splitFirst/takeN (NOT head/headOption: rule-backed, do not evaluate — WI-733). Prefer the classic Prolog encoding once the engine supports it, rather than a table-driven arithmetic-as-facts workaround; if a workaround is ever taken, say so loudly in the README. ACCEPTANCE: examples/classic-mini/eight-queens loads and RUNS from anthill source (not a Rust harness), producing correct solutions — 8-queens has exactly 92, and the first is checkable; a test exercises it so it cannot rot (github_todo_test.rs precedent; mind WI-719's load-ORDER hazard — stdlib must be collected BEFORE an examples/ dir sorting lexicographically before it); a README states the problem, the encoding and how to run it; cargo-test green via scripts/test.sh.
