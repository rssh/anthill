## Description

PROPOSAL 073 STAGE 2 — EVERY CALL PASSES WHAT ITS CALLEE READS, so no operation's own requirement slot is filled from argument values when its body is entered (docs/proposals/073-abstract-values-are-instances.md §6.3). `fill_missing_op_scoped_slots` (eval/eval.rs) builds the slots a call left out from the argument values, through `resolve_bridge_requirements`, at three entries: `enter_operation`, the bridge's dispatched-through path (eval/mod.rs), and the host raise (eval/effects.rs). TRACED on 62882ef0: 73 tests reach it, in four cases, each decided with the user 2026-11-05. (1) AN OPERATION USED AS A FUNCTION VALUE (2 tests: xqgew `tagIt`, vnqtr `tyOf`). `operation useS[P](x: P) -> Int64 requires Show[T = P] = Show.show(x)`, `operation app[X](f: (x: X) -> Int64, x: X) -> Int64 = f(x)`, `operation go2() -> Int64 = app(useS, a)`: `useS` enters with no `Show` and the fill reads `a`. DECIDED: the function value is the lambda that calls it, `app(lambda (x: A) -> useS(x), a)`, whose call is typed at `P = A` and passes `A`'s `Show`, built at load; under a caller's type variable (`go3[Q](q: Q) -> Int64 requires Show[T = Q] = app(lambda (x: Q) -> useS(x), q)`) the closure holds the caller's dictionary. Both lambda spellings run without the fill today (traced). (2) AN EFFECT ROW'S SLOT (46 tests: `MappedStreamFinite.collect`, `FilteredStreamFinite.collect`, `MappedStream.splitFirst`, the s7yf5 and 2nmxa `run`s). `effects E = ?` is `sort E = ? requires EffectsRuntime[Effects = E]` (proposal 045 §2), and the slot always holds the leaf `Dictionary(impl: EffectsRuntime)`, kept only so the other slots keep their positions (`effects_runtime_sym` in kb/typing/requires.rs, and the four readers its doc names). DECIDED: the effect handlers are installed in the interpreter (`Interpreter.effect_handlers`), and an effect row is typed and has nothing at run time: no slot, the dictionary layout losing those positions in every reader at once. (3) THE TYPE OF A RAISED ERROR (20 tests: `Error.raise`, host `Int64.rem` by zero, `KB.loaded`, `KB.execute`). `operation fail(x: Int64) -> Int64 effects {Error[String]} = Error.raise("boom")`: the fill builds `TypeValue[T = String]` from `"boom"`. DECIDED: `TypeValue[T]` is an ordinary requirement; the call passes it, built at load, and a host operation that raises is passed it at the error type its declaration states. (4) A REQUIREMENT LEAVING A PARAMETER OF ITS SPEC UNWRITTEN (5 tests: ycpaj and snjpr `useB`, dnx0e `p`, sqzpq `Box.tagOf2`). `sort Spec2 { sort A = ?  sort B = ?  operation both(a: A, b: B) -> Int64 }`, `sort Both { provides Spec2[A = WIS, B = NoSp]  operation both(a: WIS, b: NoSp) -> Int64 = a.n + b.n }`, `operation useB[P](a: WIS, b: P) -> Int64 requires Spec2[B = P] = Spec2.both(a, b)`, `operation go() -> Int64 = useB(wis(n: 4), nosp(n: 5))` answers 9.
