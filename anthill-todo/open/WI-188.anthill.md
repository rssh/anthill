## Description

Entity record-update form: `e.copy(field = v, ...)`. Pure surface syntax — no new runtime concept, no new value variant. Desugars to a constructor call that reads each unspecified field of `e` and overrides the named ones. Surface: `wi.copy(status = Claimed(agent, since))`. Work: (a) tree-sitter grammar — extend dot-call shape to recognize `.copy(named_args)`; (b) converter — emit a special CopyExpr IR node carrying receiver + override list; (c) typer — verify the receiver's declared sort (or inferred type) has all the named fields with the correct value types, generate the residual override map; (d) loader / lowering — desugar to a constructor-call term with all original-field projections plus the overrides, sort named-args canonically; (e) tests — single override, multiple overrides, invalid field name (typer error), inferred-type vs annotated receiver. Acceptance: cmd_claim in rustland/anthill-todo/anthill/main.anthill drops `replace_named_arg` in favor of `wi.copy(status = ...)`; cargo test green. Scope-bounded: doesn't introduce typed entity views over `facts_of` (separate WI for that). Independent of WI-189 / WI-190 — lands first as a stopgap and stays useful even after staging brackets land.

## Changes

### 2026-10-03T10:06:56Z — feedback — user

Design update 2026-10-03: proposal 069 supersedes the bespoke residual-override semantics in steps (b)-(d). After WI-20261003-QV5W5 lands, derive an ordinary full-arity copy(self, field...) operation whose field parameters default to self.field projections; keep WI-188 responsible for the e.copy(field = value) update surface, receiver/field validation, and lowering that surface to the derived operation ordinary named call. Constructor reconstruction then comes from operation parameter defaults, not a CopyExpr-only runtime or lowering rule.
