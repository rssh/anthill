## Description

A FUNCTION TYPE NAMES ITS OWN PARAMETER IN ITS EFFECT ROW BY THE BINDER'S NAME, NOT BY ITS POSITION — so the type alone does not say WHICH parameter a label like `Modify[k]` is about, two functions differing only in that name are two types, and such a type can be written only where an operation declares a callback parameter. Found by WI-20260929-0RP29's ninth fix pass (the eighth review's finding 13), which made the unchecked case a loud refusal and left the root here. THE PROGRAM: operation app2(q: Cell[V = Int64], f: (x: Cell[V = Int64]) -> Unit @ {Modify[x]}) -> Unit effects {Modify[q]} = f(q) — a slot that ALLOWS its callback to write the cell it is given — and operation appD[EffP](q: Cell[V = Int64], f: (x: Cell[V = Int64]) -> Unit @ {EffP, -Modify[x]}) -> Unit effects {EffP} = f(q) — one that DENIES it; go() = let c: Cell[V = Int64] = Cell.new(1), a call, then Cell.get(c). The callback is lambda (k: Cell[V = Int64]) -> Cell.set(k, 42), whose row is {Modify[k]}; to judge it the checker must know that the lambda's `k` and the slot's `x` are the same POSITION. MEASURED (current tree; "before" is the tree before that pass and the build before WI-20260929-0RP29, which agree): (1) the lambda written at the call — app2 runs to 42, appD[EffP = {}] is refused "to lack `Modify[T = f.x]` … the lambda argument declares `Modify[T = k]` on the corresponding parameter", on every build; (2) let g = lambda (k: …) -> Cell.set(k, 42) then g — app2 runs to 42 on every build; appD ran and wrote the cell (42) before, and is refused now as (1) is (the `let` keeps the lambda's binders, TypingEnv::callable_places); (3) let (g, n) = (lambda (k: …) -> Cell.set(k, 42), 1) then g — appD ran and wrote the cell (42) before and is refused now, and app2 — a CORRECT program, 42 before — is refused now too, both "expected a callback … whose own parameters are known by position — an operation, a lambda, a callback parameter, or a `let` holding one, got the callback `g` declares `Modify[T = k]`, and `k` is a parameter of the callback itself, at a position this expression does not say": the checker cannot tell the two apart, so it refuses both rather than pass the one the slot denies. The same holds, measured, for a callback taken out of a list by a pattern (let fs = [lambda (k: …) -> Cell.set(k, 42)], then case cons(g, _) -> …); a call's result and a field cannot carry such a row at all, by (6). (4) A forwarded callback PARAMETER is aligned either way — fwd(q, g: (y: Cell[V = Int64]) -> Unit @ {Modify[y]}) = app2(q, g) runs, = appD[EffP = {}](q, g) is refused naming `g.y` against `f.x` — because a callback parameter's binder is a place that says its own position. THE SAME ROOT, ON EVERY BUILD: (5) two functions differing only in the NAME of their parameter are different types — let fs = [lambda (k: Cell[V = Int64]) -> Cell.set(k, 42), lambda (j: Cell[V = Int64]) -> Cell.set(j, 43)] is refused "type mismatch in list.element 2 (collection-element-join): expected Cell[V = Int64] -> Unit, got Cell[V = Int64] -> Unit (these render alike but are not the same type …)", and so is if Cell.get(c) > 0 then lambda (k: …) -> Cell.set(k, 42) else lambda (j: …) -> Cell.set(j, 43) ("if.rule", the same two types); (6) a function type naming its own parameter can be WRITTEN only as an operation's callback parameter — the return type mk() -> (x: Cell[V = Int64]) -> Unit @ {Modify[x]}, the entity field holder(f: (x: Cell[V = Int64]) -> Unit @ {Modify[x]}), the alias sort Setter = (x: Cell[V = Int64]) -> Unit @ {Modify[x]} and the annotation let h: (x: Cell[V = Int64]) -> Unit @ {Modify[x]} = … are each "unresolved name 'x' in scope …". WHERE, from code reading: an arrow type holds its parameter type, result, effect row and arity (TypeExtractor::Arrow, typing/extract.rs) and no binder; a label's resource is a reference to the binder's SYMBOL where the function was written (a lambda's `k`, an operation's `a`), or, for a callback parameter, a registered place with a position (`f.x`; callback_binder_position, typing/unify.rs). validate_callback_effect_row (typing/args.rs) therefore reads the argument's own binders off its EXPRESSION — callback_actual_places: an operation's arg_places, a lambda's lambda_binder_slots, a callback parameter's places, a `let`'s record — and has none for any other expression, where the ninth pass's unplaced_binder refuses a label naming a binder of the callback itself wherever the declared row speaks of one of its own binders in the same effect. DIRECTION: an arrow type's reference to its own parameter is that parameter's POSITION within the arrow (as a callback parameter's place already is), formed where the type is formed — from a lambda, from an operation taken as a function value, and from an arrow type written anywhere — so that alpha-equivalent arrows are one type, a written arrow may name its own parameter wherever a type is written, and the row check aligns by position from the TYPE, whatever expression the value came through; callback_actual_places' dependence on the expression, the env's callable_places channel and the unplaced_binder refusal then have nothing left to do. The representation is the open part: arrows are occurrence-primary and a binder's scope and alpha-equivalence do not fit the hash-consed store (CLAUDE.md's representation note), so the positional reference must live in the arrow's own carrier. ACCEPTANCE: (3) runs to 42 through app2 and is refused through appD naming `-Modify[x]` as (1) is, and likewise for a callback taken out of a list by a pattern; (5) loads, and an element of that list passed to app2 runs and to appD is refused; each spelling of (6) loads, app2(c, mk()) and app2(c, h.f) run to 42 and their appD twins are refused; a label naming a value in scope (not the callback's own parameter) is still compared as it stands; WI-20260929-0RP29's rows pinning the interim refusal — wi_0rp29_nested_projection_value_in_type_test a_binder_at_no_known_position_is_refused_where_the_row_speaks_of_one and its control, with that file's ledger parts 61–65 — are rewritten to the aligned verdicts; full workspace green via rustland/scripts/test.sh; scaland follows if its typer reads callback rows.
