## description

`dispatch_origin` KEEPS ONLY ONE DEFER REWRITE PER SPEC OP FOR THE WHOLE IMAGE — a second sort whose `requires` chain names that spec EVICTS the first, silently. MEASURED at WI-858's HEAD, by loading the same stdlib beside two different fixtures and listing `kb.dispatch_origin_iter()` in full: (a) with fixture `sort Wi227Flat { sort T = ?  requires PartialEq[T]  operation use_eq(a: T, b: T) -> Bool = eq(a, b) }` the surviving `anthill.prelude.PartialEq.eq` entry is `var_ref(name = __req_partialeq_14325)` — `anthill.prelude.Pair`'s, whose chain names `PartialEq` twice — and the FIXTURE'S OWN rewrite is ABSENT; (b) with the near-identical `Wi222Box` fixture the surviving entry is the fixture's `__req_partialeq` and Pair's is absent, while in that same load the `Ordered.compare` entry is a `Pair` ordering's `__req_ordered_14331`. TOTAL entries were 11 in every configuration — the same count with and without a fixture that indisputably adds a rewrite, which is the measurement that says entries are LOST rather than merely ordered. WHY IT WAS INVISIBLE UNTIL NOW: the recorded terms carry `args = nil()` — the argument list is EMPTY in the stored rewrite — so the only distinguishing content is the requirement-param name, and before WI-858 no sort in the tree repeated a spec in its chain, so `synth_req_names` never produced a disambiguated `__req_<spec>_<n>` and every sort's rewrite for one spec was the SAME term. Two sorts sharing one entry was indistinguishable from two sorts sharing one shape. THE MECHANISM IS NOT YET IDENTIFIED and must be DRIVEN, not read: the map is `HashMap<TermId, Symbol>` (`kb/mod.rs`, `dispatch_origin.insert(rewritten_apply, spec_op_sym)`) and two rewrites differing in the var_ref name are structurally different, hence hash-cons to different TermIds, hence should BOTH be present — so either the insert happens before the requirements sub-term is filled in (one placeholder TermId reused, last writer wins) or a later pass re-allocates over the entry. Find which by instrumenting the insert site, not by inspection. CONSUMER IMPACT: three tests (wi222_defer_rewrite_test x2, wi227_projection_search_test x1) select 'the rewrite for this spec' from this map and assert the requirement-param name, so they were asserting whichever sort's rewrite happened to survive; they now assert the SPEC of the name via common::assert_req_param_spec, which tolerates the disambiguating suffix, and that helper's doc carries this measurement. Whether any NON-test consumer reads the map for anything but diagnostics is part (a) of the work — if one does, a lost entry is a lost rewrite. ACCEPTANCE: every defer rewrite in a load is present in the map (assert the count grows when a fixture adds a sort with a fresh chain); the three tests above go back to asserting the EXACT synthesized name and assert_req_param_spec is deleted (that reversion IS the acceptance); full workspace green via rustland/scripts/test.sh.
