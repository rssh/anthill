## Description

A TYPE ALIAS IN A NAME IS NOT READ THROUGH: MEMBER ACCESS, THE SUGAR, SCOPE PARENTS, BINDING BLOCKS, IMPORTS, TYPE POSITIONS. WI-20260924-F8PYZ made a SPEC CLAUSE read a type alias as the spec it stands for (`provides StoreAlias[State = WIS]` is `provides Store[State = WIS]`). Everywhere else an alias of a sort is still a name with nothing behind it — loud in each case, but not what the author means: * member access: `StoreAlias.peek(wis(n: 9))` → "unknown functor"; `qa.StoreAlias.peek` likewise; * the bare-spec sugar: `StoreAlias.State` in a signature is refused; through an alias fixing SOME parameters (`sort S2A = Spec2[A = WIS]`) `S2A.B` must keep `A = WIS` in the synthesized requirement; * the names a clause brings into scope: after `requires StoreAlias[State = S]`, a bare `peek(s)` is "not in scope"; `sort Mid provides BaseAlias[T = T]` lends `Mid` none of `Base`'s names; * binding blocks: `provides StackAlias language rust … end` is refused (they cannot read through while the 059 R3 census reads the written name at scan time); * imports: `import qa.StoreAlias.{peek}` → "unresolved import"; * call-site bracket keys: `usePeek[StoreAlias = FileStore]` → "unknown type-param" (only `[Store = …]` selects; the WI-840 shadowing guard likewise names the base); * TYPE positions: an alias applied to further arguments (`x: IntPair[R = String]` over `sort IntPair = Pair[L = Int64]`; `A1[C = C1]` over `sort A1 = A[B = B1]`) → "`IntPair` has no type parameter named 'R'"; even bare `p: IntPair` fails `p.l`; * an alias of an APPLIED alias: `sort S2AB = S2A[B = NoSp]` over `sort S2A = Spec2[A = WIS]` is refused where it is declared ("`t.S2A` has no type parameter named 'B'"), though a spec clause reads `S2A[B = NoSp]` as `Spec2[A = WIS, B = NoSp]` since F8PYZ. `alias_expansion` stops at such a link and RELIES on that refusal (row `an_alias_over_an_applied_alias_is_refused_where_it_is_declared`): when type positions read an alias through, it must follow the link and merge the two binding lists, or it reads `provides S2AB` as a provision of the alias `S2A` — the F8PYZ bug again. The positional spelling (`sort W2 = StoreAlias[WIS]`) today adds a second, knock-on error at each clause naming `W2` ("stands for `SortView(StoreAlias, WIS)`, which is not a sort"); * declaration order: an entity field `x: WisStore.State` or an alias `sort Y = WisStore.State` reads the alias only if it was declared earlier. WHY ONE TICKET — THE PHASE ORDER. The loader runs the SCAN (every name defined; imports, the scope parents a `requires` adds, and rule-head addresses with the 059 R3 census), then the DECLARATION pass (WI-936: `sort StoreAlias = Store` is recorded here — the first moment the loader knows what an alias stands for), then the LOAD pass (provisions, requirements, operation bodies), then the typer. F8PYZ's spec clauses are read in the load pass, after every alias is recorded, which is why they could read through. Every name in this ticket is resolved EARLIER — in the scan, or inside the declaration pass in source order — when the alias is not known yet. F8PYZ's review measured what goes wrong when one shared reader sees through at load time only: an alias rung in the dotted ladder moved RULE-HEAD addresses (`rule RecAlias.freshp` landed on `Rec.freshp` while the scan-time R3 census had counted it under `RecAlias` — one name, two answers, and the census escaped), dropped an alias's fixed bindings (`WisStore.State` → `Store.State`, a wildcard provision), missed qualified paths, and depended on declaration order. THE RULE TO KEEP: a name means the same thing in every phase. DESIGN, to decide: either (a) know each alias's target HEAD already in the scan (after imports, so a target naming an imported sort resolves), or (b) keep the loader to forming the symbol table and resolve a USE through an alias only once the table and every alias exist — an import or a `requires` scope parent through an alias at the start of the load pass, member access and the sugar where bodies and signatures are typed. Either way: read an alias through where a name is USED, never where one is DECLARED (a rule head; a `namespace` entry — WI-20260924-FS8M3); keep one alias table for every reader (the load-time `alias_targets` and the typer's `SortAliasIndex` could become one map kept by `assert_sort_alias`); keep a fixed member (`WisStore.State` = `WIS`) a term, which a symbol-answering ladder cannot return. ACCEPTANCE: each bullet driven by a test with the direct spelling as the control; full workspace green via rustland/scripts/test.sh.
