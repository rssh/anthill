## Description

LOAD THE STDLIB ONCE PER TEST BINARY, CLONE IT PER TEST — lever B of docs/design/test-infrastructure.md §5: a `static BASE: LazyLock<Mutex<KnowledgeBase>>` holding stdlib ∪ rust bindings, and the one recipe (`try_load_kb_named_prepared_with`, `anthill-core/tests/common/mod.rs`) clones it and loads only the user's files.

Rewritten 2026-10-06 from the April sketch, whose numbers (~50 files, ~400 ms a load, ~25 tests) are long stale. Measured 2026-10-05: 87 files, 4.85 s a load in the debug profile, about 3 100 load call sites over 7 039 tests, and `wi_tests` alone 2 h 10 min of a 3 h 27 min gate (§1, §2). The parse is already shared (`STDLIB_PARSED`, a `LazyLock` per test binary); what repeats is the load.

NOT READY. Three things come first, and one of them is filed:

1. The two-step load switch (this item depends on it): the equivalence oracle, and the list of tests that already differ when the user's files are loaded in a second call.
2. Frontier-driven passes (§4 A3; not filed). Loading a four-line file into an already-loaded KB costs 2.4–2.9 s today, ~2.75 s of it whole-KB sweeps whose input did not change (`type_check_sorts`, `eq_derive`, `check_provider_requires`; §2.3). Without them this item wins at most ~1.7×.
3. `KnowledgeBase: Clone + Send` (not filed). No `Clone` impl exists. `Send` needs `Rc → Arc`, and that is NOT the eight fields §5.2 counts — measured 2026-10-06: `Rc<NodeOccurrence>` is the body representation of ops, rules and consts (1 072 mentions in 58 files); `NodeKind` carries `Value`s, whose tuple and entity payloads are `Rc<[Value]>`, so the change reaches the interpreter's hot path and needs an eval-cost measurement; about 1 740 `Rc` uses in 68 files of `anthill-core`, 79 more in `anthill-stl` / `-cpp-gen` / `-smt-gen`; `HostFnImpl::Dynamic` is an `Arc<dyn Fn>` with no `Send + Sync` bound. A thread-local base is no way out: libtest runs each test on a fresh OS thread. Suggested shape: a `Shared<T>` alias first (mechanical, no behaviour change), so the flip to `Arc` is one line and its cost is measured against a one-line back-out; a compile-time `Send` assertion next to the struct.

Items 2 and 3 wait for the per-binary table the profile-change item produces: after it, the remaining gain may or may not be worth a multi-day change with a silent-skip failure mode.

SCOPE, once ready (§5.3). The switch lives in the one recipe, so the suite flips at once, and `ANTHILL_TEST_FRESH_LOAD=1` keeps the one-shot recipe runnable for good — for bisecting a difference, and as the control. The sites that cannot use the base stay on the fresh load BY NAME, each with its reason at the site: `try_load_kb_prepared` (5 — mounts a host fn before load, and `register_host_fn` refuses a late entry), `load_kb_bare` (19 — no stdlib), the `*_untyped` variants (4 + 4 — stop before the typer), and the tests that assert on the ACT of loading the stdlib (`incremental_load_test`, `stdlib_drift_test`, the re-type suites). `load_stdlib_kb` (137) takes a clone and no second load.

DONE WHEN: one full run under each recipe is green, and §1's table is re-taken. Expected (§9 step 4, to be re-derived from the post-profile numbers): a test stops paying for the stdlib at all.

### 2026-10-09T05:55:12Z — feedback — user

ITEM 3 IS NOT WHAT THIS TICKET SAYS, AND IS NOW WI-20261009-D0SD4 (2026-10-09). `Rc -> Arc` cannot make a KnowledgeBase `Send`: asked a field at a time, the compiler names 25 of its 116 fields, and behind them the interpreter's five arenas inside `Value` and four `RefCell` slots on every expression node. Decided (user): a DEEP COPY in the library, safe code, and one `unsafe impl Send` on a wrapper in `tests/common` (`common::SendableKb`) — so the `BASE` of this ticket is a `Mutex<SendableKb>` and a test takes `.instance()`, not `.clone()`. The `Shared<T>` alias and the eval-cost measurement suggested here are not needed.

WHAT THE BASE BUYS, MEASURED (docs/design/test-infrastructure.md §5.1; raw: docs/measurements/test-infrastructure/clone-cost-2026-10-09.txt), the gate's build, one thread: full load 320 ms, second-call load 183 ms, copy 23.5 ms, copy + second-call load 219 ms. So a load gets 1.46x cheaper with item 2 (the frontier-driven passes) NOT done — not the ~1.7x this ticket gives, which was read off the second call alone — and `wi_tests` would go from about 600 s to about 430 s. With item 2 done a test pays the copy and little else: a thirteenth of a load.

TWO THINGS THIS TICKET NOW HAS TO DO THAT IT DID NOT SAY. (1) A POOL of bases, not one: a copy is made under the base's lock, one lock gives about 43 copies a second, and twelve test threads at ~40 ms a test (after item 2) ask for about 300. Before item 2 one base is enough. (2) The sites that stay on the fresh load grow by what the copy REFUSES: a KB with a closure host function (`try_load_kb_prepared`'s five sites, already listed), a mounted extent source or mirror store, an interpreter-arena handle held by the KB, an applied layer, a live import audit. A refusal is an `Err` from `KnowledgeBase::deep_clone`, so nothing here is silent — but the base itself must be built from a KB that has none of them, which the stdlib's is.
