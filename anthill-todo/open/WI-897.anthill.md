## description

SMT-GEN MATCHES OPERATIONS BY NAME STRING, AND WI-894 UNBLOCKED THE PRINCIPLED FORM. Every `map_*_op` table in `rustland/anthill-smt-gen/src/lib.rs` (`map_arith_op`, `map_trig_op`, `map_unary_op`, `map_bool_connective`, `map_inequality_op`, `is_ite_op`) decides what an operation MEANS by comparing `qualified_name_of(functor)` against literal strings, each spelling a fully-qualified / sort-qualified / bare triple. WI-680 recorded the hazard the bare arm carries: a user's own same-named op is indistinguishable from the prelude's and is silently reinterpreted as the SMT builtin.
WHAT CHANGED: the call site already has `functor: Symbol` and `&self.kb` in hand (`lib.rs`, `translate_expr`'s `Expr::Apply` arm), so the test can be a SYMBOL-IDENTITY compare — `kb.try_resolve_symbol("anthill.prelude.Bool.ite") == Some(functor)` — which no user name can collide with. `is_eq_functor` in the same file already does exactly this, so the pattern is in-repo and proven; it was simply unavailable to the rest because a rule-introduced functor had NO qualified identity until WI-894 scoped it. WI-887's comment on `is_ite_op` states the opposite ('nothing more specific in front of it') and is now out of date.
SCOPE AND WHY IT IS ITS OWN TICKET: this is table-wide (6 predicates, ~40 name arms), it changes signatures from `&str` to `Symbol` + `&KnowledgeBase`, and each arm needs a decision about whether the bare fallback stays for un-imported rule-body uses (which still intern bare — `wi680_ite_lowering_test`'s own fixture relies on it). Doing it inside WI-894 would have been an unmeasured sweep. ACCEPTANCE: a user-defined op sharing a short name with an SMT builtin is NOT reinterpreted (a test drives the collision WI-680 described); the existing smt-gen suites stay green; full workspace green. REFERENCE: WI-680 (the recorded hazard), WI-894 (which made a rule functor nameable), WI-887 (whose `is_ite_op` comment this supersedes).
