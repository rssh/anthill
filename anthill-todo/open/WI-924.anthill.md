## Description

`SortInfo(name: <sort>, ...)` matches ONLY as a short name under `-i`; the qualified spelling matches nothing, silently. MEASURED in WI-921 on a one-namespace KB (sort Shape with constructors Circle/Rect), `anthill query --match 'SortInfo(name: X, constructors: ?c)'`, full 2x2: short+no-`-i` -> 0; short+`-i wi921.demo.*` -> 1; qualified `wi921.demo.Shape`+no-`-i` -> 0; qualified+`-i` -> 0. So the ONE cell that matches is short-under-import, and `wi921.demo.Shape` — which resolves absolutely via the dotted rung (WI-476) and denotes the SAME sort — matches nothing and reports `0 result(s)` with no diagnostic. This is the class kernel-language.md 8.6 declares closed ('a name that denotes something in one position denotes the same thing in every other'), one layer in: a DATA SLOT of a reflect fact. WI-914 closed the same divergence for a listing mode's argument; WI-917 refuses a CONTESTED name in a data slot, so the position already has a diagnostic channel — an unresolvable-or-differently-resolving one is what falls through. NOT DIAGNOSED: it is not established whether the short spelling matches because it RESOLVES to the sort symbol or because it stays an unresolved Ident that happens to be structurally equal to the stored name term; those have opposite fixes, and the reflect fact's name field is built by the loader (reflect emission), so the answer is there. FIRST STEP: print the stored `name:` term's carrier and symbol for one sort, then the converted pattern's, and compare — do not infer it from the 2x2. ACCEPTANCE: the two spellings agree, or the position states why a reflect name field is a different QUESTION (as 8.6's dot-call exception does) rather than merely a different lookup; cargo-test green via scripts/test.sh.
