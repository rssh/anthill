## Description

S4 of WI-20260908-VVM1R (umbrella): TWO ANCHORS ARE TWO DICTIONARIES -- the implicit-parameter reading -- and the CARRIER-DIRECTED, ACCUMULATING weave that makes it sound. Design: docs/design/060-implementation.md sec 8.5.

THE MODEL (settled with the user 2026-09-09, and it REPLACES an earlier proposal to refuse this case). The annotated head variables ARE the implicit parameters: one dictionary per (spec, anchor), each bound to its own variable, threaded into the calls that need THAT carrier. This is requirement-channel.md's own sentence -- 'the call site drives it; require[X] is only the explicit form', which 'simply pre-binds one of those variables' -- with the anchor as the slot source. So a clause with two typed head vars both providing one spec is NOT refused (S2 refuses it as an interim); only attributing a WRITTEN require between them needs the retained bracket, which is why this depends on S1.

THE WEAVE IS SINGLE-DICTIONARY BY CONSTRUCTION, NOT BY DESIGN, AND THAT IS THE WORK. weave_covered_call (typing.rs:71084) emits requirements: vec![Rc::clone(out)] -- ONE element, REPLACING the list -- and finds its target by Rc::ptr_eq. Two dictionaries never collide today only because collect_covered_calls filters on spec_op_parent_sort == spec_canon, so a call node is covered by at most one spec, and same-spec duplicates are refused upstream by has_duplicate_spec (the 'at most one requires on spec X per rule' error, whose stale WI-613 citation S1 retires). Under this model both consequences bite: (a) the weave must be CARRIER-DIRECTED -- pair each covered call with the dictionary whose ANCHOR matches that call's carrier ARGUMENT, not weave every covered call with the goal's out; (b) a second weave over an already-rebuilt node cannot find its target by Rc::ptr_eq, so it silently does not weave and trips the debug_assert!(wove, ...) at typing.rs:71207. ONE ACCUMULATING PASS, not two replacing ones. apply_within itself needs nothing -- requirements is already a list.

WHAT GOES WRONG IF (a) IS SKIPPED, and it is the silent class: with two Desc dictionaries and an undirected weave, a Colour-carried call gets the Shape dictionary and answers through the wrong instance. A clean load, a definite answer, the wrong one.

ACCEPTANCE. A clause with TWO typed head vars whose bounds both provide one spec loads; each dictionary binds separately; each covered call dispatches through the one matching ITS OWN carrier, asserted BY VALUE with the two suppliers answering different numbers so neither can be produced by accident. A WRITTEN require[Spec[P = <one of the two bounds>]] pre-binds the matching one (this is the row that needs S1's retained bracket, and it is what says the attribution is READ and not positional). CONTROLS: the single-anchor clause answers exactly as S2 left it (passes either way by design -- say so at the site); with the carrier-direction backed out, name the row that answers the OTHER supplier's value rather than merely failing; with the accumulation backed out, name the row that trips the debug_assert. cargo-test green via scripts/test.sh.
