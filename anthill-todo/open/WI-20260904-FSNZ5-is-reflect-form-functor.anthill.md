## Description

`is_reflect_form_functor` CLASSIFIES BY A NAME'S LAST SEGMENT, so any operation or entity whose final segment collides with one of its 19 keys is silently misclassified as a reflect meta-constructor. MEASURED over a standard stdlib load: `anthill.reflect.Expr.apply` -> true (legitimate, entity_field_names=Some(3)); `anthill.reflect.Substitution.apply` -> TRUE, entity_field_names=None; `anthill.prelude.Function.apply` -> TRUE, entity_field_names=None. Two live stdlib operations are read as reflect forms. CAUSE: it keys on `expr_form_key(qn, short)` (kb/node_occurrence.rs), which returns the LAST SEGMENT of the qualified name. That function's own doc says the namespace is dropped deliberately, so 'dispatch works whether the loader emitted a qualified name like anthill.reflect.Expr.apply or a hand-built test produced the bare short name apply' -- a TEST-CONVENIENCE affordance that became the production dispatch key. It is the one-fact-encoded-twice pattern WI-20260825-5W3RJ and WI-909 removed everywhere else by giving these forms absolute `..`-marked addresses; this reader never migrated. REACHABILITY MEASURED AT ALL FOUR CALL SITES -- THREE ARE MASKED, ONE IS LIVE. (a) resolve.rs `unknown_named_labels`: masked -- the next line is `entity_field_names(f) else return empty`, None for both colliders, same answer either way. (b) resolve.rs `positional_to_named_plan`: masked -- Substitution.apply is caught by the `starts_with("anthill.reflect.")` disjunct anyway, Function.apply falls through to entity_field_names -> None -> Skip. (c) load.rs:23801 `entity_field_names(f).is_some() && !is_reflect_form_functor(f)`: masked -- is_some() is false so the conjunction is false regardless. (d) load.rs:23817 `entity_field_names(f).is_some() || is_reflect_form_functor(f)`: LIVE. With the misclassification false||true = true, so the node takes the lossy `materialize(convert_term(..))` ROUND-TRIP; without it false||false = false and it takes WI-246's native generic-application builder. A rule-body call spelled `apply(f, x)` on Function or Substitution silently leaves the native path. THE RISK IS USER CODE, not these two. The 19 keys include `apply`, `constructor`, `var_ref`, `proof_stmt`, `apply_within`, `requirement_at_sort`, the `*_lit` family, `ListLiteral`, `SetLiteral`, `TupleLiteral`, `if_expr`, `let_expr`, `lambda_expr`, `match_expr`, `dot_apply`. A user's `operation apply` or `entity TupleLiteral` in ANY namespace is misclassified identically, with no diagnostic anywhere. NOT ALL 19 HAVE AN ADDRESS: only 8 correspond to a `dt::ALL` constant; proof_stmt / apply / constructor / var_ref / apply_within / requirement_at_sort / the *_lit family are hand-written strings with no constant, so identity-keying them needs addresses minted first or an explicit deferral. PRECEDENT FOR THE FIX SHAPE: sibling `is_dictionary_node` deliberately does NOT ride this list and says why -- it tests the SYMBOL plus the SHAPE, because a user may name a sort `Dictionary`; `is_reflect_form_functor` is keyed on a functor alone and 'could only mirror the symbol test -- which is the over-admission above'. ACCEPTANCE: is_reflect_form_functor decides by IDENTITY (resolved Symbol, or full `..`-marked address via dt::qualified / dt::is), not by last segment; a test DRIVES it and asserts anthill.reflect.Substitution.apply and anthill.prelude.Function.apply answer FALSE while anthill.reflect.Expr.apply answers TRUE; the keys with no constant are addressed or the split is stated at the site; the eight hand-written match arms keyed off expr_form_key are covered or explicitly deferred; cargo-test green via scripts/test.sh. RELATED: wi040_reserved_vocab_test::no_two_minted_addresses_share_a_short_name (WI-910) guards collisions WITHIN the minted-address domain but explicitly does NOT cover this wider key space -- see its doc.
