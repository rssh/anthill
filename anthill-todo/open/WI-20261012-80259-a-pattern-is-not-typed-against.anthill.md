## Description

A PATTERN IS NOT TYPED AGAINST THE POSITION IT IS WRITTEN AT: A LITERAL OF ANOTHER TYPE AND A CONSTRUCTOR OF ANOTHER SORT LOAD, AND THE ARM NEVER MATCHES. Over `sort Box { entity box(v: Int64) }` and `sort Shape { entity circle(r: Int64); entity square(s: Int64) }`: `f(b: Box) -> Int64 = match b case 0 -> 1 case _ -> 2` LOADS and answers 2 on every `Box`; so do `case 0` over a `String`, `case "a"` and `case true` over an `Int64`, `case 1` over a `Bool`, `case 1.5` over an `Int64`, `case 1` over a `Float` (where `k() -> Float = 1` is refused "expected Float, got Int64") and `case 0` over an `Option[T = Int64]`. A CONSTRUCTOR OF ANOTHER SORT loads the same way: `match b case circle(r) -> r case box(v) -> v + 100` over `b: Box` answers 107 — the first arm is dead, and `r` is typed `Int64` from `circle`'s field, so its body type-checks — and `match n case box(v) -> 1 case _ -> 2` over `n: Int64`, `case some(x)` over a `String`, and `case circle(r)` beside `case red`, `case green` over an `enum Color` load too. AT DEPTH: `case box(v: "a")` and `case box("a")` over a `Box`, `case some("a")` and `case some(box(v))` over an `Option[T = Int64]`. WHERE THE PATTERN MAY NOT FAIL the program loads and dies at run time: `let circle(r) = b`, `let 0 = b`, and `lambda circle(r) -> r` applied to a `Box` each raise `match_failed(…, scrutinee: box(v: 7))`. The same `Box` passed where an `Int64` is declared is refused "expected Int64, got Box". MEASURED on 773152ea with `anthill run`, 30 programs; the controls run as written (`case 3` over an `Int64`, `case "x"` over a `String`, `case box(v: 7)`, `let box(v) = b`), and over an `enum` a match whose ONLY arm is another sort's constructor is refused, as non-exhaustive — the check counts the scrutinee's own constructors, so the foreign arm covers nothing. MECHANISM: `bind_and_label_pattern` (typing/pattern.rs). Its `Pattern::Literal` arm returns the pattern as it is ("no bindings") and the literal's type is compared with nothing. Its `Pattern::Constructor` arm reads the constructor's own field types, instantiates them from whichever of the scrutinee's type arguments name a parameter of the constructor's sort — over `o: Option[T = Int64]`, `case wrap(x)` of `sort Wrap { sort T = ?; entity wrap(x: T) }` types `x` an `Int64` by the like-named `T` — and never asks whether the constructor is one of the position's sort's. A BARE NAME is the one pattern read against the scrutinee's constructors (kernel-language, "Constructor patterns resolve against the scrutinee, not the scope"); the specification says nothing of a literal or an applied constructor the position cannot hold. RULE PROPOSED, to be confirmed before the specification says it: a pattern is typed at its position — a literal whose type the position's type does not admit, and an applied constructor that is no constructor of the position's sort, are load errors naming both, at any depth, in a `match` arm, a `let` and a lambda's parameter. TO DECIDE: (1) a position whose type is not known at load — `f[T](x: T) -> Int64 = match x case 0 -> 1 case _ -> 2` loads and answers 2 on a `Box`; an unannotated lambda binder; an open slot — is left a run-time test, or refused; (2) a position typed at a sort that another sort is a subtype of, or at a spec: which constructors it admits. ACCEPTANCE: each program above is refused at load, naming the pattern's type or sort and the position's; the controls run as now; what (1) and (2) decide has a row each way; a pattern rewritten by the typer (a bare nullary name) and one under a guard are held to the same rule; kernel-language states it; full workspace green via rustland/scripts/test.sh.
