## Description

Compound-Element threading on a non-Stream FiniteCollection/Iterable provision. FiniteCollection.collect / foldLeft / foldRight (and Iterable.find/fold) on a Map fail to ground the provision's COMPOUND Element=Pair[A=K,B=V] from a concrete Map[K=Int64,V=Int64] receiver when Element ESCAPES into the result type (collect -> List[Element]) or the callback (fold x: Element) — the typer raises MissingRequiresForSpecOp ('requires FiniteCollection[Element=…] covering abstract type parameter'). size works (Element consumed internally -> Int64). WI-357's bind_spec_params_from_carrier threads simple/Stream elements but not a compound Element on a direct (non-transitive) provision. Found in WI-585 Phase A (test wi585_finite_collection: Map collect/fold deferred, concrete-element FiniteBag carrier works). Fix = thread the provision sort-params (K,V) from the receiver type args into the compound Element binding at dispatch.
