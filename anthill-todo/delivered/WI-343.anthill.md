## description

Diagnose unmet spec-level `requires` — when a carrier provides a spec whose own `requires` is not satisfied by that carrier. Today the loader/typer reports a missing `requires` only at abstract CALL SITES and for user-defined specs (wi325_missing_requires_test::user_defined_spec_without_providers_errors_on_abstract_call), but a spec-level `requires` with no satisfying provider passes SILENTLY (wi325_missing_requires_test::stdlib_spec_without_providers_still_passes_through). PROBLEM: there is no provider-side check that `fact Spec[Carrier = X]` implies X also provides everything `Spec requires`.

Concretely surfaced implementing docs/proposals/library/002-iteration-collection.md: `sort PersistentCollection ... requires Iterable[C = C, ...]`, and `List` declares `fact PersistentCollection[C = List[T], Element = T]` but provides NO `fact Iterable[C = List[T], ...]` (no ordered List->Stream bridge exists yet). So List is declared a PersistentCollection — which requires Iterable — yet List is not Iterable, and the whole stdlib still loads + typechecks green with no diagnostic. Same shape for `MutableCollection requires Iterable + Modifiable`.

DESIRED: when sort X provides `fact Spec[Carrier = X, ...]` and Spec declares `requires Other[...]`, then X must also provide `fact Other[...]` with compatible bindings; otherwise emit a diagnostic naming X, the spec Spec, and the unsatisfied `Spec requires Other`. OPEN DESIGN POINTS: (a) warning vs hard error; (b) whether stdlib gets the same treatment as user code (today stdlib is deliberately lenient via stdlib_spec_without_providers_still_passes_through) — a warning would have caught the 002 gap immediately without blocking the incremental landing; (c) transitivity (Other may itself have requires).

REFERENCES: rustland/anthill-core/src/kb/op_requirements.rs (requires / provider machinery); rustland/anthill-core/tests/include/ wi325_missing_requires_test family; stdlib/anthill/prelude/{collection,iterable,mutable_collection,list}.anthill. ACCEPTANCE: a test asserting that a carrier providing PersistentCollection (or any spec) without providing that spec's required sub-spec is reported (warning or error); existing wi325 tests stay green.

STATUS: v0 landed (load-blocking check + proposal-002 List provides Iterable/Stream + splitFirst + geometry move). Two own open design points are deferred to WI-356 (binding-precision + transitivity); the proposal-002 element-typing gap is WI-357. WI-343 depends on both, so it is NOT delivered until they land.
