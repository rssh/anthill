## Description

Bare-identifier value-receiver dot dispatch (p.x / l.method() on a param/local). A receiver that is a bare identifier resolving to a VALUE (op param, let/lambda/match local) must route to dot_apply, not flatten to a qualified name. Today the converter's is_value_receiver (convert.rs) treats an identifier-rooted receiver as a NAME (the WI-278(b)-deferred 'identifier case'), so p.x flattens to a bogus qualified symbol 'p.x' and l.length() to 'l.length' (no DotApply, no dispatch, no error). The value-vs-name decision is scope-dependent, so it must be a load-time, scope-aware re-route (identifier resolves to a local value -> dot_apply(local, member, args); resolves to a sort/namespace -> keep qualified-name flattening). Engine already dispatches once it is a DotApply. Acceptance: p.x field access and l.method() method dispatch work in op bodies; Foo.bar / Map[K=..].empty() still flatten; cargo-test green.
