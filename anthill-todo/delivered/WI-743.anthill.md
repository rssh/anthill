## Description

DESIGN + FEATURE: a finite closed ADT should BE a generator — the mode-(out) COMPLETION of WI-742's `domain(?x, T)` goal: when `?x` is UNBOUND and T is a FINITE closed ADT, ENUMERATE T's inhabitants instead of delaying, so an enum needs no hand-written domain facts. (Revised 2026-07-17 after the WI-742 design settled: open question (3) is now ANSWERED, (4) is now ANSWERED, and the ACCEPTANCE's "infinite T is a loud error" clause was WRONG and is REPLACED — see CORRECTIONS.)

MOTIVATION (user, Socratic, 2026-07-17, from the map-colouring example): a colour is one of exactly three things, and 'sort Colour { entity red, entity green, entity blue }' ALREADY says so — the spec calls a sort-with-constructors a closed ADT whose 'inhabitants [are] enumerated' and 'All constructors are enumerated' (kernel-language.md:620, :1483). Yet to actually enumerate them you must ALSO hand-write a wrapper sort + facts ('sort Palette { entity palette(c: Colour) }' + 'fact palette(c: red())' x3). The user's question: why? The information is already in the sort.

TODAY (each verified live by deleting it): (a) THE SORT DOES NOT GENERATE — drop the facts, keep 'rule colouring(?wa: Colour, ?nt: Colour) :- neq(?wa, ?nt)', and it raises 'relation_floundered': nothing binds ?wa, so the neq TEST cannot decide. A sort declaration is not callable; SLD resolves goals against facts/rules. (b) A RULE-SHAPED generator ('rule palette(?c) :- eq(?c, red())' x3, no wrapper sort) enumerates BUT yields 'Relation[(wa: ?_, nt: ?_)]' — untyped columns, because a rule subgoal constrains nothing (the same root gap as WI-741 / the WI-714 recursion fix / WI-079). (c) So the entity field 'c: Colour' is the ONLY thing that types the column — which is what makes the wrapper sort load-bearing today. NOTE (b) and (c) are what WI-742 fixes: once `?x: T` on a relational head is honored, the column types from the ANNOTATION and the entity field stops being the only channel. This ticket removes the remaining half — the FACTS.

THE INSIGHT (user): 'this means typed rule heads'. WI-582 already gives '?x: T' a MEANING and a desugaring — 'keep(?x: Summable, ?y) = ?x' MEANS 'keep(?x, ?y) = ?x :- conforms(typeof(?x), Summable)' (wi582_typed_rule_pattern_test.rs:9-17): the loader strips the annotation from the head (discrim-tree indexes it identically — carrier-neutral) and installs a per-variable bound by DeBruijn index; at fire apply_eq_rules reads the matched value's CARRIED type (WI-578 value_type_term) and checks conformance, SUSPENDING where the type is under-determined. So '?x: T' is a TEST (mode in) — and an unbound ?x IS under-determined, which is exactly why it suspends rather than generating.

THE PROPOSAL = the DUAL reading, mode-directed. WI-742 establishes `domain(?x, T)` with two modes — (in) conformance test, (out) DELAY-and-rotate. This ticket adds the THIRD arm: (out) AND T is a FINITE closed ADT → ENUMERATE T's inhabitants as a choice point, rather than delaying. 'conforms(typeof(?x), T)' read in mode (out) IS a generator — precisely a CLP(FD) 'domain'. Payoff: 'rule colouring(?wa: Colour, ?nt: Colour, ...) :- neq(?wa,?nt), ...' with NO domain facts and NO Palette wrapper, and typed columns from WI-742.

FINITENESS IS THE PRECISE LIMIT: only an ALL-NULLARY sort has a finite known inhabitant set. 'entity colour(name: String)' is infinite (String is); 'sort List { nil, cons(head, tail) }' is recursively infinite. So the rule is 'a closed ADT all of whose variants are nullary is a finite domain' — a compile-time-decidable property. This fits the EXISTING finiteness machinery (FiniteCollection / WI-589 / library-003 Phase C: 'providing collect IS the finiteness guarantee'); note a finite enum CAN honor collect, unlike Relation (maybe-infinite, WI-714). A wider rule (all variants nullary OR all fields finite — a finite PRODUCT is finite) is a possible later generalization; start with all-nullary.
