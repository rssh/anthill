## Description

Take OccurrenceId out of Term, AND give Expr a runtime Value variant. Today every Expr child-position reference is a TermId pointing at a `Term::Const(Literal::Handle(HandleKind::Occurrence, occ_id))` — a hash-consed wrapper term whose entire content is 'I'm a u64 wrapper around occ_id'. This inverts the docs/design/expr-occurrences.md model ('term is content; the occurrence is identity'): the slot type should be OccurrenceId (identity), not TermId (content). The current shape costs one TermStore alloc per occurrence reference (no real sharing since each Handle literal carries a distinct occ_id), forces every Expr-walking consumer (typer, eval, cpp-gen, rust-gen, smt-gen, persistence/print) to `split_handle` or pattern-match `Term::Const(Literal::Handle(Occurrence, _))` before getting to real content, and bakes the Occurrence variant into Literal where it doesn't belong. Concrete sites that exist only because of the squeeze (sample, not exhaustive): anthill-cpp-gen/src/lib.rs:1572, 1871, 2584, 2605; field_name_from_apply_arg's recent unwrap (post-WI-241 fix); anthill-core/src/kb/typing.rs::split_handle / resolve_handle / type_check_child / type_check_expr's Handle arm; anthill-core/src/eval/eval.rs's `resolve_handle` calls. Cleaner shape: introduce a distinct `Expr` enum used at expression-level positions, with leaves `Var | Const | Occurrence(OccurrenceId)` and forms `Apply { fn, args: SmallVec<[OccurrenceId; 4]> }`, etc. Terms stay for KB-level uses (rule heads, query terms, fact bodies, type terms) where occurrences aren't relevant. The OccurrenceStore continues to hold `{ term, span, owner, origin }` so `occ_store[occ_id].term` gives the content. Remove HandleKind::Occurrence from Literal. SECOND LAYER: KB queries that yield an Expr-typed result must produce a runtime Value, not a Term — add `Value::Expr(OccurrenceId)` (or `Value::Occurrence(OccurrenceId)`). Reflection ops on bodies (body_of(op), args_of(call), …) bind their query-variable to a Value::Expr; consumers go to `occ_store.term(id)` only when they actually need content. Without this layer, lifting Expr out of Term at the IR layer leaks at the KB/runtime boundary — queries still hand back Term-encoded Exprs that callers unwrap. SUBSTRATE: the polymorphic-binding shape already exists at anthill-core/src/kb/term_view.rs (proposal 026.1 Q2) — `TermView` trait, `ViewItem<'a> = Term(TermId) | Value(&'a Value)`, `ViewHead` enum. Used today on the resolver's target side. WI-242 extends it: ViewItem gains an `Occurrence(OccurrenceId)` variant (transparent projection — ViewHead unchanged), and generators that scan KB results migrate from reading TermId directly to reading ViewItem so Expr bindings flow through as Value::Expr without unwrap. Depends on WI-243 (provides OccurrenceOrigin enum + alloc_synthesized + PassId substrate) and WI-238 (req_insertion emitter is occurrence-native by then). Acceptance: HandleKind::Occurrence no longer exists; no `split_handle` / `resolve_handle` calls in typer/eval/codegen — those become `occ_store.term(occ_id)` direct lookups; every Expr child slot is structurally an OccurrenceId; Value gains an Expr variant; reflection-ops on bodies return Value::Expr; cargo test green. Supersedes the small unwrap patches that exist today as compatibility shims. Substantial: ~500-700 LOC touching parse/, load/, kb/term.rs, kb/typing.rs, eval/, anthill-{cpp,rust,smt}-gen/, persistence/, stdlib reflect. Should land before any new Expr-positional feature so consumers don't grow more handle-aware code.
