## description

`reflect.KB.nonvar` / `reflect.KB.ground` RE-DERIVE the resolver's answer on a
raw TermId. They must be CARRIER-NEUTRAL -- one owner per question.

FOUND WHILE DRIVING WI-981 (proposal 059 R4). The capture clause flagged
`anthill.reflect.KB.nonvar` as shadowing `anthill.reflect.nonvar`, and the
shadow turned out to be the smaller half of the finding: the QUESTION is
implemented twice.

  "is this a variable?"
    resolver  resolve.rs:3474 builtin_nonvar -> walk_arg (chases σ) +
              value_is_unbound_var; carrier-neutral via TermView;
              THREE-VALUED (Failure / delay / Success)
    host      anthill-stl/src/reflect/builtins.rs:804 kb_nonvar ->
              !matches!(interp.kb().get_term(tid), CoreTerm::Var(_));
              raw TermId; TWO-VALUED Bool

  "is this ground?"
    resolver  resolve.rs:3483 builtin_ground -> value_is_ground, documented as
              "the shared core of the ground(?x) builtin and the NAF groundness
              gate, so neither materializes the goal to a TermId"; handles
              Value::Term (chasing σ into subterms), Value::Node occurrences,
              and value-level logic vars
    host      builtins.rs:812 kb_ground ->
              interp.kb().collect_vars(tid).is_empty()

THREE DIFFERENCES, not one:
  1. σ-AWARENESS. The resolver chases the substitution; the host copy never
     consults σ. A term whose vars are all BOUND by σ is ground to one and not
     ground to the other.
  2. CARRIER. `expect_term` (builtins.rs:792) accepts ONLY Value::Term -- every
     other carrier is a hard TypeMismatch. So the host copy cannot see the
     Value::Node occurrence carrier that value_is_ground handles explicitly.
  3. VALUEDNESS. delay vs plain Bool.

THE JUSTIFICATION IS PHASE-SCOPED, AND THE LANGUAGE HAS OTHER PHASES. kb_nonvar's
doc says "Eval-time runs after SLD, so arguments are already grounded where they
will be; no DELAY semantics needed here." That is true of the post-SLD path and
false of at least two others that are DELIVERED, not planned:

  - COMPILE-TIME MACRO EXPANSION (WI-722 / proposal 043.1). simp_rewrite.rs:788+,
    in its own words: "We bind the macro's params to those occurrences as
    Value::Node -- NOT materialized: the flatten in bridge_op_to_eval is
    deliberately skipped ... so occurrence structure survives -- and run the body
    through the WI-625 scratch interpreter." Arguments are occurrences carrying
    pattern variables. Both halves of the assumption fail: not Terms, not ground.
  - ABSTRACT INTERPRETATION ON SUSPEND (WI-580, design/abstract-interpreter-and-
    rules.md §3.3, delivered 2026-07-09). `unfold_eq_operand` /
    body_specialize.rs::folded_call_match case-splits a bodied op-call's body
    PRECISELY BECAUSE the call is unground.

So the comment records an assumption about one caller, not an equivalence.

MEASURED, not inferred. Driver in anthill-stl's own `reflect::builtins::tests`
module, where both owners are reachable (anthill-stl depends on anthill-core, so
a test there can build a KB, resolve a goal, AND call the registered host fns --
an earlier attempt from anthill-core failed only because register_reflect_builtins
lives in anthill-stl):

  [resolver] ground(5)                 => 1 solution     ("yes, ground")
  [host]     KB.ground(kb, Int(5))     => ERROR: type mismatch: expected Term,
                                                 got Int64 for KB.ground
  [host]     KB.ground(kb, Str("hi"))  => ERROR: ... got String
  [host]     KB.ground(kb, Bool(true)) => ERROR: ... got Bool
  [host]     CONTROL  Term(5)          => Bool(true)

The same question about the same value gets "ground" from one owner and a hard
type error from the other. The CONTROL is the point: they agree exactly when the
carrier happens to be Value::Term, i.e. the host answers BY CARRIER, not by
content.

STATUS TODAY: the carrier divergence is driven (above). What is still LATENT is
reaching it from the phases named above -- no .anthill file calls `.nonvar(` or
`.ground(` on a receiver (measured across stdlib, anthill-stl, examples,
anthill-todo), so no macro body or unfolded body hits it yet.

WHAT TO DECIDE WHILE FIXING: value_is_ground takes a &Substitution and eval has
none. Delegation therefore means using the carrier-neutral VALUE-level check
where σ is not needed (occurrence_has_unbound_var already needs none), not
threading a σ that does not exist. Whether the reflect API stays two-valued is a
separate call: Bool is defensible for an API that can SEE every carrier -- the
delay is a resolver concern -- but it must not be Bool BECAUSE it cannot see.

RELATED: WI-535 migrated this bridge off bare TermId for other operations and
named `nonvar/ground` in its scope; this is the part that did not move.

THREE FURTHER FINDINGS (2026-08-04), each measured, which change the shape of
the fix.

1. THE `kb` PARAMETER IS DISPATCH CEREMONY, NOT A DEPENDENCY. Every reflect host
fn that takes a KB receiver IGNORES it:

     `let [_kb, ...]` (ignored):  11        `let [kb, ...]` (used):  0
     uses of `interp.kb()` instead:  64

The KB comes from the interpreter's ambient context. The parameter exists only so
the operation DOT-DISPATCHES -- the receiver of a dot call is the first param, so
`operation nonvar(kb: KB, x: Term)` is what makes `kb.nonvar(x)` a member call.
Consequence for this ticket: delegating to the carrier-neutral predicate threads
NOTHING; the member stays a receiver-shaped wrapper and `kb` stays ceremony. Note
also that the parameter which creates the 059 name collision is the one the
implementation discards.

2. THE COLLISION IS NOT LATENT -- IT BITES IN VALUE POSITION. Measured:

     import anthill.reflect.nonvar ... operation driver() -> Bool = nonvar(1)
       => REFUSED: "`nonvar` is a member of sort KB, not in scope as a bare name
          here; call it qualified as `KB.nonvar(...)` or via a receiver"
     CONTROL, the same builtin in GOAL position (a rule body)   => works
     fully qualified `anthill.reflect.nonvar(1)` in a body      => SAME REFUSAL

So the 1-ary resolver builtin is reachable as a GOAL and unreachable from an
OPERATION BODY, and the diagnostic sends the author to the 2-ary member, which is
not what was asked for.

NOT ESTABLISHED, and worth pinning first: the fully-qualified row. The name was
written `anthill.reflect.nonvar` and still drew the member's diagnostic. Either
the qualified path genuinely resolves onto `anthill.reflect.KB.nonvar`, or the
WI-565 hint is misattributed from the SHORT name. Those are different bugs --
one is resolution, one is a diagnostic -- and the fix differs.

3. CONVERGENCE: PASS KB IN NEITHER, NOT IN BOTH (user's framing). Passing it in
both is out -- the param is ignored, and adding it to the resolver form would put
ceremony in rule bodies, the one place it is pure noise. Passing it in neither
converges the two onto ONE NAME and ONE ARITY, which is what "one owner" wants
anyway. THE OBSTACLE, measured: `bare_bodied_bool_relation` (resolve.rs:6234)
routes a bare bodied Bool op used as a goal to `eq(goal, true)` -- but BAILS for a
BUILTIN or a BODY-LESS op, and both of these are exactly that. So convergence is
not free: it needs a verdict on whether one name may be both a goal-level builtin
and a value-returning operation.

CORRECTION to this ticket's own framing, from the user: CARRIER-NEUTRAL DOES NOT
MEAN STORE-FREE. A neutral `Value` still has a `Value::Term { id }` variant, so a
reader accepting every carrier still receives TermIds and still needs the store
for those; only `Value::Node` is self-describing. The rule is therefore not "drop
the KB" but "DO NOT FORCE THE TermId CARRIER -- use the store only for the carrier
that needs it."

ACCEPTANCE: one owner per question -- KB.nonvar/KB.ground answer by the same
carrier-neutral predicate the resolver uses, not by a second TermId-only
derivation. A test in anthill-stl drives each on a Value::Node carrier and on a
non-Term scalar, asserting an ANSWER rather than a TypeMismatch; and a control
asserts the two owners agree on a plain Term, which they do today (so the
control passes before and after -- say so at the site). cargo-test green via
rustland/scripts/test.sh.
