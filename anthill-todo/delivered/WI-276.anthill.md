## description

Substrate for the [simp] rewriting engine (proposal 043; docs/design/simp-rewrite-design.md sections 2.2 and 4.1): make Value::Node structural in TermView and add the occurrence build side. Today impl TermView for Value maps Value::Node to ViewHead::Opaque (term_view.rs:165), so rule LHS patterns cannot match reflect Expr occurrences. (a) Make Value::Node structural: head returns the inner Expr functor (Expr::Apply functor to Functor Some(functor); Expr::DotApply to dot_apply symbol; Expr::Const to Const; leaves to Var/Ref/Ident), pos_arg and named_arg return child occurrences. (b) Add a ViewItem::Node child shape: ViewItem (term_view.rs:46) is Copy over Term(TermId) and Value(ref Value), but occurrence children are Rc of NodeOccurrence, not ref Value, so thread the new variant through match_view (mod.rs:1379) and the discrim walker (discrim.rs query functions, generic over V:TermView). (c) Add an occurrence build side that constructs RHS occurrences via synthesized_expr (node_occurrence.rs:184), preserving spans and Synthesized origin; do not route through TermId (Value::Node is UnsupportedVariant in execute.rs:229, and terms drop inline spans). Acceptance: cargo-test green plus a unit test that a rule LHS such as add(?a,?b) matches a Value::Node Expr occurrence via match_view and binds pattern vars to child occurrences. Prerequisite for the typer-phase simp engine. Ref: docs/design/simp-rewrite-design.md and docs/proposals/043-simp-rewrite.md.
