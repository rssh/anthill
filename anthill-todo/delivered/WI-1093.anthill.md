## Description

THE ELEMENTS' DICTIONARIES ARE MISSING FROM A DEFAULTED SPEC-OP CALL. A spec op that carries a DEFAULT BODY does not get the INSTANCE dictionary built for its statically pinned carrier. What a carrier's own member actually reads are the conditions of ITS OWN provision — Ord[A] and Ord[B] for `provides Ord[Pair] :- Ord[A], Ord[B]` — and those live in the Ord[Pair] instance and in nothing a defaulted call built. The Ord a Pair is dispatched with has to use Pair's sub-dictionaries.

TWO ARMS SHARE THAT ROOT. A defaulted call with a statically pinned carrier has two exits and neither built the instance.

ARM 1 — SUPPLIER PINNED (`carrier_override_suppliers` answers exactly one). check_apply_iter's WI-1012 arm called classify_pin_or_apply_within with `resolved_tree: None`, so there was no tree, no dispatch dict, and the pinned implementation was entered with an EMPTY requirements channel. A test that reads such an op measures THE REPAIR, not the dictionary. A RECEIVER-LESS spec op has no such route — there is no argument to classify, value-direction answers NoSupplier — so the requirement dictionary is the only way to an answer.
