## Description

Add reflect.term_as_entity(t: Term) -> Option[T = E] runtime materialization. When KB queries return Term values (e.g. retrieve(store, ...)), callers currently extract individual fields via term_field + term_as_string per call site. Add a generic runtime reflect op that materializes a Term::Fn back into a typed Entity Value, using the KB's entity_field_types(ctor) index to know the expected fields and their declared types. Signature: 'operation term_as_entity(t: Term) -> Option[T = E]' (peer of existing term_as_string at stdlib/anthill/reflect/reflect.anthill:141 and term_as_sort:192). The runtime: (a) looks at t's functor — must be a known constructor symbol (kb.constructor_parent_sort returns Some); (b) walks t's named_args (and pos_args via the ctor's declared field order if needed); (c) for each field, recursively resolves the field's value (string/int/bool literal -> Value::Str/Int/Bool; nested Fn -> recursive term_as_entity); (d) returns Some(Value::Entity { functor, pos, named }). Returns None when functor isn't a constructor, when required fields are missing, or when a field value doesn't match its declared type. Driver: WI-204 Phase B1 wants WorkItemStore spec ops (lookup, by_status_of, all) to return typed WorkItem instead of Term, so cmd_show / cmd_status work with typed entities and the term_field + term_as_string boilerplate retires from main.anthill. Acceptance: cargo-test green; the helper is callable from anthill code; smoke test: parse 'fact WorkItem(id: "WI-X", status: Open, ...)', retrieve via the bundle's store path, call term_as_entity to obtain a typed Value::Entity, verify field accessors (.id, .status, etc.) work end-to-end. Out of scope: a parallel reflect.term_as_constructor for constructor-call terms (Apply form) — that's a follow-up if a use case appears. Independent of WI-189: WI-189 is about the broader typed-surface migration of KB queries; this WI provides the runtime primitive WI-204 needs.
