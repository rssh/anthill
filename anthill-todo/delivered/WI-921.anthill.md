## Description

`anthill query` has no way to list the facts of a DECLARED SORT. `--mode sort` does not do it — measured in WI-914: a clause's `sort` is the kernel's CLAUSE-KIND TAG (`Sort`/`Fact`/`Rule`/`Operation`/`Namespace`/`Constraint`/…), interned as RAW TEXT at the loader site that files the clause, so `--mode sort wi853.kb.S` answered `0 result(s)` about a sort that has a fact. WI-914 made that a loud refusal naming what the mode does list, which closes the LIE but leaves the CAPABILITY missing: to browse one sort's facts you must know its constructors and write a `--mode pattern` per constructor. NOT DRIVEN as a design. FIRST STEP: decide whether this is a new mode (`--mode kind` for the tag, freeing `--mode sort` for the sort) or a new one (`--mode entities-of`) — the rename is user-visible and breaks `--mode sort Fact`, so it is a DECISION, not an implementation. Whichever wins, the sort's constructors are reachable through `kb.sort_entities` / `constructor_parent_sort`, and the listing is a union over them. ACCEPTANCE: one documented way to list a declared sort's facts, its argument read by the SAME `_global` ladder WI-914 put on `--mode functor`/`--mode domain`; kernel-language.md §8.6's deviation list updated if the tag mode survives under a different name; cargo-test green via scripts/test.sh.
