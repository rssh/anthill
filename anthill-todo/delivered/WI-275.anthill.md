## Description

Higher-order operations: prove and enable Function-typed operation parameters. The Function[A, B, E] sort with apply(f, x) is declared in stdlib/anthill/prelude/function.anthill, multi-parameter lambdas work via (named) tuple destructuring (proposal 018: lambda (a, b) -> ..., one tuple-pattern param to avoid comma ambiguity), and the interpreter has the runtime pieces (Value::Closure, enter_closure, the local_closure branch in eval/eval.rs dispatch_call). BUT no operation anywhere in the stdlib takes a Function-typed parameter, and no .anthill program passes a closure as an argument and applies it -- the HOF-as-argument path is unexercised end-to-end. Work: (a) verify a closure value can be passed as an operation arg and invoked, both via Function.apply(f, x) and via a value-typed param called directly as cmp(a, b); confirm a binary comparator lambda (lambda (a, b) -> ready_lt(a, b)) binds and applies through a tuple arg; (b) make the typer accept a value/Function-typed parameter being applied (today operation params are data; calling one may not typecheck); (c) add the obvious stdlib HOFs that motivate this -- List.map, List.filter, List.fold, and a comparator-parameterized List.sort -- in stdlib/anthill/prelude/list.anthill. Motivation / driver: the anthill-todo bundle (rustland/anthill-todo/anthill/main.anthill, commit 77c9d89) hand-rolls TWO structurally-identical stable merge sorts (merge_ready/sort_ready vs merge_by_id/sort_by_id) that differ only in the comparator; with a generic List.sort(cmp, xs) they collapse to one call site each. Kept duplicated deliberately for now because HOF-as-arg is unproven AND closure dispatch (enter_closure + the string-keyed local_closure lookup) is heavier per-comparison than the current direct static call -- a regression on the just-optimized sort hot path. Perf caveat: under the tree-walking interpreter a generic comparator adds real indirection; it becomes cheap once bodies lower to the resolved IR (docs/design/interpreter-ir.md) where a generic merge[A](cmp, ...) can be monomorphized/inlined. So this WI is about expressiveness/correctness enablement; the bundle sort dedup can wait for the IR if perf matters. Acceptance: an integration test where an anthill program defines a comparator-parameterized sort (or uses stdlib List.sort) with a lambda (a, b) -> ... comparator and produces correctly-ordered output; stdlib List.map/fold exercised from anthill; cargo-test green.
