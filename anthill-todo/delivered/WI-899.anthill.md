## Description

A BUILTIN IMPLEMENTATION AND WRITTEN RULE CLAUSES MUST CONTRIBUTE TO THE SAME PREDICATE SEARCH. A builtin is an implementation detail, not a distinct language-level owner of a symbol. Once a rule head resolves to a symbol, every accepted clause on that symbol is an ordinary SLD clause; native backing must not make it disappear. WI-580 already gives an operation a relational view derived from its implementation. A resolver builtin is the native implementation of such a predicate/view, and its answers coexist with the answers of written clauses just as the answers of several written clauses coexist.

TODAY THE RESOLVER MAKES THE BUILTIN EXCLUSIVE. If a goal's symbol carries a resolver `BuiltinTag`, builtin dispatch decides the goal before the clause index is consulted. The clauses load and are indexed, but at the builtin's applicable arity they are unreachable. This is an implementation leak: replacing an Anthill implementation with an equivalent native implementation changes the predicate's answer set.

PRE-FIX MEASUREMENT (formerly pinned by `wi896_labeled_predicate_head_test::a_clause_on_a_builtin_backed_name_is_inert_at_sld`): with `rule or(?a) :- p896(?a)` and `rule or(?a, ?b) :- p896(?a), p896(?b)` in one namespace, the 1-ary goal yielded the written clause while the 2-ary goal yielded only the kernel disjunction's choice points. The written 2-ary clause was dead exactly where the native implementation applied. Arity therefore changed whether an accepted clause existed, silently. The old pin is replaced by `wi899_builtin_clause_coexistence_test`, which requires both sources to answer.

THE REQUIRED SEMANTICS IS ADDITIVE. For a goal on a symbol with both native handling and written clauses, resolution must include both the native predicate answers and all matching written-clause answers in the same search. The builtin keeps its existing goal semantics; it no longer short-circuits the clause path. Search order may determine enumeration order, as it does between ordinary clauses, but must not remove either source of answers. A builtin that is inapplicable to a particular arity contributes no branch and does not affect matching clauses.

AN EQUATIONAL HEAD IS NOT AN EXPLICIT CLAUSE ON THE CONNECTIVE PREDICATE. The internal rule index stores `lhs = rhs` under the canonical `eq` connective (and `lhs <=> rhs` under `unify`), but the language-level subject of that rule is `lhs`. WI-899 must therefore combine native `eq` with an explicitly written `rule eq(...)`, while it must not reinterpret every guarded equation in the knowledge base as an alternative definition of equality. The same boundary applies to `unify`.

THERE IS NO LEMMA/DEFINITION OR PROOF-ONLY DISCRIMINATOR. A rule cited by `using` is still an SLD clause; citation does not change its meaning. The `rule bound: gte(?x, 3.0) :- gte(?x, 5.0)` examples used by smt-gen/prove must therefore remain citable AND become reachable through SLD. `SymbolKind`, arity, and whether a rule happens to be cited are not semantic switches. The same rule applies to native operation predicates and native control predicates: if the language accepts a written clause on their resolved symbol, resolution must consult it.

WI-896 exposed more instances by making a rule head resolve rather than declare, but did not introduce the dispatch defect. Its old behaviour minted a new scope-local symbol and silently repointed later bare calls; that behaviour must not return. The head continues to resolve to the existing symbol, and the native and written implementations coexist there.

ACCEPTANCE:
- Replace the exclusive builtin-first dispatch with combined search over the applicable native handler and matching written clauses.
- Drive the exact-arity case with a clause whose answer is distinguishable from the builtin's answers; assert that both the native answers and the written-clause answer are present.
- Drive a rule on a builtin-backed operation such as `gte` through SLD, not merely by loading or citing it, and assert the substitution/value produced by the written clause.
- Assert the control: removing the written clause removes only its distinctive answer, while the builtin answers remain; disabling the native branch removes its answers while the written clause remains reachable.
- Preserve off-arity clause behaviour and ordinary WI-896 name resolution; do not mint a shadow predicate.
- Keep `eq`/`unify`/`struct_eq` head cases, smt-gen policy rendering, and the `prove_*` family green.
- Full workspace green.
