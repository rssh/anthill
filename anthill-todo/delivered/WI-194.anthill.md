## Description

Store transactions: single `store.commit(fact)` (and `store.commit_all(facts)`) replacing the persist + flush dance. Today every mutating command writes `let _ = persist(store, fact, Meta(entries: nil()))` followed by `let _ = flush(store, nil())`. The Meta(entries: nil()) is a placeholder that's never consumed; the explicit flush is bookkeeping. Replace with a single `store.commit(fact)` that buffers + flushes in one op, taking no Meta arg (callers that need meta use `store.commit_with_meta(fact, meta)`). Generalizes: a `store.transaction(|tx| { tx.persist(...); tx.retract(...); ... })` block makes batch updates atomic — all-or-nothing on Error effect raise. cmd_claim's retract+persist pair becomes `store.transaction(|tx| { tx.retract(fid); tx.persist(new_term); })` — the retract auto-rolls-back if the persist raises Error. Work: (a) add `commit(store, fact)` and `commit_all(store, facts)` as builtins on top of the existing persist+flush primitives; (b) optional `transaction(store, body)` builtin with rollback semantics — buffers all persist/retract calls in a sub-buffer, applies them atomically on body return, discards them on Error effect raise; (c) port bundle commands to use `commit` instead of persist+flush pairs; (d) for retract+persist (cmd_claim/deliver/verify/update), switch to `transaction { tx.retract(...); tx.persist(...); }` so a mid-step failure doesn't leave half-applied state. Acceptance: persist + flush call pairs retire from main.anthill (the underlying primitives stay for advanced uses); cmd_claim's retract+persist becomes one transaction block; cargo test green. Depends on WI-195 (Error effect must be wired for transaction rollback semantics to be meaningful).
