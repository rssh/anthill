## description

Resolve converter-synthesized kernel vocab DIRECTLY to its reserved qualified namespace, eliminating the _global imports + collision blocklist. The synthesized vocab already lives in reserved homes: anthill.reflect.* (Expr/Pattern ctors, field_access, dot_apply, occurrence_*), anthill.prelude.List.* (cons/nil), anthill.kernel.*. APPROACH (reserved-name, NOT node-keyed provenance — see docs/design/kernel-vocab-provenance.md "Primary approach 2026-06-20"): path 1 (op-body build_load) ALREADY resolves these direct via ExprBuilderSyms (load.rs ~4785, kb.resolve_symbol(FQN)); generalize that to path 2 (convert_term_with_expected ~5334/5425) — for the names convert_term itself synthesizes (field_access from x.f, dot_apply, the literal carriers ListLiteral/SetLiteral/TupleLiteral) resolve via a direct name->qualified map instead of remap_symbol. Then DELETE register_kernel_vocab_imports/KERNEL_VOCAB_QUALIFIED, the carrier _global imports (~2404-2406), and the blocklist (kind/fields/rules/kb/constructor exclusion ~765-770). No ParsedFile change, no converter side-table. Safe because the converter-synthesized names are kernel-owned (non-shadowable, accepted) and the user-definable blocklist names are NOT synthesized (grep: convert.rs never interns kind/fields/etc.; they stay explicit-import). CONFIRM before deleting: no reflect.typing_pass rule names the Expr/Pattern ctors bare via the _global import. OUT OF SCOPE: cons/nil already direct via build_list/typer (Part B); user-facing names incl. operator targets -> Prelude (WI-521). Node-keyed provenance kept in the doc only as a fallback escape hatch (unused by the current vocab).
