## Description

Unchecked arithmetic overflow PANICS in both the resolver and the eval interpreter; unify to a consistent non-panic policy. FOUR-WAY inconsistency, all measured (WI-863 review, 2026-07-30). RESOLVER (kb/resolve.rs builtin_arith dispatch): add/sub/mul closures are |a,b| Some(a+b) (UNCHECKED) — anthill query add(9223372036854775807, 1, ?r) PANICS in debug (attempt to add with overflow), WRAPS in release (silent-wrong); but div/mod use checked_* -> clean Failure. EVAL (eval/builtins.rs): int_mod (x.rem_euclid(*y), :394) and int_rem (x % y, :403) are UNCHECKED -> PANIC on (i64::MIN, -1) in BOTH debug AND release (integer remainder overflow traps unconditionally); but int_div (:416) uses checked_div -> clean Err(Overflow). numeric_add/sub/mul (:320/332/344) use checked_* -> Err(Overflow). So: eval add is safe but eval mod/rem are NOT; resolver add is NOT but resolver div/mod ARE. Reachable: eval mod/rem panic via anthill run on any program evaluating mod/%/rem at (i64::MIN, -1); resolver add/sub/mul panic (debug) / wrap (release) on any overflowing query. NOTE the correct answer for mod/rem at (MIN, -1) is 0 (x mod -1 = x rem -1 = 0 for every x) — representable, so it can be RETURNED. DESIGN (settle at pickup): pick ONE overflow policy across resolver + eval so NO path panics. Options: (a) checked everywhere -> a loud non-panic result (eval has EvalError::Overflow; the resolver has only Success/Delay/Failure so overflow is a Failure/no-solution or a new diagnostic); (b) for mod/rem, guard y == -1 -> 0 (the representable answer), leaving only genuine div-quotient overflow (MIN/-1) to error. WI-863 deliberately left resolver mod(MIN,-1) as no-solution and did NOT touch the eval panic — this WI owns both, plus resolver add/sub/mul overflow. SCOPE: Rust — resolve.rs builtin_arith add/sub/mul closures, eval/builtins.rs int_mod/int_rem. Distinct from WI-874 (div-by-ZERO, which has a declared Error[DivisionByZero] effect; overflow has NO declared effect). ACCEPTANCE: no arithmetic input panics the resolver or the eval interpreter — add/sub/mul overflow, and mod/rem at (i64::MIN,-1); the two engines handle the same overflow input consistently; the eval int_mod/int_rem panic reproducer no longer panics; full workspace green via rustland/scripts/test.sh.
