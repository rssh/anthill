## Description

BOTH IMPLEMENTATIONS: `_global` IS A LEGAL IDENTIFIER, SO THE SYNTHETIC GLOBAL SCOPE CAN BE SHADOWED BY A DECLARED ONE THAT RENDERS IDENTICALLY. The file-level scope is named by interning the spelling `_global` — scaland `KnowledgeBase.globalScope`, rustland `kb/mod.rs:5506` plus four more sites (`flow_derive.rs:83`, `execute.rs:445`, `extent.rs:621`, `body_specialize.rs:1162`). That spelling matches both identifier grammars (`tree-sitter-anthill/grammar.js`; scaland `Tokens.identToken`, whose first char class includes `_`). So a file containing `namespace _global` makes `define` register `byQualifiedName("_global")` -> a symbol DIFFERENT from `intern("_global")`, because `define` never consults the intern map. Two live scopes, and `scopeDisplayName` prints `_global` for both, so a WI-962-style diagnostic cannot say which one it means; worse, names the user expects at file level resolve against one of them and not the other. Nothing today rejects the declaration. WORK: pick a sentinel the identifier grammar CANNOT produce (e.g. one containing a character no token admits) so the collision is unrepresentable rather than merely unlikely, and change BOTH trees together — a one-sided change silently diverges the two diagnostics, and rustland reads the spelling in five places. Alternatively refuse `namespace _global` with a load diagnostic, which is cheaper but leaves the sentinel expressible. NOTE the related mint hazard is separate and filed as its own ticket: `scopeByQualifiedName` cannot name this scope at all, because `_global` is interned and never defined. ACCEPTANCE: a test that DECLARES `namespace _global` and asserts the chosen answer — a diagnostic, or a resolution that proves the two scopes are one. Say at the site which test fails when the change is backed out. Found by code review of WI-976/WI-983 (2026-08-04). Related: WI-983, WI-984.
