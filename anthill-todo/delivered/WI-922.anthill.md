## Description

A clause's `sort` key is a RAW-INTERNED clause-kind tag at every loader site but ONE. Measured in WI-914 over a full stdlib + rust-bindings load: 16 of the 17 distinct `by_sort` keys are raw interns (`intern("Fact")`, `intern("Rule")`, `intern("Sort")`, `intern("Namespace")`, `intern("Constraint")`, and dotted spellings like `intern("anthill.prelude.PartialEq")` from `emit_operation_equation`); the 17th is `emit_effects_runtime_bridge_fact` (load.rs ~3495), which files its bridge fact under the RESOLVED `anthill.prelude.EffectsRuntime` symbol. Those two key spaces are DISJOINT — `intern(qn)` and `by_qualified_name[qn]` are different symbols (`define` never touches `intern_map`) — so the one declared key is reachable only by a second, differently-spelled lookup, which is why `anthill query --mode sort` carries two. The site's own comment justifies it as 'the same convention as the stdlib's `fact Effect[T = Modify[?]]` (its fact sort is `Effect`)'; that convention is DEAD — `Fact.sort` is `None` at every parser site (`parse/convert.rs` builds `Fact { sort: None }` and nothing else constructs one), so a source `fact` is filed under the tag `Fact`, and no `fact Effect[…]` survives in the stdlib. NOT DRIVEN beyond the measurement. FIRST STEP: decide which way the one site moves — file the bridge fact under a raw tag like every sibling, or make the tag space declared. ACCEPTANCE: one key space for `by_sort`, the stale comment at the bridge site corrected or removed, the second lookup in `--mode sort` deleted if it becomes dead; cargo-test green via scripts/test.sh.
