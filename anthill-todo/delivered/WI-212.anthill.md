## Description

scaland stdlib full-load regression — AmbiguousSymbol on prelude type parameters. Loading the full embedded stdlib (51 files, post-WI-153) in a single scaland KB pass fails with AmbiguousSymbol(T, …) repeated for the prelude sorts Numeric, Lattice, Modifiable, Option, Eq, BoundedLattice, List, Field, Effect, Stream, Ordered, plus AmbiguousSymbol(A) / AmbiguousSymbol(B) for Function and Pair. The unqualified type-parameter names appear to leak from per-sort scope into ambient namespace scope, so when many sorts that share the canonical T/A/B parameter names load together the resolver sees them as competing candidates. Single-file parse + load tests pass; failure is specific to the full-stdlib pass. Failing tests: ParserIntegrationTest "WI-153: stdlib float.anthill parses + loads (depends on algebra)", "WI-153: stdlib geometry.anthill loads end-to-end (depends on algebra + Float)", "WI-153: stdlib witness.anthill loads end-to-end with full sort/entity counts", "WI-153: EmbeddedStdlib loads as a single KB load pass", "WI-155: ProofRecord fact with witness + state_hash round-trips through parser + loader", "WI-155: SmtDischarge witness with SmtVerdict round-trips". Rustland does not exhibit this; check how rustland scopes type-parameter Symbols inside scan_definitions and mirror in scaland. Acceptance: sbt test green; full stdlib KB load reports no AmbiguousSymbol on prelude type parameters.
