## Description

Loader/typer: named-argument OPERATION calls fail name resolution ('expected resolved name, got unresolved'). Any body call passing args by name -- pair(y = 1, x = "a") -- fails for BOTH non-projection and projection ops (constructor named args work; operation-call named args do not). The named-arg label is not resolved against the callee's params in convert/typing, so the arg is dropped/unbound. Surfaced by WI-398 review: the cross-param projection receiver-passed-by-name path is blocked by this (e.g. check(k = ..., s = w) reports 's.name unresolved'). Pre-existing, orthogonal to projection. Probe: a no-projection op two(a,b) called two(b=b, a=a) reproduces it.
