## Description

Runtime catchability for match-failure (deferred half of WI-467): route the 3 eval-side MatchFailed sites (enter_closure, LetBind, MatchDispatch in eval/eval.rs) through interp.raise_error so an installed Error[MatchFailed] handler actually catches a match failure, instead of the bespoke EvalError::MatchFailed. BLOCKER (why WI-467 deferred it): the MatchFailed payload sort is match_failed(occurrence: NodeOccurrence, scrutinee: Term), but the eval sites only reliably hold the scrutinee Value (rendered to a diagnostic String via scrutinee_diag) — not a NodeOccurrence for the match node nor a reified Term — so a faithful entity a handler could destructure isn't cheaply constructible there. DESIGN QUESTIONS: (a) reify the scrutinee Value -> Term (find/confirm a Value->Term helper); (b) which NodeOccurrence fills the occurrence field (the match/let/closure pattern occurrence is available at each site, but is that the intended semantics?), or should the sort field be made optional/simpler; (c) whether to keep EvalError::MatchFailed as the Display path or remove it. WHEN DONE consider factoring a shared raise_error_payload(ctor_qname, named) helper on Interpreter (WI-467 left raise_division_by_zero single-purpose; match-failure would be the 2nd caller). Update the runner render_payload (anthill-stl) if match_failed carries a NodeOccurrence/Term that needs readable rendering. Acceptance: cargo-test (a handler catches a match failure; unhandled surfaces Raised).
