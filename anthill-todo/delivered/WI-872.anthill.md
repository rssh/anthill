## Description

A PROVISION'S CARRIER BINDING IS MATCHED BY SHORT NAME AT DISPATCH, so a LOCAL sort that merely SHARES a provider's short name is offered that provider's impl and then refused. Against the repo's standing direction (WI-672: same_symbol DELETED; 'identity is by resolved symbol, never by last segment', spec §8.6) and against CLAUDE.md's no-short-name-comparison rule. PRE-EXISTING, MEASURED at WI-858's HEAD in two independent instances, neither involving the other: (1) `namespace p; sort Set { entity mkset(a: Int64, b: Int64) } operation f() -> Bool = eq(mkset(a:1,b:2), mkset(a:1,b:2))` — error 'type mismatch in anthill.prelude.PartialEq.eq.dispatch: expected matching impl for per-call bindings, got no impl matches', the prelude `Set`'s `provides PartialEq[T = Set]` having been offered for a carrier that is a DIFFERENT sort with the same last segment; (2) the identical program with `sort Pair` after WI-858 gave `anthill.prelude.Pair` a `PartialEq` provision. CONTROL, same file, same load: an identically-shaped `sort Duple` — a short name nothing provides for — loads and evaluates clean, so the refusal is attributable to the NAME and not to the shape or to composite equality. HOW IT SURFACED: WI-858 broke wi664_composite_eq_test, whose fixture happened to name a two-Int64 composite `Pair`; the fixture was renamed to `Duple` with the reason recorded in place, which is a workaround and not the fix. IMPACT: every short name the prelude provides an instance for (`Set`, `Map`, `List`, and now `Pair`) is effectively RESERVED against a user sort with an entity — a name-shadowing rule nobody declared, reported as an impl mismatch rather than as a collision. TWO THINGS TO SETTLE, in order: (a) WHERE the conflation is — a carrier compared by last segment somewhere on the provides-candidate path rather than by canonical symbol (`same_sort_canonical` is the correct comparator and has one owner; find the site that does not use it, by DRIVING the two reproducers above under a probe rather than by reading); (b) the DIAGNOSTIC — 'no impl matches' names neither the candidate that was offered nor the carrier it was offered for, which is why this read as a composite-equality failure for as long as it did. ACCEPTANCE: both reproducers load and evaluate; the `Duple` rename in wi664_composite_eq_test is REVERTED to `Pair` with its note deleted (that reversion IS the acceptance); a test pins a local sort per colliding prelude short name; full workspace green via rustland/scripts/test.sh. REFERENCE: CLAUDE.md 'no short-name comparison'; WI-672; docs/kernel-language.md §8.6.
