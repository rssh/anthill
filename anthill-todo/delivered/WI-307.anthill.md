## description

Implement Proposal 045 — effect sets, effect expressions, and effect checking (docs/proposals/045-effect-sets-and-expressions.md). Introduce effect-sets as a new bindable kind (effects E = ? / effects E = (expr)), an EffectExpression algebra ({}, e, E, +e, -e, merge, and { E1, …, EN } as merge-sugar) that denotes an EffectSet (Set of effect types, normalized modulo ACI), and effect-checking that verifies an operation's actual effects satisfy its declaration. First cut decisions (per the proposal's resolved open questions): finite rows only — defer * (top), +*, -*, and co-finite * - e; 'allow all' = omit the annotation (open by default, closed once annotated, pure = effects {}); merge present/absent conflict is a hard error at normalization; negation on open rows handled by lazy symbolic evaluation (no presence variables in v1); decidability via structural induction on the body + monotone fixpoint over the program's finite effect-label set for recursion. Phased next steps from the proposal: (1) land Set/EffectSet laws + ACI matching substrate; (2) EffectExpression reflect sort + +/-/merge grammar; (3) effects E = ? declaration, arrow.effects/Function.E carry EffectExpression; (4) effect checking (satisfaction, propagation, handler discharge); (5) migrate typing_pass_spec effect handling onto this. Completes proposal 013's deferred effect checking; reframes WI-301 (effect-sets are not type args); type-level analog is WI-302/denoted. Reconcile orphaned stdlib: prelude/set.anthill, prelude/effect-set.anthill, prelude/function.anthill (sort E = ? -> effects E = ?).
