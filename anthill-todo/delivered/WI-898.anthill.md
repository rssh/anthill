## description

AN EQUATION-INTRODUCED FUNCTOR BORROWS `SymbolKind::Goal`, AND A NON-REDEX USE THEN GETS A MISLEADING DIAGNOSTIC. WI-894 registers a rule-introduced functor as `SymbolKind::Goal` — the kind WI-714 reserves for a RELATION REFERENCE. An equation's clauses are indexed under the `eq`/`unify` connective, not under the functor, so when the relation machinery looks the functor up it finds zero clauses and reports something that is not true.
MEASURED, the same program in both spellings, with an operation body whose condition is NOT a literal (so there is no `[simp]` redex to inline):
  operation pickMax(a: Int64, b: Int64) -> Int64 = ite(Int64.gte(a, b), a, b)
  - bare, no import (the pre-WI-894 spelling): 'type mismatch in ite.apply: expected known operation or arrow-typed variable, got unknown functor' — ACCURATE.
  - with an `import anthill.prelude.Bool.{ite}` (the spelling WI-894 tells users to write): 'type mismatch in ite.name: expected resolved name, got unresolved' — MISLEADING. The name IS resolved; it is a `Goal` routed into `relation_reference_type_applied`, which finds no clauses because they live under `eq`.
NOT A NEW FAILURE — both spellings fail to load, and this shape has never worked (WI-884's `a_simp_ite_reaches_only_a_literal_condition` pins that a computed condition has no redex; that test uses a DECLARED operation, which is why it dies at eval rather than at load). What regressed is the MESSAGE, on the recommended spelling. `wi894_rule_functor_scope_test` pins that both spellings are refused, deliberately without pinning the string, so this can be fixed without editing a test.
TWO DIRECTIONS, and the ticket should pick one. (a) Give an equation-introduced functor its OWN SymbolKind rather than borrowing `Goal`, so it never enters the WI-714 relation path — the honest fix, but `Goal` is read at ~8 sites (`typing.rs` x4, `eval` x2, `resolve.rs`, the reflect bridge) and each needs a decision. (b) Make the relation path FALL THROUGH when a `Goal` functor has zero clauses, which lands on the same `unknown functor` message the bare spelling gives — small, but it changes a WI-714 site on one measured shape. ALSO IN SCOPE: WI-565's remedy-naming refinement (`member_owning_sorts_for_bare`) filters on `SymbolKind::Operation`, so it cannot see a `Goal` and the user never gets the '`ite` is a member of sort Bool — call it `Bool.ite(...)`' hint that exists for exactly this confusion. REFERENCE: WI-894, WI-714 (the relation-reference reading of `Goal`), WI-565 (the remedy naming), WI-884 (the literal-condition limit).
