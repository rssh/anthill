## description

Remove parse-side side-channels SimpleTermStore.let_type_annotations and SimpleTermStore.call_type_args (WI-270 deferred acceptance). The HashMaps currently carry the let-annotation TypeExpr and call type-arg Vec<SortBinding> from convert.rs to load.rs, where the loader threads them onto the KB let_expr / apply Term as k_type_name / k_type_args named args. WI-270 deferred this cleanup because removal requires either (a) a parse-time TypeExpr -> parse-side Term encoder that mirrors the loader's scope-aware type_expr_to_term (the loader-side resolves a Simple(name) reference as Var(Global(vid)) when the name is a registered type-param in scope, or sort_ref(name) otherwise — this scope tracking lives in load.rs's loader struct, not in convert.rs), or (b) a deferred-lowering parse-side encoding where convert.rs emits a placeholder Term::Fn shape (e.g. functor 'type_expr_simple', 'type_expr_parameterized', 'type_expr_arrow') and the loader's convert_term recognizes these and routes through type_expr_to_term equivalent. Acceptance: SimpleTermStore::let_type_annotations and ::call_type_args fields are deleted; convert.rs no longer populates them; load.rs no longer reads them; the let_expr KB Term still has k_type_name and apply KB Term still has k_type_args (so the typer's NodeOccurrence path is unchanged); the parse_test.rs tests that currently inspect parsed.terms.call_type_args (lines 3664, 3682, 3691, 3694, 3709) are updated to inspect the new representation; cargo test green workspace-wide; simplify clean on the changed files. Out of scope: changing the KB-side Term shape; changing the typer's NodeOccurrence path. Independent of WI-270 because the typer refactor is already complete; this is purely a parse-IR cleanup.
