## description

CppCodegenError conflates NOTHING-TO-EMIT with FAILED-TO-EMIT, so the CLI discards real codegen errors for the anthill.geometry header. emit_namespace_header_in (anthill-cpp-gen/src/lib.rs:1621) returns a plain CppCodegenError when a namespace declares no emittable entities/sums/traits/consts -- a benign "nothing here" signal. Two CLI sites treat that as the ONLY reason emission can fail and swallow every error: run_codegen_cpp (anthill-cli/src/main.rs:966) wraps the call in an `if let Ok(...)` and run_codegen_cpp_project (anthill-cli/src/main.rs:1021) ends it in `.ok()`, both with the standing comment "anthill::geometry only emits if the namespace declared anything there; ignore the error when the namespace is empty (carrier-only / unrelated namespace)". Their INTENT is sound and should be preserved -- the geometry header genuinely is optional. The defect is that the error type carries no way to tell the two apart, so ANY failure lowering anthill.geometry is silently dropped and the header is quietly absent from the output directory, with the user's only clue being a missing file at C++ compile time. FOUND WHILE DELIVERING WI-576 (the effect capability gate), which is what makes this newly load-bearing: before that gate, emitting a namespace essentially only failed for the empty reason, so the swallow was near-harmless in practice; WI-576 added a whole new class of hard failure ("operation X requires effect E, which profile P cannot realize"), and if anthill.geometry ever carries such an op the diagnostic naming the effect and profile is thrown away at exactly these two lines. Directly contradicts the repo rule in CLAUDE.md, "prefer a loud error over a silent skip ... surface it as an explicit error or diagnostic rather than silently continue/dropping it". FIX DIRECTION: make "nothing to emit" a DISTINCT outcome rather than an error string -- either a dedicated variant/flag on CppCodegenError (e.g. an is_empty_namespace predicate the callers match on) or, cleaner, have the optional-header path return a Result of an Option where Ok(None) means "namespace declares nothing" and Err stays a genuine failure. Then both CLI sites skip ONLY on the empty outcome and report everything else via the same eprintln + non-zero exit the primary header already uses at main.rs:927. Prefer not to add a second "does this namespace have anything?" pre-check helper -- that would duplicate the classify_namespace + consts_in_scope work the emitter already does, and the two could drift. WATCH: check whether any other caller of emit_namespace_header_with_profile / emit_namespace_header depends on the current error-for-empty behavior before changing the signature, and keep the primary-namespace path (main.rs:927) failing loudly on an empty namespace since a typo'd --namespace SHOULD be an error there, which is the reason the error-on-empty behavior exists at all. ACCEPTANCE: a genuine lowering failure in anthill.geometry (e.g. an op declaring an effect the profile cannot realize, per WI-576) makes the CLI report the underlying message and exit non-zero rather than silently omitting the header; a genuinely empty or carrier-only anthill.geometry still skips quietly with no error, as today; a typo'd primary --namespace still fails loudly; cargo-test green via scripts/test.sh.
