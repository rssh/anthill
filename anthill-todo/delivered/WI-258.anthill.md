## Description

Rc<TypingEnv> with copy-on-write mutation for the iterative typer. WI-255 made type_check_node iterative; each Visit op now stores TypingEnv by value, so pushing a child Visit clones the HashMap. For an Apply with N args, that's N HashMap clones where the recursive version had zero (it passed &TypingEnv). Wrap TypingEnv in Rc<TypingEnv>; the only mutating call sites (Let body, Lambda body, Match branch body — all of which already build a fresh env via extend_env_from_pattern) clone-on-write. Saves N-1 HashMap clones per multi-arg call site on deep specs. Acceptance: typing_pass_spec_parses_and_loads still passes on default 2 MiB stack; full workspace green; optional bench shows typer wall-clock reduction on typing_pass_spec.
