## Description

Anthill-side logical variable construction for pattern_query / sort_query goals (cmd_next blocker). The bundle's cmd_next needs to run the workflow.claimable(?id, ?desc) rule via KB.execute(kb(), pattern_query(claimable(?id, ?desc))). Anthill code today can't construct Term::Var values from user code: the resolver allocates fresh logical vars via kb.fresh_var(sym), but no builtin exposes that to anthill. Plus, building a Fn term containing variables requires the alloc_from_value path to lower a Value::Entity with Value::Term(var_tid) named-args — possible if (a) anthill writes 'claimable(id: ?id, desc: ?desc)' as a constructor expression with logical-variable terms in scope, or (b) a builtin like reflect.fresh_var(name: String) -> Term lands. Required: wire reflect.fresh_var as a builtin (Interpreter::kb_mut().fresh_var(intern(name)) and alloc Term::Var(Var::Global(_))). Once available, cmd_next is a 30-line port: build the goal, execute, splitFirst the stream, lookup ?id and ?desc bindings via Substitution.lookup, print 'WI-NNN — desc'. Acceptance: rustland/anthill-todo --anthill next byte-identical to legacy run_next; anthill-core tests still green. Driver: WI-009 phase 2 read-only commands — status/list/show/graph already byte-identical, cmd_next is the last one.

## Changes

### 2026-05-06T18:28:43Z — feedback — claude

Landed two builtins (fresh_var, make_fn) plus the cmd_next bundle port. fresh_var(name: String) -> Term allocates Term::Var(Var::Global(_)); make_fn(name: String, args: List[Term]) -> Term resolves a functor by qualified name and builds a Fn term — needed because rule-head symbols (like anthill.stage0.workflow.claimable) aren't scanned as Operations or Entities, so the expression-level claimable(...) form fails at evaluation. The cmd_next port walks the solution stream single-pass (split-first → dedupe-by-id → print) to avoid the O(n^2) append-pair recursion that overflowed the stack on real workitem sets. Acceptance note: 'byte-identical to legacy run_next' isn't achievable because both legacy and bundle iterate the SLD resolver in HashMap order, which varies per run; what's achieved is format equivalence (the two-space '  WI-NNN — desc' shape and the empty-set 'No claimable items (all blocked or none open).' message) and the same dedupe semantics. Tests: wi182_fresh_var_test.rs (2 cases — direct fresh_var and end-to-end pattern_query → execute → splitFirst → lookup); full anthill-core suite green.
