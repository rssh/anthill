## Description

WI-307 phase 4: handler discharge — handler drops a label by row unification (proposal 045 §5.6, §Phase 4). A 'handle_K(λ → e)' expression discharges effect K: the handler's body row equals the inner row MINUS the K label. Under v1a/v1b row unification this is mechanical — the handler's expected type carries a 'shared-tail' row pattern '{handled_labels | ρ_shared}' against the body's actual row, with the handled label REMOVED from the result row. PIECES: (a) typer: handle-expression's expected effects = body's actual effects ∖ {K} ∪ tail ρ_shared; the row-unification arm of unify_effect_rows drops the matching label and binds the result tail; (b) interaction with the ambient-handler runtime (proposal 027): the typer's check is purely static — it asserts the program is well-typed, not that the runtime handler exists. The runtime side is independent (027's perform/install machinery); (c) tests: 'handle_Error(λ → may_fail())' has result row without Error; nested handlers drop labels successively; un-handled labels propagate; handle of a non-present label is a type error. Available the moment v1a's row unification landed (it has). Depends on WI-307 v1a; the surface-syntax 'handle_K' grammar is part of (or precedes) this WI — coordinate with proposal 027 / WI on the handler-bundle direction. ACCEPTANCE: handle-expr tests pass; full cargo-test green; the runtime handler mechanism (027) is NOT in scope (separate WI).
