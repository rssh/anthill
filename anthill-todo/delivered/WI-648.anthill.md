## Description

Modular typeclasses -- scoped / named (NON-CANONICAL) instances. Today Anthill enforces GLOBAL instance coherence: exactly one provider per (spec, carrier); load.rs rejects an "ambiguous witness" (two providers). Some use cases need a NON-CANONICAL instance chosen AT A USE SITE rather than the carrier's default -- the standing example is SortedSet / sorted Map ordered by a CHOSEN comparator rather than the carrier's default Ord (Scala's `SortedSet(...)(Ordering)`, Haskell's newtype-per-order). (Proposal library-004's TotalFloat newtype is the coherence-preserving workaround for the Float case; a scoped-instance mechanism would let you pick an ordering/equality without a wrapper.)

SCOPE (design first, then implement): a mechanism to (a) DECLARE named / local instances (a named `provides`, or a first-class witness value -- WI-431 instance facts are the substrate), (b) SELECT one at a use site (`SortedSet.new(cmp)` / a `using`/`given`-scoped instance in a lexical region) while KEEPING global coherence as the DEFAULT, and (c) THREAD the selected witness through dispatch via the requirement-dictionary path (WI-300 / design/requirement-dictionaries.md) rather than the canonical provides-lookup. The hard part is the COHERENCE STORY: does a local instance override the global one? how is ambiguity ruled out? (Scala `given` priority / Haskell orphan-instance hazards are the cautionary prior art.)

DRIVER: SortedSet (needs a chosen Ord to be useful). RELATED: library proposal 004 (the canonical PartialEq/Eq/PartialOrd/Ord split -- this is its deliberately-DEFERRED modular extension; library-004 is built on canonical instances so it neither needs nor forecloses this), WI-300 (requirement dictionaries -- the witness-threading substrate), WI-431 (instance facts -- op-valued provisions, a candidate for first-class witnesses), WI-616 (semantic-eq dispatch).

NON-TRIVIAL -- start with a DESIGN PROPOSAL (a new docs/proposals/ entry), not code. ACCEPTANCE (design phase): a proposal covering declare / select / thread + the coherence story, with SortedSet as the worked example and the interaction with library-004's canonical instances spelled out. Rust + scaland.

THE DELIVERED SPELLING, and the three ways it differs from the shorthand — each a RULE, not a naming accident:

  SortedSet.empty[T = Pair[Int64, Int64], O = ByFst]()      -- wi858_pair_orderings_test:441

(a) `empty`, not `new` — that is the constructor `stdlib/anthill/prelude/sortedset.anthill:126` declares. A rename is available and is a stdlib decision, not a 058 one.
(b) `WeakOrd`, not `Ord` — WI-1109 split the ordering into THREE floors, and the set's clause is `requires O: WeakOrd[T]`. That is deliberate and `sortedset.anthill` states the consequence at its declaration: a SortedSet keyed by a WeakOrd that is not an Ord stores CLASSES — it collapses members that compare equal, and `union` keeps the left operand's representative, so it is not commutative. Requiring `Ord` is what buys a set of ELEMENTS.
(c) the key is `O`, not the spec's short name — §5.4's two rungs. A slot the author NAMED is reached by its BINDER under rung (1), and is no longer answered by its spec's short name, so one bracket cannot bind one slot twice; `SortedSet.empty[WeakOrd = ByFst]()` is refused at load. Keying by spec short name is rung (2), and it exists for the ANONYMOUS slots — which is what `Ord.compare[Ord = ByFst](p, q)` uses, and that form IS delivered (wi858).

So `X.op[Spec = Witness]` and `X.op[Binder = Witness]` are both live surfaces; which one a given call writes is decided by whether the callee NAMED that slot. If the intent of `SortedSet.new[Ord]` was that a named slot should ALSO be keyable by its spec's short name, that is a widening of §5.4 rung (2) and wants its own decision — say so and I will open it. What it would cost is the property that one bracket cannot bind one slot twice.

docs/design/058-implementation.md §31 is corrected accordingly.
