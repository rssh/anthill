## description

A SELF-SORT RETURN LAUNDERS THE SAME EXISTENTIAL WI-1063 CLOSED FOR FOREIGN ONES — and the spec's stated reason for the gate ('the call's own arguments pin it') is refuted by a five-line program.

MEASURED on the WI-1078 tree, both before and after it, so this is NOT a residue of the
named-variable exemption WI-1078 retired:

  sort MyStream
    sort T = ?
    effects E = ?
    entity mystream
    operation widen(s: MyStream[T = Int64, E = {Error}]) -> MyStream[T = Int64] = s
  end
  operation takes_pure(s: MyStream[T = Int64, E = {}]) -> Int64
  operation use(s: MyStream[T = Int64, E = {Error}]) -> Int64 = takes_pure(MyStream.widen(s))

LOADS. That is WI-1063's headline exploit verbatim — {Error} reaching a slot that declares
E = {} — with the only change being that widen is declared INSIDE the sort its return names.
BOTH SPELLINGS AGREE (the omitted E above, and E = ?E written out), which is what says it
belongs to the SELF GATE and not to WI-1078: the named-variable seam is closed and this
program still loads. wi1078_unbound_return_var_test::a_self_sort_return_is_not_opened_in_-
either_spelling holds both halves today, asserting the LOAD — it is a boundary record, and
this ticket is what it points at.

WHY IT LAUNDERS, mechanically: open_existential_return runs SlotPosition::CallResult, whose
fill_self returns None for a self reference, so the slot is left UNWRITTEN. A missing binding
is width-ignored by unify_parameterized_view, so the consumer's E = {} demand is satisfied
vacuously — nothing was ever claimed about E, and nothing refutes it.

THE TWO ANSWERS WI-1063 TRIED ARE BOTH RECORDED AS WRONG, at SlotPosition::fill_self:
a FRESH SKOLEM 'would refuse takes_int(reverse(xs)) for every self-returning member in the
stdlib' — driven, the PRELUDE stops loading (cons.type_args) and 1590 tests fail; and the
CANONICAL VAR 'would stamp a dangling FLEX var into resolved_ret for an argument-less
List.empty()'. So this is not a small fix and must not be attempted inline.

THE THIRD ANSWER HAS NOT BEEN TRIED AT A CALL, and it is the one the PARAMETER side already
uses for exactly this position: UnwrittenFill::Projection — the receiver's own projection
(s.E), byte-identical to a hand-written one and already a RIGID neutral (WI-400 zeta). On the
parameter side minting a fresh var instead cost 27 stdlib load errors and the projection fixed
them; the symmetric question here is whether a self slot in a RESULT should take the
projection off the argument that supplied the receiver. It needs the receiver to be
identifiable at the call (param_to_arg_sym already carries that map, and
refine_self_receiver_body_type builds the same projection for the same reason), and it has a
real failure mode to measure: a self-returning member called with no receiver at all
(List.empty()) has no value to project off, which is the case the canonical-var answer died
on.

SCOPE: decide and implement the self-slot filler at CallResult, or record with evidence that
the gate is deliberate and the laundering accepted (in which case say so at
SlotPosition::fill_self and in kernel-language 8.1, and retire the TICKET marker this ticket
put there). ACCEPTANCE: the five-line program above is REFUSED at takes_pure (or the
acceptance is explicitly the other verdict, argued); the prelude still loads; the 1590-test
back-out is re-measured on the delivered tree rather than quoted; List.empty()/Set.empty()
and every self-returning stdlib member (reverse, takeN, filter, map) keep working, each named;
wi1078_...::a_self_sort_return_is_not_opened_in_either_spelling is rewritten to whichever
verdict lands and says which case fails when the change is backed out. cargo-test green via
rustland/scripts/test.sh.

REFERENCE: WI-1063 (the polarity rule, the four use sites, the FOREIGN-only scope and the two
rejected fillers at SlotPosition::fill_self), WI-1078 (the named-variable seam, closed — this
is the other half of that measurement), WI-1059/WI-1061 (UnwrittenFill::Projection, the
parameter-side filler proposed here), WI-374 + docs/design/type-parameter-scoping.md section 3
(the parametricity tie the gate exists to protect) and section 5, docs/kernel-language.md
section 8.1 'In a RETURN the quantifier flips'.
