## description

Typer: resolve a DEFINED-TYPE / ALIAS to its underlying shape BEFORE expansion and projection (design docs/design/expansion-during-unification.md sec.6 OQ6, sec.1). A bare reference to sort IntStream = Stream[T = Int] must resolve to Stream[T = Int, E = ?] BEFORE counting ungrounded positions -- so only E is fresh, T stays Int -- and a projection s.T on s: IntStream must project off the RESOLVED shape (=> Int), not the opaque alias. Likewise a parametric alias sort PairKey = Pair[?X1, ?X2] resolves to Pair[X1',X2'] with fresh leaves per use; chains (A=B[?X], B=C[?Y]) follow to a finite shape. WITHOUT this, a bare alias reference wrongly goes all-fresh (loses the alias-fixed bindings) and a projection over an alias mis-resolves. Prerequisite for correct WI-374 (expansion) and WI-376 (projection) over aliases. RELATES to proposal 011 (type-resolution, still Brainstorming) -- if 011's namespace-level alias-resolution path already resolves defined types to shape, this is a VERIFY + wire-up; if incomplete, this implements it in the typer (extract_type / the unify-boundary). ACCEPTANCE: a bare alias reference expands only the genuinely-open params (IntStream => E fresh, T=Int kept); s.T on an IntStream projects Int; nested/parametric aliases resolve to finite shape; full anthill-core green. Rust-only (typer).
