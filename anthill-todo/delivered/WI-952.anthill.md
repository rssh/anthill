## description

SCALAND'S TRIVIA SKIPPER SWALLOWS AN UNTERMINATED `{- -}` / `{< >}` BLOCK SILENTLY, and then reports a parse error pointing INSIDE the comment. FOUND by /code-review on the WI-950 delivery (2026-08-03); pre-existing, untouched by that change, which is why it is its own ticket. MECHANISM: the `given ws: Whitespace` instance in `AnthillParserImpl` (core/src/main/scala/anthill/parse/AnthillParser.scala) scans a block comment with the guard `index + 1 < length`. On a file that ends mid-comment the inner loop exits with `depth > 0` at `index == length-1`; `continue` is still true, so the OUTER loop reads that last character, finds it is not trivia, and stops. The parser then tries to begin a declaration on the final character of an unterminated comment and reports `Parse error at <length-1>` — a position inside text the author intended as a comment, with no hint that a `-}` is missing. The `{< >}` doc-block arm has the same shape, where `if index + 1 < length then index += 2` silently no-ops on the unterminated case. CONSEQUENCE is a confusing diagnostic, not a wrong parse: the file does not load either way. But CLAUDE.md asks for a loud error over a silent mis-handle, and "unterminated block comment" is decidable exactly where the skip gives up. WORK: on exhausting the input with `depth > 0` (or with no `>}` found), report an unterminated-comment error naming the OPENING position, not the position where the scan stopped — the opener is what the author has to fix. The whitespace instance has no error channel today, so this needs a decision on how it reports: `AnthillParserImpl` holds the `errors` buffer, so the instance can push into it directly, but note WI-950 — the buffer is refusal-SCOPED, and a trivia error recorded inside a production that later backtracks would be dropped with it, so this one probably belongs on the `Parsed.Failure` path in `AnthillParser.parse` instead. NOTE for whoever takes it: rustland does not share this defect — tree-sitter handles comments as `extras` and reports its own unterminated-token error. ACCEPTANCE: a file ending inside `{- ... ` and one ending inside `{< ... ` each produce an error that says the comment is unterminated and points at the opener; plus a control that a well-formed nested `{- {- -} -}` still skips exactly as today.
