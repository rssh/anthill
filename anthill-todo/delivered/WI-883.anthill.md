## Description

GIVE `Ordered`/`PartialOrd` A USE-SITE PROVISION CHECK — an operation of a spec the carrier does not provide must be refused at LOAD, naming the carrier and the missing provision, not left to fail at eval as an Internal. FOUND DELIVERING WI-876, which made the case REACHABLE: before it, `Ordered.compare`/`max`/`min` and `PartialOrd.gt`/`gte`/`lt`/`lte` were eval builtins on the SPEC op, so they answered for ANY operand pair whether or not its carrier provided the spec — `Ordered.max(1.5, 2.75)` returned 2.75 even though `Float` deliberately provides `PartialOrd` and NOT `Ordered` (WI-644: an IEEE order is partial), and it answered using `total_cmp`, under which NaN ranks LARGEST — the 'same program, opposite answers by backend' `wi645_float_nan_ieee_test` exists to forbid. With the host implementations keyed per carrier, that call correctly no longer resolves. MEASURED, and the defect is the DIAGNOSTIC: it dies at eval with `Internal("var_ref(__req_eq) unbound in requirement position")` — the typer could not resolve `Ordered`'s own `requires Eq[T]` at `T = Float` (`Float` provides `NonEq`) and emitted a var_ref forward rather than an error, so the failure surfaces as an interpreter-internal message naming a synthetic slot. Pinned as `eval_test::m3_float_comparison_and_max`'s second arm, deliberately asserting only `is_err()` and NOT the message, with a comment saying pinning the message would pin the defect. THE SHAPE TO COPY IS WI-835's, which built exactly this for `Eq`: a use-site check refusing a `NonEq` carrier at a parameter whose sort `requires Eq`, fired wherever the type is WRITTEN. Ordering needs the dual and does not have one — WI-877's own note records it ('no use-site check exists for Ordered, unlike Eq's') as the reason `Pair`'s `requires Ordered[A], Ordered[B]` over-claim is unenforced and therefore measured harmless. NOTE the two halves are different questions and both are open: (a) a CALL to a spec op whose receiver carrier provides no such spec (this ticket's `max(1.5, 2.75)`); (b) a TYPE written at a parameter whose sort `requires Ordered` (WI-835's shape, the `SortedSet[T = X]` case). Decide whether one check covers both. SCOPE NOTE: the general form is 'any spec', not 'Ordered' — keying a check on op identity is against the repo's typer rule (feedback-typer-no-nongeneric-code); `Ordered` is only the family with a demonstrated bad diagnostic. ACCEPTANCE: `Ordered.max(1.5, 2.75)` is a LOAD error naming `Float`, `anthill.prelude.Ordered` and the unprovided requirement; `m3_float_comparison_and_max`'s second arm is upgraded from `is_err()` to an assertion on that message; the `Float` `PartialOrd` surface (`gt`/`gte`/`lt`/`lte`, IEEE) is unchanged and still loads; full workspace green via rustland/scripts/test.sh. REFERENCE: WI-835 (the `Eq` twin), WI-876 (what made this reachable), docs/design/058-implementation.md §10.
