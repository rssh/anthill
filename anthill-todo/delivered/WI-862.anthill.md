## Description

Proposal 058 SURFACE CONSOLIDATION (058 §4, proposed). TWO HALVES, one grammar session. (a) SUGAR: default provides X[…] — one leading modifier (the internal-modifier pattern), desugared by the converter to a DefaultProvider row with provider = the enclosing sort. A trailing [default] annotation is REJECTED — a bracket list after a bracketed type invites a GLR tie, and [simp]'s precedent follows a rule BODY, not a type. coherent on a PROVISION is REFUSED: the attachment principle — a modifier attaches where its relation's KEY lives — puts Coherent's sugar on the spec sort (coherent sort X, the enum-sort precedent), and that arrives with the DEFERRED Coherent re-homing, not here; a provision must not foreclose a spec/carrier it does not own. (b) RETIREMENT: the fact spelling of provisions retires — provides becomes the one provision spelling, fact returns to plain data assertions — removing the language's one container-sensitive construct (a fact inside a sort meant something different than outside). The provides/fact synonymy is MEASURED (probe q5, recorded in 058-implementation.md §6: a witness spelled provides loads and runs identically). Deprecation warning at the loader's provision-lowering site, which already distinguishes a provision fact from a plain one; then migrate: the stdlib binding fact-rows (rustland/anthill-stl/anthill/*.anthill), the wi84x fixtures, examples, and the 038 provides-block idiom. OUT OF SCOPE: namespace-level op-binding instance facts (outside sorts, quarantined by the nameability gate); the per-clause provides-with-body form (recorded, not required — lands with or after WI-857's one-chain settlement if wanted). ACCEPTANCE: default provides desugars to a row one_default sees — a collision with an explicit DefaultProvider fact is refused naming both; a provision-fact warns (with the flag-day refusal staged behind the migration); the full tree migrated; binding-free stdlib load clean; full workspace green via rustland/scripts/test.sh. REFERENCE: 058 §3.6, §4; design/058-implementation.md §6.
