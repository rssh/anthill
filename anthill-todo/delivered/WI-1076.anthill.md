## description

A SELF-CARRIED SPEC HAS NO CARRIER PARAMETER, AND THE POSITIONAL HEURISTIC PICKS ITS ELEMENT TYPE — measured while settling WI-1069.

`provision_carrier_binding` (kb/typing.rs) identifies a spec's carrier parameter
POSITIONALLY: `sort_type_params_as_pairs(spec).first()`. Nothing declares a sort to
BE a spec or a parameter to be its carrier (059's fact-ban section: no `spec`
keyword, no `SymbolKind::Spec`), so the position is a heuristic. It is right for
every spec that HAS a carrier parameter — `Iterable[C = …]`, `FiniteCollection[C =
…]`, `Eq[T = …]`, `Ord[T = …]` — and wrong for a SELF-CARRIED spec, one whose
carrier is the spec sort itself and which therefore declares no such parameter.

MEASURED over the loaded stdlib, driving `anthill.reflect.typing.provision_carrier`
and `self_provides` through SLD (the probe is in WI-1069's delivery notes):

  List           | Stream        | T      <- carrier is the TYPE VARIABLE T
  List           | FiniteStream  | T
  FiniteStream   | Stream        | T
  MappedStream   | Stream        | T
  FilteredStream | Stream        | T
  Relation       | LogicalStream | T
  List           | FiniteCollection | List   <- the explicit `C =` provisions are RIGHT
  List           | IndexedSeq       | List

`Stream`'s parameters are `T` (element) and `E` (effect row); its carrier is
`Stream` itself. So `List provides Stream[T, {}]` records its carrier as `T`, a type
variable, and `self_provides(List, Stream)` is FALSE — `self_provides` answers only
`FiniteCollection`, `IndexedSeq`, `Iteration`, `PersistentCollection` for `List`.

CONSEQUENCE, and it is why this is a ticket rather than a curiosity: 058 §3.6's
defaults substrate infers "the carrier's own provision is its default" from
`self_provides`, and `defaults.rs` SKIPS any provision the witness classifier
accepts. Six stdlib provisions are therefore classified as witnesses for a type
VARIABLE and contribute no inferred default row. Nothing in the suite fails today,
which is the point — a silent hole in a substrate whose consumers are still being
built (WI-861 onward) is cheapest to close before they arrive.

NOT WI-1069's, and WI-1069 measured why: that ticket asked whether a `provides`
clause's bindings select a carrier at all. They do, the shape is the witness
spelling, and refusing it fails 90 tests. THIS is the residue — WHICH parameter the
reader should read, which WI-1069's description already called "itself unsettled".

WHAT MUST BE DECIDED: whether a self-carried spec's provision should record the
PROVIDER as its carrier (making `List provides Stream[T]` a self-provision), or
whether `Stream` should gain an explicit carrier parameter, or whether spec-hood
should stop being inferred from shape. The first is the smallest and matches what
`Iterable[C = Stream]` already says about `Stream`; it is still a change to the ONE
owner every reader shares (`provision_carrier_binding`), so dispatch, coherence
grouping and the defaults index must be re-measured together — WI-860's
relation-vs-index agreement test is the instrument that catches a drift.

ACCEPTANCE: the six rows above are re-measured and reported after the change; the
chosen reading is written into kernel-language §5.1 (which currently records the
defect with this ticket number) and 058 §3.6; a test DRIVES `self_provides` and
`provision_carrier` for a self-carried spec and for a carrier-parameterized one in
the same program, so the two cannot be conflated again; each test says which case
fails when the change is backed out. cargo-test green via rustland/scripts/test.sh.

REFERENCE: WI-1069 (settled what the bindings mean; measured this), WI-859 (the
own-type-param fold this is adjacent to but NOT the same as), WI-860
(`provision_carrier_binding`, the shared owner; the agreement test), proposal 058
§3.6, kernel-language §5.1.
