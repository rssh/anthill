## Description

§3.4 prover site: extract an operation's DEFINING EQUATIONS from its body ON DEMAND for proofs (design docs/design/abstract-interpreter-and-rules.md §3.4). The last consumer of WI-580's "operation body is the single source of truth" vision — WI-580 itself delivered the eval and SLD-resolver consumers (append structural-unfold + member eq-vs-unification) and the carrier prerequisite (WI-668); the prover/SMT view is the remaining §3.4 piece, framed there as "separate future."

PRINCIPLE: proof/SMT wants an operation's defining equations, but hand-written <=> defining rules duplicate the body and can drift or diverge unsoundly (exactly the problem WI-580 fixed for eval/resolution). Instead, the SAME one-step specializer that serves the SLD site (kb/body_specialize.rs::folded_call_match / reduce) produces the defining-equation SET for an operation when a proof needs it: each match arm's specialization IS one defining equation, op(params) = arm_result_i :- arm_cond_i (design §2 — a derived rule is one step of abstract interpretation of the body). Generated per-proof (proof obligations are generated per-proof anyway; design §3.4).

LAWS ARE THEOREMS (WI-580 scope item 3, unchanged): extra laws (e.g. append associativity) are NOT hand-written defining rules — they are theorems PROVED from the body. Hand-written rules survive only for genuine bodyless relations.

CONSUMER: the prover / SMT path. Today WI-558 delivered the prove-pass (discharge_by_derivation via SLD + verify_proofs); anthill-smt-gen translates rule/fact bodies to SMT. Wire defining-equation extraction so a proof about a bodied operation reads body-derived equations (via the specializer) instead of needing hand-written <=> twins. Determine whether the extraction feeds the SLD prove-pass (discharge_by_derivation), the SMT translation (anthill-smt-gen), or both.

FOUNDATION (delivered, reuse): WI-580 body_specialize engine — folded_call_match returns the top match's per-arm (pattern, residual); reduce does the one-step abstract interpretation with the purity/requires/disjoint-arm gates. The prover consumer likely wants the FULL arm set (including the recursive residual per arm) rather than only the flex-scrutinee case the SLD site case-splits on, so expect an adjacent extraction entry point beside folded_call_match. WI-668 (Continuation carrier) is a resolver-side prereq, NOT needed here.

ACCEPTANCE: design-first — a note specifying (a) how the specializer's per-arm output maps to a defining-equation set consumable by the prover/SMT, and (b) which consumer(s) are wired; then an implementation letting a proof about a small bodied op (e.g. an append or length property) discharge from body-derived equations with NO hand-written <=> defining rule. cargo-test green.

Follow-on to WI-580 (completes its §3.4 / prover scope item). Reuses the delivered body_specialize engine; not blocked on it.
