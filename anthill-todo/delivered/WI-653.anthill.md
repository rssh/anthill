Every invocation re-type-checks the whole embedded stdlib+bundle: type_check_sorts = 3.63s of a ~5s 'status' (ANTHILL_LOAD_TIMING=1, repo project, 114 sorts; debug build). WI-650's new check_eq_override_backing pass alone = ~1.5s (disabling it drops type_check_sorts 3.63s->2.09s). FIX DIRECTIONS (ranked): (a) SCOPE check_eq_override_backing to skip trusted stdlib/bundle bodies -- the stdlib never compares Maps by WI-650's design, so walking it always finds nothing; only project/user code can trigger it -> recovers ~1.5s, targeted+low-risk. (b) BROADER: the CLI loads a known-good embedded stdlib; skip the pure-CHECK typer passes for it (keep the REWRITE passes eval needs: simp, req_insertion) -> recovers most of the 3.63s, more invasive/riskier. (c) WI-652 dedup the 4 walks into one shared walk_body_occurrences -> helps all four. Amplifier: debug build (~10-50x); a release CLI would mask it but the relative regression is real. Acceptance: anthill-todo 'status' on the repo project drops back toward pre-WI-650 timing; full suite green; WI-650's Map eq-override guard still fires on user code (map_eq_error_test.rs green). ### 2026-07-07T10:11:53Z — feedback — user

Eval/resolution consume these rewritten bodies. So 'skip the typer for trusted stdlib' (rejected direction b) is doubly wrong: it would break RUNNING (the rewrites wouldn't happen), not merely relax checking. This CONSTRAINS the cache design (direction 3): the memoized artifact must be the FULLY-LOADED, TYPED, AND REWRITTEN KB image (post build_type, post req_insertion), not the raw parsed stdlib -- so a cache hit yields a KB that both passed checks AND carries the run-ready transformed bodies. Invalidation key = the embedded stdlib+bundle content hash (baked into the binary, so bumps only on rebuild); the per-project workitems.anthill loads/typechecks incrementally on top. Directions (1) dedup walks and (2) make check_eq_override_backing's walk cheap remain valid independent speedups that also help the one-time cache-build cost.
