## Description

Synth-rule lifetime — memoize, don't retract (framing corrected 2026-06-25). `synthesize_conjunction_rule` (kb/execute.rs:288), reached from `coerce_to_single_goal_value` (execute.rs:325), mints a uniquely-named `_synth_{rules.len()}` rule on every multi-goal disjunction/negation lowering (proposal 033 §M4 / WI-076). The name is unique by construction, so hash-consing never collapses two structurally-identical synths, and each `KB.execute` (eval/builtins.rs:755 -> execute_logical_query, execute.rs:608) of such a query permanently grows the symbol table, the append-only `rules` Vec, and the discrim tree. REAL but LATENT: the only entry point is one-shot today (anthill CLI, anthill-todo); no daemon/REPL/server issues queries in a loop, so nothing triggers the aggregate growth. Priority stays LOW until a long-running query consumer lands (proposal 047 effect loop / a query server). CORRECTION to the original framing — the two retract-based options it preferred are the weak ones. (a) 'retract on Drop' is architecturally impossible: `SearchStream` (resolve.rs:431) does NOT own or borrow the KB — it threads `&mut kb` through split_first/step per pump — so a Drop impl has no KB handle to call retract. (b) 'bulk-retract after stream exhaustion' misses abandoned streams: lazy streams are routinely dropped half-consumed (take(1), short-circuit, walk_solutions stopping early) and never reach an exhaustion hook. Worse, `KnowledgeBase::retract` (kb/mod.rs:1556 — the original '710' ref is stale) only flips entry.retracted=true and cleans indexes/discrim/refcounts; it does NOT reclaim the RuleEntry slot (the Vec is append-only, RuleIds must stay stable). So (a) and (b) cannot fix RuleEntry growth — the very thing the WI calls the larger leak. CHOSEN FIX — option (c), structural-dedup memoization. Cache the synth head functor keyed on a canonical form of the body. The rule is already stored De Bruijn (assert_rule_debruijn_with_nodes abstracts over the fresh free-vars), so key on (canonical De Bruijn body, arity); a repeated query reuses one rule, re-allocating only the head application with the current query's fresh free-var args. This converts the leak from unbounded-in-#queries to bounded-by-#distinct-multi-goal-bodies (a static program-text quantity), needs NO retraction (sidesteps both the Drop-can't-reach-KB and abandoned-stream problems — the synth rule is a memoized lowering artifact, not garbage), and is a small perf win on hot repeated reflect queries. Residual: the interned synth symbol still can't be reclaimed (no symbol GC), but #distinct-bodies-bounded interning is acceptable. Acceptance: issue the SAME multi-goal disjunction/negation query N times and assert KB rule count is CONSTANT after the first (zero growth, not merely sub-linear); plus N distinct bodies -> growth <= N. Exercises the synth path via tests/eval_q3_test.rs::q3_disjunction_multi_goal_branch_lifts_via_synthesized_rule.
