## Description

Migrate Type/EffectExpression from hash-consed Term to an occurrence (node-world) carrier; keep hash-consing as an OPTIONAL derived Node->TermId index only where dedup/equality pays (row canonicalization, the unify_effect_rows shared-field fast-path, recoverable via Rc::ptr_eq). Rationale: the representation note says hash-consing is not required for type-hood and is disclaimed for binders/arrows; this continues the WI-246/251 node migration (rule bodies and op bodies are already NodeOccurrence). Scope is the whole Type spine, NOT just the row: a hash-consed arrow term cannot hold an occurrence child (WI-251), so the inner EffectExpression cannot migrate without the enclosing arrow/Type. Much is already carrier-agnostic: unify_effect_rows is generic over TermView, subst.bind_value binds Value::Node (WI-375 E={Modify[c]}, WI-342 type params), substitute_ref_syms_occ rewrites occurrences, Positioned/make_positioned bridges binder leaves into terms, discrim keys on structural DiscrimKey; WI-375 already node-carries WRITTEN effect rows. Remaining holdouts: term-building construction (make_effect_expression_*/build_canonical_effects_rows/make_effects_rows_type), making decompose_effect_row structurally walk a Node-carried row, the arrow/Type cascade per WI-251, reification (extract->TypeExtractor) and any TermId-keyed row indices. Payoff: proposal 048's guarded-effect guard becomes List[NodeOccurrence] uniform with rule/op bodies, dissolving the term-vs-occurrence split documented in proposal 048 open question F.
