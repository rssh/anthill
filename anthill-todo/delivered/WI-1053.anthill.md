## Description

scaland re-derives `getNamedArg` and the string-field decoder privately in FOUR places; rustland has the same primitive factored once in `kb::typing` with 203 call sites.

MEASURED 2026-08-08 while delivering the Scala 3.8.4 bump / language_version work (commit f7951aca), by the /simplify review pass over that diff.

THE COPIES. Named-arg lookup over a fact's `namedArgs` (`while` loop, `kb.resolveSym(sym) == key`, `Option[TermId]`):
  * scaland/core/src/main/scala/anthill/codegen/scala/ScalaProfile.scala (private getNamedArg)
  * scaland/anthill-smt-gen/src/main/scala/anthill/smtgen/Policy.scala:100 (private[smtgen] getNamedArg)
  * scaland/anthill-smt-gen/src/main/scala/anthill/smtgen/SmtGen.scala:346-355 and :494-507 (inlined twice, not named)

String-literal field decode (`case Term.Const(Literal.StringLit(s)) => Some(s)`):
  * Policy.scala:86-95 (readStringField), ScalaProfile.scala (stringOf), TacticEmit.scala:75 and :146 (inlined twice)

And the body-less-fact walk itself — `tryResolveSymbol -> byFunctor -> if ruleBody(rid).isEmpty -> Term.Fn -> string-field filter -> first match` — is duplicated between `Policy.lookupExplicitPolicy` (:42-69) and `ScalaProfile.findMapping`, ~25 lines each, down to the same comment explaining that the string-literal filter is what skips the loader-synthesised schema-declaration fact.

WHY IT IS NOT JUST TIDINESS. `Policy.scala:98`'s own docstring says it "Mirrors `anthill_core::kb::typing::get_named_arg`" — so the tree KNOWS this is a shared primitive, and mirrors the function while not mirroring the thing that makes it worth mirroring: that it lives in `kb` and everybody calls it. The "skip bodied clauses" decision is currently made independently at two sites and documented at only one; the retraction and schema-fact rules are likewise duplicated. A change to any of those has two homes and no compiler help finding the second.

DIRECTION. The helpers belong in scaland's `anthill.kb` (the peer of rustland's `kb::typing`), NOT sideways: `anthill-smt-gen` and `anthill-scala-gen` both `dependsOn(core)`, so core cannot call `Policy`'s copy — the lift has to go down. Note `TermView.namedArg` (core/src/main/scala/anthill/kb/TermView.scala:183) already exists but keys on `TermSymbol` and returns `Value`, and its own header says NOTHING READS THROUGH IT YET; making a profile reader its first consumer is a bigger decision than this ticket. The string-keyed reader should sit above it for now.

SCOPE: `getNamedArg`, a string-field variant, and a body-less-facts-by-functor walk in `anthill.kb`; then convert all six call sites and delete the private copies. `unwrapOption` is NOT duplication — ScalaProfile's is scaland's only one (rustland has `unwrap_option` in kb::typing, so it is a parity gap, not a scaland duplicate) — but it may as well move with the others.

ACCEPTANCE: one implementation of each helper in `anthill.kb`; zero private copies left in ScalaProfile / Policy / SmtGen / TacticEmit; a test that DRIVES the shared walk (resolve a real fact and read a field off it), not merely one asserting the helpers compile. Say at the test site which assertion fails if a call site is reverted to its private copy. sbt test green.

SOURCE: /simplify review of commit f7951aca.
