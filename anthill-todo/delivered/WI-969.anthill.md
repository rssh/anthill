## description

Decide whether a NEVER-BOOTSTRAPPED KnowledgeBase is a supported configuration, and retire the fallbacks it exists to feed.

WI-967 established that register_prelude is the one owner of bootstrap and that every load entry point calls it. It deliberately did NOT put bootstrap in KnowledgeBase::new(), because a bare KB turned out to be a real, load-bearing configuration. This ticket is that deferred decision.

MEASURED under WI-967 (probe: register_prelude called from KnowledgeBase::new(), full workspace run):
  - every load-entry arrival becomes pre-bootstrapped: 3911 of 3911.
  - exactly 25 tests fail, in three groups:
      22 in kb/resolve.rs + kb/simp_rewrite.rs - the decisive ones. KnowledgeBase::eq_functor / unify_functor resolve the qualified name and FALL BACK to a bare intern("eq") / intern("unify"), documented as 'only for kernel-less unit KBs'. Those tests build their [simp] equations on that fallback (see the comment at resolve.rs, `let eq_sym = kb.intern("eq"); // matches eq_functor()'s bare fallback`). On a bootstrapped KB their rules stop matching, so they stop firing - the failure is a rewrite that silently does not happen, not an error.
      2 in kb/mod.rs - assert whole-KB counters (fact_count() == 0) that the WI-320 bridge fact breaks. Shallow; these tests should count what they asserted, not the whole KB.
      1, typing_test::types_compatible_bootstrap_safe_when_prelude_not_registered - WI-337 made the typer's arrow comparison return false instead of panicking on a KB that was never register_prelude'd.

THE TENSION, and it is a CLAUDE.md one: 'avoid fallbacks, better know about errors early' vs a bare-name fallback that exists solely so unit tests can skip bootstrap. The fallback is not reachable from any real program - every production path loads, and every load bootstraps. So today the kernel carries two spellings of `eq` where only one can occur in production, and the test suite is the only thing that exercises the second.

IF the bare KB is declared unsupported, the following all become dead and removable, which is the actual prize:
  - eq_functor / unify_functor's unwrap_or_else(|| self.intern(..)) fallbacks
  - WI-337's try_make_empty_effects_rows bootstrap-safe path (verify: check whether it has any other caller first)
  - register_prelude's idempotency guards could be reconsidered (NOT removable on this ticket's evidence alone - a KB loaded into twice still re-enters; see the emit_effects_runtime_bridge_fact doc)
and KnowledgeBase::new() can bootstrap, making 'un-bootstrapped KB' unrepresentable per 'prefer make illegal state unrepresentable'.

COST: the 22 tests must be rewritten to build equations on the QUALIFIED eq/unify symbol. That is arguably a fix in itself - they currently test a symbol resolution that production never takes.

WATCH FOR: this is NOT a pure refactor. Rewriting a [simp] test onto the qualified functor changes what the test drives. Each of the 22 needs its assertion re-checked against what it was pinning, not just made green.

ACCEPTANCE: a stated decision on whether a bare KB is supported, written where the answer lives (KnowledgeBase::new and/or register_prelude, which currently states the WI-967 position); if unsupported, the fallbacks named above are GONE, not merely unused, and each rewritten test says at its site what it now drives; cargo-test green.

SOURCE: WI-967 - measured and deferred there as its own decision, not a refactor detail.
