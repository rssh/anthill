## description

Typer: implement EXPANSION DURING UNIFICATION at every sort application (kernel-language.md section 8.1 'Expansion during unification', added 2026-06-03). A parametric sort referenced as a type with unbound parameters must unify as that sort applied to a FRESH VARIABLE per unbound parameter -- type parameters AND effect-row parameters (effects E; proposal 045 section 2) alike -- so the parameters participate even when no binding is written. TODAY this is only HALF-implemented: unify_parameterized_with_sort_ref (typing.rs:7965) binds a sort's loader-cached canonical param Vars from a PARAMETERIZED side against a bare sort_ref, propagating the parameterized side's bindings into the sort's return-type/effect positions. But a BARE-vs-BARE application (both sides sort_ref(S)) does NOT expand -- so when iterator(l: List) -> Stream returns a BARE Stream (list.anthill:67) and collect's param s: Stream is also bare, the call collect(iterator(xs)) unifies sort_ref vs sort_ref, binds NOTHING, and the Stream's element T and effect-row E never thread (the WI-368 leak: undeclared effect ?_). FIX (kb/typing.rs unify_types / the sort_ref arms): expand a bare sort_ref to its full fresh-var-parameterized form at the unification boundary so every sort application threads its parameters, including the effect row. The expanded effect-row fresh var must then CLOSE to the closed empty row {} against a pure declared context (row unification at the effect check -- WI-307 territory). SUBSUMES the special-cases it generalizes: WI-357 (carrier element threading) and WI-365 (effect grounding) both special-case what this general rule does uniformly. NOTE the surface gap: writing Stream[E = {}] in .anthill is ungrammatical (the SortBinding value slot is _type = simple/parameterized/variable/tuple/arrow; the {} effect-row literal is not in it -- the library/002:132 gap); the typer expansion + row-close is the route that needs NO new source syntax (the empty row IS representable internally: make_effect_expression_empty_row, mod.rs:3090; effects_rows Type node, term_view.rs). ACCEPTANCE: a bare-vs-bare sort application expands its params (incl. the effect-row) during unification; length(collect(List.iterator(xs))) typechecks pure (no undeclared ?_); an abstract-carrier walk (operation walk(c: C) effects E where C provides Iterable = collect(iterator(c))) stays effect-polymorphic; wi357/wi362/wi365 + full anthill-core green. BLOCKS WI-368, and is the principled generalization of WI-357/365. RELATED WI-307 (045 row-unification -- the row-close half). Rust-only (typer; scaland has no typer).
