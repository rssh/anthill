## Description

Tail-call optimization for operation/closure dispatch + bump activation-stack cap. Follow-on to WI-060. At dispatch_call time the current frame has nothing left to do (its expr has been fully consumed by the time we dispatch), so replacing it with the body frame is always safe — no static tail-position analysis needed. Change: enter_operation / enter_closure replace the top frame instead of push + awaiting=OperationResult. Also bump DEFAULT_DEPTH_CAP from 1024 to 1_000_000 (activation frames are heap-allocated; cap is a safety valve not a memory bound). Update m1_infinite_recursion_hits_depth_cap to use non-tail form (let _ = f() 
 0) since tail infinite recursion is a correct constant-time loop under TCO. Preserve original op on replacement so error messages stay readable. Acceptance: existing tests green; new test m1_tail_recursion_runs_deep showing O(1) stack over 10000 levels.
