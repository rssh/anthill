## Description

Pattern reform: lift patterns to occurrence-native via a new NodeKind::Pattern(Pattern) sibling to NodeKind::Expr / NodeKind::RuleHead. PROBLEM: the original NodeOccurrence design (node_occurrence.rs:343-346) deferred 'pattern reform' — Expr's binding-position slots (Lambda.param, LambdaWithin.param, Let.pattern, MatchBranch.pattern) stayed as TermId even though every other child slot is Rc<NodeOccurrence>. The asymmetry forces the De Bruijn opener (open_debruijn_node) and closer (node_to_debruijn) to special-case those fields via term_from_debruijn / term_to_debruijn rather than uniform for_each_child + reassemble walking — the structural concern WI-298 was originally written to patch. The hash-consing of pattern TermIds is incidental (bodies are GOALS, not search keys; patterns aren't discrim-tree keys), so there's no search reason to keep TermId; the deferral was a 'separate concern' marker, not a load-bearing decision. DESIGN: patterns are not expressions (they have their own grammar — VarPattern / Wildcard / Literal / Constructor / Tuple — match-time matchers, not evaluable forms), so they get their own NodeKind variant rather than Expr sub-variants. (1) Add NodeKind::Pattern(Pattern) to NodeKind. (2) enum Pattern { Var { name: Symbol, type_ann: Option<Rc<NodeOccurrence>> }, Wildcard, Literal { value: Literal }, Constructor { name: Symbol, pos_args: Vec<Rc<NodeOccurrence>>, named_args: Vec<(Symbol, Rc<NodeOccurrence>)> }, Tuple { positional: Vec<Rc<NodeOccurrence>>, named: Vec<(Symbol, Rc<NodeOccurrence>)> } }. Each Pattern child is itself an Rc<NodeOccurrence> whose .kind is NodeKind::Pattern(...) (or NodeKind::Expr for the type_ann slot inside Var). (3) Change Expr::Let.pattern / Expr::Lambda.param / Expr::LambdaWithin.param / MatchBranch.pattern from TermId to Rc<NodeOccurrence>. TOUCH POINTS: (a) node_occurrence.rs: NodeKind + Pattern enum; extend for_each_child / reassemble / drain_expr_children to recurse into Pattern children; open_debruijn_node loses Lambda/LambdaWithin/Let/Match-pattern special-case arms (uniform fall-through via for_each_child); node_to_debruijn drops its Lambda/LambdaWithin arms and the pattern paths in Let/Match. (b) load.rs: build_frame now takes &KnowledgeBase and runs term_to_param_occurrence on the carried pattern TermId at BuildFrame::Lambda / Let / Match assembly. (c) eval/eval.rs::reduce_lambda / start_let / MatchDispatch bridge via pattern_to_term for the existing TermId-based match_pattern / extend_env_from_pattern paths; native Pattern dispatch is a follow-up. (d) typing.rs Lambda / Let / Match arms also bridge via pattern_to_term. (e) persistence/print.rs renders Pattern via write_pattern; Expr-kind sub-children delegate to write_occurrence. (f) cpp-gen pattern_var_name_occ / analyse_pattern_occ are Pattern-occurrence variants of the term-based helpers. OUT OF SCOPE: Let.type_annotation, Apply.type_args, ApplyWithin.type_args — type-position TermIds; their DeBruijn-remap stays in WI-298 scope. KNOWN DEFERRED (handled in a follow-up): collect_occurrence_global_vars_ordered / collect_occurrence_type_constraints / collect_unbound_vars_node / occurrence_to_term — three walkers don't yet descend into Pattern-kind occurrences (the asymmetry vs node_to_debruijn). Latent today because Pattern.Var.type_ann is always None at load_pattern_var; will become live the moment any pass populates that slot. ACCEPTANCE: NodeKind::Pattern(Pattern) exists; all 4 pattern slots are Rc<NodeOccurrence>; open_debruijn_node has no pattern arms; node_to_debruijn drops its pattern-position term_to_debruijn calls; full cargo-test green; multi-agent code review clean (with the documented deferrals).
