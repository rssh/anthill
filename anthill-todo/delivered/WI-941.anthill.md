## Description

A NULLARY bodied operation in value position answers 1 INDEFINITE solution with an unbound result -- silent in debug AND release.

MEASURED (2026-08-02, via common::load_kb_with + query_unary against the shipped stdlib):

  rule z_out(?z) :- ?z = Vec3.vec_zero()
  -> 1 solution(s); definite = false; value = Term { id: TermId(...) }  (unbound residual)

No panic, no diagnostic, no zero. A caller that counts solutions -- 'query_unary(...).len()', the dominant pattern in this repo's suites -- sees SUCCESS and consumes a residual as if it were a value. That is worse than either sibling defect: WI-937 aborts loudly in debug, WI-938 answers 0. This one answers 1 and is wrong.

CAUSE (read, not inferred): rustland/anthill-core/src/kb/resolve.rs:5726-5728 --

  let params = self.symbols.arg_places(op);
  if params.is_empty() { return v; }   // nullary / unscanned op -- nothing to fold

-- so a nullary bodied op never folds and never reaches bridge_op_to_eval at all. The comment conflates two cases ('nullary' and 'unscanned'), and for the nullary one the early return is not a decline but a silent wrong answer.

NOT COVERED BY THE SIBLINGS. WI-937 is the SLD->eval bridge aborting on an entity-field read; WI-938 is the arity+1 goal form answering nothing. Neither names nullary ops, and neither fix would reach this line.

CONTROL that separates it from WI-937: the SAME operation called through the interpreter works -- vec3_ops_test::the_four_members_evaluate drives anthill.geometry.Vec3.vec_zero and asserts (0,0,0). So the body is fine; the resolve-time fold is the defect.

WHY IT MATTERS NOW: WI-935 gave anthill.geometry.Vec3 a nullary member (vec_zero), so this is reachable against a stdlib type from a plain rule body. Found by /code-review on that ticket and re-measured independently.

ACCEPTANCE: '?z = <nullary bodied op>()' either EVALUATES (preferred -- it is the same fold the n-ary case gets) or DELAYS/errors visibly; it must not answer a definite-looking solution carrying an unbound residual. Driven by a test that resolves the goal and asserts BOTH the bound value AND is_definite(). CONTROL: an n-ary op is unaffected, and the interpreter path still answers. Split the conflated 'nullary / unscanned' comment so the remaining early return says which case it is. cargo-test green.

SOURCE: /code-review on WI-935.
