## Description

Bootstrap must REFUSE a declaration it cannot emit correctly, instead of emitting uncompilable Scala -- measured, 27 of 44 prelude files do not compile, and every one of them emitted quietly.

DECIDED 2026-08-08 (rssh): keep Bootstrap minimal -- it stays parse-IR-driven with no KB and no typer (proposal 034) -- and make the constructions it cannot handle a LOAD-TIME REFUSAL rather than a plausible-looking emission. This is the WI-891 inversion applied to scala-gen: cpp-gen turned an unlowerable body from a silent zero into a build failure. `BootstrapError` already exists and already does exactly this for one case (the eponymous-variant-alongside-siblings shape, WI-940), so the mechanism is in place and this ticket widens its remit.

WHY IT MATTERS FOR WI-1020: that ticket requires the emitted prelude CLOSURE to compile, and says "any file excluded from compilation must be named in the test with its reason -- no silent skips". A refusal IS that named exclusion. Without this the closure test cannot be written at all, because the files that would fail are precisely the ones nothing refuses.

MEASURED INVENTORY (WI-1020's harness, commit 0ebec357), split by whether the information Bootstrap needs is ALREADY IN THE PARSE IR. This split is the ticket's main content -- the first group is a fix, the second is a refusal.

== GROUP A: information IS present and is dropped. FIX, do not refuse. ==

A1. Operation type parameters are never read. `Operation.typeParams: IndexedSeq[TypeParam]` exists (parse/IR.scala:373); grep for it in OpGen.scala and Bootstrap.scala returns NOTHING. So `operation pure[A](a: A) -> M[A]` emits `def pure(a: A): M[A]` with `A` unbound. Affects monad, delay, and every operation with its own type params.

A2. A sort's HEAD type parameters are not collected. `renderMainSort`'s `typeParams` takes only `Item.AbstractSortItem`, so `sort anthill.prelude.Monad[M[T]]` emits `trait Monad:` with no parameters at all. (`SortWithBody.isTypeParam`, IR.scala:339-345, is how the parser marks these; the loader reads it and Bootstrap does not.)

A3. A sort's OWN name in a member signature loses its type arguments. `sort Cell[V]` emits `trait Cell[V]:` and then `def new(v: V): Cell`. The enclosing sort's parameters are in hand at `renderMainSort`; `TypeGen.render` is simply never told them. Same mechanism as WI-1021's second half -- see the feedback on that ticket; fix once, in the same place.

== GROUP B: information is genuinely absent without a KB. REFUSE. ==

B1. A name that resolves to nothing Bootstrap can see. `Term`, `NodeOccurrence`, `Type`, `Duration` reach the output as bare identifiers that name nothing in the emitted tree (effects, meta, sort). Bootstrap cannot know whether such a name is a sort in another file, an import, or a typo -- that is a resolution question.

B2. `TypeExpr.Variable` renders as `?`, which is not a Scala type (TypeGen.scala:18-21); `Denoted` and `EffectRow` render as `Any` placeholders (:29-39). WI-1020's own text flags these as the open question of what to do about files that legitimately cannot compile. The answer is now: refuse them.

B3. Prelude type-map arity mismatches: anthill `Stream[Element, E]` maps to Scala `LazyList`, which takes ONE parameter, so `Iterable` emits `def iterator(c: C): LazyList[Element, E]` -- `Too many type arguments`. Whether the map entry is wrong or the mapping is unrepresentable is WI-1021's question (it already asks about `List`/`Set`/`Map`/`Stream`); until that is settled a refusal beats an emission.

SCOPE: fix Group A; refuse Group B through `BootstrapError`, naming the declaration and WHY it cannot be emitted. Then WI-1020's closure test becomes writable: generate the prelude, compile what was emitted, and assert the refusal set equals a named, explained list.

A REFUSAL IS NOT A SKIP -- it must name the declaration, its span, and the construct that defeated it, the way the existing `BootstrapError` does. A caller catching it and continuing would recreate exactly the blindness this closes.

WATCH OUT: refusing too much makes the backend useless -- 16 of 44 prelude files compile TODAY, and that number must not go DOWN. State it as a floor in the test.

ACCEPTANCE: Group A fixed, driven by the compile harness (monad/cell emissions compile). Group B refused with a located message per case, each pinned by a test asserting the message names the declaration. The count of prelude files that compile is asserted and is >= 16. Say at each test site which assertion fails when that arm is backed out. sbt test green.
