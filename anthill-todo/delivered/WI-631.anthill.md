## Description

unique-or-loud short-name entity resolution (WI-515 follow-up, user-directed). KB::resolve_entity_functor currently resolves an AMBIGUOUS short entity name by silently picking the minimal qualified name (the WI-515 compat tie-break) — real stdlib collisions exist (entity 'guarded' in anthill.prelude vs anthill.reflect.LogicalQuery; 'Unknown' in prelude/meta vs realization/witness), so a caller silently gets one sort's schema. Per the loud-over-silent principle: make resolution three-way (Unique / Ambiguous(candidates, qualified-name order) / NotFound); a short name resolves ONLY when unique; ambiguity surfaces loudly listing the candidates and asking for a qualified name — EvalError from the interpreter KB.fields builtin, Err through the bridge's SortQuery lowering (query_to_goals has the Result channel), panic on the bridge's Vec-returning fields() surface (precedent: facts_of panics on caller type errors). Exact qualified-name resolution stays O(1) and unaffected. Rationale discussion: the short-name string surface is a display-name convenience with no scope context — the principled endgame is WI-632 (typed refs / scoped resolution); this WI just removes the silent-arbitrary-pick hazard cheaply. ACCEPTANCE: ambiguous short name errors loudly on all three surfaces (tests incl. a two-sorts-same-ctor fixture); unique short and qualified names unchanged; cargo-test green.
