## Description

SCALAND: THE `requires`/`import` PATH DROPS THREE CASES SILENTLY, WHICH THE PROJECT FORBIDS. All three are in `Loader`, all three load with ZERO diagnostics, and all three leave a name the user wrote doing nothing. (1) A WILDCARD IMPORT FROM A NAME THAT IS NOT A SCOPE. `processImports`'s `Wildcard` arm does `addParent(scope, ScopeInclusion(ScopeId.of(sym), …))` on a symbol of ANY kind. MEASURED: `sort User { import demo.Host.op1.* }` where `op1` is an OPERATION loads clean, and `resolveInScope("op1", demo.User)` answers `NotFound` — `addParent` creates the IMPORTING scope's record but never the parent's, and `resolveRecursive` then treats the missing parent as eligible and finds nothing. (2) The same shape in `processRequires`, where a `requires` naming a non-sort symbol links a parent that resolves nothing. (3) `case _ => // Parameterized requires — TODO` in `processRequires` drops `requires Ord[T]` entirely: no scope-parent link, no message, and every name the requirement was meant to bring into scope then fails to resolve later — where `resolveName`'s `NotFound` arm answers `kb.intern(name)`, also with no diagnostic. OUTCOME: (1) and (2) DELIVERED — a `parentScopeOf` gate admits only a namespace or a sort for a wildcard import and only a sort for a `requires` (§5.1/§5.2), and otherwise raises naming the symbol AND the kind it actually got, because "did nothing" is not a diagnosis a reader can act on. (3) MOVED TO WI-992, measured rather than assumed: routing the parameterized form through ordinary resolution fails EIGHT tests, and not one of them is a binding — every failure is a base name that does not resolve, e.g. `requires PartialEq[T]` inside `sort anthill.prelude.Eq`. The cause is not in this clause: a top-level DOTTED declaration is defined in `_global` under its whole dotted spelling, so a sibling's SHORT name is unreachable from it, which is also why the stdlib's only two bare `requires` are its only two fully-qualified ones. Deferring it kept a name-resolution change out of a stop-dropping-things-silently ticket; the arm now carries that reasoning and the WI-992 pointer instead of a bare TODO. The rustland twin of (1) is WI-993 — `find_scope_by_name` there checks nothing about scope-hood; (2) has no twin, rustland's `requires` emits a fact rather than linking a parent. ACCEPTANCE MET: one test per delivered case asserting the diagnostic, plus the probe that the import contributes nothing; both fail with the gate deleted and no other test moves. Related: WI-992, WI-993, WI-986.
