## Description

scaland twin of WI-995 (rust side DELIVERED, commit b16e44b8): an import is spent in the file that lists it — and the rule is keyed on the SYMBOL, not the name.

THE RULE (user decision 2026-08-04, delivered rust-side): an import resolves ONLY in the
file whose text lists it, and it is SPENT at name resolution — nothing after the symbol
table reads it. Scaland reproduces the pre-rule divergence exactly, via symbol identity
instead of TermId hash-consing:
  - a scope IS the address: `opaque type ScopeId = TermSymbol` (intern/SymbolTable.scala:75),
    and `define` merges by short name (:184), so `namespace demo` opened in two files —
    or `sort X` next to `namespace X` — is ONE scope entry;
  - one shared import table per address: `Scope.imports: HashMap[String, TermSymbol]` (:89),
    written by `addImport` (:201) from pass-2 `processImports` (load/Loader.scala);
  - sole reader: `resolveRecursive` step 1b (:227) — the line-for-line mirror of rust's
    `resolve_in_scope_recursive` step 1b. So WI-995 fixtures B and D (an import written in a
    separate file at the same address changes a bare name in an unedited file) reproduce here.

WHAT THE RUST DELIVERY SETTLED — inherit, do not re-decide:
  - corpus cost MEASURED ZERO (counterfactual double-answer audit, six groups, 10.9k-24.1k
    resolutions; 238/250 imports selective, 0 wildcard, 0 top-level), so the rule lands
    directly — no warning/migration phase;
  - THE RULE IS KEYED ON THE SYMBOL, not the name: `imports` is last-write-wins, so asking
    "did some visible file write this NAME" still lets file A read file B's target by load
    order. The check must ask "did THIS file's import bind THIS symbol". Fixture D cannot
    catch this (its foreign import is the only writer of the name); the TWO-WRITER fixture
    (two files import the same short name from different targets at one address) is the
    control and must fail with the fix backed out;
  - an import writes BOTH an alias (`addImport`) and, for a wildcard, a parent link
    (`addParent(scope, p, isEnclosing = false)`, WI-988) — both must be file-scoped, and
    they are suppressed by different predicates.

SCALAND-SPECIFIC SHAPE. There is no source registry — `Span.file: String`
(span/Span.scala:53) is the existing file-identity carrier, and the loader is already
per-file (`scanDefinitions(kb, files)` / `loadAll`). Thread a file identity (rust:
SourceId + ImportOrigin) through addImport/addParent and into resolveInScope so step 1b
honors only the resolving file's own imports. Rust's `ImportOrigin::Invocation`
(`anthill query -i`) has no scaland analog today — state the gap at the seam rather than
inventing one. Prelude/global registrations (load/Prelude.scala:182 wires global imports
for reflect entities) get the treatment rust gave `_global`: a synthetic origin, exempt by
construction, stated at its site. Expect suite migrations where a test relied on an import
re-exporting through the address (rust had 12); each is a fix to the test's imports, not a
counterexample to the rule.

ACCEPTANCE: WI-995 fixtures A-D ported to scaland (B and D flip to the file-local answer,
A and C unchanged) plus the two-writer symbol-keying fixture, each DRIVING resolution
(resolve the bare name, assert WHICH symbol it binds), with the two-writer test verified to
fail with the fix backed out; sbt test green.
