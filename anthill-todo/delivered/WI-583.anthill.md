## Description

Position-directed automatic gating of Bool-returning operations as rule-body conditions (the implicit eq(op, true) desugaring). GOAL: let a Bool-returning operation be used directly as a rule-body goal/condition — write `:- valid(?x)` instead of the explicit `:- eq(valid(?x), true)`. Sibling of WI-529 (position-directed boolean connectives and/or/not): this extends position-directed handling to Bool-returning OPERATIONS in goal position. SEMANTICS: a bare op-call goal boolOp(args) whose functor is an operation with return type Bool desugars to eq(boolOp(args), true) — reduce the op-call; reduces to true => goal SUCCEEDS, false => FAILS, under-determined (args unbound / abstract carrier) => SUSPEND (residual, never NAF-decided, WI-067 discipline). GATING CONDITION (typer-checked): apply ONLY when the goal head is an operation returning Bool; a relation (rule-head functor) still resolves relationally; a non-Bool op in goal position is a LOUD error, not silently treated as a relation. POSITION-DIRECTED: goal/rule-body position only; a Bool op in VALUE position is unaffected (it is just a value), exactly the WI-529 split. REALIZATION (decide at impl): (a) loader desugaring — rewrite a bare Bool-op goal to eq(op, true), reusing the resolver builtin_eq + reduce_operand (which already evaluate an op-call operand and compare); or (b) a resolver bridge — a goal reducing to Value::Bool maps true to Success / false to Fail. Option (a) is the lower-risk reuse. COMPOSES: a Bool SPEC op gated this way dispatches through the requires dictionary over the carried type (WI-573 spec-op guard discharge) — gating + WI-573 compose for non-native carriers; and a gated Bool-op condition owes the op requires as a rule condition (the owed-on-use model, docs/design/constrained-term-substrate.md §Rules about an operation). SOUNDNESS: gate ONLY PURE Bool ops — an effectful op evaluated in a guard is a silent side effect (reject, or require purity); a partial/erroring op surfaces its error, not a silent fail. NOT a WI-502 prerequisite (WI-502 typed rule patterns use type guards + comparisons; this is an ergonomic surface). ACCEPTANCE: a pure Bool op used bare in a rule body (`:- valid(?x)` with valid: T -> Bool) parses, loads, and resolves as eq(valid(?x), true) — true=success, false=fail, unbound-arg=suspend; a non-Bool op in goal position is a loud load/type error; cargo-test green.
