## description

RUSTLAND: `scope_display_name` IS DUPLICATED, AND IT DISAGREES WITH SCALAND ABOUT WHAT A SCOPE IS CALLED. Found while driving WI-962 (the scaland twin), verified in the source, NOT fixed there. Two defects, one file: (1) DUPLICATION — `load.rs` has the helper at ~:8320 and a byte-identical open-coded copy of the same unwrap at ~:3299 (the `ForbiddenInternalAccess` raise, which builds `scope_name` inline off `kb.get_term(scope)`). That is exactly the two-copies state scaland just retired: WI-962 promoted its helper to `KnowledgeBase` and routed both unwraps through one `scopeFunctor`, so 'what do we call this scope' has ONE answer. (2) DIVERGENCE — rustland's helper returns `local_name` (the SHORT name: `C`), scaland's returns the QUALIFIED name (`demo.C`); rustland degrades a non-`Fn` scope term to the string `"_unknown"`, scaland REFUSES with an IllegalStateException on the grounds that every scope term is a nullary name term by construction so a degraded string can only hide a producer bug. So the same source file loaded by the two implementations yields two different scope names in the same diagnostic, and two different not-a-scope policies. WORK: pick ONE of each and state it in `docs/kernel-language.md` — this is a user-visible diagnostic, so the choice belongs in the spec, not in whichever implementation was edited last. Qualified is the argument-carrying one (a short `C` does not say WHICH `C` among sibling scopes); the refusal is the one this repo's 'prefer a loud error over a silent skip' principle points at, and `_unknown` is precisely the placeholder-that-reads-as-handled that principle names. Note rustland has NO drifting raise site of the kind scaland's pass-4 import retry was — both its `UnresolvedName` sites (~:8605, ~:8686) already go through the helper. ACCEPTANCE: a test that DRIVES it — provoke the diagnostic and assert the rendered scope name, not that an error came back; say at the site which test fails when the change is backed out. Related: WI-962, WI-957.
