## Description

Language surface: a PARAMETERIZED type expression as a value argument -- `is_modifiable(Cell[V = Int64])`, `facts_of(kb(), List[T = Int64])`. Today a `Type`-declared parameter accepts only a BARE reference: a free-standing entity (`facts_of(kb(), WorkItem)`) or, since WI-206, a bare sort (`is_modifiable(Cell)`). A parameterized type in the same slot fails to load: the parser already produces the right shape (`Cell[V = Int64]` -> `Fn{Cell, V: Ref(Int64)}`), but the loader converts it to an Expr::Apply whose args are typed as VALUE expressions, so the inner `Int64` dies as UnresolvedName. This gap is shared by EVERY `Type`-taking reflect op (facts_of / sort_template / operations / fields / rules / assert / is_modifiable), none of which can currently be handed a parameterized type from source. Note none of them would USE the type arguments -- they all key on the head sort -- so this is about the surface not FAILING, not about extra expressive power. Implementation sketch: (a) typer -- in visit_type's Expr::Apply arm, when `expected` is `anthill.prelude.Type` and the functor is a SymbolKind::Sort, push a `Type` hint into every argument (so nested bare sort names read as types via check_bare_ref's WI-206 arm), and in build_type's Apply frame return a `Type` result for a sort-headed apply instead of falling through to operation dispatch; (b) eval -- a sort-headed apply must build the parameterized type TERM from its evaluated args rather than dispatching a call, which needs a new frame variant mirroring `start_constructor` (evaluate args, then assemble), because named args are otherwise bound to callee params and a sort has none. Also worth covering in the same pass: the Expr::Constructor arg chain, so an entity field declared `Type` accepts a bare sort name too (today `ResourceRow(t: Cell)` still fails while the operation-parameter form works -- an asymmetry users hit in the reflection-driven-listing use case). Acceptance: `is_modifiable(Cell[V = Int64])` written in anthill source loads and returns true; `facts_of(kb(), List[T = Int64])` loads; cargo test green.
