### 2026-08-29T21:52:28Z — feedback — claude

CORRECTION (from WI-20260829-BAD3V, which now owns and has closed the gap).

This note's gap (2) is WRONG, and has been since WI-311. It reads:

  PARSE GAP -- qualified call with explicit type-arg brackets, e.g.
  FilteredStream.filter[S = Int64, Eff = {}](...), is a syntax error; only the
  unqualified-import form takes brackets

The QUALIFIED form PARSES, and did from the moment WI-311 merged parameterized_type and
instantiation_term into one `application` node whose base is the dotted `$.name` -- nobody
re-measured the note. Measured: `Iterable.map[Dst = Int64](xs, f)` and
`map[Dst = Int64](xs, f)` both parse, and did before BAD3V's change.

What actually refused the bracket was a DOT CALLEE -- a `field_access`, which
`application`'s base excluded. The rule was the REVERSE of the note's: the bracket was
admitted wherever the callee was a pure NAME PATH (which is exactly a qualified call, not
a dot call), and refused on every value-receiver dot at every depth, including the first
hop `?xs.map[Dst = Int64](f)`. WI-20260829-BAD3V admits it on a dot callee and decides its
meaning in the converter.
