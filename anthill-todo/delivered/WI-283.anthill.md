## Description

The [simp] rewriting engine is TYPE-DIRECTED and integrated with the typer (corrects the 'type-independent engine' framing of proposal 043 4/5; supersedes WI-277's guard-free scope). See docs/design/simp-dot-finding.md. One tree-producing occurrence-rewrite WALK (keep simp_rewrite's machinery); firing = structural LHS match (TermView) + a GUARD/selection check that, for spec/sort rules, is type-directed: e.g. Numeric.add_identity (add(?a,0)=?a :- requires Numeric[T]) and Ordered.min only fire where the receiver's type satisfies the spec — the rule's add is Numeric.add but a real term is Int.add(x,0), a different symbol that matches only via the satisfaction relation, and the requires only holds by a type check. So firing needs min_sort + satisfaction, known only in the typer. Today BOTH sites are guard-free (apply_eq_rules resolve.rs:1410 and simp_rewrite, gated by is_equation=empty body) -> requires-guarded spec/sort rules fire NOWHERE (incomplete; unsound if a guard-free firing rewrites where requires is unmet). Make firing type-directed + guard-aware in the typer and converge the two sites onto one engine (resolver-side runtime firing of truly type-independent monomorphic identities still allowed). Equational spec/sort rules AND dot rules (WI-279) are clients of this one engine. Acceptance: a requires-guarded [simp] spec/sort rule fires only where its requires/satisfaction holds; trivial monomorphic identities still fire; one shared engine; cargo-test green.
