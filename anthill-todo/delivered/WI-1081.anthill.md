## Description

scala-gen Bootstrap: a QUALIFIED type occurrence loses its written package prefix — `TypeGen.named` reads only `n.last`, so `anthill.reflect.Symbol` is re-anchored to the DECLARING package and emitted as `anthill.prelude.Symbol`.

MEASURED (2026-08-11, at WI-1080's delivery): the whole-prelude peel ladder is now `4 -> clean at 44 files`, and all four errors are this one defect — `type Symbol is not a member of anthill.prelude` and `type Term is not a member of anthill.prelude`, twice each, in `TypeBinding.scala` and `NamedTupleElement.scala`. Both come from sort.anthill:291-292, which write the type QUALIFIED and get it re-anchored:

    entity anthill.prelude.TypeBinding(param: anthill.reflect.Symbol, value: anthill.reflect.Term)
    entity anthill.prelude.NamedTupleElement(name: anthill.reflect.Symbol, type: anthill.reflect.Term)

UNCOVERED BY WI-1080, NOT CAUSED BY IT: sort.anthill was refused WHOLE before that ticket (its `EffectExpression` names an abstract sort with no emitted type), so none of its six emittable declarations ever reached a compiler. Per-declaration refusal put them in the tree, and two of them are wrong. Loud-and-narrow is the trade WI-1080 chose; this is the bill.

THE SITE: `TypeGen.named` opens `val leaf = sym.name(n.last)` and hands the LEAF to `TypeScope.place`, whose entire precedence chain (params, scalars, enclosing sort, file types, package placement, imports, prelude table, ambient) is keyed on a leaf. The written prefix is discarded before placement, so `anthill.reflect.Symbol` and a bare `Symbol` are the same query. The bare one is at least an honest guess — `Placement.Ambient` exists for a name Bootstrap cannot see — while the qualified one is the source stating exactly where the type lives and the emitter emitting somewhere else.

DESIGN QUESTIONS THE FIX MUST ANSWER, which is why this is a ticket and not an inline edit at WI-1080:
 * PRECEDENCE. Does a qualified occurrence still consult the type parameters (no — a parameter has no package), the scalar table (`anthill.prelude.Int64` must still be `_root_.scala.Long`), the enclosing sort?
 * EXACT PACKAGE OR THE NESTING WALK. `ScalaTypes.packagePlacement` walks dotted ancestors, which is right for a BARE name's lookup chain and wrong for a written one — the source named a package, not a search.
 * ABSENT → REFUSAL OR AMBIENT. Refusal is the WI-1055 reading (Bootstrap can PROVE the emitted spelling names a different type than the source wrote, exactly as for an import from elsewhere), and it is what would make the whole prelude closure clean at 45 files with no peel rounds. Ambient would keep today's silent re-anchoring.
 * `docs/scala-forward-mapping.md` §2.1a needs the rule; it currently states placement for bare names only.

RELATION TO THE UNMAPPED-REFLECT-TYPE FAMILY (WI-1080 arm 3, WI-1020's partial-delivery measurement): mapping `Term` / `NodeOccurrence` / `Symbol` would ALSO clear these four errors, and would additionally unrefuse `MatchFailed` / `RelationFloundered` / `Meta` / `guarded_of` / `TypeExtractor`. It is the larger, KB-gen-scale arm. This ticket is the smaller and independent half: even with every reflect type mapped, a written prefix that is dropped is a wrong emission waiting for the next qualified occurrence.

ACCEPTANCE: a written `a.b.C` places by the package it NAMES, driven by a fixture in which the leaf alone would select a DIFFERENT declaration (so the assertion fails when the prefix is dropped, which is the control); a qualified occurrence naming a package outside the emitted closure has its pinned outcome stated with the reason; the whole-prelude peel ladder is re-run and recorded at the ladder comment in BootstrapTest (expected: clean at 45 files with no peel round); the refusal-set test's sort.anthill entry and the standalone-compile floor updated if they move; say at each test site which assertion fails when the change is backed out. sbt test green.
