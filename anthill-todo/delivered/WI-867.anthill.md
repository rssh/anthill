## Description

WI-857 FOLLOW-UP — the PUBLIC host-facing dictionary constructor is layout-blind, and 058 phase 7 is what turns that from latent into live. Interpreter::alloc_requirement (eval/mod.rs) is what call_with_requirements' own doc points hosts at ('Use alloc_requirement to build each handle'), and it takes (functor, subs) with no knowledge of the WI-857 layout — so a host can build a dictionary claiming a provider and bundling nothing, which is precisely the shape that dies later at a frame push, attributed to the CALLEE rather than to the caller that built it. WI-857 added a per-dict layout check inside call_with_requirements (each supplied chain dict is validated against dict_layout(chain[i].required_sort, dict.functor())), so the BOUNDARY is guarded; the CONSTRUCTOR is not, and neither is any other host path. MEASURED: the one in-tree host (rustland/anthill-todo/src/main.rs) builds alloc_requirement(impl_sym, SmallVec::new()) for each of Main's chain slots — arity-0 dictionaries for spec WorkItemStore supplied by FileBasedWorkitemStore — and is layout-valid ONLY because both chains are empty. That is the same chain-free-provider accident WI-857 documents as the reason the split went unnoticed for so long. WI-858 (058 phase 7) gives Pair/SortedSet specs real chains, so this is a near-term trap, not hypothetical. FIX DIRECTION: expose the layout-aware constructor — either make stand_in_requirement pub, or add alloc_dictionary(spec, provider, subs) that ERRORS unless subs.len() == dict_layout(spec, provider).arity() — repoint call_with_requirements' doc at it, and convert anthill-todo. ACCEPTANCE: a host that hand-builds a short dictionary is refused AT CONSTRUCTION with a message naming the spec, the provider and both halves; anthill-todo converted and its CLI still runs (anthill-todo list / show); the doc in eval/mod.rs points at the layout-aware constructor; full workspace green via rustland/scripts/test.sh.
