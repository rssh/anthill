## Description

EVERY ARROW IS A `Function`, IN THE TYPER AND THE RUN TIME (proposal 002 §"Correction (2026-11-03)", decided with the user 2026-11-03 and 2026-11-04). Today an arrow carries a parameter count (WI-791) and a call of a function value must pass that many arguments (WI-792), so a one-tuple-parameter operation and a two-parameter one are different types, and `h((1, 2))` over `h: (Int64, Int64) -> Int64` is refused "expected 2 arguments". WHAT: drop the count from the arrow (the `arity` child, `agreed_arrow_arity`, the two relations it selects, `TypeExtractor.Arrow.arity`, the printer's one-tuple wrapping); check every application by the application match against `A`, positional arguments by position and named ones by label, one tuple being always the argument list, through a value and in a call of an operation by its name; a callable at a function type meets it by label when the two tuples carry the same labels, by a mapping of labels by position otherwise (a lambda's tuple is its pattern's, an operation's its parameters); a callable's count is the size of its own tuple, so WI-801's check is the application match and no count stands beside it; the run time makes the same match where a callable takes the tuple (`classify_application`, `spread_eta_args`, `gather_closure_arg`). Also decided with the user 2026-11-04 (002 §"Four more consequences", kernel-language §4.4): one tuple is any one argument of tuple type, a one-parameter operation called by its name still naming its parameter; a callable of one parameter written at the slot drops what its tuple lacks, one of several refuses it; a function value drops nothing, and meets another function type only where the two tuples carry the same labels in the same order or one is positional (WI-1088's refusal kept, unrelated labels refused); an arrow's parameter list with a repeated label is refused where written (§4.5); a callback's row places are aligned by the same label-or-position mapping. The source comments citing the retired sections of kernel-language §4.4 ("Parameter lists correspond slot by slot", "An arrow records its parameter ARITY", "`Function` states no arity"; typing/callable.rs, subtype.rs, args.rs) follow the change.
