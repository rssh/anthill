## description

CONTEXT (WI-278): provision is currently NON-transitive, so List, MappedStream, FilteredStream each hand-write `provides Iterable[…]` + `operation iterator(x) = x` even though Stream already provides Iterable (stream.anthill:107). Fix: engine-side transitive provider derivation in the value-directed dispatch gate (provision_binds_param_to_carrier / carrier_param_receiver_for_values in typing.rs) AND/OR the load-time SortProvidesInfo closure, composing the intermediate spec's bindings. Then delete the 3 `provides Iterable` clauses + 3 identity iterators from the stdlib. Acceptance: removing provides-Iterable+iterator from MappedStream/FilteredStream still lets xs.map(f).filter(p) evaluate; cargo-test green.
