## Description

TYPER STACK OVERFLOW (infinite recursion at typecheck) on a cross-sort call to a requires-op typed with the CALLEE sort's own bare sort-parameter. MINIMAL REPRO (N1): `sort Coll { sort T = ?; operation contains(items: List[T], x: T) -> Bool = List.member(x, items) }` — `anthill check` overflows the stack (SIGABRT) at typecheck. NO `requires` on Coll needed. NARROWING: (a) calling `List.length` (no deferred spec op) from a sort op is FINE; (b) calling `List.member` from a FREE op with no enclosing sort (WI-415's `has2() = member(2,[1,2,3])`) is FINE; (c) calling `List.nth` (its own `[Elem]` type-param) gives a CLEAN error ('needs nth[Elem=…]'), not overflow. So the trigger is: a call FROM WITHIN A SORT's operation body, to a cross-sort op (member's parent List != caller sort) that is typed with the CALLEE sort's BARE sort-param (member's `x: T`, T=List.T) AND whose body defers a spec op (member's `eq` -> List requires Eq[T]). The bare-sort-param unifies caller-elem with List.T and something in the typer (requirement/projection/sort-alias resolution) re-enters without a cycle guard. PRE-EXISTING: overflows on 7e829bf (before WI-415); NOT caused by WI-415. ALSO (likely same/related recursion): an UNRESOLVED `requires X[T]` (X not imported into scope) ALSO stack-overflows instead of emitting a clean 'unresolved name' error. IMPACT: violates 'loud error over silent loop' — a malformed/cross-sort call should typecheck or error, never infinite-recurse. BLOCKS the WI-415 cross-sort-ABSTRACT requirement-threading gap (a sort `Coll requires Eq[T]` whose op delegates to `List.member` on its abstract element cannot even be typechecked, so that runtime gap is unreachable/untestable until this is fixed). ACCEPTANCE: N1 repro typechecks or errors cleanly (no overflow) — add cycle/depth guard; then a cross-sort-abstract eval test (Coll.contains threading its __req_eq onward to member, Strategy-1 var_ref) becomes writable.
