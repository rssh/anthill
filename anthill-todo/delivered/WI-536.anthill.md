WI-533 follow-up: carrier-bound sorts term-level consts do not reach generated C++ via the cpp PROJECT pipeline. WI-533 delivered const-DECLARATION codegen — non-carrier-bound sort-body consts emit as struct static constexpr members, namespace consts as inline constexpr, and the standalone emit_traits_struct API emits consts for ANY sort (the WI-533 acceptance test lf1_emitter_emits_broadcast_channel_const uses exactly this path). BUT classify_namespace (anthill-cpp-gen/src/lib.rs) EXCLUDES carrier-bound sorts from the namespace/project header (a carrier-bound sort already maps to a host type, so emitting a fresh struct would shadow it), so a const declared INSIDE a carrier-bound sort (lf1 Emitter.BROADCAST_CHANNEL, or a future Motor.VELOCITY_MODE_POSITION = infinity) never reaches the header that codegen cpp-project writes. Consequence: the lf1 motor velocity-mode sentinel does NOT flow end-to-end to generated C++ through the project pipeline, even though WI-532 (infinity value) and WI-533 (const codegen) are both delivered. Also: a const REFERENCE in an operation body lowers (lower_node Ref branch) to the bare short name (e.g. BROADCAST_CHANNEL), which will not resolve in C++ unless the const is emitted somewhere reachable. DESIGN (pick one, realization-layer concern): (a) inline a const reference to its folded value at the use site (BROADCAST_CHANNEL to -1; infinity to numeric_limits double infinity) — simplest, loses the named constant; (b) emit a carrier-bound sorts consts as free inline constexpr at namespace scope via a non-shadowing companion; (c) map a const reference to the carrier static member via a realization mapping (BROADCAST_CHANNEL to webots Emitter CHANNEL_BROADCAST). RELATED minor gap (fold in or note): a SUM/entity sort that ALSO carries a const drops it in cpp-gen (emit_sum_in emits a std variant alias with no place for a static const; rust.rs already emits it via enum+impl).
