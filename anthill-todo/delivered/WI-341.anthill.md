## description

denoted value-in-type: migrate the carried value from Ref/TermId to Rc<NodeOccurrence>, aligning the impl with the canonical schema. SCHEMA vs IMPL DIVERGENCE: stdlib/anthill/prelude/sort.anthill:40 declares 'entity denoted(value: NodeOccurrence)' — the value standing in a type-arg position (e.g. the 'c' in Modify[c], a value occurrence / ExprOccurrence) is, per schema, occurrence-world content. But the Rust side flattens it to a hash-consed Term::Ref: make_denoted(value: TermId) (kb/mod.rs:2308) builds denoted(value: Ref(sym)), and load.rs:5217 lowers value-in-type to denoted(value: Ref(sym)); the parse-IR twin is TypeExpr::Denoted(TermId) (parse/ir.rs:177). This is expression-position content stored as TermId INSIDE an otherwise-legitimate type term — the last occurrence-on-the-wrong-side piece (WI-246 boundary: type terms stay Term, but a value occurrence inside a type is positional/expression content, not structural). It is lossy: the Ref collapse discards the occurrence identity + span the schema's NodeOccurrence would carry. Pre-existing since WI-302 name-case; broader than effects (every value-in-type site). PIECES: (a) make_denoted to carry Rc<NodeOccurrence> (or the occurrence-id handle the rest of the migration uses); (b) load.rs value-in-type lowering + TypeExpr::Denoted to build/carry the occurrence natively (front-end, not materialize-from-Ref), mirroring WI-246's 'produce occurrences natively, not derived from terms'; (c) unwrap_denoted_value (typing.rs:7243) + the denoted display arm (typing.rs:706) + extract_effect_resource_sym path (WI-302) read the occurrence; (d) label COMPARISON must become occurrence-aware: today effect-label matching in v1a pair_present_labels / cover_present_labels AND WI-328 lacks (label_violates_lacks via unify_types, decompose_effect_row present/absent clash via TermId-equality) all work ONLY because two Modify[c] collapse to one hash-consed Ref(c); once denoted carries a non-hash-consed Rc<NodeOccurrence>, TermId-equality and unify_types over the label will no longer recognize same-value labels — so a value-equality/occurrence-aware comparator for denoted labels is REQUIRED as part of this WI, and the v1a + v1b row-label sites migrate together. ACCEPTANCE: denoted carries the occurrence per schema (no Ref-flattening for value-in-type); make_denoted / TypeExpr::Denoted / unwrap_denoted_value migrated; effect-label comparison handles occurrence-carrying denoted labels (test: {Modify[c], -Modify[c]} rejected as clash; {Modify[c]} unify {-Error|rho} ok; {Modify[c]} unify {-Modify[c]|rho} fails — all with c as a real value occurrence, not a bare symbol); cargo-test green; v1a + WI-328 row tests still green.
