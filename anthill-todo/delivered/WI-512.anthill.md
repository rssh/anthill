## Description

Resolver: enforce intra-atom non-linear (repeated-variable) consistency in the discrim-query-as-unifier. A goal f(?x, ?x) over-matches a fact f(a, b): the discrim ViewHead::Var arm (discrim.rs query_node/query_arg_value) and SmallSubst::with_binding (persist_subst.rs) push the query var binding without a conflict check, and resolve_leaf binds each occurrence independently (last-wins), so a repeated query variable within a single atom is not unified. Affects non-linear queries/constraints: self-loop detection (no ?x -: edge(from:?x, to:?x)) and the FunctionalDep guards assumed by WI-020/021. Fix: enforce repeated-variable consistency either at the discrim var-edge binding (reject/merge when a query var is already bound to a different value/path) or via a post-unification consistency pass in resolve_leaf. Surfaced during WI-023 quantified-constraint enforcement.

### 2026-06-18T21:12:16Z — feedback — user

CORRECTION (mis-framed originally). The non-linear-pattern consistency MACHINERY already exists and works: Substitution::bind_term (subst.rs:100) and bind_value (subst.rs:130) set contradiction=true when a var is bound twice to structurally-unequal values (WI-246), exposed via is_contradiction(). It is honored by the simp_rewrite matcher (simp_rewrite.rs:286). The actual gap is narrow: the SLD resolver (resolve.rs) NEVER consults is_contradiction() on the discrim-query candidate substitutions, so a goal atom with a repeated query var (edge(from:?n,to:?n)) over-matches a fact (edge(a,b)) — the conflict IS recorded in the candidate subst but the resolver counts it as a solution anyway. FIX (reuse existing machinery, not new): in the resolver's consumption of query_view/query_resolved candidates (and/or when merging a candidate subst into the frame subst), drop candidates whose resulting Substitution::is_contradiction() is true. Localized; queries are NOT meant to be linear. Empirically confirmed via WI-023 (edge(from:V,to:V) vs edge(a,b) returned count=1).
