## Description

Variant-exposure link is order-dependent: `namespace X` before `sort X { entity V }` leaves bare `V` unresolvable from the enclosing scope.

FOUND WHILE DRIVING WI-979, and the obvious fix was TRIED AND REVERTED there --
the revert is the finding, so read it before re-attempting.

THE DEFECT. scan_items_pass1's Item::SortWithBody arm gates the variant-exposure
link on `is_new && has_variant` (kb/load.rs ~2771). Measured, on a NON-eponymous
sort (the eponymous shape cannot see this -- with `entity Rec` inside `sort Rec`
the bare name resolves as the sort itself, so the link is never consulted):

  namespace vb
    namespace Colour  operation twice(c: Colour) -> Int64 = 2  end
    sort Colour  entity Red(v: Int64)  end
    operation drive() -> Int64 = Red(v: 5).twice()
  end
    => 10:32: type mismatch in Red.apply: expected known operation or
              arrow-typed variable, got unknown functor
  CONTROL, the same two declarations swapped  => loads clean, drive() = 2

Same class as WI-979's category loss -- a fact read off WHICH DECLARATION CAME
FIRST rather than off the declarations -- and reachable through exactly the pair
proposal 059 R2 blesses. Pinned in both directions by
wi979_declaration_order_test::variant_exposure_is_still_order_dependent_wi984,
which uses expect_load_errors, so when this lands that test FAILS and the fix
cannot arrive silently.

WHY `if has_variant` ALONE IS WRONG -- MEASURED, this is the whole ticket.
`is_new` is false for TWO unrelated populations, and un-gating serves the wrong
one:
  (a) declaration-reuse -- `namespace X` (or `entity X`) already defined the
      name. This is the case that wants the link.
  (b) BOOTSTRAP-reuse -- register_prelude pre-registered the symbol. Measured:
      anthill.prelude.{List, Option, TypeExtractor, EffectExpression} and
      anthill.reflect.{MemberKind, Expr, Pattern} are all pre-registered and then
      re-declared with variants in stdlib source. Un-gating hands all seven an
      exposure link they never had -- ~55 short names newly bare-resolvable from
      anthill.prelude / anthill.reflect.

DRIVEN CONSEQUENCE of (b), the reason for the revert:

  namespace p
    import anthill.prelude.*
    import anthill.reflect.*
    operation p(t: Type, g: List[T = Term]) -> EffectExpression
      = guarded(label: t, guard: g)
  end

  with `has_variant` alone => ambiguous symbol 'guarded': candidates
      ["anthill.prelude.EffectExpression.guarded",
       "anthill.reflect.LogicalQuery.guarded"]
  gated (today)              => resolves uniquely to LogicalQuery.guarded

THE FULL WORKSPACE SUITE STAYED GREEN THROUGH THIS. There is exactly one wildcard
import in the repo (inside a parse test), so nothing in-tree trips it. A green
suite was not evidence, and will not be for the real fix either -- this ticket
needs its own ambiguity guard.

SECOND CONSEQUENCE, also driven: un-gating half-wires the shape 059 R1 refuses.
`entity Rec(n)` + `sort Rec { entity Inner }` starts loading clean with bare
`Inner` resolving OUT of the sort, while the body still cannot see IN, because
the ENCLOSING link (load.rs ~2725) stays `is_new`-gated. Variants leak out of a
scope whose body resolves nothing. WI-979's pinning test for that shape was blind
to it (its fixture had no variant); the fixture now carries one.

WHAT THE FIX NEEDS: a predicate that tells declaration-reuse from bootstrap-reuse.
`is_new` cannot -- it is false for both. Candidates worth measuring: whether the
existing symbol was defined by `define` (scope-local) vs `define_qualified_only`
(which is what register_prelude uses, and which deliberately does NOT insert into
any scope's locals); or recording the reuse REASON at the site.

ALSO CONSIDER, same arm, same class: the ENCLOSING link at load.rs ~2725 is
`is_new`-gated too. Left refused deliberately under WI-979 because 059 R1 refuses
`entity X` + `sort X` outright -- do not un-gate it without that verdict.

ACCEPTANCE: both declaration orders resolve a bare variant from the enclosing
scope; the sort-first control still passes; a GUARD test asserts the wildcard-import
`guarded` case still resolves uniquely (it is the regression the naive fix causes,
and no existing test covers it); the `entity X` + `sort X` shape still fails
loudly; variant_exposure_is_still_order_dependent_wi984 is flipped to assert
success rather than pinned failure. cargo-test green via rustland/scripts/test.sh.

DELIVERED as a PLAIN UN-GATE (`if has_variant`), NOT the declaration-vs-bootstrap
predicate this ticket prescribed. User decision, 2026-08-04, after the measurement
below. Two of this ticket's own claims were wrong.

THE CONTROL THIS TICKET LACKED, and it inverts population (b). Under `import
anthill.prelude.*`:
    bare `pair`      (enum anthill.prelude.Pair, NOT pre-registered)  => RESOLVES
    bare `merge`     (enum anthill.prelude.EffectExpression, pre-reg) => unknown functor

Same namespace, same wildcard, same `enum ... entity ...` shape. So the 7 bootstrap
sorts are not a population that "never had the link" — they are 7 sorts whose §8.6
exposure the bootstrap silently DELETES. A pre-registration is the loader's own
stand-in for the SAME declaration, so gating on it made the exposure read off which
REGISTRATION came first — the very class of bug this ticket is about, one level down.

ACCEPTANCE CRITERION 3 WAS INVERTED for the same reason. It asked for a guard that
the double-wildcard `guarded` "still resolves uniquely". Measured, that unique
resolution was the loader binding a name the author never chose: the fixture spells
`guarded(label:, guard:)` — unmistakably EffectExpression.guarded — and the loader
bound LogicalQuery.guarded, then reported `'guarded' has no field 'label' (declares:
query, condition)`. §8.6: two sorts exposing one variant name make the bare name
AMBIGUOUS "rather than letting one silently win" — the verdict anthill-cli's
ambiguous-symbol.anthill already pins for two wildcard-imported SORTS. The guard test
now asserts the ambiguity; a single-wildcard CONTROL pins that `guarded` still
resolves uniquely and passes either way.

The `define` vs `define_qualified_only` candidate this ticket suggested is also
refuted: register_stdlib_scopes uses `define` (scope-local) for all 7, so that
predicate cannot tell the populations apart either.

SECOND CONSEQUENCE DISSOLVED, not handled. `entity X` + `sort X` is refused outright

re-offer a present link rather than supply a missing one. The one shape it genuinely

A REGRESSION THE UN-GATE INTRODUCED, found by review and FIXED here. `is_new` had
been capping the exposure link at one push per name as a side effect. load_incremental

without the cap every reload pushed another copy: anthill.prelude 28 -> 56 exposure
parents on the second load, unbounded in the number of loads, and silent (the WI-997
ledger is per scan_definitions call, so it reports no duplicate declaration).
SymbolTable::add_parent is now IDEMPOTENT per distinct ScopeInclusion — the set
semantics resolution already assumes (visited-guarded walk, matches deduped by
symbol). Dedup is on the WHOLE inclusion, so two links differing only in
instantiation_term_raw (one spec required at two instantiations) both stand.
