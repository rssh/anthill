## description

A FORWARDING ROW IS OFFERED AS A PROVIDER CANDIDATE, AND IT IS NOT A PROVIDER. Found while writing library proposal 007 (WI-1109), and the finding corrected two of my own claims.

THE DEFECT. `Ord provides WeakOrd[T = T]` is a spec forwarding — a rule about the relation, not a claim that anything has type `Ord`. But `impl_sorts_providing_spec(WeakOrd)` returns `Ord`, so the resolver offers it as a candidate provider, and `Ord requires WeakOrd[T]` then closes a loop. MEASURED: a carrier providing `Eq` and `PartialOrd` but no `compare` gets

  type mismatch in WeakOrd.compare.dispatch: ... unresolved: WeakOrd[T = Half]
  (construction is cyclic: WeakOrd[T = Half] -> WeakOrd[T = Half])

where the truthful answer is 'no impl provides WeakOrd'.

IT IS A DIAGNOSTIC WART, NOT A WRONG ANSWER — the cycle detector catches it, so the program is refused either way. That is why this is a ticket and not a hotfix.

TWO CORRECTIONS IT FORCED, both recorded at their sites. (1) WI-1109's first probe of this used a carrier with NO provisions at all, which fails at `PartialOrd` before the cycle can form, and I read that clean refusal as the cycle being ABSENT from the ordering tower. It is not absent, it is MASKED by an earlier failing requirement — the probe was too weak to see it. (2) eq.anthill's note claimed the cycle was why `Eq` cannot forward to `PartialEq`. Also wrong: both towers cycle identically. THE FIX, and why it needs its own measurement rather than being obvious: exclude IDENTITY-FORWARDING rows from candidate collection. `is_identity_forwarding` (kb/typing.rs) already names the predicate, so the change is small. The risk is that `Stream provides Iterable` (stream.anthill) is exactly the same shape and has been in the library far longer — value-directed dispatch of `Iterable.find`/`map` on a stream may reach `Stream` as a candidate deliberately, and WI-495/WI-496 DELETED List's explicit `provides Iterable` on the strength of that route. So the acceptance must show Iterable dispatch on List/Relation/MappedStream unchanged, not merely that the cycle is gone.

ACCEPTANCE: the Half fixture above reports 'no impl provides WeakOrd' rather than a cycle, driven with a value-carrying control that a real provider still resolves; wi496_transitive_iterator_test, wi495_non_stream_iterable_test and wi1076_self_representing_spec_carrier_test stay green; full workspace green via rustland/scripts/test.sh.
