## description

SCALAND: AN ENTITY'S "PARENT SORT" IS ITS ENCLOSING SCOPE, SO AN ENTITY UNDER A NAMESPACE IS AN ENTITY OF A NAMESPACE. `Loader.DefinePass`'s `EntityItem` arm calls `kb.registerEntityOf(entityTerm, kb.scopeTerm(scope))` where `scope` is whatever scope encloses the declaration. Inside `sort S ... end` that IS the parent sort and everything is right. Written directly under `namespace demo`, it registers `entityParent_(Foo) = Fn(demo)` — so `KnowledgeBase.isEntityOf(Foo, demo)` answers true, `bySort(demo)` sweeps in the entity's facts, and the `IsEntityOf` builtin reports an entity "of" a namespace. The `entity_of` FACT asserted in `LoadPass` (Loader.scala, the EntityItem arm) carries the same wrong second argument, so a reflect query sees it too. `stdlib/anthill/reflect/typing.anthill` already documents and guards this exact hazard for the RULE form; the KB-index form has no guard. WORK: decide what an entity outside a sort body means — parent `none`, a load diagnostic, or a distinguished marker — and make the registration say it rather than defaulting to the enclosing scope. A load diagnostic is the likely answer if the kernel language does not admit the form at all, in which case say so in `docs/kernel-language.md` too. ACCEPTANCE: a test that DECLARES an entity under a bare namespace and asserts the chosen answer by resolving `is_entity_of` — not by checking that the file loads. Say at the site which test fails when the change is backed out. Found by code review of WI-976/WI-983 (2026-08-04). Related: WI-983.
