## Description

Diagnostics: error SPAN side-table keys on hash-consed TermId, so a shared subterm's span resolves to whichever file registered it FIRST — an error about a term in file A can print a span pointing into file B (observed in WI-445: an UnresolvedName for a test-source 'x' printed list.anthill 1945..1946). Span lookup should key on the OCCURRENCE (per-use), not the hash-consed TermId. Surfaced while debugging WI-445; not blocking (the WI-445 fix removed that particular error).
