There are TWO typer-side [simp] firing sites. simp_rewrite::try_fire builds the RHS template and then calls try_expand_macro (so 'rule where(?r,?c) <=> guarded_of(?r,?c) [simp]' runs the macro at compile time); typing::try_fire_dot_rule -- the WI-279 INC2 sort-scoped dot-rule path, 'rule dr: dot_apply(?e, member, ?x) = rhs(...) [simp]' -- ends at substitute_to_occurrence and returns the template with NO expansion. So a macro-headed dot rule silently declines. MEASURED: a sort with 'operation wrap(r: NodeOccurrence, x: NodeOccurrence) -> NodeOccurrence = make_apply(...)' plus 'rule dr: dot_apply(?e, bump, ?x) = wrap(?e, ?x) [simp]' reports 'type mismatch in wrap.r (op-arg): expected NodeOccurrence, got Holder' -- the pattern vars arrive as their VALUE types because the macro never ran. Consequences: (a) a macro is unusable from a dot rule; (b) WI-757's rejection channel is unreachable there, so an untranslatable input falls back to exactly the residual-template message WI-757 exists to eliminate. Pre-existing since WI-722 (WI-757 only made the asymmetry visible).
