## Description

Arrow PARAMETER LISTS are compared by NAME with width subtyping, which licenses three more load-clean-then-trap programs. All PRE-EXISTING (measured identical on WI-775's parent commit db69a842 and after WI-775; WI-775 neither introduced nor widened them) and all distinct from WI-775's DATA-tuple bridge, which is closed. SITE: align_named_tuple_fields (rustland/anthill-core/src/kb/typing.rs) tries the by-NAME rung FIRST in BOTH TupleAlign modes, and that rung is order-insensitive and width-subtyping -- neither of which is sound for a list that is APPLIED POSITIONALLY. (1) ORDER: 'operation take(f: (x: Int64, y: Bool) -> Int64) = f(7, true)' + 'operation pass(g: (y: Bool, x: Int64) -> Int64) = take(g)' + 'operation impl(y: Bool, x: Int64) -> Int64 = x' loads clean; drive() DECLARED -> Int64 evaluates to Bool(true) -- a wrong-typed value, no trap. (2) ARITY: take3 expecting a 3-param callback accepts a 2-param one (extra field width-ignored), then traps ArityMismatch{expected:2,got:3}. (3) SLOT COLLAPSE: operation_as_function_value puts the PARAM'S TYPE in the arrow param slot for an arity-1 op ('if op.params.len() == 1'), so a 1-param op whose param IS a tuple is indistinguishable from an n-param list; 'operation get_a(t: (a: Int64, b: Int64)) -> Int64 = t.a' with 'let f: (_1: Int64, _2: Int64) -> Int64 = get_a' then 'f((7, 8))' loads clean and traps Internal(field_access: tuple has no component 'a'), plus the dual. (3) is the deepest: it means the param slot does NOT faithfully carry parameter-list-ness, so WI-775's TupleAlign::ParamList mode positionally aligns a data tuple there. ACCEPTANCE: in ParamList mode require equal arity and same-ORDER names on the by-name rung; decide how the arity-1 tuple param is represented so a parameter list is distinguishable from a single tuple parameter (a wrapper/marker at the mint in operation_as_function_value is the obvious route); regression tests DRIVE each program end-to-end (load AND evaluate -- all three load clean today); full workspace green via scripts/test.sh.
