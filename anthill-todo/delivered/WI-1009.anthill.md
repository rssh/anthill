## Description

SCALAND: A PARSE-TIME EXPRESSION MARKER IS NAME-RESOLVED AS IF IT WERE THE REFLECT ENTITY IT SHOULD HAVE BEEN TRANSLATED INTO — capture or leak, decided by a spelling coincidence.

TWO LAYERS, DELIBERATELY NAMED DIFFERENTLY. The parser mints PARSE-TIME MARKERS (`lambda_expr`, `match_expr`, `if_expr`, `let_expr`, `match_branch`, `pattern_var`, `pattern_wildcard`, `pattern_literal`, `pattern_constructor`, `pattern_tuple`). The REFLECT ENTITIES are a different vocabulary — `stdlib/anthill/reflect/reflect.anthill` declares `var_pattern`, `wildcard`, `MatchBranch` — and rustland's `convert_expr_term` is the translation between them (rustland's own parser mints `pattern_var` 9x, `pattern_constructor` 8x, `match_branch` 5x, so the split is by design, NOT a scaland typo). `Prelude.registerExprSorts` registers the ENTITY side. Scaland's copy of the translation was dead and WI-1007 deleted it, so the entity vocabulary now has NO producer at all.

THE BUG IS NOT THE ORPHANS, IT IS THE FOUR SPELLINGS THE TWO LAYERS SHARE. A marker written in a rule body reaches `reallocTerm`, which resolves EVERY `Term.Fn` functor by name — so where a marker and an entity are spelled alike, the marker CAPTURES the entity symbol. MEASURED (probe written, run, deleted), loading `namespace demo / rule r(?x) :- p(lambda s -> s) / end`, load errors EMPTY:
    Fn p                                   [bare intern]
      Fn anthill.reflect.Expr.lambda_expr  [RESOLVED  <- the MARKER, captured]
        Fn pattern_var                     [bare intern — no entity of that spelling]
          Ident(69)
        Ident(69)
Two distinct defects in one term. (1) CAPTURE: the KB now holds an `Entity` symbol applied POSITIONALLY to (pattern, body), which is not that entity's declared shape — reflect.anthill gives `lambda_expr` NAMED fields, as `entity match_expr(scrutinee:, branches:)` shows. Anything that later trusts `is_entity_of`/`entityFields` for this symbol reads a term that never went through the translation. (2) LEAK: `pattern_var` one line down has no entity to capture, so it lands as an undeclared predicate name with NO diagnostic — the silent skip the repo forbids. Which of the two a marker gets is decided by nothing but whether Prelude happens to register the same string.

SCOPE, so this is not mistaken for a rename: 4 of 12 `Expr` entities are capturable (`match_expr`/`if_expr`/`let_expr`/`lambda_expr`); the other 8 (`apply`, `constructor`, `var_ref`, the 5 `*_lit`) have no producer; ALL 6 `Pattern` entities and `MatchBranch`/`ApplyArg` have neither producer nor colliding marker. Reachable from any rule body — `fnArg` accepts a full `exprBody`, so `lambda`/`match`/`if`/`let` are legal call arguments (the stdlib's cli/parse.anthill uses that form).

WORK. Settle FIRST which of three scaland actually wants, because they differ in cost and none is obviously right: (a) REFUSE a marker in a position scaland cannot translate — loud, small, honest while there is no consumer, and it turns both defects into one diagnostic; (b) TRANSLATE — restore the WI-1007 cluster from 03415ce1 and give it a caller, which needs somewhere to PUT the result (scaland's KB has no op-body/occurrence slot; rustland uses `set_op_body_node`), so it is the big one; (c) RETIRE the entity registrations and let markers ride as bare interns — cheapest, but then the capture must still be broken or the four keep resolving. NOTE (a) and (c) are not exclusive.

ACCEPTANCE: scaland-sbt-test green, plus a test that DRIVES the loaded shape — load a rule body containing `lambda`, and assert what the functor IS (refused / translated to the entity WITH its named fields / a bare intern that is provably not the entity symbol). `hasQualifiedName` is not evidence: `ExprLoaderTest`'s four surviving registration tests pass today and this defect is why they mean nothing. Whatever is chosen, `pattern_var` and `lambda_expr` must stop getting DIFFERENT treatment for no reason.
