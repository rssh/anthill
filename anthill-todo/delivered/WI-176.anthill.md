## Description

Wire anthill.persistence.{persist, retract, flush, pull} as interpreter builtins. Today rustland/anthill-core/src/eval/builtins.rs registers prelude/Console/Modify and anthill.reflect.KB.execute, but NOT the four persistence operations declared in stdlib/anthill/persistence/ — so they're unreachable from interpreted anthill code. Required: Interpreter gains a Store registry mapping a Value::Entity (the FileStore(...) term, or other concrete store entity) to a Box<dyn Store>. Four register_if_present entries dispatch from the qualified anthill names to Store::persist / Store::retract / Store::flush / BulkStore::pull. Pull returns a List[Term] (the fact heads of every persisted fact). The shim populates the registry before calling main; programs receive the store as an opaque Value::Entity. Acceptance: integration test where an anthill program asserts a WorkItem fact, calls persist + flush, the file on disk contains the fact, a fresh KB calls pull and the fact reappears. Prerequisite for WI-009 — without this the anthill side has no way to write back to disk. Design: see examples/github-todo/docs/anthill-migration.md §5.2.
