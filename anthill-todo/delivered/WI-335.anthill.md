Code-review WI-326 F6: nested arrow_compatible uses a fresh local Substitution per level → soundness gap for arrows with shared row vars across param/result positions. PROBLEM: each arrow_compatible call (any nesting depth) allocates 'let mut local_subst = Substitution::new()' (typing.rs ~6785, ~6792, ~6798) and discards it on return. For an arrow with a row var shared across multiple positions, the substitution that binds it at one position does not propagate to checks at sibling positions. EXAMPLE: actual = arrow(arrow(Int,Int,{rho}), arrow(Int,Int,{rho}), {}) — nested arrows share rho. expected = arrow(arrow(Int,Int,{E1}), arrow(Int,Int,{E2}), {}). Outer arrow_compatible's param (contravariant): types_compatible(arrow(Int,Int,{E1}), arrow(Int,Int,{rho})) with local_subst1, binds rho := {E1}. Result (covariant): types_compatible(arrow(Int,Int,{rho}), arrow(Int,Int,{E2})) with local_subst2 (fresh, doesn't see prior binding), binds rho := empty_row. Both individually succeed; outer returns true. No consistent global binding of rho can satisfy both — unsound accept. SCOPE: thread a single shared Substitution through nested arrow_compatible calls within one types_compatible invocation. This may require expanding the entry-level types_compatible / arrow_compatible signatures to take an optional &mut Substitution (the caller could allocate it once and pass it down). Alternative: short-circuit the row binding to a fresh tail only when the variables are truly local to the row (not visible to outer scope). Carries design weight — may need an explicit free-vars analysis to detect 'this row var was passed in from outside'.
