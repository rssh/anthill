## Description

Reflect operation: is_modifiable(t: Type) -> Bool. Add to stdlib/anthill/reflect/reflect.anthill alongside the existing introspection ops (sort_template, occurrences_of, etc.). Body: queries the KB for fact Modifiable[T = t] (the marker introduced by WI-205); returns true iff such a fact exists. Use cases: (a) defensive programming — a function that takes any type and only mutates if its modifiable, queries is_modifiable before deciding to call set/get; (b) reflection-driven UIs and dispatchers — listing all modifiable resources at runtime; (c) typer-side helpers in user code that mirror the kernel typer rule (the kernel typer enforcing Modify[T] requires Modifiable[T] is WI-205 internal; user code can introspect via this reflect op). Implementation: a Rust builtin that wraps a KB query for the Modifiable fact functor with the type as the T parameter binding. Acceptance: anthill.reflect.is_modifiable(Cell[Int]) returns true after WI-205 lands; is_modifiable(Int) returns false; cargo test green. Independent of WI-205 implementation order — could land before WI-205 (returning false for everything until Modifiable facts are registered) or after.

## Changes

### 2026-07-12T22:16:06Z — feedback — user

Delivered (code 107f6e31), with one deviation from the acceptance line, agreed with the user before implementing. ACCEPTANCE AS WRITTEN said `is_modifiable(Cell[Int])` returns true from source; the op's SEMANTICS does that (a value-level test builds Cell[V = Int64] and asserts true), but WRITING a parameterized type in an argument slot is a language surface that does not exist for any `Type`-taking reflect op (facts_of(kb(), List[T = Int64]) fails identically, and always has) -- split out as WI-707. Source-level acceptance met for the BARE form: is_modifiable(Cell) = true, is_modifiable(KB) = true, is_modifiable(Int64) = false.

TWO THINGS THE WI TEXT GOT WRONG, both now settled in code:

(1) The suggested implementation -- 'a Rust builtin that wraps a KB query for the Modifiable fact functor with the type as the T parameter binding' -- CANNOT satisfy the acceptance. The stdlib fact is `Modifiable[T = Cell]`, whose T is a bare Ref(Cell); that does not unify with `Cell[V = Int64]`, so a literal query answers FALSE for the parameterized case the acceptance calls out. The op matches the HEAD SORT of the fact's T binding instead, so a parameterized instance answers as its base does.

(2) 'Add to reflect.anthill alongside the existing introspection ops' understated it: a bare SORT name had NO value denotation at all. Only a free-standing ENTITY could be passed to a `Type` param (facts_of(kb(), WorkItem)); a sort name was an UnresolvedName error, so is_modifiable(Cell) did not type-check. Delivery therefore includes the sort-as-Type reading: typer check_bare_ref + eval reduce_var, gated on the slot expecting a `Type` (new type_slot_arg_hint), so a sort name in an ordinary value slot stays a loud error (test pins it).

LANDMINE for anyone touching this: do NOT reuse region::region_sorts as the 'is modifiable' test, even though it reads the same facts. It over-approximates ON PURPOSE (every sort reachable anywhere in the fact head), because effect-masking must keep a Modify when the result type merely MENTIONS a region-bearing sort. As an exact predicate it INVERTS the answer: under a parameterized `Modifiable[T = Box[V = Int64]]` it collects Int64 (a subterm) but not Box (a Fn's functor is excluded from subterms()) -- so is_modifiable(Box)=false, is_modifiable(Int64)=true. Found in /code-review, fixed by reading the T binding via extract_type_param; regression test wi206 pins it (verified it fails against the old reader).
