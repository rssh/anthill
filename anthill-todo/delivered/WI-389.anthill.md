## description

Extract the HandlerAction carrier out of WI-082 Phase A into its own substrate WI (per proposal 027 §Outputs — the HandlerAction carrier). Define enum HandlerAction { Pure(Value), Throw(Value), Fail, Choice(Value, Vec<AltMarker>), Suspend(ContSnapshot) } in eval/effects.rs and change EffectHandler's return type from Result<Value, EvalError> to Result<HandlerAction, EvalError>. Migrate existing handlers (Console stdio/buffered/scripted, Modify) to return Pure(v). Implement dispatch-site interpretation for Pure (resume current path with the value) and Throw(payload) (abort: the DISPATCH SITE — not the handler — converts Throw into the evaluator's internal unwinding carrier, i.e. an EvalError::Raised { payload: Value } variant, propagating the opaque payload up the defunctionalized step loop). Leave Choice / Suspend / Fail arms returning an explicit 'not yet supported' EvalError until the Branch substrate lands. KEY SCOPING DECISION (the reason this is extracted): this WI does NOT depend on WI-075 — the Pure/Throw subset needs no snapshot, no push_choice, no Frame/ActivationStack Clone; only Choice/Suspend do, and those stay stubbed. So Error (WI-073) and the bundle wiring (WI-195) can build on the carrier without waiting on the Branch/resolver substrate. Design principle established in design discussion (2026-06-05): error-ness lives in the CHANNEL, not the value — the payload is an ordinary anthill Value of type T (the T of Error[T]), opaque to the runtime; nothing tags the value as an error; the handler's Throw variant (the return vocabulary) is what marks it, and the Error handler 'knows' it is an error tautologically because it is the Error handler. Replaces WI-082 Phase A step (b); WI-082 keeps its WI-075 dependency only for the Choice/Suspend/Branch portion. Acceptance: HandlerAction enum defined; EffectHandler signature changed; all existing handlers return it (Ok(v) -> Pure(v)); Pure and Throw interpreted at the dispatch site; cargo test green.
