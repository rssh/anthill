NON-COPY TermView follow-up (design note, surfaced in review with user 2026-06-28). The value-typer's child recursion (child_types_pos/named) uses ViewItem::to_value() to materialize each structural child to an owned Value before recursing with &mut kb. That copy (a cheap O(1) Rc-bump / TermId-copy) is NOT fundamental -- it works around an OVER-CONSERVATIVE TermView signature, not a real data dependency. pos_arg<'a>(&'a self, kb: &'a KnowledgeBase) -> Option<ViewItem<'a>> unifies ONE lifetime 'a across self, kb, AND the result; but the returned ViewItem never borrows kb (term_view.rs:1089-1095: a Term child is a .copied() OWNED TermId, an Entity/Tuple child is &pos[i] borrowing SELF, a Node child is an owned Rc). Because 'a is unified, calling pos_arg with a long &self and a short &mut-kb-reborrowed-as-& collapses 'a to the short kb borrow, artificially tying the result to kb and blocking &mut kb while the item is held -- which to_value() severs by going fully owned. THE NON-COPY FIX: relax the signature to pos_arg<'s>(&'s self, kb: &KnowledgeBase, i) -> Option<ViewItem<'s>> (independent kb lifetime, result tied to self only) on pos_arg/named_arg across the TermView trait + all impls; then a &mut kb walker holds a child view (borrowing the immutable &Value) and still calls &mut kb builders with no copy. It is a RELAXATION (loosens the bound) so existing callers still compile, but it touches the trait + every impl (incl the Node/occ_* arms) and needs its own verification -- a TermView-substrate improvement, likely its own WI, NOT WI-578 core.
