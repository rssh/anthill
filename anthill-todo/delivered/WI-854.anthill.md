## Description

Rendering a diagnostic re-walks its whole source from byte 0, so N errors in one file cost O(N x len) — measured at 50 SECONDS for one `anthill check`.

WHAT I MEASURED (2026-07-29, HEAD c6f6a7e7). `Span::line_col(source, offset)` walks `source.char_indices()` from byte 0 until it reaches the offset, and EVERY located diagnostic calls it — once per parse error (`ParseError::format_with_source`) and once per span-bearing load error (~20 hand-rolled arms in kb/load.rs). Printers loop over a whole `Vec` of errors from ONE file, so the source is re-walked per error. Driving the debug CLI:
  - 2100 parse diagnostics in a 2.7 MB file: 50.3 s
  - 600 load diagnostics in a 2.4 MB file: 23-26 s
Both are ~99% location rendering: the same input renders in 2.0 s / 0.93 s once the source is indexed once. This is not a synthetic shape — anthill-todo's own workitems.anthill is 3.1 MB, and a stale grammar against a large project produces exactly this: hundreds of errors in one big file.

CONSEQUENCE. The cost is invisible at small scale (a 45 KB file with 3 errors is ~20 us) and quadratic past it, so it shows up as "the compiler hangs" precisely when the author has the most to fix. It also lands on the two paths that matter most: `anthill check` on a broken file, and `anthill-todo` on a big tracker.

WORK. Resolve positions through a per-source LINE INDEX built once: line starts in a `Vec<u32>`, binary search for the line, walk ONE line for the column (columns count CHARACTERS, not bytes — that is why the column cannot be a subtraction). Give both error families a BATCH entry point (the printers always hold a whole `Vec`), and route every printer through it. `Span::line_col` stays as the one-shot wrapper so single-lookup callers are unaffected.

THE CORRECTNESS BAR IS EQUIVALENCE, not plausibility: this changes no output, so keep the old scan verbatim as an ORACLE in a test and assert the index agrees at EVERY offset of a set of sources — including the offsets no caller means to produce but a recovery span can: past the end, inside a multi-byte character, on a `\r\n` file, in a source that is only newlines.

WATCH FOR: the ~20 load arms must keep their exact message strings (they are pinned by tests, and the rewrite is mechanical); `LoadError::Located` renders from its OWN source and must ignore a passed index; a batch renderer keyed on the source's identity must not confuse two files.

ACCEPTANCE: the two measured cases above drop from tens of seconds to ~1-2 s (state the measured before/after); an equivalence test pins the index against the scan it replaces at every offset; no rendered diagnostic changes; full workspace green via rustland/scripts/test.sh.

SOURCE: recorded as out-of-scope in WI-852's delivery note (a /code-review finding measured it at ~1.3 s debug for 688 errors on 3.1 MB), then measured properly here at 50 s for the real end-to-end run.

SCOPE: rustland/anthill-core/src/{span.rs, parse/error.rs, kb/load.rs}, plus the printers in anthill-cli, anthill-stl, anthill-todo, anthill-rust-gen.
