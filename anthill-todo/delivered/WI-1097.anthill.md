## Description

`anthill-todo list` defaults to the SHORT (one-line, truncated) row; full description is opt-in via `--long`.

Today the two list renderers disagree on description length, and the asymmetry is backwards. `cmd_list_tagged` -> `print_tagged_rows` (rustland/anthill-todo/anthill/main.anthill:1665) prints `truncate_desc(desc)` — first 100 chars + '…' — so `list --tag modins` is a scannable sequence. `cmd_list_plain` -> `render_ready` / `render_blocked` (main.anthill:1401,1410) print the RAW `desc`, so plain `list --status open` dumps every ticket's full body text and is unreadable at any real queue size. The default view is the one that most needs to be scannable.

Change: make truncation the default on BOTH paths, and add a `--long` bool flag to `spec_list()` (main.anthill:310) that opts back into the untruncated description. `--long` applies to the plain and the tagged view alike — one flag, one meaning, so `list --tag t --long` also widens. Wire it as an explicit argument threaded from `cmd_list` into the renderers (the row shaping decision belongs to the caller, not to a renderer sniffing the arg list); `render_ready` / `render_blocked` / `print_tagged_rows` take the already-shaped description string, and `truncate_desc` stays the single truncation site both call.

Docs: update the usage block in rustland/anthill-todo/src/main.rs:47-49 and skills/anthill-todo/SKILL.md so the `list` line documents the new default and `--long`.

Acceptance (each drives the surface, not just "it loads"):
- add an item whose description is >100 chars; `list --status open` prints the '…'-terminated 100-char prefix and NOT the tail. FAILS before the change (today it prints the tail), passes after.
- same item, `list --status open --long` prints the full description including the tail. FAILS before (no such flag — the arg parser must reject or ignore it today), passes after.
- `list --tag <t>` still truncates, and `list --tag <t> --long` prints full text. The plain-truncate half is the control: it passes either way by design and pins that the tag view did not regress.
- an item with a <=100-char description renders IDENTICALLY under both modes — passes either way by design; it guards against the truncation helper mangling short rows.
Existing `cmd_list_*` tests in rustland/anthill-todo/tests/include/ that assert on plain-list description text need re-baselining; check cmd_list_id_order_test.rs, cmd_list_unblocked_test.rs, cmd_default_parity_test.rs, wi711_preopened_dep_blocks_test.rs.
