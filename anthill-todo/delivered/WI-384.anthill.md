## description

Typer: bidirectional (args-before-expected) inference for the CONSTRUCTOR path (check_constructor_iter) -- the constructor analogue of WI-379, surfaced by its code-review. GAP: check_constructor_iter (kb/typing.rs) seeds the caller 'expected' into the parent type BEFORE the field-unify loops, so a wrong declared return masks a contradicting field exactly as the pre-WI-379 apply path did: 'operation make() -> Option[T = String] = some(42)' loads CLEAN (some(42) is Option[Int], silently accepted as Option[String]). OBSTACLE (why WI-379's reorder does NOT transfer): unlike check_apply_iter (which builds resolved_ret = walk_type_deep(op.return_type) and rejects at the use site), check_constructor_iter BUILDS its result type by reading each parent type-param's Var binding out of subst, and DROPS any param whose Var resolves to None. Seeding 'expected' first binds the params to concrete values so they survive the build; moving it AFTER the field loops makes a field that is an unbound element var alias the param to an unbound var (-> None -> dropped) -- e.g. inner pair(h, t) builds Pair[B=List] losing A, breaking stdlib splitFirst/List laws ('match.rule: expected Option[Pair[A=T,B=List]], got Option[Pair[B=List]]'). FIX DIRECTION: make the build-from-subst robust to unbound-var params (include a param bound to an unbound var as Param=Var(?_) rather than dropping it), THEN apply the args-before-expected reorder (expected fills still-free, field contradiction surfaces, use-site check rejects). Alternatively add an explicit field-vs-param conformance check after the field loops (mind the 'args/fields never checked' broader hole). ACCEPTANCE: 'make() -> Option[String] = some(42)' REJECTED; 'make() -> Option[Int] = some(42)' clean; 0-arg constructors (nil(), Map.empty()) still pick up the expected hint; full anthill-core green; un-#[ignore] wi379_inference_order_test::constructor_wrong_return_rejected. REF: WI-379 (apply-path delivered), code-review finding. Rust-only (typer).
