## Description

`not` IS THE ONE RESOLVER PRIMITIVE FILED OUTSIDE `anthill.kernel`, and the boolean-`!`/NAF conflation load.rs promises "its own ticket" has never had one. MOVE `anthill.reflect.not` TO `anthill.kernel.not`, and DECIDE how the two readings compile. THE MISFILING, measured on main 2026-08-20: `kernel.anthill`'s own header says the namespace is "Resolver primitives. Not for application code", and it holds `push_choice(a: Term, b: Term) -> Bool`, `unify[T](a,b) -> Bool`, `struct_eq[T](a,b) -> Bool`, `cut() -> Bool` and `rule or(?a,?b) :- push_choice(?a,?b)`. `not(query: Term) -> Bool` (stdlib/anthill/reflect/reflect.anthill:338) has the IDENTICAL shape to `push_choice` and is backed by `BuiltinTag::Not` -> `step_naf` (resolve.rs) -- a resolver primitive by every test -- yet lives in `anthill.reflect`. The `PRELUDE_QUALIFIED` list (load.rs, the const by that name -- 3816 as of this writing, and CITE IT BY NAME: the line moved once already, between filing this ticket and the first edit to the doc comment above it) shows it as the single odd one out among its own siblings: `anthill.reflect.not` sits directly above `anthill.kernel.or`, `.push_choice`, `.unify`, `.struct_eq`, `.find_dictionary`, `.cut`. THE CONVENTION IT VIOLATES IS WRITTEN IN THIS STDLIB, on `kernel.unify`: "`-> Bool` names the test outcome; the substitution it really produces is the term-level `anthill.reflect.unify` face." So `anthill.kernel.X` = the resolver primitive returning the test outcome, `anthill.reflect.X` = the term-level face returning data. `not` is filed in the term-level-face namespace WHILE BEING the primitive, and the `anthill.kernel.not` that convention calls for does not exist. That also settles the question of whether the return type is wrong: `-> Bool` is the documented kernel convention for a primitive (`push_choice`/`unify`/`struct_eq`/`cut` all return it), so it is the NAMESPACE that is wrong, not the signature. Corroboration that this is unowned rather than settled: the doc comment above `PRELUDE_QUALIFIED` (load.rs ~3802) says `not` -> `anthill.reflect.not` "keeps the boolean-`!` / negation-as-failure conflation INTACT (a deliberate, separate decision -- its own ticket)"; the queue has no such ticket. SECOND HALF -- HOW THE TWO READINGS COMPILE, and this is the part to think about rather than mechanically rename. `not` is an instance of proposal 052 open question 7 (one symbol, an operational/value reading and a relational/goal reading) AND it is the instance that BREAKS that question's uniform mechanism. 052's routing for a bare Bool goal is `bare_bodied_bool_relation` -> `eq(op(args), true)`: the operation is CALLED and compared. For `contains` the two readings are one predicate under two consumptions -- same extension. For `not` they are not the same function at all: `Bool.not` takes a Bool VALUE and is two-valued; `reflect.not` takes a `Term` (a reified GOAL) and is THREE-valued (succeed / fail / DELAY -- the floundering guard at resolve.rs `step_naf`). `eq(Bool.not(P), true)` would evaluate `P` as a boolean value where `P` is a goal, so the uniform routing is not merely inconvenient here, it is wrong -- which is why `not` gets a DIFFERENT SYMBOL by position instead (WI-529 `redirect_op_body_boolean` value-side, WI-1046 `route_body_goal_boolean` goal-side). CONSEQUENCE FOR 052: the replacement direction 052 section 7 proposes -- "an explicit form that selects the same symbol's relational face" -- would NOT cover `not` on its own, because there is no single symbol whose relational face is NAF. Either `not` stays two names with an explicit reflection step between them, or it becomes one operator over `Term` with the Bool case a coercion. `docs/design/brainstorms/operation-rule-shared-name.md` does not mention `not` anywhere, so this instance is recorded nowhere today. WHY IT MATTERS BEYOND TIDINESS, and the reason it surfaced: WI-567 paid for the conflation. An `if` condition is an operation-body VALUE expression, so `if not(isEmpty(xs))` loads as `Bool.not` (INSTRUMENTED: exactly one routing event, `value-position: anthill.reflect.not -> anthill.prelude.Bool.not`, across a whole stdlib+program load), while proposal 050 ALSO reads that same condition as a logical fact and the consumer asks in goal vocabulary. The fix had to undo the routing at the Gamma door (`typing::goal_form` -> `KnowledgeBase::goal_position_boolean`). Every later consumer that reads a value-position expression as a proposition will pay the same cost until the two readings are separated at the source. SCOPE: stdlib/anthill/reflect/reflect.anthill:338 declaration; `PRELUDE_QUALIFIED` (load.rs, the `"anthill.reflect.not"` entry -- 3851 as of this writing, `anthill.kernel.or` on the next line); `KnowledgeBase::POSITION_DIRECTED_BOOLEANS` (mod.rs); ~20 `try_resolve_symbol("anthill.reflect.not")` / `resolve_symbol` sites across resolve.rs, typing.rs, execute.rs, mod.rs; the anthill-stl host binding (anthill-stl/src/reflect/builtins.rs:247); kernel-language.md sections 330 and 6.6; scaland mirror. Keep a deprecated alias or not is part of the decision. ACCEPTANCE: `anthill.kernel.not` is the primitive and the stdlib loads clean; a rule body `l(?x), not(empty(?x))` still answers 1 (the WI-1046 regression row) and `if not(isEmpty(xs)) then List.head(xs)` still discharges (the WI-567 row) -- both as CONTROLS that the move changed no behaviour; the 052 open-question-7 analysis above is written into 052 section 7 or the brainstorm; cargo-test green.

DELIVERED. Both halves: `anthill.kernel.not` is the primitive, and the boolean-`!`/NAF "conflation" turned out not to be one.

THE MOVE, with NO ALIAS. Declaration relocated into `kernel.anthill` directly after `push_choice` — "identical shape to `push_choice`" is the whole argument, so the placement makes it visible. Moved with it: `PRELUDE_QUALIFIED`, `POSITION_DIRECTED_BOOLEANS`, `register_builtin_tags`, ~20 resolve/typing/execute/mod sites, the anthill-stl eval binding (`reflect_not` → `kernel_not`, which STAYS in `src/reflect/builtins.rs` and says why: it needs that module's `expect_term`/`require_symbol` substrate, and the kernel has no other eval-side binding for it to sit beside), and every `import anthill.reflect.{not}` line. Docs: kernel-language.md §330 + §6.6, kernel-vocab-provenance.md. No alias, and not for tidiness: nothing CALLS the qualified name, so an alias would have had zero users — and it would have had to live in `anthill.reflect`, i.e. a SECOND `not` reachable from reflect's own rule bodies, which is exactly the `AmbiguousSymbol(not, [reflect.not, reflect.not])` scaland hit in WI-212.

SCALAND MIRRORED, and this is where the WI-212 shape actually lives. `StdlibScopes` gains a `kernel` scope; `(kernel, "not", BuiltinTag.Not)`. `anthill.kernel` is deliberately NOT a `<global>` parent — bulk-parenting it would put `or`/`cut`/`unify`/`struct_eq` into every user scope as ambiguity candidates — so the one bare-spelled member carries a single-symbol `addImport`, KEYED ON THE SCOPE so a later kernel builtin inherits the reach without a second decision.

HALF TWO — DECIDED: two symbols, selected by position, and the split is not a conflation to resolve away. `Bool.not` takes a Bool VALUE and returns one; `kernel.not` takes a reified GOAL and is three-valued (succeed / fail / DELAY on an unbound variable, undecided on a depth-truncated search per WI-628), and a failed goal is not the value `false` — it contributes no answer at all. THE SHARPEST MEASURE IS `sort Bool`'S OWN LAW BLOCK, which the ticket did not cite: read as goals, none of its five `not` laws survives. `not(true) <=> false` has no goal-side reading (neither side is a value). `not_not: not(not(?a)) <=> ?a` is false because `?a` BINDS where `not(not(?a))` discards whatever the inner search found, and for a non-ground `?a` the inner `not` flounders exactly where `?a` would have bound — double negation under NAF is a check with the bindings thrown away, not an identity. Both de Morgan directions need a goal `and` and there is no `kernel.and`, so two of the five are not even spellable in goal position. Untagged, so they fire nothing today, but they are the DECLARED algebra of the symbol, and one symbol cannot mean that and also mean NAF.

CONSEQUENCE FOR 052, written into §Open questions 7 with a cross-reference and a new decision item 9 in the shared-name brainstorm: the replacement direction is BOUNDED, not blocked. "An explicit form that selects the same symbol's relational face" presupposes a symbol whose relational face is the wanted one; `not` has none, because NAF is not the graph of any function on values — `relation(Bool.not)` would select the singleton `{false}`, correctly and uselessly. So position-directedness is the RIGHT answer where the two readings are two functions, and what the form must serve is the other case (one predicate, two consumptions); item 9 asks its scope statement to say so, with a driven control. The ticket's third option — one operator over `Term`, Bool case a coercion — is REJECTED: it loses the law block, and it costs the value side its lowering, since an operation body must EVALUATE and codegen emits `Bool.not` as the host's `!`.
