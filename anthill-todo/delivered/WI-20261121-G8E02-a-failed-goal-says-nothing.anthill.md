## Description

A FAILED GOAL SAYS NOTHING ABOUT WHY: `query` answers `no solutions` and names no subgoal, so a specification that checks a value has to restate the names of its own rules to report which one fails.

FOUND while modelling a shop's state as a value (the setting of WI-20261115-32WQJ). Each invariant of the state is a named rule over it (`rule product_has_positive_price(ShopState(products: ?ps)) :- (forall ?p in ?ps: ?p.price > 0)`), and validity is their conjunction. A test of a bad state must check that the state fails in the rule it is meant to break, and in no other. The query gives no such answer, so the model adds `violation(?s, "product_has_positive_price") :- !product_has_positive_price(?s)` for each of its 34 invariants: one line per rule that only repeats the rule's name as a string. No KB constraint is involved: the state is a value, never a fact.

WHY THE RESOLVER CANNOT TELL ITSELF [ADDED 2026-11-21, review]. It searches depth first, and a failed branch is popped off the frame stack without a record. It delays a goal whose variables are not yet bound and rotates it behind the others (`delay_goal`, `rotate_first`, kb/resolve.rs). It replaces a bounded `forall` by the flat conjunction of the body's instances, one per element (`step_bounded_quant`). So inside the resolver there is no "first conjunct that fails". [CORRECTED 2026-11-21 with the user: the reordering and the flattening describe how a query runs, and are not the reason; a record that tagged each goal with its origin would follow the rule as written. The reason is that a search stops at the first goal that fails, so the goals after it are never asked, and no record could say that they fail too (`even(1)` in row 1). Proposal 075 §1, History 12.] The explanation is a separate walker that runs only after a query has answered `no solutions`. For a rule call it finds the candidate clauses and opens each (`KnowledgeBase::with_fresh_vars`). It then resolves the body one conjunct at a time through the ordinary resolver and descends into the conjunct that fails. An ordinary query costs nothing more. The walker repeats searches, so the whole explanation has a step limit of its own (fuel) as well as a depth limit, and reaching either is shown on the frames it cuts.
