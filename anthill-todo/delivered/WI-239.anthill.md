## description

Make requirement name synthesis + frame.requirements tree-native. synth_req_names and build_dispatching_dict_direct currently walk flatten_requires_tree(...) — the transitive flat chain, a positional-model vestige. Under the names model a body only reads its DIRECT requires by name; transitive requires live inside a direct requirement's tree-shaped dict value (reached via requirement_at_sort). Pre-order flattening also duplicates shared subtrees: 'Wi222Multi requires Eq, Ordered' + 'Ordered requires Eq' yields chain [Eq, Ordered, Eq], which causes a benign synth_req_names name collision (identical entries hash-cons to one __req_*_<raw> name). Fix: synth_req_names + build_dispatching_dict_direct walk the sort's direct requires (top-level RequiresNode list), not the flattened chain; start_apply_within projects the dict against the direct-requires count. The codebase is already half tree-native — RequiresNode, emit_tree_as_projection, and the runtime RequirementHandle are all tree-shaped. Orthogonal to the WI-237 positional->named migration.
