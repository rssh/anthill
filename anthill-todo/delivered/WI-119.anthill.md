## Description

BRAINSTORM ACTIVITY (proposal 030 phase α.8 design pivot): do we need 'provides' clause at all? Insight: a sort X 'provides' spec S at substitution σ iff every requires-clause lemma of S has a kernel-checked ProofRecord at σ. That's a derived predicate, not a primitive declaration. Implications: (1) no new SortProvidesInfo schema needed — the relation lives in the ProofRecord registry already; (2) source-level 'provides A[T = X]' clause becomes optional, serving as documentation/intent marker only — actual discharge happens via concrete ProofRecords on the requires-clause lemmas; (3) load_provides_clause (currently stub) repurposed as a CHECK — does the user's claimed 'provides' have the supporting proofs? Error if not. Open questions: (a) does this mean parametric_context derivation in α.7's induction records gets simpler too? (b) for polymorphic specs like List[T] requires Eq[T], does the auto-derivation interact with the parametric_context field correctly? (c) what about specs whose requires-clauses themselves contain abstract references — do we need transitive closure? Decide before resuming WI-118 (Specialization composition). Acceptance: design notes captured here; document outcome in proposal 030 §α.8 or a §α.8.1 addendum.
