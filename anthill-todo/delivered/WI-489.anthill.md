## description

Validate field existence in type-position field projections (WI-262 follow-up). The value-in-type projection path (try_denoted_value_path / the denoted place) interns field names raw and defers resolution to the elimination/eval site, so a projection onto a NON-EXISTENT field of a CONCRETE-typed head — e.g. Modify[result.nonexistent] for a named-tuple return (a:.., b:..), or Modify[c.bogus] for an entity/tuple param c — is silently accepted at load instead of erroring. The HEAD is already validated (an unresolved head is a loud unresolved-name error); only the field/tail is unchecked. Pinned by wi262_type_level_projection_test::bogus_field_projection_is_not_yet_rejected (currently asserts the silent-accept). Scope: when the projection head's type is statically known (param/result/local of entity or named-tuple type), validate each tail segment names a real field of the running type and emit a loud load error at the projection span otherwise; flip that test to assert the rejection. Must NOT regress the legitimately-deferred abstract projections (s.T / s.E off an abstract spec receiver, WI-376/WI-475) where the field/member is only known once the carrier is concrete. Honors the repo 'prefer a loud error over a silent skip' principle.
