## description

scaland scala-gen hardcodes a DRIFTED copy of scala_std's type_map, and the fact file that claims to be the source of truth has no reader.

MEASURED 2026-08-08 while delivering WI-1055 (which renamed the table `TypeGen.preludeMapping` and gave each entry a Scala ARITY, so the duplication got bigger rather than smaller).

THE TWO TABLES. `stdlib/anthill/realization/scala_std.anthill` declares thirteen `TypeMapping` facts and its own header says: 'Codegen reads this from the KB; changing it changes generated code without touching the codegen implementation.' Nothing reads them. `ScalaProfile` is the module built for exactly that seam -- its doc says it 'turns a loaded scala_std profile into the plain values an emitter takes as parameters' -- and it reads only `language_version`.

THE DRIFT, measured entry by entry:
 - the fact says `Int64 -> Int64`; the code says `Int64 -> Int`. The CODE is right (Scala has no `Int64`, and the emitted `Int` is what WI-1020's compile harness proves compiles). The fact is a WI-068 rename artifact -- the mass Int->Int64 rename hit the host_type column too, which `rust_std.anthill` shows by contrast: it still says `Int64 -> i64`.
 - the fact carries `Duration -> scala.concurrent.duration.Duration` and `Timestamp -> java.time.Instant`; the code has NEITHER, so both fall through to WI-1055's `Placement.Ambient`.
 - the code carries `Unit` and `Nothing`; the fact has neither.
 - the code's per-entry ARITY has no counterpart in the `TypeMapping` schema at all, so it cannot be cross-checked even in principle.

WHY IT WAS NOT FIXED INLINE IN WI-1055, stated so the next person does not redo the reasoning. (a) Bootstrap reads no KB by design (proposal 034), so the fix is the shape `buildSbt` already has -- the CALLER resolves the profile and passes the table in -- which is a `generate` signature change touching every caller and test. (b) The arity column needs a schema decision on `TypeMapping` first. (c) Adding the missing entries to the code to 'catch up' would silently decide WI-1021's open question: `Duration` is ALSO an anthill sort (primitives.anthill declares `sort anthill.prelude.Duration`, and Bootstrap emits it), so a map entry for it picks host-over-nominal for a type whose nominal-vs-host status that ticket is still adjudicating.

SCOPE: give `ScalaProfile` a `typeMap(kb)` reader mirroring `languageVersion`; decide where arity comes from (a `TypeMapping` field, or derived); thread the resolved table into `Bootstrap.generate` as a parameter; delete the hardcoded table. Fix the `Int64` entry in scala_std.anthill in the same change -- deliberately NOT done in WI-1055, because with no reader no test could drive it.

ACCEPTANCE: the emitter's type map comes from the KB, asserted by a test that CHANGES a `TypeMapping` fact and sees the emitted Scala change (a table that is merely read but not used keeps passing otherwise). A test that the fact file and any residual hardcoded knowledge agree, or that no hardcoded copy remains. rust_std's own hardcoded `map_primitive_type` (codegen/rust.rs) has the identical shape -- say whether it is in scope or explicitly deferred. sbt test green.

SOURCE: /code-review reuse finding on WI-1055.
