## Description

Spec 6.3's standalone-entity desugaring is NOT IMPLEMENTED, and it is the ORIGIN of the parentless-entity case that WI-922 found being papered over. kernel-language.md 6.3 (and the 5.x summary) state that `entity Account(id: AccountId)` desugars to `sort Account { entity Account(id: AccountId) }`, and `entity Marker` to `sort Marker { entity Marker }`. The loader does not do this. MEASURED with a probe over `namespace test / sort Project { entity Project(name: String, language: String) } / entity Standalone(a: String) end`, reading the KB after load_all: `test.Standalone` -> Symbol(176), sort_kind=None, constructor_parent_sort=None, entity_field_names=Some(1). So a standalone entity gets its field schema registered but NO enclosing sort and NO EntityOf link. Confirmed structurally: `register_sort` is called only from the sort-body path (load.rs:12945 and 13004); `load_entity` (load.rs:13531, the namespace-level arm reached from load.rs:12834) calls neither `register_sort` nor `register_entity_of`. The loader KNOWS and documents the divergence in place -- load.rs:13578 reads "A namespace-level entity has no parent sort, so the `entity_of` typing rule is guarded with a trailing `is_entity_of(?x, ?sort)`". WHY THIS IS AN ORIGIN, not a cosmetic gap: because an entity may legitimately have no parent sort, `constructor_parent_sort` can miss for a perfectly good entity, and callers invent something for the miss. WI-922 found `term_ser.rs::entity_sort` doing exactly that -- `constructor_parent_sort(functor).unwrap_or_else(|| kb.intern("Fact"))` -- returning a real declared SORT on a hit and a clause-KIND tag on a miss, one Symbol holding answers to two different questions, selected by whether registration had happened yet. FIRST STEP: decide the desugaring's SYMBOL SHAPE before writing it, because a same-named sort and constructor collide -- see WI-926, which measures that collision on today's sort-body form and is the reason this ticket must not land first. ACCEPTANCE: a standalone `entity E` produces a sort and an EntityOf link per 6.3, or the spec is amended to match the loader; the `is_entity_of` guard at load.rs:13578 revisited with its comment; cargo-test green via scripts/test.sh.
