## Description

Typer: consumption-side element precision for a body-ful self-receiver spec op. collect(xs: List[Int]) should statically type List[Int] (the CARRIER's element), but currently takes the CALLER's expected-return element. ROOT CAUSE (kb/typing.rs check_apply_iter): WI-270 expected-type seeding (unify_types(op.return_type, expected)) binds the sort element param (Stream.T) from the declared return BEFORE the carrier is consulted; the WI-365 additive carrier-binding (bind_spec_params_from_carrier) then SKIPS because Stream.T is already bound (its guard leaves any already-bound slot). So drain(xs: List[Int]) -> List[String] = collect(xs) is wrongly ACCEPTED (element String, not Int) — unsound, since the runtime element is Int. FIX DIRECTION: for a self-receiver spec op the carrier (argument) is the ground truth for the element and must override / conflict-check the expected-seeded binding — either run the carrier binding BEFORE expected-seeding, or make bind_spec_params_from_carrier refine an alias-to-unbound-var and contradict a differing concrete (surfacing a type mismatch). TRIP-WIRE: wi365_abstract_self_typing_test::collect_wrong_element_return_is_rejected (currently #[ignore]d 'WI-365 follow-up: consumption-side element precision vs WI-270 expected-seeding'; un-ignore when fixed). RELATED: WI-270 (expected-seeding), WI-357 (concrete-carrier element threading, delivered), WI-365 (abstract self-typing parent; this surfaced delivering it). Rust-only (typer; scaland has no typer).
