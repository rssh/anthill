## description

A type parameter's canonical var is reconstructed by the READER; the LOADER already computes it uniformly and throws it away.

WI-943 gave `typing::type_param_global_var` a two-channel ladder — exact `SortAlias` for an alias-form declaration, `OperationInfo.type_params` for a bracket parameter, then the legacy short-name guess. That satisfied WI-943 (one owner, no reader has to know), but it RECONSTRUCTS at every read a fact the loader already had.

MEASURED (WI-943 /simplify altitude pass): `LoaderState.type_param_vars: HashMap<(u32 scope_raw, String short), TermId>` (rustland/anthill-core/src/kb/load.rs, field decl ~7536) IS the unified map, filled by BOTH declarers — `type_param_var` (~11653, alias-form) and `load_operation` (~15116, bracket). Its key is literally the key `SymbolTable::is_type_param` uses. It is dropped at end of load and never published. The four `add_type_param` sites (load.rs ~2318 op bracket, ~2759 WI-452 marked, ~2772 `sort T = ?`, ~14945 WI-402 existential carrier) are the same uniform choke point.

COST OF NOT PUBLISHING IT: (a) two scan tiers survive that a loader-filled index would delete — `op_info::declared_type_param_var`'s pre-`build_op_signatures` `lookup_operation_info` fallback, and `scan_sort_aliases`; (b) the identity round-trips THROUGH STRINGS in both directions (`op_declared_type_param_var` goes symbol -> scope -> op -> short name -> pick; WI-708's `op_scoped_type_param_symbol` does the inverse); (c) the ladder's RUNG ORDER is load-bearing with nothing enforcing it — WI-402's existential carrier is an OP-SCOPED parameter that publishes via `SortAlias`, so it is only correct because the alias rung runs first.

SHAPE: `named_requirement_slots` (kb/mod.rs ~809) is the precedent — loader-produced, typer-consumed, no runtime or persistence surface, therefore a side-table rather than a fact field. A `type_param_canonical_var: HashMap<Symbol, VarId>` is its sibling. `type_param_global_var` then becomes one map read: no ladder, no channel dispatch, no order to get wrong.

NOT THE ALTERNATIVE WI-943 REJECTED: asserting a `SortAlias` fact per bracket param was evaluated and REFUSED — see the sibling ticket on `reconstruct_sort_params`' two keyings, plus it pollutes `by_name` and redefines a user-queryable relation.

ACCEPTANCE: driven — `wi943_type_param_identity_test` still green with the ladder REPLACED by the single map read, plus a test that an op-scoped WI-402 existential carrier resolves correctly WITHOUT depending on rung order (today's only protection). cargo-test green.
