## Description

Retire the operation-body term handle entirely. After WI-304 (op-body occurrence built natively) and WI-252 (NodeOccurrence rename), the term handle from convert_expr_term is still built and stored only to fill OperationInfo.body and OperationImpl.body, which no consumer reads as a term (all read kb.op_body_node). Drop both fact body fields and stop building the handle: (a) remove the body field from the OperationInfo entity (reflect.anthill) and OperationImpl (realization.anthill); (b) migrate the only logical use of body presence — the typer/spec OperationInfo(body: some(_)) has-body check (docs/proposals/typing_pass_spec.anthill ~410,796) — to derive has-body from kb.op_body_node instead; (c) in load.rs load_operation, stop building/storing the handle (convert_expr_term need only return the NodeOccurrence) once nothing needs the TermId; keep set_op_body_node. Then materialize_from_handle is gated only by its remaining callers (rule-body reflect atoms in build_body_atom_occurrence, the apply_subst reify path). Acceptance: OperationInfo/OperationImpl have no body field; no convert_expr_term handle stored; cargo test green; typing_pass_spec loads with no NEW warnings.
