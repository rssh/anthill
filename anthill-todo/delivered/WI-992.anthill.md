## Description

SCALAND: A TOP-LEVEL DOTTED DECLARATION IS NOT ATTACHED TO THE NAMESPACE IT NAMES, SO A SIBLING'S SHORT NAME IS UNREACHABLE. `sort anthill.prelude.Eq` written at file top level is defined by `Loader.DefinePass` in `_global`, keyed by its WHOLE dotted spelling ("anthill.prelude.Eq" is both the short name and the qualified name), and its scope's only enclosing parent is `_global`. Nothing ever links it to a scope called `anthill.prelude`. So from inside `anthill.prelude.Eq` the name `PartialEq` resolves to nothing, even though `sort anthill.prelude.PartialEq` sits eleven lines above it in the same file. MEASURED, and this is how it surfaced: WI-988 routed the parameterized `requires` through ordinary resolution and EIGHT tests failed, every one a short spec name — `anthill/prelude/eq.anthill:35` `requires PartialEq[T]`, `ordered.anthill:77-78` `requires Eq` / `requires PartialOrd`, `numeric.anthill:8`, `lattice.anthill:5,30`. Corroborating evidence that this is the rule and not an accident: of the stdlib's 26 `requires`, the only TWO written without bindings are also the only two written FULLY QUALIFIED (`anthill/logic/classical.anthill:13`, `constructive.anthill:10`), which are exactly the ones the dotted `byQualifiedName` rung answers. `Loader.findInNestedScope` is a second workaround for the same gap on the import side, and says so in its own doc ("registered at global with the dotted name and never gets attached to the `anthill.prelude` namespace's exports"). CONSEQUENCE BEYOND DIAGNOSTICS: scaland's `requires` LINKS A PARENT SCOPE (it has no typer, so that is the whole of what a requirement does here), so the requires-chain inheritance the stdlib documents — `Eq` inherits `eq`/`neq` from `PartialEq`, WI-614 — has never worked in scaland for any stdlib spec. WORK: decide where a dotted top-level declaration lives. Either the loader synthesizes/enters the `anthill.prelude` scope and defines the SHORT name there (making the scope graph match what the reader sees, and retiring `findInNestedScope`), or the language requires such declarations to be qualified at every use — in which case say so in `docs/kernel-language.md` and fix the stdlib's 24 sites. Settle it against rustland, whose `find_scope_by_name` shows the same flat treatment. DO NOT fix it inside the `requires` clause: a local "also try my own namespace prefix" rung there is the second ladder WI-986 removed. ACCEPTANCE: `requires PartialEq[T]` in `sort anthill.prelude.Eq` links a parent, DRIVEN by resolving an inherited name (`eq`) from inside `Eq` — not by a clean load. Then WI-988's parameterized arm can stop deferring. Say at the site which test fails when the change is backed out. Related: WI-988, WI-986.
