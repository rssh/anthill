## Description

TWO HAZARDS ON `Value::OpRef::spread_labels`, both found by review of WI-1087 and both left standing there with a stated reason. The field is the eta-site mapping from the slot's `A` to the callback's parameters; WI-1087's own soundness fix rides on it. These are its two edges.

(1) IT IS OUTSIDE THE VALUE'S STRUCTURAL IDENTITY. `opref_shape` (kb/term_view.rs) lists `op`, `dict` and `named`, and its doc states the rule: 'both are IDENTITY … Dropping either would make two distinct values compare equal and share a key — a false positive, and this feeds fact dedup, where merging DROPS A FACT (WI-815).' `spread_labels` changes which component fills which parameter, so two `OpRef`s to the SAME op eta'd at `Function[A = (acc, x)]` and at `Function[A = (x, acc)]` answer differently from one argument and yet compare structurally equal and share a `goal_fingerprint`.

WHY WI-1087 DID NOT ADD IT. The shape's keys are DECLARED reflect accessors — `opref_key` maps each to `anthill.realization.runtime.OpRef.<k>` — so listing a fourth means declaring a fourth field on the reflect `OpRef` entity in the stdlib. That exposes an internal dispatch mapping through reflect and moves every tier's fact totals, which is a surface decision rather than a bug fix, and WI-1087's acceptance holds those totals fixed.

WHAT MUST BE DECIDED: declare the accessor and extend the shape to eight arms (`opref_shape` / `opref_head` / `named_arg` / `named_keys`, the WI-814 four-site discipline), or establish that the two values cannot both exist and be compared — and say which at `opref_shape`'s doc either way.

(2) THE MAPPING IS PINNED AT THE MINT SITE AND SURVIVES RE-TYPING. `Function`/`Function` conformance takes the by-name relation, which WI-803 made ORDER-FREE for a data tuple, so a value may be re-typed at a second slot whose `A` orders the same labels differently — and the runtime keeps the FIRST slot's mapping. MEASURED (review), loading clean and running:

  operation inner(g: Function[A = (x: Int64, acc: Int64), B = Int64]) -> Int64 = g((acc: 3, x: 10))
  operation outer(f: Function[A = (acc: Int64, x: Int64), B = Int64]) -> Int64 = inner(f)
  inner(sub2)         => 7     -- inner's own A says q <- acc
  outer(sub2)         => -7    -- the mint site's A wins
  the LAMBDA spelling => 7 / -7 identically

The operation and the lambda AGREE (so WI-784 holds, and this is not a WI-1087 regression in that sense), and the LAMBDA half already answered this way BEFORE WI-1087 — a value whose `A` is re-ordered at a second slot has always carried its first slot's reading. What WI-1087 changed is that the operation spelling now reaches the same shape. So `inner`'s DECLARED `A` is silently not the mapping used, which is the class of wrong answer WI-1087 set out to close, one hop away.

CANDIDATE: refuse a `Function`/`Function` pairing whose two `A`s are PERMUTATIONS of each other at the spread arity — the whole-`A` reading may permute freely (a consumer reads by name), but the SPREAD reading makes `A` a parameter list, where order is identity (WI-782/§4.5). A slot's `A` must satisfy BOTH readings, so the intersection is order-preserving. Measure what that refuses before taking it: the corpus and `wi803_destructure_by_label_test` are where any cost would show.

ACCEPTANCE: for (1), two `OpRef`s differing only in `spread_labels` either compare UNEQUAL through `views_structurally_equal` — driven, not asserted from the shape table — or the site says why they cannot co-exist; for (2), the pair of programs above returns the SAME answer through both routes, driven, with the lambda spelling asserted beside the operation one (WI-784), and whichever way it lands the verdict is stated at `Value::OpRef::spread_labels` rather than left to the reader. Say which rows fail when each half is backed out. Every seven-tier corpus load keeps its fact/rule totals unless (1) deliberately changes them, in which case state the new ones and why. cargo-test green via rustland/scripts/test.sh.
