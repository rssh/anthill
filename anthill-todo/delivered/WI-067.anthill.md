## description

Discharge Error-effects from local proofs. When Int.div / Field.div declare Error[DivisionByZero] unconditionally, callers must propagate the effect everywhere — even where b≠0 is locally obvious (pattern match arm after case 0, explicit if neq(b, 0) guard, or a refinement-typed non-zero Int). Design + implement a mechanism to elide the effect at call sites where the partiality-triggering condition is statically ruled out. Three candidate mechanisms, not mutually exclusive: (1) flow-sensitive typer that narrows value facts inside if/match branches; (2) refinement types, e.g., NonZero Int with a require clause; (3) pattern-match refinement, same as (1) applied to match arms. Unrelated to proposal 023 (KB guards — that's about assert-time fact integrity). Needs its own proposal; this WI is the placeholder.
