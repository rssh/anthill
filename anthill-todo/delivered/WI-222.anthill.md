## Description

Operation-call-model: requirement-insertion pass. Per docs/design/operation-call-model.md §'Pass structure', the requirement-insertion pass is a separate pass after the typer that rewrites typed bodies to use apply_within / ho_apply_within / constructor_within / lambda_within IR forms with requirements slots populated. Scope: (a) add the four IR variants to kb/term.rs; (b) implement the call-rewrite cases (Direct / Pin-now / Defer-to-requirement) per the design's table; (c) emit requirement_at_current(i) / requirement_at_sort(chain, k) / construct_requirement(impl, [...]) terms based on resolved instances; (d) implement the env_chain grammar restriction (env_at_sort's first arg always rooted at env_at_current); (e) Op.requirements computation via body walk + fixed-point per design §'Op.requirements computation'. This depends on WI-223 (runtime support) for the Value::Requirement variant and frame.requirements field but the IR shape and the rewrite pass can be developed against a stub runtime first. Acceptance: cargo-test green; tests pin (1) Direct call rewrite preserves semantics, (2) Pin-now rewrite resolves a ground spec op, (3) Defer-to-requirement rewrite emits correct env_chain projections at dispatch sites, (4) Op.requirements computation handles mutual recursion via fixed-point, (5) sort-level requirements coverage validated (per-op requirements ⊆ Sort.requires + body-derived). Reference: docs/design/operation-call-model.md §'Call rewrite cases', §'Op.requirements computation', §'Two primitives: requirement_at_current and requirement_at_sort'. ~600-800 lines.
