## description

An effect-row PARAMETER has no Scala form under scala_std, so eight prelude files are refused -- decide what an effect parameter erases to, or that it cannot.

MEASURED 2026-08-08, delivering WI-1021. That ticket removed the `Stream -> LazyList` map entry (an effect-carrying anthill collection is not a Scala one), so `Stream[Element, E]` now places against the two-parameter `trait Stream[T, E]` stream.anthill emits and the ARITY refusal is gone. What surfaced underneath it is a different question, and it is the one that keeps the prelude closure red.

THE REFUSAL, WI-1055 B2: a written effect ROW in a type-ARGUMENT slot. `iterable.anthill`'s `operation map[Dst, EffP](...) -> Stream[Dst, {E, EffP}]` writes the row `{E, EffP}` where `Stream`'s second parameter goes. scala_std erases effects (docs/scala-forward-mapping.md §2.8 maps them to METHOD SHAPE, and says nothing about a sort's effect PARAMETERS), so the row has nothing to erase to -- but the argument slot still needs a type. `Any` was emitted before WI-1055 and is a silent widening.

EIGHT FILES, all the same construct: combinators, delay, finite_collection, finite_combinators, iterable, map, mutable_stack, relation.

THE CASCADE, and it is why this blocks WI-1020: `iterable.anthill` being refused means nothing emits `anthill.prelude.Iterable`, so `PersistentCollection` and `MutableCollection` -- which DO emit -- name a type that is not in the tree. That is 7 of the 11 errors left in WI-1020's whole-closure compile. WI-1020's feedback attributed those to WI-1021; measured, WI-1021's fix moves the refusal's REASON and not the file's fate. This ticket is what actually unblocks them.

THE CANDIDATE ANSWER, and the reason it is not a one-liner: ERASE the effect parameter. `sort anthill.prelude.Stream` declares `sort T = ?` and `effects E = ?`; if effects are erased then the emitted trait is `Stream[T]`, not `Stream[T, E]`, and `Stream[Dst, {E, EffP}]` is `Stream[Dst]` with the row dropped. That is coherent and it also makes the emitted arity smaller and the signatures simpler.

WHY IT NEEDS A TICKET AND NOT AN INLINE FIX -- three things stand in the way, in order:

 1. THE PARSE IR DOES NOT MARK EFFECT PARAMETERS. `AnthillParser.effectsSortItem` desugars `effects E = ?` to a plain `AbstractSort` (deliberately: rustland's `sort E = ? + requires EffectsRuntime[...]` anchor is inert without a typer). So Bootstrap literally cannot tell `sort T = ?` from `effects E = ?` and cannot know which of its own parameters to drop. Needs a field on `AbstractSort` (`isEffectRow`), set at that one site; the loader ignores it.

 2. A USE SITE'S ARGUMENTS ARE POSITIONAL AND FOREIGN. `iterable.anthill` writes `Stream[Element, E]` -- positional, and the second argument is a plain NAME indistinguishable from a type. Knowing it is the effect one means knowing `Stream`'s declared parameter kinds, which live in another file: exactly the cross-file knowledge proposal 034 denies Bootstrap. A rule that erases (a) a written effect-ROW literal and (b) a name that is a LOCALLY-declared effect parameter would cover the measured corpus -- `E` in iterable.anthill is iterable's own `effects E = ?` -- but it is a rule about the use site guessing, and it needs to be stated and defended, not assumed.

 3. ARITY BOOKKEEPING RUNS THROUGH THREE PLACEMENTS. `Placement.Enclosing` re-attaches the sort's own params (they must shrink), `Placement.Known` checks written-vs-declared (both sides move), and `fileTypes` records the emitted arity. Getting one of the three wrong is a silent wrong-arity emission, not an error.

THE ALTERNATIVE, which must be argued rather than assumed away: KEEP the refusal and accept that an effect-parameterized sort is outside scala_std's reach, then decide WI-1020's closure scope around it. That is defensible -- `scala_caps` is the profile where a row has a real counterpart (a capture set) and inventing one for `scala_std` may be worse than admitting the gap. If this is chosen, say so at the B2 refusal site and give WI-1020 its exclusion list; do not leave it looking like unfinished work.

ACCEPTANCE: whichever is chosen, the eight files' status is DECIDED and stated at the refusal/erasure site with its reason. If erasure: the emitted `Stream`/`Iterable` arity is asserted, `iterable.anthill` and `combinators.anthill` compile, and the prelude refusal set in BootstrapTest shrinks by those files with the count re-measured. If refusal: the B2 message names the effect parameter specifically (today it says only "a written effect row"), and WI-1020's exclusion list carries the cascade. Say at each test site which assertion fails when the arm is backed out. sbt test green.
