## Description

Unrec the typer's remaining recursive-helper expression arms. visit_type (kb/typing.rs ~1160-1182) handles If/ListLit/SetLit/TupleLit by calling check_if_expr/check_list_literal/check_set_literal/check_tuple_literal, which re-enter type_check_node on children — the last recursive arms; Let/Match/Lambda/Apply/Constructor are already work-stack Build frames. Convert these four to native Visit/Build frames so the whole typer is one iterative walk. Motivation: else-if chains nest in the else branch, so a deep if/else-if recurses one host stack frame per nesting level — the residual overflow class the earlier unrec-ing removed for the other forms (the Drop walk and main dispatch were made iterative to survive the 624-line typing_pass_spec.anthill). Collection literals nest by breadth (flat element lists), lower risk, folded in for uniformity. With WI-284's Stamp work-frame this is purely a stack-safety/uniformity refactor — stamping already works for these arms via per-call type_check_node re-entry, so no behavior change is required, only the host-stack shape. Acceptance: If/ListLit/SetLit/TupleLit are handled by work-stack Build frames (visit_type no longer re-enters type_check_node for them); a deeply-nested else-if chain types without host-stack overflow; cargo-test green.
