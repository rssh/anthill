## description

Computed type arguments: allow an expression (operation / method call) as a type-binding value, e.g. `Function[A = param_type, B = result_type(br), E = result_effects(br)]` and `List[T = TypingEnv.apply_subst(env3, elem_type)]`. PROBLEM: sort_binding's value slot is `_type` (tree-sitter-anthill/grammar.js:1001) = {simple_type, parameterized_type, variable_term, tuple_type, arrow_type}; a function/method call (fn_term / field_access call) is not a `_type`, so `[T = f(x)]` is ungrammatical. The reference typing spec docs/proposals/typing_pass_spec.anthill NEEDS this to express type construction from computed components (a Function type whose B / E are computed from sub-results) in its reference-algorithm part. These parse errors are masked because parse() swallows tree-sitter ERROR / MISSING nodes (see WI-303). CONSEQUENCE: the test typing_pass_spec_parses_and_loads (rustland/anthill-core/tests/include/typing_test.rs) is GREEN only because the errors are swallowed; making it honest is part of WI-303. TASK: decide and implement how computed expressions may appear in type-argument position — likely widen the sort_binding value slot (and convert_instantiation_term's named branch + convert_type_value, which today only preserves parametric type shapes) to accept a term expression, with the typer evaluating / normalizing it to a Type; define the interaction with the existing _type forms. ACCEPTANCE: `List[T = f(x)]` and `Function[B = g(y)]` parse; typing_pass_spec.anthill parses with 0 errors; cargo-test green. SCOPE: grammar + converter are shared; typer is Rust-only (scaland has no typer). RELATED: WI-301 (effect-set type args) — both widen what may appear as a type argument; coordinate the grammar change.
