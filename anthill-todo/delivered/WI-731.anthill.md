CONTEXT: proposal 052 join increment (6185dbc2). join(r1, r2, cond) wraps guarded(conjunction(r1.query, r2.query), goal); the merged schema T = Concat[A = r1.T, B = r2.T], a bare type CONSTRUCTOR reduced by an internal typer op (reduce_concat_in_type / concat_named_tuple_types) at the return-type normalization boundary. DEFERRED (today a LOUD error, correctly -- never a silent wrong schema): (a) a SHARED column name across the two rows ('eq(c.x, q.x)' when both have x) -- the merged schema would have to QUALIFY or RENAME the clashing column, and join_run's hole fill (by name, disjoint in this increment) would need the same disambiguation; (b) a 1-COLLAPSED or membership operand -- a 1-collapse DROPPED the column name at the schema boundary, so Concat has no name to merge and it would have to be RECOVERED.
