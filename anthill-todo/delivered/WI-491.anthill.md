## description

Covariant / projection return types: allow an operation's return to be a projection of a parameter's own type — e.g. `operation iterator(m: MappedStream) -> m.Sort = m` — instead of forcing explicit type-param threading. CONTEXT (WI-278): the lazy Stream carriers must provide Iterable, so each needs `iterator` returning the receiver AS a Stream. The natural identity body `= m` could not be written concisely: (a) a bare `-> Stream` return is REJECTED by the escape-free-return / avoidance check (WI-401) because the abstract members T,E are left unbound and would escape; (b) so it had to be written verbosely as `operation iterator[Elem, EffS, EffP](m: MappedStream[T = Elem, ES = EffS, EF = EffP]) -> Stream[T = Elem, E = {EffS, EffP}] = m` (mirroring FilteredStream.splitFirst), re-declaring every carrier type param just to thread it through the return. The DESIRED form is a COVARIANT return rooted at the receiver: `-> m.Sort` (the receiver's own type/sort projection), input-rooted by construction (passes the avoidance check), meaning 'returns a value of the receiver's type', admissible wherever that type's provided spec (here Stream) is expected. Sibling of receiver-type projections (WI-376 x.A / X.L; WI-430 carrier-precise) but projecting the WHOLE type (`m.Sort` / Self). Acceptance: the two combinators' iterator ops (combinators.anthill) rewrite to `-> m.Sort = m` and still type-check + the xs.map(f).filter(p) chain still evaluates; cargo-test green.
