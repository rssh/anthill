## Description

A DOT-spelled call on a defaulted spec op never consults the supplier set, so a 2-supplier TIE is silently first-match — on BOTH the rule-body and the operation-body paths, which is what makes this WI-1012's gap and not WI-1026's. MEASURED on WI-1010's fixture with two suppliers (the carrier's own member = 7 beside 'fact Desc[T = Leaf, describe = otherDescribe]' = 9): 'rule answer(?r) :- leaf().describe(?r)' answers 7, and 'operation probe() -> Int64 = leaf().describe()' answers 7 as well, while the QUALIFIED spelling of the same tie is REFUSED AT LOAD on both paths. Both arms are pinned by WI-1026's 'a_dot_spelled_operation_body_is_silent_on_the_same_tie' — asserting BOTH is the point, since a test on the rule-body arm alone would pass equally if this were a rule-body defect and would license closing it in the wrong place. MECHANISM: the dot resolves 'describe' on receiver sort 'Leaf' BY NAME to the carrier's own member, so 'check_apply_iter' is reached with fn_sym = Leaf.describe — not a spec op at all — and the WI-444 block (which is what compares 'carrier_override_suppliers') is never entered. The rival supplier is invisible because nothing ever asked which spec the member is backing. This violates 058 S3.7 verbatim ('a read that SELECTS one goes loud on the second candidate - NEVER FIRST-MATCH'). WHY IT IS NOT INLINE: the fix is in DOT MEMBER RESOLUTION, which is the WI-907/908/914 name ladder, and it changes operation bodies too — so it needs its own corpus blast-radius measurement over every dot in the tree, not WI-1026's rule-body-only one. WORK: at the point the dot resolves a member on the receiver's sort, ask whether that member backs a spec the carrier provides and whether that spec op has RIVAL suppliers for this carrier; if so, raise the WI-1012 refusal ('supplier_tie_error') rather than taking the member. ACCEPTANCE: both arms of the WI-1026 test above flip from answering 7 to a load refusal, with a stated blast radius over the corpus. REFERENCE: WI-1026; WI-1012; WI-1010; WI-444; docs/design/058-implementation.md S3.7.
