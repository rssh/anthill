## Description

Bundle the canonical stage0 domain into the anthill-todo CLI so it is version-locked with the bundled logic, instead of relying on each project's drift-prone anthill-todo/domain.anthill. PROBLEM (observed 2026-06-17): the CLI embeds its LOGIC (anthill_bundle.rs: store.anthill + main.anthill via include_str!) which references anthill.stage0 entities (WorkItem, WorkStatus.PreOpened, Tag, ...), but the ENTITY DEFINITIONS are loaded from the PROJECT's anthill-todo/domain.anthill (collect_anthill_files over the scanned project dir, main.rs:~403-415). The domain the bundled logic depends on is therefore owned per-project and NOT version-locked with the binary. When the grammar or domain changes (e.g. the parser dropped the multi-name `export` clause; the CLI added WorkStatus.PreOpened), every project whose domain.anthill predates the change silently breaks: a stale heimdall (/home/rssh/packages/lantr/heimdall/anthill-todo/domain.anthill) failed to parse on its `export` lines, which cascaded into a wall of `unresolved import anthill.stage0.WorkStatus/WorkItem/...` errors; fixed only by hand-syncing the project copy to the current standard domain. There are also TWO in-repo copies that can diverge: anthill-todo/domain.anthill (this tracker's) and examples/github-todo/domain.anthill (the one `init` writes via include_str! at main.rs:~284). FIX: add the canonical domain to the embedded bundle (anthill_bundle.rs, alongside store/main) so entity defs ship with the binary and cannot drift. Make the project's domain.anthill OPTIONAL: when the bundled domain is present, do NOT also load a project-local domain.anthill (avoid double-definition of anthill.stage0.WorkItem etc.) -- either skip it, or treat its presence as an explicit override with a staleness warning. Stop `init` from writing a domain.anthill that can later drift (write nothing, or a comment stub pointing at the bundled domain). De-duplicate the two in-repo copies into the single bundled source. CONSTRAINTS / GOTCHAS: (1) the synthetic `namespace anthill.stage0` wrap for bare workitems.anthill files (main.rs:~161-178) must still resolve against the bundled domain's scope; (2) existing projects that still ship a domain.anthill must keep working (skip-or-override, not hard error); (3) rules.anthill is a sibling per-project file with the same drift exposure (claimable/blocked/dep_satisfied workflow rules) -- decide whether to bundle it too or note it as a follow-up; (4) keep the crate's own anthill-todo/ self-hosting working (it scans its own dir per main.rs:~190). ACCEPTANCE: a project directory with NO domain.anthill (and one with a deliberately stale/old domain.anthill) loads and runs status/list/next against the bundled domain with no parse/unresolved-import errors; `init` produces a project that survives a future domain change without hand-editing; a regression test loads a domain-less project dir; cargo-test green.
