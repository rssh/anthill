## description

stdlib argparse module for `anthill run` programs. New `stdlib/anthill/cli/` files: `spec.anthill` (OperationSpec, ParamSpec, CliBinding — sort-typed params, not strings; CliBinding maps spec params to argv positions so the spec stays neutral re: CLI vs JSON tool-calling; param-type field references a KB Symbol so JSON-schema export and type coercion key off the sort lattice), `parse.anthill` (subcommand-aware parse_argv rule: walks argv[0]→child-spec→recurse), `help.anthill` (format_help operation rendering --help text from spec). Subcommand support is v1-critical: dogfood target `anthill-todo` has 16 flat subcommands (init/add/status/list/next/show/claim/deliver/verify/feedback/delete/update/add-dependency/remove-dependency/graph/skill). Each subcommand becomes its own OperationSpec; the registry is List[OperationSpec], parented via `parent: Option[Symbol]`. Out of scope for v1: JSON-schema export, nested subcommand groups (current need is one level), type coercion beyond String/Int/Bool/Option/List. Effect annotations on the dispatched operation should propagate (Console/Modifies/Error) so tool-calling hosts can later reuse the same spec for sandboxing decisions. Acceptance: a sample anthill program declaring three subcommands parses `prog update WI-001 --description "x" --acceptance cargo-test` into the expected typed param map and dispatches to the correct operation; round-trips a help-text golden file.
