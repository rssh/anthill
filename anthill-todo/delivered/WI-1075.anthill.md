## description

ABSOLUTE PATHS GET A SPELLING (`::a.b.c`), AND A BARE DOTTED PATH BECOMES PURELY RELATIVE. One spelling per meaning.

THE DEFECT (measured, WI-999). A qualified path whose HEAD is SHADOWED re-roots at the
bare GLOBAL twin instead of resolving relatively — silently. All three rows drive the
SAME unedited body:

  namespace outer
    namespace inner
      operation g(x: Int64) -> Int64 = 1
      sort Box
        entity box(v: Int64)
        operation use(b: Box) -> Int64 = inner.g(b.v)
      end
    end
  end

  base                                          => outer.inner.g
  + a member `Box.inner`                        => LOUD 'unknown functor'
  + `Box.inner` AND a top-level `namespace inner` => LOADS CLEAN, calls the TOP-LEVEL
                                                    inner.g  (proved by giving the twin a
                                                    different return type: the same file
                                                    then fails 'expected Int64, got Bool')

WHY IT CANNOT BE FIXED BY A RULE OVER THE EXISTING TEXT. The bug and a CAPABILITY are
structurally identical at the point of decision — head resolves locally, rung 1
(head-qualification) misses, rung 2 (dotted_absolute) hits:

  capability  outer.inner.g  with `outer` shadowed   -> rung 2 supplies the right answer
  bug         inner.g        with `inner` shadowed   -> rung 2 supplies a foreign answer

The only difference is whether the author meant the path absolutely, which is not in the
text — a relative path can COINCIDE with some other symbol's fully-qualified name. So
every rule keyed on the current syntax picks one side and loses the other. Measured:
making rung 2 stand down whenever the head resolved (`head_owns_path -> head_sym.is_some()`)
fails 8 tests, 4 of them wi751's capability.

THE CAPABILITY IS REAL AND MUST SURVIVE. Measured: an FQN needs no import and is immune to
shadowing today, including of its OUTERMOST segment —

  sort Box
    operation outer(n: Int64) -> Bool = true
    operation inner(n: Int64) -> Bool = true
    operation use(b: Box) -> Int64 = outer.inner.g(b.v)   -- loads clean, returns Int64
  end

with the relative spelling `inner.g(b.v)` in the same fixture answering 'unknown functor'.

THE DESIGN (user decision, 2026-08-11).

  a.b.c     Resolved THROUGH THE SCOPE CHAIN: bind the head at scope-distance 0, then
            resolve the rest under that binding. A miss under the head is LOUD; the path
            is never re-anchored somewhere else.

            THIS STILL REACHES THE ROOT, and that is why the migration is zero rather
            than lucky. The scope walk goes out to _global, where a top-level namespace
            is an ordinary local — so with nothing shadowing `outer`, the head of
            `outer.inner.g` binds to the top-level `outer` and the path resolves exactly
            as today. MEASURED: the unshadowed FQN loads with the rung-2 instrument
            silent, i.e. rung 1 carried it. `::` is needed ONLY where something shadows
            the head.

  ::a.b.c   ABSOLUTE, always. Straight to by_qualified_name — the same channel `import`
            already uses (process_imports resolves its path with a bare
            by_qualified_name.get, no scope walk), so nothing can shadow it.

WHAT ACTUALLY CHANGES — one row of three:

  nothing shadows the head                     unchanged (rung 1)
  head shadowed, path resolves under it        unchanged (rung 1)
  head shadowed, path MISSES under it          today: rung 2 silently re-anchors the
                                               whole path at a global twin.
                                               proposed: loud, and `::a.b.c` is how you
                                               ask for the root.

TO RE-ROOT, in this ticket's vocabulary, is to throw away the scope reading after it
misses and reinterpret the literal path text as a top-level qualified name — re-anchoring
what the path is relative to. That is step 3 of: (1) head `inner` binds to `Box.inner`,
(2) no `g` under it, (3) reinterpret "inner.g" as a top-level name and find an unrelated
one. Only step 3 is removed.

NON-COEXISTING, and that is the point. If `::` were additive while an unmarked path stayed
absolute-when-it-needs-to-be, there would be two spellings for one meaning differing only
in a rare corner — and the safe one is the one nobody writes, because the unmarked one
appears to work. That is the defect 059 refuses for `fact Spec[X]` vs `provides Spec[X]`.
So the marker REPLACES the implicit absolute reading; it is not offered beside it.

WHY `::` AND NOT A NAME. Verified free: `::` appears in tree-sitter-anthill/grammar.js only
inside comments, and the pratt operator table is ! != % & * + - -> / : < <= <=> = === > >=
@ ^ | — no `::`. It burns NO identifier, so the marker itself cannot be shadowed. `_root_`
(Scala) and `_global` (which IS the root scope's owner symbol — global_scope() interns that
exact string) both name something real but are ordinary identifiers, so a declaration can
shadow the escape hatch itself, and reserving them cuts into the `_`-prefix space intern.rs
leaves to users.

WHAT OTHER LANGUAGES ANSWER, measured on this machine (Rust edition 2021, Scala 3.8.2,
javac 21), same fixture in each:

  Rust    mod lib + fn lib COEXIST; lib::f(1) reaches the module, lib(1) the function.
          Separate TYPE / VALUE / MACRO namespaces, so a value declaration can never
          capture a path prefix. mod lib + struct lib is refused AT THE DECLARATION:
          'lib must be defined only once in the type namespace'. Not available to Anthill,
          which merges every category onto one symbol (WI-926).
  Scala 3 shadows; SILENT when the shadowing value's type happens to have the same member
          chain (2 => 1001). Escape is _root_.
  Java    shadows; SILENT identically (2 => 1001). JLS 6.4.2 obscuring, precedence
          variable > type > package. NO escape; the mitigation is the naming convention
          and 'import the type'.

Anthill today is worse in KIND than Scala/Java: their silent answer at least comes from the
object the author wrote as `lib`; ours comes from an unrelated top-level namespace nobody
named in that path.

SCOPE. One token, one grammar rule, and one arm in resolve_dotted_in_kb — the ladder is
shared by six resolvers (WI-752) so it lands in one place and every position inherits it
(term, type, proof/describe citation; kernel-language.md 8.6 says the ladder is
position-independent). Retiring the implicit reading is the same function.

MIGRATION: ZERO, MEASURED. An instrumented dotted_absolute (logging every hit, with the
head's resolved state) over stdlib + anthill-stl + github-todo + sql-store + webots +
ring-polynom + anthill-todo records ZERO rung-2 hits. Instrument self-checked: it fires on
both the capability shape and the bug shape, so the zero is coverage and not silence.

DO NOT BREAK THE VISIBILITY FALL-THROUGH. WI-752 deliberately made a head-qualified hit
hidden by `internal` keep descending — 'a rung's hit being unusable is a reason to try the
NEXT rung'. A head whose hit is REJECTED FOR VISIBILITY has not bound the path, so the
descent must continue there. The naive one-line change conflates the two and fails
wi752_internal_head_hit_falls_through_to_the_absolute_rung and three of its neighbours;
those four are a separate correction, not part of the capability change.

RENAME `head_owns_path` when its condition changes — the name states the old rule.

TESTS TO REWRITE (4, and they are the deliberate change, not collateral):
wi751_root_shadowing_declaration_keeps_qualified_paths (its acceptance states the OLD
principle in as many words — 'an inert declaration cannot change what a fully-qualified
path means' — which becomes true only for the `::` spelling),
wi751_absolute_path_respects_internal_visibility,
wi751_entity_field_does_not_capture_a_namespace_path,
wi751_rule_reference_citation_under_a_shadowed_root. Each keeps its fixture and gains
`::` on the path.

RELATION TO WI-999. 059 R4 clause 3 declines to refuse a declaration that captures a
NAMESPACE name, on the ground that a namespace has no answer for a body to get a different
one of. Row 3 above refutes that literally — the answer that changes is a qualified path's —
so the exclusion currently rests on the hazard being rare rather than absent. This ticket
makes it absent: with `::` the absolute reading is spelled and the relative one is loud, so
capturing a namespace name can neither re-root a path nor silently change one.

ACCEPTANCE: drive all three rows of the defect and assert the VALUE each answers, not that
they load; keep the differing-return-type variant as the control that proves WHICH `g` was
bound. Drive `::a.b.c` resolving with its head shadowed, and the unmarked twin being loud.
Drive the head_owns_path control — a genuine member miss under a namespace root stays loud —
and the wi752 internal fall-through. Say at each test's site which rows fail when the change
is backed out. Re-run the rung-2 census and assert it stays zero. Run rustland/scripts/test.sh.
