## description

SCALAND: THE `Index ~ x ~~ Index` + `mkSpan` SPAN-CAPTURE IDIOM IS OPEN-CODED AT ~50 PARSER SITES. FOUND by /simplify on WI-961 (2026-08-03); the WI-947 convention put it at ~35 sites and WI-957/961 added ~15 more. Two combinators would collapse most of them: `private def spanOfToken[$: P](p: => P[Unit]): P[Span] = P(Index ~ p ~~ Index).map { case (s, e) => mkSpan(s, e) }` covers the keyword-led forms (`ifExpr`, `letExpr`, `lambdaExpr`, `matchExpr`, `matchBranch`, `proofStatement`, `effectPresence`, `effectAbsence`, `patternTuple`'s empty case), and `private def located[A, $: P](p: => P[A]): P[(A, Span)] = P(Index ~ p ~~ Index).map { case (s, a, e) => (a, mkSpan(s, e)) }` covers the value-carrying ones (`boundedQuantification`, `typedVarArg`, `typedBinder`, `patternVar`, `patternLiteral`). THE FLATTENING OBJECTION DOES NOT APPLY, and this was CHECKED rather than assumed: the reviewer ran fastparse 3.1.1 (the version scaland depends on) and confirmed that `~`-flattening decomposes only literal `scala.TupleN`s, so a nominal case-class-valued slot — `Span`, like the existing `Name` / `OpToken` / `ProjectionMember` — rides through further `~` composition as ONE opaque element. WHY IT WAS NOT DONE IN WI-961: converting only the new sites would leave two idioms side by side, a net readability LOSS, and converting all ~50 is well outside that WI's scope. So this is all-or-nothing and wants its own change. ACCEPTANCE: every site converted (grep for `Index ~` should leave only genuine multi-token spans), suite green, and — because this is a pure refactor with no behavioural delta — say at the site which EXISTING span tests (`DiagnosticLocationTest`, `DeclarationSpanTest`, `ParseSpanCoverageTest`) are the ones that would catch a mis-conversion, since none of them will change.
