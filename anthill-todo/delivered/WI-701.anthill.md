## Description

WI-698 child C (proposal 054, section Branch and External): the typer REJECTS an effect row carrying BOTH `Branch` and `External`. WHY (054): 027 / 037 / 047 section 8 give a tracked resource exactly two lawful branch-interaction contracts -- ranked ABOVE Branch it is snapshotted on entry and rolled back on backtrack (register_undo), ranked BELOW it survives across branches -- and BOTH rest on one premise: the runtime mediates every change to the resource. External names precisely the state for which that premise fails, so NEITHER contract is available. ABOVE IS IMPOSSIBLE: there is no register_undo for the world -- a branch that fails after create_issue cannot un-create the issue; the id is burnt, the notification sent, another writer may already have read the registry. Search would leave debris in the world on behalf of computations that officially never happened. BELOW IS UNSOUND: a solver multi-shot-resumes the continuation once per solution (the 027.2 eval-SLD switch), so an External call reached after a `reflect` runs ONCE PER BRANCH -- create_issue inside a ten-solution region mints ten issues -- and even pure READS break the search, since recent_issues re-executed per branch can answer differently in different branches, so the branches explore different worlds and the solutions are no longer answers to one question. 027 already rules plain sticky-under-Branch a soundness HAZARD for tracked resources that merely LACK snapshot hooks today; External is the state for which the hooks are impossible IN PRINCIPLE, so the hazard is permanent. WRITABLE NOW, statically: Branch is already a declared effect kind (`fact Effect[T = Branch]`, stdlib/anthill/prelude/effects.anthill:136), so rows can carry it and a load-time co-occurrence check can reject it; and the gate forbids nothing we can currently RUN, since the Branch / suspend-resume runtime is still a placeholder (rustland/anthill-core/src/eval/effects.rs:42 and :438 -- WI-075 delivered push_choice, the SUBSTRATE, not the Branch effect). SHAPE: the end-state gate is a LACKS-CONSTRAINT -- a solver region row demanding `-External`, the `-Modify[x]` surface of Iterable.find -- which is exactly why this item depends on WI-700: lacks-constraints parse but do not ENFORCE at explicit row-instantiation shapes today. FOLLOW-ON, not in scope: WI-329 (handler discharge, Open) is what makes the rule COMPOSITIONAL and exact -- a solver reify discharges Branch from the row, so External becomes legal again at precisely the point where the search has committed to its solutions. That is the sound sandwich: read the world before the search, search over tracked state only, write the world after the commit (WI-437 does this twice -- buffered flush, and sync reconcile). Until WI-329 lands, this gate is a blunt co-occurrence reject with no discharge path; that is acceptable and intended.
