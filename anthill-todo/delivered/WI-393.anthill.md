## Description

Typer (CONSUMPTION side): thread a cross-sort carrier's provider bindings into the CONSUMING operation's OWN type parameters when the op uses [Elem,Eff] (042) mapped via its param type Spec[P = OpParam]. WI-380's rewrite (Stream ops: sort-params -> own [Elem,Eff]) makes the stdlib LOAD (WI-392) and same-sort consumption work (collect of an iterator result = real Stream[T=Int,E={}]; wi368 green), but breaks cross-sort DIRECT consumption (List[Int] used AS a Stream: collect(xs), splitFirst(xs)). Root cause: the carrier machinery binds the SPEC SORT's params (bind_spec_params_from_carrier, typing.rs:6291, via type_param_vid_in_sort(Stream, Stream.T/E)) -- which the rewritten ops NO LONGER use -- not the op's [Elem,Eff]; AND it SKIPS ground provider rows (carrier_value not a type-param ref ->  at ~6338), so E={} from  never reaches the op's Eff. TWO facets: (1) body-ful collect/takeN -> 'Eff unconstrained' (ground row E={} not threaded into Eff; the E2 finding); (2) dispatched bodyless splitFirst/head -> element ?_ (cross-sort WI-357 re-walk keys the spec sort's T, not the op's Elem; the S1 finding, whose 'deeper fix' WI-387 already flagged). FIX: at the cross-sort consumption boundary bind the OP's type params (found via the param type's Spec[T=Elem,E=Eff] mapping) from the carrier's provider view INCLUDING ground rows; preserve the WI-357 dispatched-element re-walk for bodyless ops. Consumption-side analog of WI-392 (body side). ACCEPTANCE: with WI-380's [Elem,Eff] rewrite re-applied, wi357 + wi365 + wi368 + full anthill-core green.
