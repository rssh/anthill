## Description

Implements 059 R1 (a type is defined once) and builds the pass-1 DECLARATION LEDGER
that R4 clauses 1 and 2 also consume. Spec: docs/proposals/059-secondary-entries.md.

WHY A LEDGER AND NOT A SYMBOL WALK. `SymbolTable::define` MERGES two same-named
declarations in one scope into ONE symbol, so by the time symbols exist the
duplication is gone — no post-hoc check can find it. Pass 1 must record each
DECLARATION as it makes it.

THE KEY IS (scope, local name) — THE DECLARATION AS WRITTEN, NOT THE ADDRESS IT ENDS
AT, and §6.3's eponymous constructor is why. `sort Vec3 { entity Vec3(…) }` collapses
the constructor onto the sort's own symbol (WI-926), so both declarations end at
address `ns.Vec3`; address-keyed that is indistinguishable from the SIBLING pair
`entity Vec3` + `sort Vec3` that R1 refuses, and a legal shape gets rejected.
Written-keyed they differ — the sort is (ns,"Vec3"), the nested entity
(ns.Vec3,"Vec3") — while the sibling pair is (ns,"Vec3") twice and stays caught.

THE RECORD MUST CARRY THE SourceId. 059 individuates an entry BY FILE: two
`namespace X … end` blocks in one file are ONE secondary entry, the same text in a
second file is a second one. Nothing else can express that — two blocks at one
address compute the same qualified name, reuse the same symbol and alloc the same
hash-consed scope term, so no per-block identity exists to group by. `file_idx` is
already threaded through both scan passes.

R1. Two TYPE declarations sharing a (scope, local name) are a load error naming BOTH
spans: `sort X`+`sort X`, `enum X`+`enum X`, and — as SIBLINGS — `entity X`+`sort X`
(§6.3 makes that pair two spellings of one declaration, so it is the same error).
The harm is reopening a closed ADT: measured, a second `sort C { … }` body beside
`sort C { entity Red }` SILENTLY reopens it — both variants construct and the second
body's members dispatch.

MEASURED, so the tests have their population: 4 eponymous sites (Vec3, TotalFloat,
Duration, Timestamp) among 140 sort/enum headers across stdlib, anthill-stl, examples
and anthill-todo — every one must stay legal. Over 427 operation/const declarations,
no name is declared twice in one scope, so the ledger lands with no migration.

CONTROL, stated at the test site per CLAUDE.md: the 4 eponymous sites pass WITH AND
WITHOUT this change — they are the guard against address-keying, not a measure of the
rule. The sibling pair and the second-body reopen fail ONLY with it.

DO NOT "FIX" THE LOUD SIBLING. `entity X(…)` then `sort X { … }` fails today with
unresolved-name errors (pass 1 gates the enclosing-scope parent link on the
declaration being NEW, and a free-standing entity created no scope for the later body
to inherit). WI-979 deliberately left it loud. Supplying the missing link would build
exactly the capability R1 removes.
