## Description

A SCALAND PARSE ERROR CAN BE RECORDED FROM A PRODUCTION THE PARSE LATER DISCARDS, so a failing parse may carry a message about text that is not in the final tree. FOUND by /code-review on the parser resync (2026-08-03). MECHANISM: `AnthillParserImpl` threads a shared `errors: ArrayBuffer[ParseError]` and several productions push into it from inside a fastparse `.map` — `validateProjectionLabels` (WI-639), the braced-operation-block visibility refusal, and now `refuseTypeParamDefaults` (WI-850). A `.map` runs when ITS production succeeds, which is not the same as the enclosing parse accepting that text: fastparse may backtrack out of the alternative afterwards. `AnthillParser.parse` then returns `Left` if `errors.nonEmpty` EVEN ON `Parsed.Success`, so a stale entry is not merely noise on a failure — it can refuse an otherwise-good parse. REPRO SHAPE (noise direction, the reachable one today): `operation { g[T = Int](x: A) -> B  <garbage> }` — the entry parses and records the WI-850 refusal, then the closing brace fails and the `~/` cut fails the whole parse; the returned errors carry both the genuine 'Parse error at N' and the stale refusal. The poisoning direction is not reachable today (`singleOperation` cannot reach `operationTypeParamList` on a path that later succeeds as a braced block) but nothing PREVENTS it — the next backtrackable alternative over one of these productions makes it live, silently. OPTIONS: (a) record errors with the input position and drop any whose position the successful parse did not consume; (b) return refusals in the production's VALUE (an `Either`/accumulator that rides the IR) instead of a side buffer, so a discarded parse discards them with it; (c) keep the buffer but only surface it on `Parsed.Success`, accepting that a refusal is lost when the parse fails for another reason. SECOND, SMALLER DEFECT in the same area, fix alongside: `refuseTypeParamDefaults` quotes the default via `typeExpr.!` (RAW SOURCE), so `[T = List[ /* note */ Int ]]` renders the comment and interior whitespace into the message — `.trim` only strips the ends. Rendering a structured `TypeExpr` (which is what the pre-WI-850 code held) or normalising the capture would fix it. ACCEPTANCE: a test that a discarded production contributes no error, plus one on the quoted-default text.
