## Description

Drive the interpreter reflect builtins THROUGH a single KbBridge/shared impl object (WI-551 gap (c), deferred from the gap-5 split). WI-551 part (a) already removed the parity tax by giving both realizations ONE carrier-agnostic walk (anthill-stl/src/reflect/reader.rs): the interpreter builtins and the host bridge now map the SAME reader records to their own output types (Value cons-lists vs typed structs), so per-op drift cannot happen. Gap (c) is the STRONGER goal: a single source-of-truth IMPL OBJECT. BLOCKERS: (1) KB ownership mismatch -- the interpreter owns &mut KnowledgeBase (interp.kb_mut()), while KbBridge wants Rc<RefCell<KnowledgeBase>>; unifying needs either moving the interpreter KB into Rc<RefCell> (ripples through Interpreter/Frame/builtins) or a shared-core trait both call. (2) The interpreter reflect ops are SPLIT across two crates: anthill-core/src/eval/builtins.rs (KB.facts_of, KB.execute, resolver/subst-arena ops) + anthill-stl/src/reflect/builtins.rs (introspection). (3) Output-type divergence is intrinsic (dynamically-typed Value vs static structs), so a single impl still needs a per-realization mapping layer -- the walk is already shared. Given part (a) eliminated the drift that motivated WI-551, this is lower priority. Acceptance: a design note weighing the Rc<RefCell> rework vs the shared-reader status quo, and if pursued, interpreter builtins delegating to one impl with cargo-test green.
