## Description

TypingEnv: switch HashMap<String, TermId> keys to HashMap<Symbol, TermId>. Currently var_bindings, type_bindings (and local_resources: Vec<String>) are String-keyed; every call site has the Symbol in hand and does kb.resolve_sym(sym).to_string() at bind, then again at lookup. Two wasteful costs: (1) String allocations for HashMap keys — these dominate the TypingEnv clone cost on the iterative typer's per-Visit-push env clone (WI-255); (2) Symbol→String→re-hash work at every site, despite Symbol being an already-interned Copy u32. Switch field types to HashMap<Symbol, TermId> and Vec<Symbol>. Update bind_var/lookup_var/declare_local_resource/is_local_resource signatures to take Symbol. Update all call sites to pass Symbol directly (drop the resolve_sym + to_string). Acceptance: typing_pass_spec_parses_and_loads still passes on default 2 MiB stack; full workspace tests green; wi231_req_insertion_pass_test run-time on release ~closer-to-pre-WI-242 baseline (or at least demonstrably reduced). Approach: mechanical rename + signature change; keep TypingEnv struct otherwise unchanged. Sibling fix to WI-258 (Rc<TypingEnv> with COW); this one is more impactful and simpler — land first.
