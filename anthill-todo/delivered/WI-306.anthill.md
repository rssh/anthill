## Description

Reserved keyword 'lambda' cannot be used as a term/pattern functor, blocking the reflect AST. PROBLEM: the grammar reserves 'lambda' for lambda_expr (tree-sitter-anthill/grammar.js:945, 'lambda' <param> -> <body>). But anthill.reflect defines 'entity lambda(param: Pattern, body: NodeOccurrence)' (stdlib/anthill/reflect/reflect.anthill:319) and 'entity lambda_within(...)' as legitimate Expr-AST constructors. The entity DECLARATION parses (entity-name position accepts the word), but USING it as a functor in a term or pattern — 'lambda(param: ..., body: ...)' — fails: tree-sitter sees the 'lambda' keyword and produces ERROR nodes (confirmed via npx tree-sitter parse; 'foo(body: ?b)' parses, 'lambda(body: ?b)' does not). Masked until WI-303 made parse() surface ERROR/MISSING nodes. CONSUMER: docs/proposals/typing_pass_spec.anthill lines 165 and 200 destructure occurrence_term(?e, lambda(param: var_pattern(...), body: ?body)) — 2 of the parse errors keeping typing_pass_spec_parses_and_loads #[ignore]d (the other 3 are WI-302 computed type args). DESIGN OPTIONS: (a) allow reserved keywords (at least 'lambda') as functor names in fn_term/pattern position (tricky in tree-sitter: keyword/identifier collision, ambiguity risk with lambda_expr); (b) rename the reflect AST constructor away from the keyword (e.g. 'lambda_expr'/'lam'/'closure'), updating reflect.anthill + consumers + typing_pass_spec. TASK: pick an approach, implement, add corpus/grammar tests, fix typing_pass_spec.anthill's lambda sites. ACCEPTANCE: the reflect lambda AST node is usable as a term/pattern functor; typing_pass_spec.anthill's lambda lines parse clean; cargo-test green. SCOPE: grammar + converter shared (Rust + scaland). Together with WI-302 this unblocks un-ignoring typing_pass_spec_parses_and_loads (WI-303).
