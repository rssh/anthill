## Description

WI-714 follow-up: row-lambda CONDITION compiler -- support boolean nesting (&&, ||, !) and multiple predicates, beyond the single atomic predicate the where/join first increments accept. CONTEXT: proposal 052 'Compiling a row lambda into a query'. where (681ee37a) and join (6185dbc2) both compile a ROW LAMBDA into a LogicalQuery goal at compile time via the WI-722 macro route (where <=> guarded_of [simp]; join <=> conjoin_of [simp]), each reading the typed lambda body and minting column HOLES that the runtime back-end (where_run / join_run) fills with the relation's real column vars. Both FIRST increments accept only a SINGLE ATOMIC PREDICATE -- 'eq(c.x, 1)' / 'pred(c.x, q.y)'. 052's tree->query mapping (the LINQ Expression->SQL analog) specifies the rest: &&/||/! -> conjunction/disjunction/negation of goals, composing the same atoms. GAP: 'r.where(lambda c -> and(eq(c.age, 30), eq(c.name, "alice")))' is not compiled. The compiler locus is compile_condition / compile_operand (eval/builtins.rs), which today recognize field_access(binder, Const(String(field))) operands + one predicate head. FIX DIRECTION: recurse in compile_condition over the boolean spine -- map the logical connectives to the LogicalQuery constructors already wired in kb/execute.rs (conjunction / disjunction / negation), with the atoms compiled exactly as now; anything outside the goal-expressible Bool subset stays a LOUD compile error (052: the analog of LINQ's 'cannot translate to SQL'), never a silent drop or a runtime lambda application. Watch: negation of a goal with a FREE column var flounders under NAF (the WI-728 negate hazard) -- a ! over a column-bearing atom needs the same care. ACCEPTANCE: where + join accept &&/||/! nesting and multiple atoms, each lowering to its LogicalQuery constructor and filtering correctly end-to-end (eval tests, keep + drop directions so the guard is proven to constrain rather than be vacuously true); a non-goal-expressible condition (an if, a non-predicate call) is a loud compile error; the existing wi714 where/join tests stay green; cargo-test green via scripts/test.sh.
