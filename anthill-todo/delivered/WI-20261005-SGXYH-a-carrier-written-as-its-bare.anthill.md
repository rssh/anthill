## Description

A CARRIER WRITTEN AS ITS BARE SORT RUNS A GENERIC PROVISION WHERE THE SAME CARRIER WITH ITS SLOT WRITTEN OPEN REACHES THE ONE AT THE SORT — one program, two spellings, two answers. `sort Bag { sort T = ?; entity bag(n: Int64); operation empty() -> Self = bag(n: 1) }`, `sort Store { sort State = ?; operation peek(s: State) -> Int64 }`, `sort User { sort S = ?; requires Store[State = S]; operation go1(s: S) -> Int64 = Store.peek(s) }`, and two providers: `sort PBag { sort E = ?; provides Store[State = Bag[T = E]]; operation peek(s: Bag[T = E]) -> Int64 = 7 }` and `sort Gen { sort X = ?; provides Store[State = X]; operation peek(s: X) -> Int64 = 55 }`. `User.go1(Bag.empty())` answers 55. `User[S = Bag[T = ?]].go1(Bag.empty())` answers 7, and so does `let b: Bag[T = Int64] = Bag.empty()` followed by `User.go1(b)`. `Bag.empty()` is a result nothing names, so the carrier it pins is the bare `Bag` — which proposal 070 section 1.3 reads as the sort at `?` in each slot left out, i.e. the second spelling. MEASURED on WI-20261005-2KV4Y's tree and on its parent commit alike. MECHANISM: construction (`build_dep_projection` Strategy 3, typing/dep_projection.rs) asks the goal as it is written first. `Store[State = Bag]` matches the generic head (`X := Bag`) and not the applied one, so the generic provider is the unique answer and the provision at `Bag[T = E]` is never weighed against it. 2KV4Y added `with_bare_carrier_opened`, which reads a bare carrier at the sort's open slots, but asks it only where the goal as written ends `NoMatch`. Opening FIRST answers 7 here — a first cut of 2KV4Y did, and passed the whole anthill-core suite but for one row: it trips WI-954's `debug_assert` (`published_param_var`, typing/pattern.rs) on `wi1000_secondary_entry_content_test a_dotted_declaration_name_is_not_the_entrys_content`, whose third fixture (a dotted `sort Inner.T = ?` in a secondary entry, refused by R3) leaves `Rec` a declared type parameter with no canonical variable while typing still runs over it. So the order is held by that latent state and not by a reason of its own. A DIRECTION, not a decision: settle the dotted type-parameter binder first (WI-954's open question — the binder registers the parameter on the sort it is WRITTEN in and defines its symbol in the namespace its name lands in), then open the carrier before the first resolution; or normalize the bare form where it enters the call's substitution, so that every reader of the goal sees one spelling. PINNED by `wi_2kv4y_unfixed_carrier_test beside_a_generic_provision_the_bare_spelling_runs_the_generic_one`, which asserts 55 and 7 and is to be rewritten with the fix. FOUND while delivering WI-20261005-2KV4Y (2026-10-05); filed on the user's instruction ("if we have incorrect result, we need ticket").
