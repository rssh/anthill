## description

scan_rule_goal mints a per-namespace Goal shadow (<ns>.eq / <ns>.unify) for an equation-connective rule head (the =/<=> desugar) when eq/unify is not lexically in scope, because resolve_in_scope does not consult the implicit prelude (PRELUDE_QUALIFIED) where eq/unify live. This silently hides the equation from apply_eq_rules (which selects under the canonical functor), and means a <=> equation needs an explicit 'import anthill.kernel.{unify}' to work — strange/unintuitive since unify resolves canonically in expression position. Empirically (WI-526): 5/8 prelude files (Pair, Eq, String, Int64, Float) mint a unify shadow without the import; eq.anthill's neq even REGRESSES from canonical eq to a unify shadow under <=>. FIX: in scan_rule_goal, skip minting the shadow for eq/unify connective heads that resolve via the STATIC implicit prelude (implicit_qualified) — narrow (only eq/unify, so user predicate rules with other reserved-name heads like or/not still get their Goal symbol => no WI-523-style reroute regression) and deterministic (static const check, not the load-order-dependent by_qualified_name existence check that made the WI-523 broad attempt flaky). NOTE behavior change: activates previously-dormant (shadowed) equations in files where eq/unify was not reachable; verify full suite. Unblocks an import-free WI-526.
