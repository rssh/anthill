## description

scala-gen's type tables are keyed by ONE package, but "what does this bare name reach" is a PER-PACKAGE question. Three gaps, and the first two are the same defect at two scopes.

FOUND BY /code-review ON WI-1060 (findings 2/4/5/6/9 and the sibling half of finding 1). Each is already documented at its site -- Bootstrap.FileTypes.kindsByLeaf, Bootstrap.fileTypes' namespace arm, Bootstrap.emittedTypes, TypeGen's trailing note -- so this ticket is the decision, not the discovery. Do not re-derive the evidence; read those comments.

PART A -- THE FILE-LOCAL TABLE IS FLAT. `Bootstrap.FileTypes.kindsByLeaf` drops the `EmittedType.pkg` the same walk just computed, so `TypeScope.fileTypes` maps a leaf to its arity with no record of WHERE it is emitted, and `place` returns the BARE leaf. That is right exactly when a file emits into one package -- every corpus file does -- and wrong three ways otherwise:
 - `namespace a  sort Foo ... end  namespace b  sort Bar  operation f(x: Foo) -> Foo  end end` in ONE file emits a bare `Foo` into `package b`, where it does not resolve.
 - The namespace arm merges with `acc.types ++ inner.types`, so a leaf declared in two namespaces of one file is silently LAST-WINS and the loser's consumers are arity-checked against the winner. The identical collision ACROSS files is a refusal (`emittedTypes`), so putting both declarations in one file bypasses the guard entirely.
 - `splitPath` concatenates the enclosing package with the dotted name's full prefix, so `namespace anthill.prelude  sort anthill.prelude.Concat ... end` is emitted into `anthill.prelude.anthill.prelude`. No corpus file writes that shape (sort.anthill closes its namespace before its dotted decls) and WI-1060's auto-import filter keeps such an entry out of the cross-file table -- but the EMITTER still writes to that package.

THE FIX IS NOT "carry pkg through and compare it". Scala packages nest LEXICALLY: a type in `a` IS visible from `a.b`, so the predicate is "the type's package equals the mentioning declaration's package or ENCLOSES it". The empty package is the exception -- Scala 3 does not make its members visible from a named package -- so a top-level declaration alongside a `namespace` is not reachable either way.

PART B -- THE PROJECT-WIDE TABLE HAS THE SAME SHAPE ONE SCOPE UP. `ScalaTypes` carries ONE `autoImportPackage` and one table for it, so a project declaring its own `Pair` / `Option` / `Numeric` in a SIBLING FILE reaches the prelude's. MEASURED: WI-1060's B1 CONTROL fixture had to be renamed off `Numeric` because its first draft emitted `_root_.anthill.prelude.Numeric` for a name `my.app` meant locally. WI-1060 closed the IMPORTED half (`TypeScope.shadowsThePrelude` refuses an import naming another package) and left this one, because `fileTypes` is per-file and nothing passes the project's own file set.

This is PART A's fix at a wider scope, and stating it that way is the point of one ticket: `Bootstrap.emittedTypes(files, pkg)` already produces exactly one package-keyed table. What is missing is a MAP of them and a `place` link that reads the entry for the declaration's own package before the auto-import one. The open sub-question is how a caller supplies its file set at all -- `generate` takes ONE ParsedFile today, and the emission tests drive it file by file.

PART C -- THE DERIVED TABLE PROMISES TYPES FROM FILES `generate` REFUSES. `emittedTypes` records what a file DECLARES, never what it emits. Seven prelude files are refused today (the refusal-set test names them: delay, effects, logical_stream, meta, relation, sort, sortedset), so `SortedSet`, `Delay`, `Relation`, `EffectExpression`, `Meta` and the rest sit in the table with an arity and a `_root_` name although the emitted tree will contain neither. A consumer writing `SortedSet[T = X]` is arity-checked against a declaration whose Scala type never exists, and emits `_root_.anthill.prelude.SortedSet[X]`. `ScalaTypes`' own doc calls the table "the type the auto-imported files EMIT for it", which is false for those entries. Answering properly means emitting every file to build the table -- a double emission -- so the alternative is to DECIDE that an entry is a promise about a file the caller must include, and say where that promise is enforced.

SCOPE
 1. Key `Bootstrap.FileTypes` by (package, leaf); give `TypeScope` the mentioning declaration's package to resolve against, honouring lexical package nesting. Fix `splitPath`'s doubling. Make a within-file duplicate a refusal when the two are in the SAME package (the cross-file rule) and legal when they are not.
 2. Generalise `ScalaTypes` from one `autoImportPackage` to a package-keyed set of tables, with a `place` link consulting the declaration's own package before the auto-import one. Decide how a caller supplies the project's file set.
 3. Settle part C and make the doc true: build the table from emissions, or state the promise and name what catches a broken one.

ACCEPTANCE
 - A TWO-NAMESPACE fixture whose second namespace mentions the first's sort: emitted QUALIFIED (or refused), and the emission COMPILES. Drive it through `ScalaCompile` -- a substring assertion alone passes for the wrong reason, since the bare name is also what a correct same-package emission writes.
 - A fixture where a project's own sibling-file `Pair` beats the prelude's, DRIVEN by compiling the two project files together. CONTROL: the same fixture with the sibling absent must still reach `_root_.anthill.prelude.Pair`.
 - A within-file duplicate in one package refused, naming both declarations and LOCATED; the same duplicate across two packages accepted.
 - Part C: either a test that a refused file's sorts are ABSENT from the table, or the doc corrected with a note saying what catches the broken promise.
 - WI-1060's three new placement tests (import shadowing, nested-namespace exclusion, cross-file declaredNotEmitted) must pass UNCHANGED. This widens the rule; it does not replace it.
 - `sbt test` green, and the prelude refusal set unchanged at its recorded seven -- or any change named there with its reason.

WHAT WI-1060 ALREADY DECIDED, so it is not reopened: the scalars come from the profile fact and every other prelude type is DERIVED from the prelude's files; an explicit import from another package is a refusal; only declarations emitted into the auto-import package itself are reachable by a bare name.
