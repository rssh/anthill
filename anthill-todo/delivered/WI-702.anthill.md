## Description

WI-698 child D (proposal 054, section Consumers that must decline it -- loudly): the purity-consumer gates for External. The SOUNDNESS half ALREADY EXISTS and is BLANKET: the defining-equation family routes through a shared purity gate (rustland/anthill-core/src/kb/body_specialize.rs:192 -- an effectful body is not an equation; it declines ANY op with a non-empty effect row or `requires`), with twins on the SLD unfold path (folded_call_match, body_specialize.rs:80) and on the relational-view grant (bare_bodied_bool_relation, kb/resolve.rs:5763). An External-rowed op is therefore declined FOR FREE, and the gate predicate is already the principled one -- function-hood, not the absence of one named effect: a Modify-carrying body is not an equation either, and the blanket check knows it. So this WI changes LOUDNESS plus ONE FORMATION HOLE, not soundness. (1) LOUDNESS: the existing declines are a silent `return None`. That is correct on BULK ENUMERATION paths, but where a consumer SPECIFICALLY REQUESTS equations for an op -- a proof tactic citing them; the request sites are op_defining_equations (body_specialize.rs:974), synthesize_op_defining_rule (:1003) and synthesize_op_defining_rule_at (:1129) -- an effectful, and notably External, row must produce a LOUD DIAGNOSTIC naming the offending op and its row, not a quiet absence. Repo principle: prefer a loud error over a silent skip. (2) THE FORMATION HOLE: the simp rewriter checks no effect rows at the FIRING site (fire_simp, kb/typing.rs:4289; fire_simp_equation, kb/resolve.rs:2902) -- sound today only because effectful ops never BECOME simp equations, formation being gated as above. The one real hole is a USER-WRITTEN `[simp]`-tagged equation rule whose sides mention an External-rowed operation symbol: firing it would duplicate, reorder, or drop the call by rewriting. That gate belongs at LOAD-TIME tag validation (kb/load.rs), NOT at the firing site. (3) Record the rule where it will be found: any future memoization or CSE joins the same decline list. MAY SPLIT: the load-time simp-tag check lives in a different subsystem from the request-site loudness, so if (2) turns out gnarly, split it out rather than growing this item.
