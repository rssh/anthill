## Description

MAKE A PROVISION'S CONDITIONS FACT-OBSERVABLE, so the fact path stops reading a conditional provision as unconditional. WI-869 delivered per-provision conditions (`provides X[...] :- goals`, 058 §3.8) but recorded them as a loader-written KB record (`KnowledgeBase::provision_conditions`) with exactly ONE reader: `typing::provider_dict_chain`. So the conditions bind on the DISPATCH/dictionary path and nowhere else. MEASURED consequences: `check_provider_requires` walks SortProvidesInfo FACTS and never sees a condition, so at load `anthill.prelude.Pair` still asserts an unconditional `provides Eq[Pair]`; the reflect `provides(?A, ?S) :- SortProvidesInfo(sort_ref: ?A, spec: ?S)` rule in stdlib/anthill/reflect/typing.anthill reads the same unconditional claim; and `Set[T = Pair[Float, Int64]]` still LOADS (pinned by wi858_pair_orderings_test::a_pair_of_floats_loads_and_that_has_a_recorded_cost). NOTE the second half of that last one is a DIFFERENT gap and not this ticket's: there is no positive use-site check for `requires Eq` at all — MEASURED, `Set[T = <a sort providing nothing>]` loads clean too, and the only written-site refusal is the NonEq one. WORK: a new reflect entity `ProvidesConditionInfo(sort_ref, provided, condition)` — one fact per condition, leaving SortProvidesInfo BYTE-IDENTICAL so no existing reader or reflect rule is touched (SortProvidesInfo's field list is hard-coded in four places: stdlib/anthill/reflect/reflect.anthill, kb/load.rs x2, kb/eq_derive.rs, which is the real reason not to widen it — NOT the false 'named args match as a set' claim WI-869's first cut wrote and then corrected); emit it beside the SortProvidesInfo fact in `load_provides_clause`; `provider_dict_chain` reads facts instead of the side table; `check_provider_requires` consults the owning provision's conditions. ACCEPTANCE: a reflect query over a conditioned provision can read its conditions; `check_provider_requires` refuses a provision whose own conditions cannot hold; the side table and `ProvisionConditions` retire; full workspace green via rustland/scripts/test.sh. REFERENCE: docs/design/058-implementation.md §16; kb/mod.rs's `ProvisionConditions` doc, which states this scope boundary.
