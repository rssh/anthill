## Description

Typer BUG (surfaced by WI-588 finiteness Phase B): thread the access-EFFECT row — not just the element — when a PROVIDER value flows into a carrier's spec-typed field, so the finite combinators FiniteStream.map/filter can be written WITHOUT the finiteIterator indirection. ROOT: an asymmetry — the element threads but the effect row does not — in three sites. (1) CONSTRUCTION: fmapped(s, f) over a bare s: FiniteStream binds Src = s.T (element) but leaves ES = ??_ (effect unbound). (2) DISPATCH GROUNDING: an op-type-param effect (EffS in 'map[S,EffS](s: FiniteStream[S,EffS], ...)') does NOT ground from the carrier's provision at dispatch on a List, while a SORT-param effect E (Iterable.map's) DOES — inconsistent (args not checked vs param types, WI-385). (3) PROVISION-RETURN CHECK: the body's FiniteMappedStream is matched against the declared FiniteStream return for an op-param effect row {EffS,EffP} (works, cf. MappedStream.map) but NOT when the row carries a PROJECTION {s.E, EffP} (the raw carrier head is compared instead of applying the provision). WORKAROUND in WI-588: a body-less finiteIterator(c) -> FiniteStream[Element, E] on FiniteCollection routes the effect through an explicit return type; the parallel of Iterable.iterator. ACCEPTANCE: the ignored reproducer test flips to passing AND FiniteStream.map/filter can be defined directly (fmapped(s,f) over a bare receiver threads the effect), letting finiteIterator be removed from FiniteCollection. Reproducer: anthill-core/tests/include/wi594_finite_map_effect_threading_test.rs (#[ignore]d).
