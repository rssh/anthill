## Description

Carrier-aware spec dispatch: select a spec op's concrete impl by the RECEIVER's carrier type, not only the spec's type-param bindings. Enables multi-impl specs whose carrier differs from the type param (Stream/Iterable/Iteration/Collection). PROBLEM: spec-op dispatch (typing.rs find_unique_impl_op / dispatch_spec_op_cached ~3080-3290) builds its subst by unifying arg types with param types (typing.rs:3001) and resolves the impl from the spec's TYPE PARAMS only. For Eq/Ordered/Numeric[T] the carrier IS T, so the impl is pinned. For Stream[T] the T is the ELEMENT and the carrier (List/LogicalStream) is separate and NOT a type param, so the bindings never pin the carrier -> with >=2 impls EVERY Stream-op call is DispatchAmbiguous (typing.rs:3283 via pick_most_specific:4475), even a concrete head(xs: List[Int]); collect_provides_candidates (4623) searches by spec only. PRINCIPLE (settled with user): dispatch must construct the concrete impl using the RECEIVER's carrier at the call site. (a) concrete carrier receiver (xs: List) -> pick that carrier's impl; coherence enforced PER-CARRIER. (b) abstract-spec receiver (s: Stream[T], base sort == the spec) -> no concrete impl; type via the spec op's INTERFACE signature (return from op decl + subst) and DEFER impl resolution to the requires slot (DeferToRequirement) or the runtime value's witness -- NOT Ambiguous. Today the global search is skipped only when a requires slot exists (find_requires_location pre-check typing.rs:3100); the no-slot abstract case wrongly enters concrete construction and errors. CHANGE: thread the carrier-typed receiver arg's base sort into find_unique_impl_op; filter candidates by carrier when concrete; abstract-spec receiver -> interface-type + defer. TESTS to revisit under the new model: wi210_dispatch_test::dispatch_polymorphic_candidate_matches_any_per_call_value, wi211_typing_test::stream_head_on_concrete_stream_yields_option_with_concrete_t (should type via interface -> Option[T] regardless of impl count), wi226 cache cosmetic. ALSO verify eval resolves a deferred spec-op from the value's runtime sort (add if missing).
