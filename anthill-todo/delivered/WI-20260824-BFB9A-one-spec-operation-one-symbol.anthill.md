## Description

ONE SPEC OPERATION, ONE SYMBOL: refuse a free-standing operation that rivals a spec op.

THE DEFECT. A namespace-level `operation eq(a: Int64, b: Int64) -> Bool` declares a SECOND symbol named `eq`, rivalling `anthill.prelude.PartialEq.eq`. The language's model for "my carrier's eq" is a provision — `provides PartialEq[T = MySort]` — which attaches an implementation to the ONE symbol and selects it by carrier at the call site (WI-350/444/627: `Set.eq`, `Map.eq`). A rival declaration is not that; it is a different symbol that happens to share a spelling, and everything downstream works around it.

WHAT IT COSTS TODAY. `resolve_in_scope_recursive` (intern.rs:1825) merges its parent hits, dedups, and reports `Ambiguous` only when TWO DISTINCT SYMBOLS survive — a name reachable twice by ONE symbol is `Found`, not an error. The entire justification for the implicit tier being a LOWEST-PRECEDENCE fallback (`load::resolve_implicit`, load.rs:4939; WI-521, and WI-476's collision blocklist before it) is that a user name must be able to shadow a prelude name without going `Ambiguous`. That requirement exists ONLY because the rival is permitted. The tier is check-logic standing in for an illegal state that should not be representable.

THE ASYMMETRY TO CLOSE. A rule head ALREADY resolves-not-declares (WI-896; kernel-language.md §"A rule head functor is resolved, not declared"): the functor runs the ordinary ladder and the rule contributes a clause to whatever it lands on; only a MISS introduces the name. An `operation` declaration always declares. That difference is the whole of this ticket.

REFUSE, DO NOT ABSORB. Making the declaration attach to the spec op instead CANNOT work: a free-standing operation has no carrier, and dispatch keys on the carrier, so there is nothing for `PartialEq.eq` to select. The rule is a LOAD ERROR naming the spec operation it rivals and the `provides` repair.

CENSUS (measured this session; exhaustive over every `.anthill` file and every fixture line in `.rs`, matching a line-initial `operation <name>(` for eq/neq/gt/lt/gte/lte/add/sub/mul/neg/div/mod/and/or/not; for each hit, the enclosing construct is the nearest preceding header line — namespace/sort/enum/entity/spec/abstract — at strictly smaller indent). 95 declarations: 81 `sort` members, 8 `enum` members, 6 namespace-level. The six:
  - stdlib/anthill/kernel/kernel.anthill:57 `not/1` — the implicit tier's OWN TARGET; must NOT be refused
  - wi521_prelude_test.rs:47 `eq/2` — the fixture written to DEMONSTRATE the footgun
  - eval_test.rs:1336 `neg/0`; wi532_float_infinity_test.rs:45 `neg/0`; wi_yqb1y_one_column_relation_test.rs:437 `neg/0`; wi783_function_value_named_args_test.rs:187 `neg/1` — `neg` as a plain name ("negative case", `= negativeInfinity`)
BLAST RADIUS = 5 declarations. Members split 47 under a `provides` / 42 not (the latter includes the spec declarations themselves). A FIRST PASS OF THIS CENSUS MIS-ATTRIBUTED 5 ROWS and is worth knowing before re-running it: a fixture's opening line carries a Rust prefix (`let out = gen(r#"sort Eq {`) that inflates its apparent indent, so an enclosing `sort` looked DEEPER than its own members and they read as unattributed. Measure indent after the quote marker.

TWO CONSTRAINTS THE CENSUS HANDS THE RULE, both of which the obvious implementation gets wrong:
  (1) ARITY. Three of the four `neg` rows are NULLARY; `Numeric.neg` is unary. An arity-blind refusal falsely rejects them. Decide: make the rule arity-aware, or rename the four and keep it arity-blind — and say WHICH and WHY at the site.
  (2) THE TIER'S OWN TARGETS ARE NOT RIVALS. `anthill.kernel.not` IS what the tier resolves a bare `not` to. So the rule cannot be "a namespace-level operation whose short name is in PRELUDE_QUALIFIED"; it must ask whether the name resolves to a symbol DIFFERENT from the one being declared.

NOT DRIVEN. The census is measured. The refusal is not implemented and the design above is a code read.

THE CONTROL IS AN INVERSION, not a new row: `wi521_prelude_test.rs::user_eq_shadows_prelude_without_ambiguity` asserts that the rival LOADS CLEAN — it is precisely the assertion this ticket makes false. Flipping it IS the measurement, and the delivery note must say so rather than quietly editing it. Rows that must stay green either way: the four `neg` declarations (or their renamed successors), `anthill.kernel.not`, and all 89 type-member declarations.

ACCEPTANCE: a namespace-level operation rivalling a spec op is a LOCATED load error naming the spec op and the `provides` repair; the five census rows resolve as decided; WI-521's test inverted with its polarity change recorded in the delivery note; full workspace green via rustland/scripts/test.sh.

WHAT THIS UNBLOCKS. WI-909 (the implicit tier is absent from TYPE position) depends on this. With rivals refused, the tier's lowest-precedence position stops being load-bearing for spec-operation names, which opens the option WI-909 needs: back the implicit prelude with the prelude SCOPE instead of a table of qualified strings, so it is visible to `remap_symbol_strict` (load.rs:17012) and `remap_name` (load.rs:17046) for free — both already call `resolve_in_scope`. WI-910 (nothing checks the tier tables' short names are distinct) and `implicit_target_orphans` dissolve on the same change. NOT ESTABLISHED, and WI-909's business rather than this ticket's: that scope-backing is safe for TYPE names. A user's domain `sort List` (a to-do list, a mailing list — nobody copies the prelude's) is a LEGITIMATE second symbol and must keep shadowing; today it does so as a LOCAL, and locals short-circuit before any parent (intern.rs:1657), so no ambiguity arises. But WI-521 RECORDS an `Ambiguous` under the old `<global>` injection whose scope topology is not recorded anywhere, so the safety of scope-backing must be MEASURED — build the variant, run the corpus — not argued from the current code.
