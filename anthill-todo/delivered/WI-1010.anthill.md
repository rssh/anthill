So WI-444's rule — defaults fill GAPS, they do not SHADOW — is implemented for route 1 only ('carrier_override_op', filtered 'impl_parent_of_op(o) == carrier', plus eval's 'resolve_carrier_override_by_value'); WI-431's op-valued fact binding never reaches that gate, although the LOADER accepts it as backing ('op_bound_in_instance_fact'). The load check certifies the binding backs the op and dispatch then ignores it — a silent wrong answer, not a missing feature. WORK: give the fact binding the same standing as a carrier's own member at BOTH WI-444 sites (typer 'carrier_override_op', eval 'resolve_carrier_override_by_value'), or REFUSE the combination at load if the precedence is meant to run the other way; either answer must be written into the op-model doc, since 'a retroactive instance backs the op' is what WI-431 promises and what the loader already enforces.
