## description

Implement library proposal 004 (docs/proposals/library/004-partial-vs-total-equality-and-ordering.md): split the conflated Eq into PartialEq (partial -- holds the eq/neq ops; Float provides, IEEE) + Eq (requires PartialEq + a CHECKED reflexivity law eq_refl: eq(?a,?a)<=>true; Float does NOT provide -- the instance-law conformance checker rejects it automatically), and split Ordered into PartialOrd (partialCompare -> Option[Int64]) + Ord (requires Eq + PartialOrd, total).

[EVOLUTION: this ticket started as "proposal 051 Phase 2 -- drop the universal structural Eq default"; investigation (WI-645 Float NaN soundness bug + Rust/Lean prior art) showed the principled resolution is the PartialEq/Eq SPLIT, not dropping a default -- so the design landed as library proposal 004 and THIS ticket is its implementation driver. See the feedback trail.]

NO new language machinery -- reuses the existing spec-hierarchy (`requires Spec[T]`: Ordered-requires-Eq precedent), laws-as-labeled-<=>-rules (Ordered.compare_refl precedent), and instance-law CONFORMANCE CHECKING (load.rs Specialization / requires-law Discharged, ~3866-3972,12425). The one kernel-touching piece (the resolver reflexivity-shortcut fix) is an implementation consequence tracked here, like library/003's typer work.

BUILD STEPS (proposal Build order): (1) stdlib specs+laws: new PartialEq/PartialOrd sorts; move eq/neq + neq<=>not(eq) to PartialEq; add eq_refl to Eq; re-parent `Eq requires PartialEq` / `Ord requires Eq, PartialOrd`; re-register builtins (PartialEq.eq->SemEq, ...); confirm the conformance checker REJECTS a synthetic non-reflexive `provides Eq`. (2) resolver soundness fix (CLOSES WI-645 direction B): gate sem_eq_core's `values_equal` reflexivity fast-path to reflexive-Eq carriers only; eval builtin_eq IEEE-for-Float path (numeric value_num compare; fall back to structural for non-numeric so Set/Map/entity eq unchanged, WI-616 override dispatch preserved); un-ignore wi645_float_nan_ieee_test.rs. (3) Float: provides PartialEq/PartialOrd (IEEE), drop provides Eq; add TotalFloat newtype providing Eq/Ord (total). (4) codegen: PartialEq.eq->C++ `==`, Eq/Ord/TotalFloat -> total operator==/<=> (incl. `= default` on entity structs, closing the WI-645 struct-operator== gap). (5) docs: kernel-language.md sec-equality three-notion table; sync 051.

MIGRATION (intent audit, like 051's ===): Eq.eq->PartialEq.eq (mostly source-compatible via the requires-chain, WI-614); audit every `requires Eq` / `requires Ordered` -- keep Eq/Ord for reflexivity-dependent (Set, Map keys, dedup, sort), weaken to PartialEq/PartialOrd for compare-only.

PRIOR ART: Rust (f64: PartialEq but !Eq) and, more precisely, Lean's 3-level =/BEq/LawfulBEq (Anthill ===/PartialEq.eq/Eq); Lean withholds LawfulBEq Float for BOTH non-reflexivity (NaN) AND non-congruence (-0.0==+0.0 but 1/0 != 1/-0). NB Anthill's Eq = EQUIVALENCE laws (reflexive/sym/trans), NOT Lean's coincide-with-= (since === is structural, not per-type logical =) -- else Set/Map (semantic eq != structural) would wrongly fail lawfulness.

CLOSES WI-645 (direction B). Modular/named non-canonical instances (SortedSet custom Ord) = WI-648 (deferred sibling). WI-642's is_builtin exclusion stays correct.

ACCEPTANCE: PartialEq/Eq/PartialOrd/Ord load with eq_refl a checked law; a non-reflexive `provides Eq[T=Float]` FAILS to load; interpreter Float eq/neq/ordered are IEEE and AGREE with the C++ codegen (wi645_float_nan_ieee_test un-ignored + green); Map[K=Float] is a load error, Map[K=TotalFloat] loads; Set/Map/entity semantic eq + hash-consing + === unchanged; full workspace suite green.
