## Description

reflect name resolution API: typed refs / scoped resolution for the string-name surface (the principled fix behind WI-515/WI-631). KB.fields(kb, name: String), sort_query(String), and the generated-bridge fields/operations/constructors/rules(sort_name: String) resolve entity/sort names by GLOBAL string matching with no scope context — a parallel resolution path that bypasses the symbol table's scope-aware machinery (imports, enclosing namespace), which is why short-name ambiguity (WI-631) exists at all. MIGRATE the surface to typed references: (a) KB.fields / sort_query take a Ref/Term (the facts_of precedent — it takes the entity by reference, Type carrying Ref(Color.red)), so names resolve where they are WRITTEN, by the loader, with real import/namespace scoping and zero runtime string matching; (b) keep String forms as qualified-only conveniences (resolve via try_resolve_symbol, no short-name scan) or deprecate; (c) where a runtime string is genuinely needed (host tooling), consider an explicit scope parameter routed through symbols.resolve_in_scope. TOUCHES: stdlib/anthill/reflect/reflect.anthill (KB.fields / LogicalQuery.sort_query signatures), both realizations (anthill-stl reflect builtins + generated bridge / codegen emit), execute lowering (find_entity_schema), tests. NB scaland mirrors grammar/loader/resolver only — check whether its reflect surface (if any) needs the same. Depends on: WI-631 (lands the loud-ambiguity stopgap first).
