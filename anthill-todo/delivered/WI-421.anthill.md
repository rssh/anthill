## Description

Loader/typer: an external operation cannot be referenced as a VALUE (for eta / HOF arg) inside a SORT BODY -- only as a qualified dot-CALL (WI-279 dot-dispatch). Surfaced finalizing WI-420: abstract-cross-sort eta (eta-lifting an external requires-op where the element type is ABSTRACT) requires referencing the op as a value inside a sort op (the only place the element is abstract), which does not resolve. Evidence (all in value position inside a sort body): bare 'member' with 'import anthill.prelude.List.{member}' -> 'unknown functor'/unresolved; 'List.member' as a value -> parsed as dot-access chain (List, member both unresolved); 'anthill.prelude.List.member' as a value -> parsed as a 4-ref access chain (anthill/prelude/List/member all unresolved). Contrast: the dot-CALL form 'List.member(args)' DOES resolve in a sort body (WI-418's Coll.contains test) but has no value-position equivalent for eta. The WI-420 requirement-capture mechanism is already IN PLACE and would handle abstract eta once the value reference resolves: Value::OpRef carries its dispatch dict (evaluated at mint in the eta-site frame, installed into the callee frame at apply); build_concrete_dispatch_dict forwards an abstract dep via a Strategy-1 var_ref to the enclosing frame's __req_*; entries_cover now uses same_symbol (WI-420 bug fix) so a qualified-vs-short spec symbol matches. FIX DIRECTION: (a) make sort-body bare-name resolution fall back to the namespace's imports for VALUE-position refs (today only call/dot-dispatch resolves), and/or (b) parse a fully-qualified op path in value position as a single op symbol rather than a dot-access chain. ACCEPTANCE: a sort op can pass an external requires-op as a HOF arg; the abstract-eta probe (sort Box requires Eq[T]; operation has(b: Box, x: T) -> Bool = use_pair(member, x, xs)) typechecks + evals true/false; cargo-test green.
