## Description

Rebuild value_fact_dedup_key CARRIER-NEUTRAL on GoalKey, retiring cached_term / term_cache / the pin-for-lifetime leak that WI-472 exists to reclaim. CONTEXT: surfaced while reviewing WI-762 (a projection guard reached for cached_term, which was the wrong tool). value_fact_dedup_key (kb/mod.rs:2176) needs an IDENTITY for fact-head dedup, and obtains it by MATERIALIZING the occurrence into a hash-consed TermId via node_occurrence::cached_term (kb/mod.rs:2186). It pays three costs for a question that is pure: (1) it needs &mut kb to answer a comparison; (2) cached_term's doc states it "owns the single `+1` the final `alloc` returns and never releases it (pin-for-lifetime; Drop cannot reach the store)", so every deduped fact head pins a term for the KB's life; (3) it inherits occurrence_to_term's GOAL-POSITION partiality -- a non-goal shape reifies to Term::Bottom, which is why the function already hand-codes the guard "a lossy key must degrade to no-dedup, never collapse distinct heads". THE MECHANISM ALREADY EXISTS AND THIS EXACT MOVE HAS BEEN MADE ONCE: GoalKey (kb/term_view.rs:887) is a "carrier-agnostic structural fingerprint" whose own doc says it "keys the resolver's answer-dedup set directly with no materialization to a TermId and no kb in Hash/Eq, replacing the former materialized HashSet<TermId> key" -- i.e. the resolver's seen_goals already migrated off exactly this pattern (WI-348). goal_fingerprint(kb, view, subst) -> GoalKey walks any carrier through TermView. INJECTIVITY (the fact-dedup crux, WI-472) IS PRESERVED: GoalKey is a Vec<StructToken> with derived Eq/Hash, an EXACT structural token sequence, not a lossy digest -- so distinct heads stay distinct. The Bottom rejection becomes a StructToken::Opaque rejection, the same rule made TOTAL; GoalKey::is_cacheable already performs the analogous Opaque/flex-var exclusion for the query cache, so the predicate is shared rather than restated. MEASURED BLAST RADIUS -- the chain is a straight line and collapses entirely: cached_term has EXACTLY ONE non-test caller in the workspace (kb/mod.rs:2186; every other hit is its own unit tests at node_occurrence.rs:5113-5132); term_cache is read/written ONLY by cached_term (node_occurrence.rs:2425 / :2431, the rest being the 6 Cell::new(None) inits); and KbId is stamped on term_cache expressly "so a future (WI-472) deferred term-release queue can reclaim it" (kb/mod.rs:392, :410). So converting this ONE function retires cached_term, the term_cache field on every NodeOccurrence, the KbId stamping rationale, and DISSOLVES WI-472's reclamation problem rather than solving it -- there is no allocation left to release. DIRECTION: this is one more step of the standing reify audit (WI-348 / WI-482 / WI-621 / WI-678 / WI-692), each of which removed occurrence_to_term calls by making the CONSUMER carrier-neutral rather than by widening the reifier. NOTE explicitly for the next reader: do NOT "fix" this by filling in try_occurrence_to_term's unimplemented arms (the args-bearing DotApply arm, Match/If/Let/Lambda). That makes the shim more capable, removes the pressure each None creates, and entrenches the conversion being retired. ACCEPTANCE: value_fact_dedup_key keys on GoalKey with no TermId materialization and no &mut kb for the key itself; a lossy key (Opaque) degrades to NO-dedup, never collapsing distinct fact heads, with a test asserting two structurally-distinct Opaque-bearing heads stay separate facts; cached_term, NodeOccurrence::term_cache and the WI-472 reclamation TODO are deleted (or WI-472 is closed as dissolved, stating so); fact-dedup behaviour is otherwise unchanged -- an existing test pins that re-asserting a structurally identical value-fact head still dedups; full workspace green via rustland/scripts/test.sh.
