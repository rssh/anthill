## description

Tree-sitter grammar: remove the unused brace-less `<entries> end` forms of rule_block and operation_block to kill the GLR ambiguity that lets a block greedily swallow a following declaration.

ROOT CAUSE (found in WI-291; see memory project_rule_block_greedy_parse): grammar.js `rule_block = 'rule' choice('{' rule_entry* '}', rule_entry* 'end')` and `operation_block` mirrors it. The brace-less `rule_entry* 'end'` alternative is GLR-ambiguous with a single `rule_declaration` (identical inner shape, both start with 'rule') — that's the DECLARED conflict [$.rule_declaration, $.rule_entry] (and [$.operation_declaration, $.operation_entry]) in the conflicts array. Because rule heads are SOFT-KEYWORD identifiers, a brace-less block consumes following 'rule'/'proof'/etc. keywords as bare-name entry heads and runs to the FIRST 'end' — so `rule X: ... \n proof X ... end` parses as ONE rule_block whose terminator is the PROOF's 'end', SILENTLY dropping the proof (0 ERROR nodes). In WI-291 a leading 'export' statement had been incidentally steering GLR away from this; removing export exposed it (prove_hint_test, worked around with a braced block).

KEY FACTS: (1) the brace-less form is used by ZERO real .anthill files (all rule/operation blocks use braces); (2) scaland (fastparse) has ONLY the braced form ("{" ~/ ruleEntry.rep ~ "}", "{" ~/ operationEntry.rep ~ "}") — so the brace-less form is a tree-sitter-ONLY divergence and removing it ALIGNS the two grammars.

APPROACH VALIDATED via throwaway prototype (reverted, not committed): removed both brace-less alternatives + deleted both conflicts -> npx tree-sitter generate exit 0 (conflicts genuinely no longer needed); the ORIGINAL brace-less prove_hint snippet (two 'rule X:' + standalone [hint] + two 'proof ... end') then parses as 2 rule_declaration + 2 proof_declaration + 0 rule_block + 0 ERROR. ONLY fallout: ONE corpus test 'Operation body in block' uses the brace-less operation form and fails -> update it to braced (or remove).

FIX: (1) grammar.js: drop `seq(repeat($.rule_entry),'end')` from rule_block and `seq(repeat($.operation_entry),'end')` from operation_block (keep braced '{ }'); (2) delete conflicts [$.rule_declaration,$.rule_entry] and [$.operation_declaration,$.operation_entry]; regenerate; (3) fix the 'Operation body in block' corpus test; confirm 157-ish/all corpus green; (4) OPTIONAL cleanup: revert prove_hint_test.rs to the natural brace-less rule form (now parses correctly — two single rule_declarations no longer merge); (5) kernel-language.md: if it documents a brace-less rule/operation block, switch to braces-only for blocks (single decls stay 'rule X: ...'); (6) scaland: no change (already braced-only). Full rustland cargo-test green.
