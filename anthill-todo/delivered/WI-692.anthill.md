## description

push_choice arg extraction carrier-neutral (WI-348 direction). resolve_push_choice_args (resolve.rs) accepted a reified goal TermId and returned a (TermId, TermId) pair, so a Value::Node push_choice goal had to round-trip through reify_goal_value just to index its two branch goals off a Term::Fn, and the PushChoice step handler then re-wrapped the walked TermIds as Value::term. This predates the sweep (proposal 033 / WI-075, when goals were Term-structured; the old comment admitted 'Term-structured; reify a Node goal for arg extraction'). Make it read the goal through TermView (head() 2-ary/unnamed arity gate + pos_arg) and walk_arg each branch to a Value -- a Node continuation stays a Node, no reify -- returning (Value, Value); drop the reify_goal_value fallback and the two Value::term re-wraps in the PushChoice handler. Mirrors the eq_operands idiom (self.walk_arg(goal.pos_arg(self, i), subst)). Behavioral nuance = strict improvement: a branch arg that is a var bound to a non-term Value (a Node occurrence goal) now yields the bound goal directly instead of a Value::term(var) that re-resolves. Acceptance: full cargo-test green (esp. push_choice_test incl. or_rule nested disjunction + WI-580 Node op-call cases).
