## description

Fire parse errors early: surface tree-sitter ERROR / MISSING nodes from parse() instead of silently dropping them. PROBLEM: parse() (rustland/anthill-core/src/parse/mod.rs) never inspects tree.root_node().has_error(); it returns Ok with only the converter's own errors. tree-sitter recovers from malformed input by inserting ERROR / MISSING nodes and continuing, and the converter walks past anything it does not recognise — so a broken construct is silently dropped (an `Effect = {}` binding vanishes; the anthill-stl carrier host bindings were dropped; computed type args dropped). Violates CLAUDE.md 'avoid fallbacks, know about errors early'. PROTOTYPE (validated then reverted this session): a collect_syntax_errors(root, source) walk that prunes clean subtrees via has_error, reports is_error / is_missing once per error subtree (source-ordered), and has parse() return Err if any are found. BLAST RADIUS (measured with the prototype): zero behavioural regressions, but it surfaces ~37+ latent malformed TEST FIXTURES across at least 4 binaries (builtin/toml_ser 16, parse 12, wi 2, integration+cpp-gen 7) that only ever parsed via error recovery, in three mechanical classes: (1) brace-less namespace or bare sort missing `end` (toml_ser_test build_test_kb namespace; parse_test bare `sort ns.A`); (2) variable / abstract-sort inline description missing the grammar-required trailing `?` — `?x {< .. >}` must be `?x {< .. >}?` (tree-sitter-anthill/grammar.js:778-786); (3) `?`-logic-vars in EXPRESSION positions — `let ?y = x` must be `let y = x`. PLUS a false-green canary: typing_test.rs typing_pass_spec_parses_and_loads panics on parse errors and is green ONLY because they are swallowed; it must be made honest (depends on WI-302 plus the spec gaps). TASK: land collect_syntax_errors in parse(); fix all surfaced fixtures (mechanical, no logic change); make typing_pass_spec_parses_and_loads honest; confirm full suite green. RELATED gaps that fire-error exposes: WI-301 (effect-set type args), WI-302 (computed type args), dotted-name instantiation functors (a reflect.anthill workaround was applied), and the carrier host-binding sugar (anthill-stl rewritten to the braced carrier-bindings form; anthill-cpp-gen/anthill/int.anthill was deliberately LEFT in the swallowed carrier-equals-string form because the braced form actually loads the carrier, which makes cpp-gen emit this provides block's artifact — a .rs path — as a C++ #include and breaks the header-compile tests; fix the cpp-gen carrier braced-form AND its bogus .rs artifact together).
