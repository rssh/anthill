## Description

Expose BulkStore.pull to the evaluator, and restore the file backends' BulkStore provision.

STATE AFTER WI-931. Neither FileStore nor IndexedFileStore provides BulkStore. The provision was removed (stdlib/anthill/persistence/filesystem.anthill) because BulkStore declares exactly one member -- pull(store: BulkStore) -> List[T = Term] -- and NO anthill-callable implementation of it exists. MEASURED: the six other storage operations (persist/flush/monotonicity/retract/update/retrieve) are registered eval builtins; pull is not, in either registry. A fact BulkStore[X] therefore certified an operation that dies at the call site, which is the unsoundness check_provider_operations exists to refuse (WI-363 / WI-818).

WHAT EXISTS. The Rust trait method BulkStore::pull(&self) -> Result<Vec<ParsedFile>, PersistenceError> is implemented by both file backends (rustland/anthill-core/src/persistence/{file_store,indexed_file_store}.rs) and driven FROM RUST -- the CLI's cold start reads the .anthill tree through it. So the capability is real; only the anthill-side bridge is missing.

WHY IT IS NOT A ONE-LINER, and this is the actual work. The host side returns parsed FILES; the anthill signature says List[Term]. There is no ParsedFile -> Vec<TermId> conversion in the tree -- kb::load::load asserts a ParsedFile INTO the KB rather than yielding its items as terms -- and what pull should do with a file's non-fact items (rules, namespaces, imports) is a design question, not a mechanical one. Note the sibling that already solved the easier half: persistence_retrieve wraps store.retrieve(...) -> Vec<TermId> as a Stream[Term, Error], because retrieve queries rows that are already terms.

SHAPE. Add a store_pull host function to HOST_FNS (rustland/anthill-core/src/eval/builtins.rs), map it in the BulkStore binding block (rustland/anthill-stl/anthill/persistence.anthill, which already carries Store/NonMonotonicStore/QueryableStore), and restore fact BulkStore[FileStore] + fact BulkStore[IndexedFileStore] THERE -- in the host closure, not in the stdlib, per the WI-931 rule that a satisfaction fact may only stand where the spec's operations are backed.

ACCEPTANCE: pull is callable from an anthill program against a registered file-store mirror and returns the persisted facts; both file backends provide BulkStore again; the stdlib loads clean with check_provider_operations covering them (no staging); cargo-test green via rustland/scripts/test.sh.

SOURCE: measured while delivering WI-931 (2026-08-02).
