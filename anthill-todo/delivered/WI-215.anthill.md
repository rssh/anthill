## Description

stdlib hygiene: wrap effects.anthill body in 'namespace anthill.prelude { ... }'. Today stdlib/anthill/prelude/effects.anthill has bare 'sort Modify', 'sort Error', 'sort Suspension', 'sort Branch', 'sort MatchFailed' declarations (no enclosing namespace block) — they register at global scope with qns 'Modify', 'Error', etc. instead of 'anthill.prelude.Modify' / 'anthill.prelude.Error' / etc. Sibling files (stream.anthill, list.anthill) and the top of effects.anthill itself (sort anthill.prelude.Effect, sort anthill.prelude.Modifiable) use the qualified form. The inconsistency surfaces when host-language code (e.g. test helpers, codegen) tries try_resolve_symbol('anthill.prelude.Error') and gets None. Today user code happens to work because bare global Error/Modify/etc. are visible everywhere through default-scope fallback, but the wrong qualified form is registered. Fix: wrap the body of effects.anthill in 'namespace anthill.prelude' (single block around the bare-sort declarations); leave the already-qualified anthill.prelude.Effect / anthill.prelude.Modifiable as-is or fold into the same block. Acceptance: cargo-test green; try_resolve_symbol('anthill.prelude.Error') returns Some; existing user-code references to bare 'Error' / 'Modify' / 'Branch' / etc. still resolve via implicit prelude import. Independent of WI-211.
