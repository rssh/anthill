## description

A `Function[A = …]` SLOT READS `A` AS A PARAMETER LIST WHEN THE CALLBACK SPREADS IT — so the two spellings of `A` stop disagreeing. Decided (user, 2026-08-12), NARROW scope. The derivation and measurements are in this item's feedback entries.

THE DEFECT. Two settled rules disagree and the kernel applies each where the other cannot see. WI-775 says a `Function[A = …]`'s `A` is the ARGUMENT's data type, aligned BY NAME. WI-801 says the same slot admits TWO arities — 1 (the whole `A`) and `A`'s COMPONENT COUNT (its components spread). For a 2-parameter OPERATION they cannot both hold: its eta arrow's parameter list is always minted `_1, _2` (`operation_as_function_value`; an arrow drops its binder names, WI-783), so the by-name comparison refuses every spread WI-801 admits, and WI-801's second reading is reachable only for a LAMBDA (which ADOPTS `A` and so matches by construction). MEASURED — two programs byte-identical but for whether `A`'s components carry user labels:

  Function[A = (Int64, Int64), B = Int64]           given sub2(p, q)  => loads, evaluates to -7
  Function[A = (acc: Int64, x: Int64), B = Int64]   given sub2(p, q)  => REFUSED

The positional spelling passes only because `A`'s labels ARE `_1, _2` and coincide with the synthetic escape — not because a rule chose it. And the labels play no part at eval: `spread_eta_args` reads `pos ++ named` in source order and consults none (`wi787…::named_tuple_spreads_across_eta_operation` drives `(_2: 3, _1: 10)` and `(_01: 3, _02: 10)` both to -7). The accept/refuse verdict turns on a property the runtime never reads.

THE RULE, NARROW. At a `Function[A, B, E]` slot, when the callback's ARITY equals `A`'s COMPONENT COUNT and is not 1 — WI-801's spread reading, which `arity_admitted_at_function_slot` already owns — `A` is READ AS the callback's PARAMETER LIST and compared with `TupleAlign::PARAM_LIST` (equal arity, positional, synthetic `_1.._n` escape). At arity 1 it stays the ARGUMENT's data type, compared BY NAME as WI-775 settled. Nothing else moves.

WHAT THIS DELIBERATELY DOES NOT DO — REJECTED (user, 2026-08-12) after measurement. The general rule 'labels absent -> align positionally, labels present -> reorder' was considered and NARROWED to the above, because it requires overturning proposal 004 rule 4 and kernel-language.md §4.5 ('(a: Int64, b: String) and (Int64, String) are different types because the names disagree — no subtyping between named and positional'), and with it two readers that are NOT local: `._N` on a name-keyed value and `.name` on a POSITIONAL value, the latter resolvable only from the DECLARED type's component index at every access site. §4.5 states the reason such a widening cannot be gated on the reader: 'a value flows through a Function[A, B] parameter to a consumer chosen at a DIFFERENT call site than the one relating it to A, so the site admitting a permutation cannot know which reader it will meet.' Data-tuple identity is untouched; these two matrix rows stay REFUSED:

  slot (Int64, Int64)      <- value (a: 3, b: 10)   t._1   REFUSED, stays refused
  slot (a: Int64, b: …)    <- value (3, 10)         t.a    REFUSED, stays refused

DECIDED (user, 2026-08-12). Option (a) is INCORRECT IN GENERAL and is off the table. The rule is:

  AT EQUAL ARITY —
    labels ABSENT (a positional tuple)  -> align POSITIONALLY
    labels PRESENT                      -> they may be in an order other than the

This subsumes (b) and states it in one sentence over both sides instead of as a special case for `Function`. It also answers the question this feedback opened with: 'labels absent' is exactly decidable — a positional tuple's components carry the SYNTHETIC `_1.._n` (present as symbols, absent as CLAIMS), and `is_positional_tuple_names` / `TupleComponents::has_names` are the two exact predicates (WI-790).

WHAT THE RULE DECIDES, on the pair measured above:

  A = (Int64, Int64)          given sub2(p, q)   labels absent BOTH sides
                                                 -> positional -> conforms (UNCHANGED, runs -7)
  A = (acc: Int64, x: Int64)  given sub2(p, q)   labels present on A, ABSENT on the eta
