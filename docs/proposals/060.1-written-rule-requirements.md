## The problem

Today a rule gets a dictionary in two ways. A call in its body that needs one gets a read the typer adds and nobody wrote (P7VP4):

```anthill
  rule cmp(?a, ?b, ?c) :- WeakOrd.compare(?a, ?b, ?c)
```

and since ATVC1 a rule that calls such a rule passes it on, through a slot nobody wrote either:

```anthill
  rule outer(?a, ?b, ?c) :- cmp(?a, ?b, ?c)
```

Over `sort Descending provides Ord[T = Int64]`, `operation viaOuter[A](x: A, y: A) -> Int64 requires WeakOrd[T = A] = outer(x, y).head.c` answers `4` at `Descending`, as the operation's caller chose. What `outer` takes is in no text: to see it a reader has to know that `cmp` calls `compare`.

The hidden slots do not extend to a recursion. `evenS` and `oddS` below call each other, and each would need a slot for every slot of the other:

```anthill
  rule evenS(?l) :- ?l <=> nil()
  rule evenS(?l) :- ?l <=> cons(?h, ?t), ?t <=> cons(?h2, ?r),
      WeakOrd.compare(?h, ?h2, ?c), Int64.lte(?c, 0), oddS(?t)
  rule oddS(?l) :- ?l <=> cons(?h, nil())
  rule oddS(?l) :- ?l <=> cons(?h, ?t), ?t <=> cons(?h2, ?r),
      WeakOrd.compare(?h, ?h2, ?c), Int64.lte(?c, 0), evenS(?t)
```

So ATVC1 passes nothing between them, and `isEven[A = Int64, WeakOrd = Descending]([5, 3, 1, 0])` answers `0` where it should answer `1`: below the top call each clause compares with `Int64`'s own order. Measured on `6c6df13a`. A design that collects the slots of a recursion was worked out and tried (each slot named by the dictionary it holds, the recursion's clauses routed again until nothing changes, a refusal where the types grow at each turn). It needed a fallback for reads no such name covers, and it still passed nothing, silently, where a column's type is a bare variable:

```anthill
  rule triA(?l) :- triB(?l)
  rule triB(?l) :- triC(?l)
  rule triC(?l) :- ?l <=> nil()
  rule triC(?l) :- ?l <=> cons(?h, nil())
  rule triC(?l) :- ?l <=> cons(?h, ?t), ?t <=> cons(?h2, ?r),
      WeakOrd.compare(?h, ?h2, ?c), Int64.lte(?c, 0), triA(?t)
```

`triA`'s `?l` is typed by nothing in its clause, so no slot of `triA` can name the element type `triC` compares at. `isTri[A = Int64, WeakOrd = Descending]([5, 3])` answers `0`, before and after that design.

The declared form exists already, and passes a dictionary today where no recursion is crossed — measured on `0ae049a3`:

```anthill
  rule cmp[A](?a: A, ?b: A, ?c) :- WeakOrd[T = A], WeakOrd.compare(?a, ?b, ?c)
  rule outer[A](?a: A, ?b: A, ?c) :- WeakOrd[T = A], cmp(?a, ?b, ?c)
```

`via[A](x: A, y: A) requires WeakOrd[T = A] = cmp(x, y).head.c` answers `4` at `Descending` and `-4` at `Ascending`, and through `outer` `4`. Across a recursion it still passes nothing: `rule skipN[E](?l: List[T = E]) :- WeakOrd[T = E], ?l <=> cons(?h, ?t), chkN(?t)` with `chkN` comparing under `[E]` and calling `skipN` answers `0` / `0` for `isSkip[…]([9, 5, 3])` at `Descending` / `Ascending`, where `1` / `0` is right. And a citation's bracket is not read on it: `cmp[A = Int64](1, 5)` and `cmp[WeakOrd = down](x, y)` are refused, "expected an operation, which declares the type parameters a call-site `[…]` bracket binds, got a callee with no type-parameter list".

## 1. The rule

> A rule declares the type parameters it takes a dictionary at and the requirements it takes: the head's introducer names the parameter, `rule cmp[A](…)`, and its guard states the requirement, `WeakOrd[T = A]` (kernel-language §5.3). A requirement that a rule-body call or goal needs is then supplied where the call is written, as an operation call's is (§5.2). At a concrete instance it is built from the provisions at load, and nothing is declared for it. At an instance that names a type variable of the clause, it is supplied by the requirements the clause declares: the one at that instance, or one a conditional provision builds from them. Where none does, the clause is refused, naming the introducer and guard to write. A goal of another rule needs the requirements that rule's clauses declare, at the goal's argument types; a call of an operation needs what its signature requires.

In everything about its requirements a rule is held to what an operation is held to, always (the user, 2026-11-04): how many it declares at one parameter, what two of one spec mean, what a name selects, what a citation's bracket binds. Where the two differ today, the rule is brought to the operation, and where 060.1 changes the operation's rule (§8.2), it changes for both.

The operation-body rule this repeats, measured on `8de8c22e` over `Util.sign[A](x: A, y: A) requires WeakOrd[T = A]` and `Util.same[B](x: B, y: B) requires Eq[T = B]`: `concrete() = Util.sign(1, 2)` loads with nothing written and answers `-1`; `larger[A](x: A) requires Eq[T = A] = Util.same([x], [x])` loads and answers `1`, its `Eq[T = List[T = A]]` built from `Eq[T = A]` through `List`'s conditional `Eq`; the same `larger` without `requires Eq[T = A]` is refused, "requirement `Eq[T = List[T = A]]` cannot be supplied".

The recursion above becomes:

```anthill
  rule evenS(?l) :- ?l <=> nil()
  rule evenS[E](?l: List[T = E]) :- WeakOrd[T = E], ?l <=> cons(?h, ?t),
      ?t <=> cons(?h2, ?r), WeakOrd.compare(?h, ?h2, ?c), Int64.lte(?c, 0), oddS(?t)
  rule oddS(?l) :- ?l <=> cons(?h, nil())
  rule oddS[E](?l: List[T = E]) :- WeakOrd[T = E], ?l <=> cons(?h, ?t),
      ?t <=> cons(?h2, ?r), WeakOrd.compare(?h, ?h2, ?c), Int64.lte(?c, 0), evenS(?t)
```

A clause that compares nothing declares nothing; an introducer with no guard is refused, as it is today (WI-582).

- **A goal at a concrete instance** declares nothing: `rule ints(?c) :- cmp(1, 2, ?c)` loads, `cmp`'s `WeakOrd[T = A]` being at `Int64` there, built from `Int64`'s provision.
- **A goal at the caller's instance** passes the caller's requirement: `oddS(?t)` in `evenS` is at `?t: List[T = E]`, where `oddS` declares `WeakOrd[T = E]` and `evenS` holds it, so the recursion passes it at every turn. `triA` and `triB` must declare `[E]` and `WeakOrd[T = E]` too, on `?l: List[T = E]`, or be refused at their goal.
- **A goal at a larger instance** passes what a provision builds from the caller's requirements. Over `rule same[U](?a: U, ?b: U) :- Eq[T = U], PartialEq.eq(?a, ?b, true)`, `rule sameL[A](?x: A) :- Eq[T = A], same(cons(?x, nil()), cons(?x, nil()))` loads: `same`'s `Eq[T = List[T = A]]` is built from `Eq[T = A]`. A recursion through such a goal builds one more level at each turn. Where no provision builds the instance, the clause is refused: `pb(cons(?l, nil()))` in a clause at `?l: List[T = E]` holding `WeakOrd[T = E]`, when `pb` declares `WeakOrd` at its element, needs `WeakOrd[T = List[T = E]]`, which no provision of `List` builds.

A citation from an operation is held to the same: a requirement the cited clauses declare is built at load at a concrete instance, and at the operation's own type parameter is supplied by its `requires`, directly or through a provision, or refused, as a read is now (§8.1).

## 2. A citation's bracket reads what the rule declares

A rule that declares its parameters and requirements has a list a bracket can bind, as an operation's has. At a citation — an operation body's, and a rule-body goal's — the bracket binds them:

- a parameter by its name: `cmp[A = Int64](1, 5)`;
- a requirement by its spec's name, as `Fold.all[Mon = Plus](xs)` hands an operation's unnamed requirement the caller's `Plus` (kernel-language §5.2): `cmp[WeakOrd = down](x, y)` inside an operation holding `requires up: WeakOrd[T = A], down: WeakOrd[T = A]` passes `cmp` the `down` dictionary.

This is §8.3's spelling. A bracket entry that names nothing the rule declares is refused, as on an operation; and the refusal of a bracket on a rule without an introducer — "a callee with no type-parameter list" — stands.

## 3. A spec's own laws

A law written in a spec reads the spec at its own parameter, as the spec's own operations do, and declares no requirement: `constraint compare_congruent: eq(compare(?a, ?b), 0) :- eq(?a, ?b)` in `sort Ord` is at `Ord`'s `T`. This is the one rule body in the standard library that the inference reads today at a type variable (measured on `6c6df13a`).

## 4. At run time

Load decides where each requirement comes from (§1); run time reads it. Where a caller passes it — a goal of another rule, a citation from an operation — the clause receives the dictionary load routed there, built or the caller's own, and checks it against its local row where that row is unique (WI-860). Where no caller exists — a query, and a constraint or a proof the checker runs — a declared requirement finds the dictionary from the carried types when its goal runs, and waits while the anchoring value is unbound; this is the only place a dictionary is looked up at run time.

## 5. What goes

- The inferred reads of a rule body: a spec operation's call and an operation's call with `requires` of its own (P7VP4's two demand kinds), at a type variable. A call at a concrete type was dispatched by its type and keeps that.
- ATVC1's forward slots. Its citation marker stays: it is how a goal passes what §1 supplies, the caller's declared requirement or a dictionary built at load, from provisions or from the caller's requirements.
- kernel-language §5.3's sentences that a call owes its dictionary whether or not `require[X]` is written, and that a goal of another rule's body passes what that rule was passed.
- The check-only guard `requires(X)` in a rule body (WI-300), retired (the user, 2026-11-04): no rule body of the standard library, the examples or anthill-todo writes it; ten test files do, 26 goals (measured on `0ae049a3`). An operation's or a sort's `requires` line and a sort's `requires <goal>` (062) are other constructs and stay.
- `require[X]`, both its forms (060 §1, WI-1040) — the bare goal and `?d = require[X]` — removed (the user, 2026-11-04). The introducer's guard declares what the bare form put in scope, and the named form is the one place in a rule body where `=` binds, its `?d` a dictionary value no program reads. No `.anthill` file of the standard library, the examples or anthill-todo writes it; 27 test files do, 170 goals, 160 of them named, most to read which dictionary was chosen (measured on `1f70f3f9`). Each goal is refused, naming the introducer and guard to write instead; each test row is rewritten to declare its requirement so and to check the answer the dictionary gives, not the dictionary. kernel-language's paragraph on clause-level requirement binding goes with it.

## 6. The spec text this asks for (to be agreed)

§5.3, replacing "Writing `require[X]` names the dictionary or shares it among calls; the call owes it either way" and the ATVC1 sentences after it:

> A rule takes a dictionary at a type variable only where it declares it, with the introducer and its guard. A requirement that a rule-body call or goal needs is supplied as an operation call's is (§5.2): at a concrete instance it is built from the provisions, and at an instance that names a type variable of the clause it is supplied by the requirements the clause declares, directly or through a conditional provision; the clause is refused where none supplies it. A goal of another rule needs the requirements that rule's clauses declare. Over `rule cmp[A](?a: A, ?b: A, ?c) :- WeakOrd[T = A], WeakOrd.compare(?a, ?b, ?c)`, `rule ints(?c) :- cmp(1, 2, ?c)` loads, `rule outer(?a, ?b, ?c) :- cmp(?a, ?b, ?c)` is refused, and `rule outer[A](?a: A, ?b: A, ?c) :- WeakOrd[T = A], cmp(?a, ?b, ?c)` loads. Where no caller passes a declared requirement — a query — it is found from the carried types when its goal runs.

§5.4, where the bracket is read: a citation of a rule that declares type parameters or requirements, in an operation body or as a rule-body goal, reads the bracket as a call's (060.1 §2).

## 7. Stages

1. The citation's bracket of §2 and the law rule of §3, additive: a citation can say what §1 and §8.3 ask. And `requires(X)` and `require[X]` removed (§5), the refusals of this stage, their rows rewritten to the introducer's guard.
2. The refusal of §1, with the inference and the forward slots withdrawn (§5), and every program of the suite, the examples and anthill-todo that relied on them rewritten to declare its requirements. Each rewritten row is driven to the answer it gave before; ATVC1's rows through `outer`, `outer2`, the connectives and the recursion are rewritten so, and `evenS`/`oddS` and `skipN`/`chkN` answer `1` / `0`.

## 8. Open questions

2. A rule declared in a sort that has a requirement: does it use the sort's requirement with nothing declared, as the sort's operations do, or declare its own as any other rule?

     operation order(r: Self) -> Int64 = WeakOrd.compare(r.a, r.b)

6. Are `WeakOrd[T = A]` written as a goal and `require[WeakOrd[T = A]]` one requirement in a rule? Answered (the user, 2026-11-04) by removing `require[X]` (§5): the guard is the one spelling.
