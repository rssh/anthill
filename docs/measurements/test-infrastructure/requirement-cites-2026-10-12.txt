== 3. the decision (user, 2026-10-12) ==
#   1. THE CARRIER — the scope's abstract parameter is ITS OWN SMT SORT (`declare-sort`), a spec's operations on it
#      uninterpreted functions, `eq` included, a variable's sort read off its bound. Not the `Real` every operand
#      is today: that assumes identity for `eq` and a total order for `gt` that no requirement states, and a law
#      that bounds the carrier's size is inconsistent over the reals.
#   2. STAGING — this ticket: a requirement lowers to its spec's laws, a spec with no law to nothing, the
#      reproduction proves, proposal 030 records the lowering. Lowering a LAW is an emitter rework and its own
#      ticket; BVG8M's DONE WHEN is narrowed to match.
#   3. UNTIL A LAW LOWERS it is LEFT OUT AND SAID: the proof runs without it and stderr names each. Not a refusal.
#   4. THE CHAIN — a spec's OWN laws. Those of what it requires or provides in turn are not followed.
#   A LAW is a `rule` or a `constraint` item written in the spec's sort: not a default operation body (a carrier
#   may supply its own), not a fact, not a body-less declaration. `premises -: conclusion` and
#   `conclusion :- premises` are one stored form, so both are laws.
#   NOT BUILT, and nothing reaches either: lowering a specialization record; an explicit cite of a requirement.
#   FILED 2026-10-12, with the user's word, as WI-20261012-ZZ7PH: lowering a law — the head, the operations, the
#   carrier's sort — and with it section 4's (1), the verdict that is of the reals.

== 4. what /code-review changed, each reproduced on the first cut ==
# THE FIRST CUT kept S8CYD's reader — the requirement RECORDS of the enclosing scopes, by each record's witness —
# found each record's clause again by the text the witness has (`load::requires_clause_of`, which `anthill check`
# was moved onto too), read the laws of the clause's spec, and warned at every query, naming the proof. Fifteen
# findings; what was done with each:
#
# (1) UN-REFUSING THESE PROOFS LETS A CLAIM ABOUT THE ABSTRACT CARRIER BE "PROVED" OF THE REALS. Reproduced:
#       sort Scope  sort T = ?  requires anthill.prelude.PartialOrd[T = T]
#         rule refl_like: gte(?a, ?a) :- gte(?a, ?b)     proof refl_like by z3(logic: "LRA") end
#     `✓ … proved (z3: unsat)`; the document is `(declare-const var_0 Real) (declare-const var_1 Real)
#     (assert (>= var_1 var_0)) (assert (not (>= var_1 var_1)))`. `PartialOrd` has no law, so nothing is said.
#     THE SAME RULE IN A SORT THAT REQUIRES NOTHING PROVES TOO, before this change and after it: the model is the
#     emitter's, not the requirement's. What the change adds is the population — proofs under a `requires` were
#     kept from running, by accident.
#     NOT FIXED HERE: it is the carrier's own SMT sort (section 3, 1), which is the other ticket. DONE: the doc at
#     `tell_laws_left_out` and proposal 030 no longer say a proof that needed a law fails — they say what leaving
#     a hypothesis out guarantees and what it does not; and a row holds the document as it is,
#     `a_verdict_under_a_requirement_is_about_the_reals`, which is the row the sort turns.
# (2) AN EQUATION WRITTEN `fact lhs <=> rhs` WAS NO LAW (it is stored as a fact, and the first cut took rules
#     and constraints by kind). Reproduced: a spec with four laws and such a fact reported four. A fact that is an
#     equation is a law now; any other fact is not.
# (3) THE CHAIN, as decided (section 3, 4), and what it leaves unsaid. Reproduced: `requires Ord[T = T]` names
#     `Ord.compare_eq` and not the nine laws of the `WeakOrd` that `Ord` provides; `sort Strict  provides
#     Ord[T = T]` and `requires Strict[T = T]` says nothing at all. NOT CHANGED — the decision stands; a row holds
#     both (`the_laws_of_what_a_spec_provides_in_turn_are_not_read`) and the proposal says them.
# (4) A RULE WRITTEN WITH TWO HEADS is two clauses under one label, and was "2 laws" named twice. A name is
#     printed once now, with how many clauses go by it: `Measured.two_heads (2 clauses)`.
# (5) A READ THAT FAILED WAS AN EMPTY LIST — a bodied rule in the relation printed `error:` and the proof ran as
#     if its scope required nothing. It is the proof's EmitError now (`implicit_cites_for` returns a `Result`).
# (6) "WITH NO CITATION LABEL" said nothing of what the seven were, and one of `WeakOrd`'s seven is a constraint
#     that HAS a name in the source. A law is named by its label, or by the predicate a rule with no label is of
#     (as `using` cites it); the rest are counted by kind: `6 unlabelled equations, 1 constraint`. A constraint's
#     name is a declaration's and is not on the stored clause — to name it the loader would label the clause,
#     which would also change what `using <that name>` resolves to. Not done.
# (7) THE WARNING WAS ONCE A QUERY: a structured proof of N steps printed N + 1 lines. Once a run for each
#     requirement now, and it names the scope and not the proof.
# (8) THE CLAUSE WAS FOUND BY RE-RENDERING EVERY ROW'S TEXT AND MATCHING IT, which made a state to check for —
#     a record of no clause — and an error branch to refuse it. The clauses are read off the declarations now, by
#     the scope each is of (`load::requires_clauses_of`); there is no record to mismatch. `anthill check` is as it
#     was before this ticket: the first cut's move of it onto the shared lookup is taken back.
#     A row holds the records and the clauses to each other: the same set, by name.
# (9) the text assembly written twice (`requires_clause_of` beside `qualified_spec_text`): gone with (8).
# (10) the relation read once a requirement: once a query now, and a scope's name compared without a copy.
# (11) `RequirementCite.record`, derivable from its other two fields: gone with (8). `SpecLaw.clause` is read
#      now — its kind and its head name the law (6).
# (12) a copy of `prove_dry_run` and one more of `z3_available`: both are in the CLI suite's `common` now, and
#      `wi781_policy_dispatch_test` uses the first. Twelve older files keep their own `z3_available`; not moved.
# (13) proposal 030's "`using` semantics" still said the two kinds of cite are joined into one list: corrected.
# (14) `spec_laws` looks the spec up by the symbol the clause's row has, uncanonicalized. NOT CHANGED: the
#      review could build no case, and neither could this — a spec forward-referenced, imported, aliased and
#      written by its qualified name all resolved.
# (15) the unit row counted every proof of the KB, the library's with them: it dispatches its three by name.
