== 5. why the later load is the dearer: eight rows the load that asserted them never checked ==
# 405 rows when the stdlib's own load runs the pass, 413 at every load after it. The eight, listed by a temporary
# line (the row's carrier and spec), are the `NonEq` provisions `eq_derive::run` derives for the composites that
# reach a Float:
#     anthill.prelude.List, .Option, .Result; anthill.reflect.Expr, .LiteralRepr, .TermRepr;
#     anthill.geometry.Vec3, .EulerAngles                                    — each `provides anthill.prelude.NonEq`
# `eq_derive::run` stands BELOW `check_provider_requires` in `load_phase_inner`, so the load that derives one of
# these never asks whether it holds; the next load does, for all eight, and they hold (0 failures).
# They are 8 more rows with a goal, 9 more resolutions, 15 more frames and 684 more candidate rows visited
# (8 987 against 8 303, +8.2 %): the pass is 26.9–27.0 ms on a later load where it is 24.9–25.4 on a full one.
# WHAT THIS MEANS FOR A FRONTIER: "a provision is checked by the load that asserted it" is not what happens today
# for a row derived below the pass. A pass that skipped every row of an earlier load would never check these.

== 6. two probes: what each shape would buy (the MARKED binary, a temporary switch; ITERS=15, one run each) ==
# (a) `memo` — the search as it is, three of its per-row reads memoized for the length of the pass: `sort_provides`
#     by (carrier, spec), `is_conversion_row` by row, `impl_param_symbols` by provider. Valid for a probe because
#     the pass asserts nothing. Every count of sections 2 and 3 unchanged (the same 8 987 rows visited, the same
#     167 candidates, 0 failures).
# (b) `sealed` — the pass skips a row a seal holds (`kb.sealed.holds_rule_slot`), with NOTHING put in its place:
#     no refusal, no re-check, the eight rows of section 5 skipped with the rest. An upper bound, not a design.
#                                              full    later, plain   later, sealed   later, copy   later, sealed copy

#     which seals nothing, and a full load are as they were.

== 7. what a later load can change of an earlier provision's verdict — probed where it could be, read otherwise ==
# A verdict is: each `requires` of the provided spec, at the provision's bindings, resolves under each clause of
# the provision, the carrier's own provision first (`resolve_within_provider`). What it reads, and who can write it
# after the fact:
#   * THE SPEC'S `requires`, AND THE CARRIER'S (the assumptions). PROBED, the CLI (stdlib sealed, then the file):
#         namespace anthill.prelude.Eq    requires test.f1.Marker[T = T]  end      79 errors
#         namespace anthill.prelude.List  requires test.f2.Marker[T = T]  end       1 error
#     Both are refused where they are written — "`requires` is not allowed in a secondary entry of sort …" — and
#     the fact is asserted all the same: the first load's other 78 errors are this pass refusing every provider
#     of `Eq` in the stdlib, and every provision whose contract reaches one ("'anthill.prelude.Pair' provides
#     'anthill.prelude.WeakOrd', which requires 'anthill.prelude.Eq', and its provider … was chosen, but
#     `test.f1.Marker[…]` beneath it does not hold"). So the one way to add a `requires` to an earlier sort is a
#     refused load already; what the pass adds to it is 78 errors about the library. A refused load does not
#     unwind, so the fact is in the KB for the load after it — which this pass is what refuses, today.
#   * THE PROVISION'S OWN CLAUSES (`ProvidesConditionInfo` by carrier and spec). A later `provides S[…] :- g` for
#     a sealed carrier that already provides `S` at an overlapping head is the typer's refusal behind a seal
#     (`sealed::provisions_that_change_a_sealed_dispatch`, "written for … which a sealed load declared and which
#     already provides it there"). Read, not probed here.
#   * WHO ANSWERS A GOAL — the provider relation, which only grows. A goal of an earlier provision names that
#     load's types and the carrier's own parameters, nothing else. The same refusal holds a later provision whose
#     spec and head types are all a sealed load's to leaving every such answer where it was (it refuses the more
#     specific one, the tie no default arbitrates, the overlap); a provision with a type of the later load's own
#     in its head is not held by it. Read, not probed; and that rule was written for the calls in sealed BODIES —
#     whether it is complete for the goals of sealed PROVISIONS is what an oracle run would say.
#   * Nothing sealed (a plain sequence of `load_all`; `KB.loaded` at eval): none of the above is refused, and a
#     second provider can tie an earlier provision's goal.
