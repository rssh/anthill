== 1. the count (before anything was decided) ==
# WHAT A STORED RULE KEEPS OF A VARIABLE'S BOUND.
#   A bound can be written on a HEAD variable and nowhere else. In `sort Scope  sort T = ?  requires Eq[T = T]`:
#     rule irreflexive(?a: T) :- neq(?a, ?a)                loads
#     rule refl_like: gte(?a: T, ?a) :- gte(?a, ?b)         loads
#     rule refl_like: gte(?a, ?a) :- gte(?a, ?b: T)         load error: "type mismatch in typed_var.apply: … unknown
#     rule irr :- neq(?a: T, ?a)                              functor"; "rule-body term `typed_var` names nothing"
#     rule sym: eq(?b, ?a) :- eq(?a: T, ?b: T)              the same
#   The rule keeps a bound two ways (`anthill query --mode domain`):
#     irreflexive(?#1) :- __domain_guard(?#1, ?#0), neq(?#1, ?#1), apply_domain(?#2, ?#1, ?#0),
#                         find_dictionary(SortDomain, SortDomain, ?#1, out: ?#2)
#   — `rule_type_bounds` (De Bruijn index → type), and goals the loader generates: the type test in front of the
#   body, the fill and the read of its dictionary behind it, with one more frame variable. The scope's `T` is a
#   VARIABLE OF THE RULE'S FRAME (`?#0`), not a name. `ProgramClause`, which is what the emitter reads, carried
#   neither the bounds nor the rule's id.
#
# THE EMITTER REFUSED EVERY PROOF WHOSE RULE HAD A BOUND:
#     rule pos(?x: Float) :- gte(?x, 5.0), gte(0.0, ?x)     error: … v0: unhandled body goal functor
#     rule posi(?x: Int64) :- gte(?x, 5), gte(0, ?x)          'anthill.kernel.__domain_guard'
#     rule irreflexive(?a: T) :- neq(?a, ?a)                the same
#   So NO DOCUMENT THAT EXISTED HAD A BOUNDED VARIABLE. And past the guard two more refusals stood, which the
#   ticket did not list: a one-variable head `irreflexive(?a)` is read as a result the body must bind ("rule body
#   never bound the result variable"), and a head of two variables is "rule head shape not supported
#   (functor=…, pos_args=2)" — so a violation rule could not have two bounded variables at all.
#
# WHAT THE TYPER KNOWS OF A RULE VARIABLE THAT HAS NO BOUND (read of the code by a search agent; the accessors
# it names were checked to exist, the stamp itself was not dumped). The rule-body sweep infers a type for each
# variable from the declared types of the operations and fields the body names
# (`typing::rule_dispatch::collect_rule_var_types`) and stamps it on the body's variable leaves
# (`NodeOccurrence::inferred_type`); the map is then dropped. For `neq(?a, ?a)` the stamp is a FRESH,
# UNCONSTRAINED type variable — `PartialEq.T` instantiated per application — and nothing ties it to the scope's
# `T`. A BODYLESS clause gets no stamp at all, which is most laws (`rule eq_refl: eq(?a, ?a) <=> true`), and a
# head-only variable none. So the typer does not say more than the signatures do, and for a law says nothing.
#
# WHICH VARIABLES OF THE PROOFS RANGE OVER AN ABSTRACT PARAMETER. 35 files of the tree hold a `by z3`; the ones
# that are driven to a document are lf1's three (16 proofs), the CLI suite's `prove_*` / `check_*` /
# `wi781` / `wi_bvg8m` files and `prove.rs`'s unit rows, and the emitter crate's suite. A `sort T = ?` stands
# above a driven proof in BVG8M's fixtures and nowhere else. Of their variables ONE proof's range over the
# parameter: `refl_like`'s `?a` and `?b` (`gte(?a, ?a) :- gte(?a, ?b)` — no bound, and nothing else pins them),
# in two rows. Every other variable there is compared with a literal or read off an `Int64` field. lf1 has no
# abstract parameter.
#
# THE LIBRARY'S 42 REQUIREMENT RECORDS (`SortRequiresInfo`, by `anthill query`). The 11 of a spec with a law:
#     Lattice requires Eq[T]            Map requires Eq[K]              Set requires Eq[T]
#     WeakOrd requires Eq[T]            Field requires PartialEq[T]     NonEq requires PartialEq[T]
#     PartialOrd requires PartialEq[T]  Field requires Ring[T]          VectorSpace requires Ring[F]
#     SortedSet requires WeakOrd[T]     BoundedLattice requires Lattice[T]
#   ALL ELEVEN bind the spec's parameter to the scope's OWN parameter. None is at a concrete type, and no scope
#   has two requirements of one lawful spec.
#
# z3 ON HAND-WRITTEN TARGET DOCUMENTS (a declared sort `T`, `eq` and `neq` declared `(T T) Bool`, one constant):
#     (assert (neq var_1 var_1))  with `eq_refl` and the `neq` law          unsat
#                                 with `eq_refl` alone                      sat
#                                 with the `neq` law alone                  sat
#                                 with neither                              sat
#   — so the ticket's control under `requires Eq[T = T]` ALONE needs `PartialEq`'s law, which is the chain (e).
#     `gte(a, b)` and `(not (gte a a))`, `gte` declared, no law                sat
#     `(forall ((a T) (b T)) (= (eq a b) true))`, alone                         sat  (consistent over a declared sort)
#     any of them under `(set-logic LRA)`     (error "… logic does not support uninterpreted functions"), then `sat`
#     under `UFLRA`, `UFLIA`, `ALL`, `UF`, and with no `set-logic` at all     as above; `LIA` took the declarations
#   — so the logic a proof writes cannot be used as it stands once its document declares a function.
#
# AND ONE THING THE CORE ALREADY HAD: `typing::requires_tree` — the transitive chain of a sort's `requires`, a
# spec's `provides` in it as a conversion, the bindings composed into the root's terms. Proposal 030 had the
# chain as "not built — it wants the bindings composed along the chain".

== 2. the decisions (user, 2026-10-12, on section 1) ==
#   (a) A VARIABLE THAT NEITHER A BOUND NOR AN OPERATION'S SIGNATURE GIVES A SORT, in a rule under a scope that
#       has an abstract parameter, is REFUSED. Sorts come from bounds and follow through signatures (`gte(?a: T,
#       ?a) :- gte(?a, ?b)` gives `?b` the sort of `?a`); in any other scope such a variable stays a `Real`.
#   (b) A REQUIREMENT AT A CONCRETE CARRIER takes the THEORY'S operations: `Int64` / `Float` a `Real` as in every
#       proof, `eq` is `=`, the law emitted whether or not it is a theorem; a law naming an operation with no
#       row, or at a carrier with no SMT sort, is left out and said.
#       TURNED AFTER THE REVIEW (section 6, finding 4), to the option it was chosen over — "left out and said":
#       a law true of the integers and false of the reals, asserted over `Real`, is inconsistent, and a proof
#       under it proved anything. NO LAW IS LOWERED AT A CONCRETE CARRIER: a law is asserted only where every
#       variable it quantifies is of a declared sort. The question as put to the user said "whether or not it is
#       a theorem there" and did not say "or false there".
#   (e) THE CHAIN IS FOLLOWED: a requirement gives the laws of its spec and of what that requires or provides in
#       turn. BVG8M's "a spec's own laws" is turned.
#   THE LOGIC IS DERIVED: the one written, `UF` added when the document declares a function, `QF_` dropped when
#       a hypothesis is quantified; a document that declares nothing keeps it.
#   Taken as following, and said to the user with the questions:
#   (c) TWO REQUIREMENTS OF ONE SPEC AT TWO PARAMETERS — an instance is (operation, carrier sort), so `eq` at `T`
#       and `eq` at `U` are two functions; a variable whose sort nothing gives is (a)'s case.
#   (d) A CONSTRAINT'S NAME — unchanged: counted by kind, its clause not labelled.
#   A ROW-LESS OPERATION AT THEORY OPERANDS stays the loud error it is; it is uninterpreted at a declared sort only.
