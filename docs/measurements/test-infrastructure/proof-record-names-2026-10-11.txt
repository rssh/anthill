== 2. the decision (user, 2026-10-11) ==
#   * THE BINDINGS GO INTO THE NAME, bracketed: `<X-qn>.provides.<PE>.<SE>`, `<PE>` the provided spec by its
#     qualified name with its bindings — `test.sg.W.provides.test.sg.Tag[T = test.sg.P].<SE>`. Not a flattening
#     (shorter, and `a.P` / `b.P` still one name), and not "a record is its name and its substitution" (two
#     records under one `rule`, and every whole-string reader given a second key).
#   * `<SE>` AND THE WITNESS'S `substitution` TAKE THE SAME TEXT, in the same change: `<scope-qn>.requires.<SE>`
#     with `<SE>` written as `<PE>` is, the `aspect` with it, and `concrete_sort` the binding's value as the name
#     has it.
# The text of a spec at its bindings (`load::qualified_spec_text`): the spec's qualified name; in brackets each
# binding as `<parameter> = <value>`, in the order of the parameters' names; a value the type it is, in full, every
# sort by its qualified name, a nested application's bindings in the order of their names; a binding whose value is
# an operation left out. The value is written by the walk a diagnostic's type is written by
# (`typing::display`), in a third spelling of it — a second renderer would be a second answer to how an arrow, a
# row or a value held in a type is written.
# Recorded in proposal 030, "Record names".
