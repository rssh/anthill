## Description

Typer: higher-kinded / structured sort parameters + sort-carried projection (X.L / T.V) -- the SOUND-tie destination surfaced by the Modify-model redesign (WI-379 follow-on). GAP (recon OQ-E, expansion-during-unification.md sec.3.6 + sec.4 case 3 / WI-376): the typer has NO semantic support for (a) a STRUCTURED/higher-kinded sort parameter -- a sort param that itself declares members, e.g. 'sort T' with a nested 'sort V = ?' (the BODY form; the alias spellings 'sort T = { sort V = ? }' and 'sort T = sort { sort V = ? }' do NOT parse -- verified tree-sitter; the body form DOES parse, including the projection in op sigs), nor (b) the sort-carried projection 'T.V' (= the X.L form) that reads such a member as a type. The doc's 'check_ho_apply_pattern' reference is a conflation -- only check_ho_apply_pattern_occ exists (rule-body ho_apply SLD fragment), unrelated to type-level HKT. MOTIVATING USE CASE (the immediate driver): the SOUND Modify value-type model. ModifyRuntime[T = resource, V = value] now carries the value type V as a SEPARATE param, but V is inferred per-call and UNTIED to the resource (free: filled from the value arg for set, from the expected return for get) -- so 'read() -> String = get(counterHoldingInt)' is wrongly accepted (a soundness hole). The principled fix records the tie ON THE RESOURCE: 'sort CounterState' declares 'sort V = Int' (body form), and 'get(target: T) -> T.V' projects it so get(counter()) : CounterState.V = Int and a String read is REJECTED. DESUGARING (type-parameter-scoping.md sec.1 / 042): T.V == an op type param + a requirement, get(target: T) -> T.V  ==  get[Vi](target: T) -> Vi requires T[V = Vi]; the requirement binds Vi from the resource's declared V member (or a 'fact ModifyRuntime[T=R, V=...]' provider fact -- the GROUND-valued provider-fact bind is itself a small bind_spec_params_from_carrier extension, the cheaper half). Cell already provides 'fact ModifyRuntime[T = Cell, V = V]' (V threads from Cell's own V param, the List-provides-Stream-style carrier bind) -- but the TYPER does not yet consult that at a non-self-receiver get(target:T) call (target is typed T, not ModifyRuntime, so receiver_carrier returns NotApplicable). SCOPE: (1) structured sort-param representation through parse(verified)->load->typer; (2) sort-carried projection T.V elimination at the unify boundary (the WI-376 case-3 half) + its requires plumbing; (3) ground-valued provider-fact binding (the small bind_spec_params_from_carrier extension) for entity resources; (4) ground/abstract split + decidable-pattern-fragment bound for an unbound higher-kinded head (loud error outside it). RELATES WI-376 (projection x.A/X.L; this is the sort-carried T.V half over structured params), expansion-during-unification.md sec.3.6/sec.4 case 3, OQ-E, type-parameter-scoping.md. Body-form syntax 'sort T ... end' with nested 'sort V = ?' is the ACCEPTED surface (user-confirmed). Until delivered, ModifyRuntime keeps V free (loose; m5 tests pass but the wrong-value-type read is not caught). Rust-only (typer). DESIGN-then-impl.
